## 2. Qualify numerator/denominator across physical resource boundaries

First prove that one actual DSA A2A exposes nonempty native op→rank/peer→bytes/path records. Use real count ABI, ordered group membership, source/destination mapping and correctness checks; distinguish useful payload, retransfers/multihop bytes and duplex direction. Empty exports or zero unavailable transit fields must return UNSUPPORTED, as Run414 prescribes. Do not repeat an entire profiled service until this minimal export works.

A paired weight-working-set screen should identify which hierarchy boundary the counter measures and whether the selected data were already resident above it. Reuse existing GMM bank evidence; add new measurement only for an unresolved physical boundary or mixed condition. AIC+AIV task reads and GM→L1 are not automatically HBM transactions. Validate counters using controlled known bytes and resident versus larger-than-fast-memory working sets before applying them to model traffic.

Then measure concurrent same-shape attainable service and contention, but distinguish:
- an attained bandwidth is a **lower observation on achievable capacity**;
- a latency floor requires a justified **upper bound on capacity**;
- dividing necessary bytes by an attained bandwidth is a conditional engineering model, not a rigorous physical floor.

A conservative physical/specification capacity cap can supply a deliberately loose strict denominator once units, channels/topology, dtype execution resources and duplex conventions are proven. It should be reported beside empirical attainable service, never substituted for an achievable estimate. Peak-only arithmetic remains insufficient for the requested useful bound.

Promotion gate:
- identified hierarchy/cut, byte accounting and topology match the denominator;
- a positive compulsory-byte/work subset is proven for the declared architecture class;
- capacity upper cap is justified separately from sampled service;
- shared links/AIC/AIV/HBM are not counted as independent full-rate resources;
- mixed service/overlap uncertainty is preserved when estimating achievable performance.

Run414's 306.659328 MB two-way logical 4|4 census does NOT satisfy the compulsory subset gate. Current placement, opaque fresh payload, no reuse/recompute/zero elision are restrictive assumptions. Hidden→router recomputation, embedding zeros, dead MTP stash and alternative consumer placement invalidate treating all265 materializations as semantic information. Physical transport measurement cannot repair this logical gap by itself.

## Finite endpoints: correct the overly strong closure requirement

A **strict but loose finite throughput ceiling does not require a complete work numerator, every DAG edge, or an E2E intervention**. One proved positive compulsory resource subset W^- and a valid capacity upper cap C^+ suffice:

    T* >= L = W^- / C^+ > 0
    TPS* <= Q / L, Q = 49152 external output tokens

Multiple valid resource/path relaxations combine by max, not by unqualified summation. Add lower times only where their serial dependence and non-overlap are proved. A relaxed resource-constrained DAG must admit every legal execution in its stated class; retaining optional Current barriers can falsely raise its lower time.

Current V3.10 still has no demonstrated valid W^-/C^+ pair, so this review promotes no numeric endpoint. But its missing-fields list should not be interpreted as requiring total Target+Draft+prefill closure before ANY finite ceiling can exist. Partial necessary work can suffice; partial CURRENT work cannot.

An **achievable Engineering/Aggressive interval** is a different claim. It needs a legal construction with semantics, storage and resource feasibility plus measured service/calibration; a lower relaxation alone supplies no attainable endpoint. A feasible execution and a valid relaxation can bracket optimum time within a declared class. Formal repeated E2E decides a delivered candidate's product performance. A formal intervention is not logically required to publish a correctly scoped analytical outer bound.

## Overlooked architecture-independent and broader floors

1. **Memory-capacity cuts / red-blue-pebble style accounting.** For any necessary distinct input set S consumed during a window and at most M bytes of usable resident capacity above a memory boundary, at least max(0, |S|-M) bytes must enter that boundary, assuming those inputs cannot be generated/reconstructed there. This is independent of kernel names and current scheduling. It avoids charging the entire expert set once per cycle and explicitly permits cache reuse. Need actual usable fast-memory capacity, initial residency/replication and representation/recompute assumptions. For HBM traffic, M is capacity ABOVE HBM, not total HBM capacity. With recomputation/weight movement alternatives, derive a compute/communication/storage tradeoff rather than a universal byte count. Run405's conditional retained set is not yet a certified S.

2. **Request-causality/cardinality plus external ledger.** Once p_i is known, under the explicitly fixed ordinary DSpark7 contract (at most8 newly committed tokens per request per verification), n_i >= ceil((1024-p_i)/8). This survives runtime/host rewrites but not an unrestricted alternative speculative algorithm or prior-output cache. Current zero-output handoff gives the recorded512 global capacity term for four c12 cohorts. It is dimensionless; never multiply by an observed Current cycle time and call it a hardware floor. Request chains and slot capacity are separate necessary constraints; actual arrivals/prefill/state strengthen them.

3. **Required externally visible I/O.** Frozen API publication has a positive data-transfer/output-serialization requirement independent of NPU execution layout. A verified minimal byte ledger plus conservative relevant interface capacity yields a very loose Product floor even if model-resource proof remains open. Do not equate output tokens to arbitrary bytes or assume all output is a dense logit/ID tensor. This bound will probably be practically weak; record it only if essentially free to derive, not as a new measurement campaign.

There is no justified nonzero universal internal TP8 wire-byte floor in the current evidence: placement, representation, recomputation and output-owner choices remain free. Likewise2MNK standard GEMM equivalents are not proven minimum arithmetic over every legal algorithm. State the admissible algorithm/model-evaluation class explicitly; otherwise broad “architecture independent” labels overclaim.
