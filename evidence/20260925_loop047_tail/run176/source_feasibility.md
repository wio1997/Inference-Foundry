# Run176 fixed-tail compaction source feasibility

Read-only source audit; no service/NPU use. Product: DeepSeek V4 Flash W4A8, TP8, DSpark7, fixed c12, warm 1024-output cohort.

- Run175 measured cohort exposure:296 cycles, 18.525% parked slot-cycles;44 cycles active<=6,27 active<=3,16 active<=1. Warmup cohort fractions range9.68-19.47%. These are not marginal device-latency measurements.
- `runtime/fixed_serving.py::_park_completed` retains fixed shape: it rewinds finished slots to their own reserved KV blocks, asks DSpark to park them, and sets active_mask false. `FixedDecodeRuntime.advance_state` zeroes committed counts for parked slots; the target and proposer still execute all12.
- `runtime/fixed_decode.py::FixedDecodeConfig` defines 12x8=96 target tokens; state.bind, prepare_target_inputs and advance_state use batch12 layout and physical block table. `runtime/target_adapter.py::FixedTargetAdapter.execute` requires exactly96 input/position tokens and stable data pointers, then expects96 hidden tokens. `runtime/target_metadata.py::FixedTargetMetadataUpdater` explicitly requires query_start_loc length13, target96, batch12, CP shard12, and writes 12/96-element metadata, rotary and SWA mappings.
- `runtime/extreme_decode.py::step` consumes complete12x8 acceptance/draft shapes each cycle; `bootstrap/vllm_dspark_handoff.py` requires fixed draft tensor shape12x7. A smaller target alone must scatter output back into the original slot order and provide valid hidden/aux states to the unchanged proposer, or redesign both together. Physical KV/DSpark parking addresses, prefix/CP ranks and collective order must remain exact.
- Borrowed service `FULL_DECODE_ONLY` config captures token sizes8..128 in steps of8 (Run173 engine startup log), including48, but this does not create a usable c6 Extreme target closure. The bound metadata and runtime ABI are c12-specific.
- Run150 one-card GMM counters imply W4 weight traffic near1 TB/s at product shape. Fixed weight reads may not shrink when active slots do. No measured c6 vs c12 target latency exists, so Run175's2.553s/cohort linear arithmetic exposure cannot be promoted to an achievable bound.

Sol triage: do not build a c6 runtime image yet. The least-cost falsification is a legal real-weight TP8 target graph marginal-latency comparison at matched KV lengths for c12 versus c6/c3, with full graph replay and exact metadata, and explicit HCCL/compute effects. If the latest-rank target cadence barely falls, reject compaction despite parked slot cycles. If a material reduction appears, then design slot gather/scatter, metadata/graph variants and A/B/A-prime state parity. Keep product runtime unchanged until that gate passes.
