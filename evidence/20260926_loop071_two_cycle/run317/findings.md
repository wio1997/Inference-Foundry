# Run317 — two-cycle selected-backing envelope from existing real trajectories

`loop071_two_cycle_union.py` reuses Run301 original FULL Graph read-only metadata, not a new service. For each of eight ranks and five true adjacent-cycle pairs (0→1, 63→64, 127→128, 175→176 first parking, 255→256), it converts all 14 selected layer0–5 source candidate write pages to typed byte intervals and merges them on the three shared physical backings. The result is 40/40 valid pair registries, three backings per pair, conservative two-step interval unions of **7,181,056–7,705,344 B/rank** (median 7,312,128 B). The eight ranks share the same union size for each selected pair: 0→1 7,705,344B; 63→64 7,181,056B; 127→128 7,643,968B; first parking 175→176 7,250,752B; 255→256 7,312,128B.

This is an address envelope for **selected** metadata-derived candidate writes. It is not measured HBM traffic, native exact writes, all 43 Target layers, Draft KV, Host mirrors, metadata, Graph workspace or a complete mutable-state snapshot. The noncontiguous byte intervals can be substantially smaller than cloning the three complete backings (~2.376GB/rank in Run299). Cross-run allocation pointers differ, so only shape/offset methodology transfers. The page union gives a plausible bounded storage strategy for a layer2 shadow, but no semantics or performance claim.
