# Run299 — typed cache alias and selected-cycle liveness screen

Original frozen DP1×TP8 DSpark7 c12 Runtime, Target FULL Graph. The environment-gated diagnostic only reads typed cache views and pre-Target metadata; it does not change the Graph or claim a performance improvement. `scripts/run299_storage_census.sh` exited **0**. The 12 diagnostic clients each produced 1024 tokens, all eight Runtime cohort reports passed with `target_graph_mode=FULL`, and all eight NPUs returned to idle. The 526.207 tok/s single-cohort diagnostic result is not comparable to formal Run99.

All eight ranks registered 196 typed static-context KV leaves, including three DSpark draft leaves. Fifteen typed views per rank touch three layer2-related backing stores (141,810,240 + 1,117,028,352 + 1,117,028,352 = **2,375,866,944 bytes/rank** in this allocation). The three draft leaves overlap none of these stores. The neighboring Target layers do alias the two large stores, so the earlier Run287 pointer census did not cover all typed interpretations. The one-page difference from Run287 reflects allocator sizing in this bootstrap, not a traffic change.

Ten selected pre-Target samples/rank include cycles 0→1, 63→64, 127→128, first parking 192→193, and 255→256. For the five layer2 cache sources, a source-derived candidate nonowner current-write domain has **zero page intersections** with the corresponding owner read domains, including cross-view pairs on the same backing, across the 80 rank-cycle samples. The read domain is last eight state tokens for layer2 state, 128-token SWA window plus current eight, and conservative prefix pages for compressed QLI/Sparse. A deliberately overbroad all-history SWA page envelope gave 35 page intersections; refining the actual 128-token window to physical `(page, slot)` gave **zero** intersections. This shows why whole-page or full-prefix alias checks can misclassify a hazard.

Astra High requested a second source-derived check rather than treating the above as lifetime closure. For all same-backing layer2 source pairs, nonowner writes also have zero page intersections with owner current-write domains in 80 samples and owner bounded reads in the five adjacent sampled pairs/rank (40 pairs). The candidate compressed write envelope was conservatively expanded to every one of the eight original positions before this check. This still leaves unobserved intervening cycles and later layers.

The compressed writes and QLI/Sparse prefix reads are source-derived address envelopes, not native per-byte traces. Nonowner writes might still affect a later consumer, a different rank, or another layer through shared backing. The current capture omits live metadata for layers 0/1/3/4/5 that alias the same stores and does not establish page epochs, last writer, actual read-from values, mathematical necessity, or a Product critical-path saving. No compulsory traffic or Resource/Scheduling/Product numeric bound changes.

**Decision:** Run299 passes as a read-only census. Next capture a compact current-write / protected-read page and typed byte-domain registry for all 14 Target source names on these three backings, including adjacent cycles and parking. For c128 neighbors, derive cache address ratio, producer compression ratio and `coff` separately from actual objects/specs; the state-cache address ratio 1 is not the c128 producer ratio. Preserve complete Draft typed descriptors. Classify semantic RAW separately from allocator WAR/WAW, and respect layer order: layer3/4/5 reads follow layer2 writes in the same cycle, while layer0/1 reads can follow in the next cycle. Only an unresolved concrete overlap warrants a value-level same-prestate consumer experiment; avoid cloning whole multi-GB stores.

Evidence: `analysis.json`; eight `rank*_registry.json`; eight raw `rank*.jsonl` files (large diagnostic logs kept locally); `bench12.json`; eight `runtime/rank*_cohort1.json`; `stop.log`. The independent Astra High review is requested separately.
