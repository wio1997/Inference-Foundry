## Exact reconstruction and admission

Use explicit symbols in the artifact: `q[c,s] = count_history[c,s]` is effective count **after active-mask application**; raw acceptance count can differ for parked slots. Define Runtime retained count `R[c,s] = min(q[c,s], max(0, remaining[s] - sum_{k<c} R[k,s]))`. Concatenate `tokens[c,s,:R[c,s]]` to reconstruct precisely the Runtime bulk output. Require exact equality with runner output before Scheduler. Do not equate staged token sum with useful tokens.

Let `G` be Scheduler output length just before the bulk append, and `A` the actual post-append admitted bulk list. Require `G_after-G_before=len(A)` and exact `A == incoming_bulk[:len(A)]` for the inspected nonstale greedy branch; preserve failures rather than force this relation. Map each Runtime token offset to an admitted offset only if it survives this prefix clipping. Subsequent output processor/API transformations are independently joined, not inferred from completion_tokens=1024. Preserve ordinary pre-handoff outputs, so the external sequence is ordinary output followed by admitted bulk, under verified source behavior.

The pinned greedy implementation and Run524 establish a conditional lemma: each accepted speculative-prefix token equals the corresponding Target argmax, including recovery/bonus. This avoids capturing every logits vector. The sparse selected row still needs actual row/logits mapping, context/position, generation and source-class execution ownership. A source theorem is not an observed all43 native traversal.

**Raw ID delivery relation is a transducer relation.** The API parser can consume tokens then return `delta_message=None`, suppressing a yield; detokenization may buffer text and stream_interval may aggregate tokens. Store ordered raw input chunks, their exact output text/parser outcomes and the actual serialized yields. Replay the pinned tokenizer/parser offline if claiming an exact external representation relation. Matching client/server payload bytes proves which representation reached the client; it does not prove an injective text→token mapping or that suppressed control tokens were exposed. Keep such raw-token membership conditional where the product definition requires literal ID delivery. Do not retokenize concatenated text and assume identity. Do not turn on `return_token_ids`: current API source shows that this can force otherwise-suppressed chunks and change the frozen streaming protocol.

## Preparation and timing scope

Warmup48 followed by measured48 at c12/1024 is 96 requests, normally eight12-request cohorts and 64 rank-cohort records. Treat those counts as expected under unchanged fixed handoff; fail or explicitly explain deviations rather than renumber missing cohorts. Capture both phases, but compute measured Product interval solely from actual client wall_start→wall_end. Separate Host monotonic_ns from device/event clocks; record boot/time-namespace/offset/resolution identity in each process and client. Do not subtract unvalidated clock domains.

Cache lookup and schedule ranges give actual residual work, arrival and enqueue give legal releases, and seed/handoff gives Host transitions. None is a device-ready event. The minimum acquisition should report `prefill_device_complete`, `seed_device_ready` and all8 collective-ready edges as unknown unless an existing supported completion observation directly establishes them. A first-Target Host submission provides only a dependency/source observation. Later instrument only the preparation/Target/DSpark frontier selected by these records to acquire mixed-resource service; do not delay this ledger for exhaustive native terminal identity.

**Warmup/reuse caveat:** warmup runs the same prompts to1024. A new measured request ID, fresh observed launch, or no Current result-cache branch does not prove that every semantically necessary key is new under every allowed architecture. Compare semantic keys across warmup/measured and declare the permissible pre-window state/result reuse policy. First F can be promoted for a source-pinned execution class only if its necessity/freshness conditions are established; leave universal/architecture-independent F null. Full context identity includes model/quantization/config, prompt and prior accepted prefix, absolute position, relevant KV/compression semantics, and applicable layer/group. Deduplicate semantic keys, not request IDs. Pin unchanged model state; hashes of raw pointers are not semantic hashes.
