# Run594 — compact cycle-basis regression on one diagnostic W₀

Run594 uses the existing Run566 A0 full 48-request diagnostic trajectory, with 32 rank/cohort traces and 32 Runtime files. From each first-cycle position/last-token/draft state, per-cycle accepted tokens/counts and next-draft state, plus Host parking transitions **extracted from the old full trace**, it reconstructs every observed Target input ID and position, pre-cycle last/draft state, and the Run570 A0 census: 1,206 cycles, 115,776 physical, 98,496 active and 17,280 parked Target-8 rows per rank. All eight ranks agree by cohort. No service or NPU workload ran.

Astra High independently verified 64 source SHA and all 32 rows. The first negative-test implementation used a three-cycle prefix with full-cohort staged totals, so even an unmutated fixture failed; that certification is invalid. The revised script SHA256 is `ffc6832018fa7097037e4f615ca63bd59eeb522541b474041794036aec419fe6`. It first passes an unmutated full-cohort control and then rejects five full-cohort mutations for the intended dependency. The original summary is retained as `summary_pre_review_invalid.json`; its bytes happened to equal the corrected result, so cite the revised script and Astra review together.

The Host parking transition is an **extra basis input**, not derivable from accepted counts alone. Run594 validates Target ID/position and draft lineage for A0; it does not prove complete Draft execution work, compulsory fresh rows, KV equivalence, Run99 same-state, or an execution-time Bound. The next collector must record parking events explicitly, and a pure basis replay should reject missing, shifted, duplicate and wrong-anchor events. Formal Current stays 571.681 tok/s; strict finite endpoints remain null.
