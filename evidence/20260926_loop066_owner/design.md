# Loop066 first owner-compact fixture design

The frozen Target c4 layer2 receives gathered `[96,4096]` BF16 hidden per rank. Run287 confirms every rank has 12 local Q rows spanning two adjacent requests; each of those owners needs the full 8 newly gathered rows, a contiguous 16-row input. The original indexer Compressor updates all 12 requests. This fixture challenges only that update, not the model's mathematical Q/attention or persistent cache policy.

At the real DirectTargetHandoff entry, eager Target layer2 makes four independent private copies of the complete shared indexer backing storage (141,814,400 bytes/rank in Run287). Each copy rebuilds FP32 state, INT8 key and FP16 scale views with the original dtype/offset/shape/stride; no candidate write reaches the live KV cache. It invokes native Compressor A(full96), A2(full96), B(owner16; two complete requests, qsl `[0,8,16]`, original request positions and physical block IDs), A3(full96). Metadata B is regenerated by the same native CompressorMetadata using full RoPE cache and the compact request table. Native output rows are matched by `(block_id,offset)` slot keys; expected full valid rows are 24 and B owner valid rows 4. A/A and A3 compare raw entire backing bytes; B compares byte-exact owner state regions across every owner page. The outer runner requires one JSON artifact and passing gate on each of eight ranks, plus exact 12×1024 client output.

The borrowed framework hook runs during capture but does no device work there. Only DirectTargetHandoff marks its ForwardContext `additional_kwargs` at the actual Runtime invocation, and the helper requires that marker before setting its one-shot flag. The service uses eager Target for this diagnostic. Both borrowed sources have pinned hashes, reversible backups and cleanup on exit. A worker stores comparison results even when a gate fails, preserving all-rank evidence.

Passing only proves a private, one-call native Compressor output/state relationship at the selected layer entry. It does **not** prove key/scale scatter, QLI/Sparse output, actual producer/consumer lifetime, full Graph capture or Product E2E speed. A failing whole-owner-page state comparison may be due to an overbroad byte range or alias; inspect the first divergent byte before claiming semantic failure. The next gate is a typed alias-preserving update+scatter/QLI fixture, then complete-cycle correctness and measured exposed endpoints.

## Run295 attribution refinement

Run294 established exact owner16 native output at all ranks but the whole historical owner-page byte gate failed on 7 ranks. The state block table covers thousands of historical pages and may share prefix pages between logical requests. Run295 keeps the same private A/A2/B/A3 real-layer fixture and adds a prestate-relative byte mask: A-changed, B-changed, A/B-different, B-changed-but-A-different, and A-only changed bytes, plus the first physical differing page/byte and all request/block aliases for it. It also counts owner/nonowner shared block-table pages. This is the smallest causal localization before typed scatter or live-path timing. A changed-byte mask cannot see writes that reproduce the prestate; source-derived write addresses remain necessary for the final gate. No Product TPS claim follows from this eager fixture.

## Run296 same-prestate typed consumer gate

Historical preflight: pinned old source `db3beef`; query `QLI real shape` retrieved R19, where exact topk parity was a useful gate but QLI v2 latency failed to reach old prefill service. PK-003 covers R18 valid-row/state addressing and R33's nonaliasing scatter fixture. Their DP2×TP4 prefill conditions do not settle current DP1×TP8 decode owner update.

The first hook at the actual layer2 Target c4 `_update_indexer_cache` entry creates four private, alias-preserving state/key/scale backing stores from one live prestate. It runs native Compressor A96/A2-96/B16/A3-96, compares valid output slots, and compares **all 2048 bytes per logical state token** in owner current `[start,start+8)` write domain and preceding conservative `[start-8,start)` live-read domain. It then executes original conditional rotate, native dynamic quant and the real INT8-key/FP16-scale scatter on each private backing store. It compares owner physical typed slots and full self replay. The original live update continues unchanged.

The second hook sits inside `_indexer_select_topk` after the original query, query scale and weights exist and immediately before original native QLI. It calls native QLI on each private cache with copies of that same query/weights/scale and original 12-request block table, local query/key lengths and metadata. It compares A/A2/B/A3 topk and leaves original live QLI to run normally. Only the actual Runtime entry carries the marker; startup Graph capture and draft do no fixture device work. Failure is saved per rank and the original path continues so all-rank evidence survives. Eager bench12 is a correctness/fixture carrier, never a Product speed sample.

Passing would close one-call layer2 owner state and immediate QLI consumer under this input and prestate. It would not prove Sparse, repeated cycles, parking/prefix lifetime, all21 layers, FULL Graph or exposed Product gain. Native 96→16 timing is deliberately deferred until this semantic gate. Runner: `scripts/run_loop066_owner_consumer.sh`; helper/patch/checker are separate from Run294/295.

## Run297 paired native-chain cost screen

Run296 passed all8 private state/scatter/QLI parity. Run297 asks whether reducing c4 indexer input from full96 to owner16 actually shortens the native chain at the same real layer2 shape. Historical source pinned `db3beef`; `compressor latency overlap` retrieves R21/R28. Their older DP2×TP4 prefill stream-overlap regressions warn that local timing and resource competition may diverge from Product wall, but do not predict this owner16 standalone chain. PK-005/006 are the current semantic prior.

The same Run296 private A/A2/B/A3 gate runs first. Before the original live cache update, timing setup copies the full shared indexer backing prestate and records original full/owner metadata. When the original query/weights/scale are available immediately before native QLI, the Run296 parity gate runs first. Only if it passes, timing executes two warmup and five measured A(full96)–B(owner16)–A2(full96) triplets. Each private alias-preserving bank is reset from the identical prestate and synchronized **before** the start event. The event window records after scatter (`update_ms`) and after fixed-query native QLI (`through_qli_ms`); QLI tail is also recorded. Raw reset, metadata clone, event allocation and topk equality are outside the event windows. All 21 topk outputs must match the first A bit exactly. The original live QLI then proceeds unchanged.

This is an eager one-layer capacity screen, not a whole-layer critical-path or Product speed estimate. Resetting 141.8 MB private backing before each arm changes cache residency; A/B/A2 and repeated triplets control the immediate comparison, not FULL Graph resource contention. If B shortens both update and through-QLI endpoints stably across all8, next test continuous ownership state and a full-Graph one-layer causal intervention. If not, pivot from this native owner16 implementation without declaring a hardware ceiling. The borrowed source patch is SHA guarded and must be independently verified restored after run.

## Run298 one-shot private Graph replay disambiguation

Run297's all8 semantic and repeated topk gates passed, but A96/B16/A2 eager event spans have no stable update or through-QLI advantage: B wins both full controls only 9/40 pairs, with A/A2 drift larger than the paired effect. Eager event spans can include Host submission gaps. Historical R21/R28 are stream/resource-competition priors and do not answer this capture question. The repo's Run221 has already demonstrated private service-side `torch.npu.NPUGraph` capture/replay on all8; Run298 uses that method, not a new performance baseline.

At the same real Target layer2 eager Runtime entry, repeat the Run296 private correctness gate, then save the complete shared backing prestate and fixed real q/weights/scales/metadata. Keep A96, B16 and A2-96 alias-preserving private banks. A3-96 runs an eager full-chain oracle. Capture three independent private Graphs containing only Compressor→conditional rotate→typed quant/key scatter→scale scatter→native QLI; no clone, sync, CPU comparison or reset inside capture. Each capture is treated as mutating its private backing. Before every replay restore its full backing and static QLI metadata from immutable copies and synchronize outside timing. Require Graph topk and post-replay owner state/key/scale bytes to match eager A3; then report 3 warmup and 10 measured A–B–A2 event spans per rank. Graph capture failures are saved and fail this diagnostic without changing the live path. Current source SHA and all8 idle are checked after cleanup.

This private graph removes most Python per-op submission gaps but still omits target-layer contention and full-cycle dependencies. If B does not repeatably shorten the through-QLI endpoint beyond A/A2 drift, pivot away from the current native owner16 small-shape implementation; retain the broader whole-DSA owner/halo architecture as a separate hypothesis. If a stable Graph delta exists, test continuous state ownership and actual FULL Graph critical-path exposure before any Product E2E claim.
