# Astra independent Run295 Bound and semantic review

Read-only review of all eight Run295 private fixture JSON files and the native/source state address path. A/A2/A3 outputs and full private backing bytes agree; owner16 Compressor outputs are exact by valid physical slots. In Run295 all A/B differing state bytes are A-only prestate changes and `B_changed_bytes_different_in_A=0`. The first differing byte on each affected rank maps to a nonowner current logical position when its 2048B state-token offset, `start_pos` and block table are combined: rank0/1/2/4 req10 pos32860; rank3 req8 pos32859; rank5 req9 pos32860; rank6 req11 pos32858. These pages also appear at older owner logical table entries. Source c4 state `sliding_window=8`; an entire historical block table is not the live read set.

This strongly supports an overbroad whole-page comparison as the cause of the old gate failure, but only each rank's first difference is fully address-attributed. A prestate mask misses same-value native writes; Run294 and Run295 have different prestates and cannot be byte-compared across runs. The next high-information gate is same-private-prestate parity of source-derived owner current write and conservative live8 read domains **including unchanged bytes**, then original rotate/quant/key-scale scatter and fixed-query QLI against alias-preserving caches. Isolated 96→16 timing is lower priority than consumer closure, though it may be collected in the same fixture. Historical PK-003 contributes validation method, not an alias safety proof.

Bound placement: owner16 exact Compressor outputs are a local Resource redesign possibility. Current compulsory HBM/compute deletion, Scheduling-aware latency, full Target exposed gain and Product E2E gain remain unproved. No numeric bound or KEEP follows.
