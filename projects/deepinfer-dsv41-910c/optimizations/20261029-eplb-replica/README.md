# 910C 热专家副本适配试验

## 结论

固定负载下，静态 16 冗余专家候选完成两轮测试及独立核验，完整输出与修改前版本一致；吞吐未达到保留版本，本次不启用。结果不代表官方在线 EPLB 在其他负载下无效。本候选使用预先计算的静态布局，没有实现在线负载统计和权重迁移。

## 设置和比较

测试在 172 的 16 个逻辑设备上进行，DeepSeek-V4.1-Flash W8A8，DP2、TP8、EP16；32,768 输入、1,024 输出、并发 8，正式请求每轮实际 KV 命中 235,904 / 262,144。DSpark、Engram CPU 卸载及已验证的其他优化保留，主干 CPU prefetch 关闭。两组数据来自不同服务进程、前后测试各两轮，并非同进程 ABBA；短样本及 TTFT 波动限制了归因。

| 配置 | 轮次 | 平均 TTFT（ms） | 平均 TPOT（ms） | 输出吞吐（token/s） | 完整 1,024 token 输出 |
| --- | --- | ---: | ---: | ---: | --- |
| 修改前：投票缓冲复用 | 1 | 599.7 | 12.3 | 612.945 | 基准 |
| 修改前：投票缓冲复用 | 2 | 587.5 | 12.2 | 609.094 | 基准 |
| 候选：静态 16 冗余专家 | 1 | 636.7 | 12.4 | 606.648 | 8 条与基准一致 |
| 候选：静态 16 冗余专家 | 2 | 563.1 | 12.3 | 604.111 | 8 条与基准一致 |

两轮合并吞吐分别为 611.013 和 605.376 token/s，候选低约 0.92%。候选第二轮 TTFT 较低，第一轮较高；不能据此声称稳定的 TTFT 改善或退化。两轮 TPOT 均比修改前显示值高 0.1 ms，原始报告精度和样本量有限。

运行计数显示，第一轮两版本均有 223 次验证图 replay；第二轮由 225 次变为 226 次。对应 DSpark 草稿验证及接受计数也有小幅变化，尽管完整输出相同。这可能影响耗时，不能仅凭此次数据判断吞吐差距来自专家分流或映射开销。

## 改动和验证

候选沿用固定官方策略的 `early_to_late` 静态布局，目标模型 384 个逻辑专家映射到 400 个物理槽位，每 EP rank 25 个。将官方 TileKernels 2.1.0 的 `ep_rank + row * 23333` 副本选择用于目标模型路由，保留原融合 MC2 路径；DSpark 草稿层继续使用原布局，每 rank 3 层各 8 个专家。未修改共享专家、DSpark、Engram 或投票复用实现。

CPU 上完成 320 组与官方参考实现的映射对照，并检查 40 层映射完整性。候选的 16 个 rank 完成目标图初始化，逐 rank 加载记录确认每个目标层 25 槽、DSpark 草稿层 8 槽且未启用副本映射。两轮正式输出逐 token 对照修改前的同一请求，均为完整 1,024 token 一致；逐 rank 的 DSpark、Engram、YOCO 和投票复用证明，以及实际缓存命中经独立核验。图捕获计数并非单独的设备内核计数；结果仅适用于所测工作负载。

候选源码位于 `/data/tiankuan/wio/910c-deepinfer-172/src/DeepInfer-eplb-replica16-v2-20261029`；两轮原始数据位于 `/data/tiankuan/wio/910c-deepinfer-172/fair-comparison-20261028/completion/eplb-replica16-v3b-perf-20261029`。独立核验文件 `independent-eplb-replica16-v3b-review-20261029.json` SHA256 为 `60e73ebf502abea5da5e9a395e0edf5258675ff462e41c5d0f64613c2261990b`。

第一次启动时，控制器错误地将目标层 24 个专家的基线数量用于草稿层，因校验失败而退出；实际逐 rank 记录显示草稿层每层为 8 个。更正控制器校验后重启同一候选源码；失败证据和两份控制器均保留。
