# YOCO 短末块窗口候选

## 范围

保留版本在恢复前缀后，如果四个请求的最后查询块均不超过 256 token，会回退到完整 SWA 滑窗。[官方元数据对照](../20261030-replay-semantics/OFFICIAL-ALIGNMENT.md)显示：对部分短末块，官方 `mask` 在 consumer 层收窄了该窗口。完整滑窗回退并非据此判定错误；两者对应不同的注意力可见范围。

本候选默认关闭，仅在恢复前缀、四个槽位、相同且 128 token 页对齐的最终长度、`ignore_eos=true`、序列/上下文并行和保留长度 256 等条件下，在最终 KV 源层之后使用现有 910C 页对齐窗口接口。所有 rank 对资格达成一致；其余情况使用原路径。候选不删除查询、不更改压缩索引和 KV 写入，不接入官方 140 token 路径，也不构成官方 YOCO 的完整移植。

现有保留版本的 32K、约 90% KV 命中主负载，其未缓存末块约为 3,200 token，继续使用原有 256 token 压缩路径，不进入本候选。

## 已完成检查

使用官方 C++ 元数据和合成短末块，确认与完整滑窗的范围差异；使用实际 910C BF16 算子、相同查询和索引进行单设备对照，两种窗口分别符合各自的独立 CPU 注意力参考。该设备测试的末块为 200 token，属于合成接口测试，不是模型执行。

在独立 16 rank 服务中，对同一条截断后的长输入分别关闭和开启候选：输入 29,824 token，实际命中 29,568 token，并发 8、greedy、忽略 EOS，生成 16 token。开启侧每个 rank 记录一次候选激活和 19 次 consumer SWA 调用；关闭侧均为零，未发生查询压缩。两侧 8 条请求的 16 个输出 token 一致。

该模型诊断仅覆盖一条重复输入和短输出；未逐层对照官方 mask 模型中间张量，也未完成完整输出、质量和性能验收。其 99.14% 缓存命中不同于主测试的约 90%；诊断时间不作为性能数据。候选未采纳，保留服务仍使用原精确回退。

模型审计：服务器项目目录 `evidence/yoco-short-mask-model-audit-20261030.json`，SHA256 `fa2a4dec2fc05d292947cf1375ddebd589aeefb7708d3af42494be6bb3781389`。候选清单的服务器原件 SHA256 `13944fb496cbe47d89dbb13b378c201002e762498cbfa984d8630931ce3bb9ed`。

## 复现与回退

补丁针对服务器上的冻结父源码 `/data/tiankuan/wio/910c-deepinfer-172/src/DeepInfer-zos-vote-reuse-20261029`。使用前应按 [manifest.json](manifest.json) 核验父文件 SHA256，在新目录复制父源码后执行：

```bash
patch --dry-run -p1 < candidate.patch
patch -p1 < candidate.patch
```

补丁应用后必须按清单核验四个修改文件及新增文件的 SHA256。补丁 SHA256 为 `9bb5122825b34bce91b820bf39706aa7c1780483ffef1a2f74762d6e8baa4157`；已在隔离目录完成应用和反向预检。

作业配置中 `yoco_short_mask=true` 才启用该候选，同时要求 `yoco_bounded=true`、`yoco_bounded_140=false`。不设置该字段或设为 `false` 时使用原回退。该选项仅供独立验证；保留的父源码和原服务配置是回退依据。服务切换前核对设备归属及请求空闲。
