# YOCO 有界重放边界审查

## 范围

对照 DeepInfer 固定提交 `553741557a57df44a46fb3ab72b6aafeaf945337` 的输入元数据和 172 保留版的 910C 有界重放代码。官方示例使用保留长度 140，当前保留版使用 256；两者不能仅因窗口相同就视为等价。本次没有修改或运行模型。

910C 的有界路径只在四个请求均从已恢复前缀继续、处理到各请求最终分块、终点相同且按 128 对齐等条件满足时启用。最终分块的每个请求长度至少为保留长度。其他条件不满足时，该候选回退原路径。

## 保留区间与滑窗

在最终分块终点等于完整输入长度、窗口 128、SWA 有效下界为 0 的假设下，官方保留区间与 910C 的每请求后缀计划，在统一保留长度时选择相同行；将 910C 的 SWA 表按 `终点 - 保留长度` 重新定位后，模型化的因果窗口下界与官方的滑窗和矩形交集相同。以终点 16,384 / 32,768 / 65,536、保留长度 140 / 256、不同请求长度组合，检查 18 个组合的 14,256 个保留位置，标量公式一致。

这里的滑窗比较是 Python 对官方 C++ 标量公式及 910C 表偏移的模型化，未调用官方 C++ 或昇腾 SparseFlashMla，也未验证官方非零 `valid_start` 的行为；不能据此认定实际注意力结果或不同保留长度等价。

## CP 逻辑索引

从已核对 SHA 的 910C 源码提取实际 `QuerySlice.build`、后缀规划及预规划函数，用纯 Python 模拟 8 rank 的贡献、补齐、按 rank 收集和再次切分。在上述 18 个长度组合共 144 个 rank 计划中，重组出的保留行与全局选择顺序一致，重分配后每个 rank 的查询绝对位置一致。源码 AST 检查确认当前默认的非预规划分支使用相同的索引构造语句；它还增加索引源就绪检查。

官方 CP 采用镜像布局，当前 910C 使用连续区间。此次只检查逻辑索引和位置，没有执行设备通信、图重放、压缩 KV、缓存写入或回退，也不能证明两种 CP 执行或模型质量完全相同。140 与 256 的质量和缓存语义仍需独立评估。

结果：`scalar-review.json` SHA256 `20b4baa9e227caea46163dc78092acd678cdcf42d9f6a9315a36a4aaf1dced95`；`cp-review-v2.json` SHA256 `3c7504247109d1482481cb37176afa883204b8673f4b0d2302279261245de180`。代码和结果保存在同目录；源代码 SHA 已与 172 保留版核对。

## 压缩索引的标量可见上界

官方元数据对每个保留查询的压缩可见长度使用 `(位置 + 1) // 压缩比`；当前 910C 索引筛选使用相同的标量上界。对上述 14,256 个保留位置分别以压缩比 1 和 2 核对，公式相同。此检查不执行索引器或设备算子，也不验证候选块选择、实际压缩 KV 值和缓存页映射。

扩展检查结果 `scalar-review-v2.json` SHA256 `d36e92efd31817e0fa4f8edd3e6d4ea94252d6564561fc0072911c1f29bb0a43`；该结果不替代模型级质量或缓存语义验证。
