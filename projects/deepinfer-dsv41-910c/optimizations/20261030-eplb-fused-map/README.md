# 静态 EPLB 副本映射的图内耗时

针对此前静态 16 副本候选在正式负载下低于保留版约 0.92% 的吞吐，验证单独融合副本映射是否值得进入模型对照。候选只改物理专家映射，不改变权重、路由分数、融合 MC2、DSpark 或 Engram；它是静态布局实验，不实现在线 EPLB。

一张 910C 逻辑设备使用实际第 14 层映射、模拟 rank 7 和 6 路 top-k；每个 NPU 图重复同一映射 40 次，先预热，再以交替顺序各测 40 次。原版和融合版输出逐元素一致。下表为每个图的设备事件耗时；每张图含 40 次映射。

| 输入行数 | 原映射中位数 | 融合映射中位数 | 融合 / 原映射 |
| --- | ---: | ---: | ---: |
| 4 | 1124.23 μs | 261.78 μs | 23.3% |
| 24 | 2317.45 μs | 853.86 μs | 36.8% |

这组隔离图没有 MC2、其他层计算或跨设备同步，不能直接推算 40 层模型的端到端加速，也不能证明实际服务图中同样节省时间。此前 3 层、4 种行数、3 个 rank 参数共 36 组与输入变化图重放的原语正确性已通过；多 rank 模型执行、完整输出与正式负载性能仍需验证。源码比对显示，静态副本版相较现行保留源码仅修改模型与 worker 两个文件并增加映射模块；融合版相较静态副本版仅修改该映射模块并增加一个内核文件。因此，应先比较两种静态副本版的完整运行，再将综合结果与保留版比较；不能把前一对照误称为相对保留版的单因素性能。

原始数据：`/data/tiankuan/wio/910c-deepinfer-172/evidence/eplb-fusedmap-timing-20261030.json`，SHA256 `04121b431d146403c5347a6f03d90e69f5ebcc4d09a87b37202b1cfbc2d774fc`。保留版与两份候选均未替换。

## 完整模型对照

两种候选均使用相同静态 16 副本布局，按原映射、融合映射先后启动，每组两轮。各轮 32K 输入、1K 输出、并发 8；实际 KV 命中均为 235,904 / 262,144。请求 ID 由服务独立生成，其余请求字段相同。四轮各 8 条完整输出逐 token 一致，16 rank 的已启用路径通过核验。

| 轮次 | 映射 | TTFT（ms） | TPOT（ms） | 输出吞吐（token/s） |
| --- | --- | ---: | ---: | ---: |
| 1 | 原映射 | 630.4 | 12.4 | 607.213 |
| 1 | 融合映射 | 4590.8 | 12.4 | 469.421 |
| 2 | 原映射 | 587.7 | 12.3 | 604.793 |
| 2 | 融合映射 | 544.6 | 12.2 | 608.597 |

第二轮融合映射吞吐高 0.63%，但首轮 TTFT 增加 3,960.4 ms、吞吐降低 22.69%。服务依次重启，样本较少，不能把第二轮差异视为稳定收益，也不能忽略首轮退化。候选不采纳。

首轮 DP0 的 prefill 主机区间从原映射约 0.523 秒增加至融合映射约 4.416 秒；融合版第 0、20、21、37 层的单层提交区间分别约 1.089、0.962、1.117、0.855 秒，第二轮均明显缩短。这些主机时间包含隐式等待，不是算子独占耗时；首次编译或首次执行可能有关，但现有证据尚不能确定原因。两个候选比较只隔离静态副本的映射实现，不能作为相对无副本保留版的单因素收益，也不能代表在线 EPLB。

跨候选核验证据 `/data/tiankuan/wio/910c-deepinfer-172/evidence/eplb-map-ab-audit-20261030.json`，SHA256 `382ee05204455effed8d627963e0095cb66cb39a87d605a3635eb30849315feb`。首版比较因要求请求 ID 相同而未通过；确认差异仅为 ID 后，修正为比较其他全部请求字段，保留原始失败记录。

进一步核对融合服务的 Triton 缓存：以首轮 job 请求文件时间为提交近似起点、DP0 首 token 的相对耗时为观察窗口，窗口内出现 47 个新 `_map_kernel.json`。TTIR 显示融合内核以输入元素数进行编译期特化，首轮窗口内出现多种行数。文件时间与 worker 计时并非同一时间原点，且主机区间包含等待；这些事实支持首次编译参与首轮延迟，但不能仅凭相关性认定全部 3.96 秒均由编译造成。对应时间线 SHA256 `b59331d62e56376cc7ad184ab7f87460ab5fdab2ea357c46db2b1c723cc84835`，行数特化证据 SHA256 `cfe3b8d3831c0c5826e165711d98aee356661c4ecfe3369b0ba880e342333b53`，均保存在服务器 `evidence/`。
