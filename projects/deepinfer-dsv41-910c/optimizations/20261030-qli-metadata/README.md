# QLI 元数据复用候选

现有 32K、并发 8 的 rank 0 短输出轨迹中，14 个模型执行窗口各包含 8 次 QLI metadata 事件，累计时长中位数 0.565 ms。当前实现对每一层分别生成元数据；候选仅在同一 `DSABatch` 内，对 heads、Top-K 和压缩比相同的调用复用 metadata 及对应长度张量。候选默认关闭，通过独立服务开启；QLI 本体、注意力范围、KV 精度、DSpark 和其他已启用优化均未修改。

## 固定负载对照

两种实现分别使用独立服务，均先做相同的 32K 预热及精确、256 路径检查，再使用 AISBench 各运行两轮。输入 32,768 token、输出 1,024 token、并发 8；每轮实际缓存命中均为 235,904 / 262,144 token。

| 轮次 | 版本 | 平均 TTFT | 平均 TPOT | 输出吞吐 |
| --- | --- | ---: | ---: | ---: |
| 1 | 保留版 | 618.5 ms | 12.3 ms | 610.168 token/s |
| 1 | 候选 | 591.0 ms | 12.2 ms | 618.022 token/s |
| 2 | 保留版 | 591.1 ms | 12.2 ms | 606.554 token/s |
| 2 | 候选 | 591.9 ms | 12.0 ms | 614.609 token/s |

候选吞吐两轮分别高约 1.29% 和 1.33%；第二轮 TTFT 高 0.8 ms。两轮 8 条请求的完整 1,024 token 输出分别与保留版一致，16 rank 的重放和现有优化标志通过。预热诊断的精确及 256 路径各 8 条请求的完整 512 token 也均一致。

测试跨服务重启，只有两轮，不能将波动全部归因于元数据复用；TTFT 的细小变化也不能据此认定稳定退化或改善。上述输出一致不证明所有形状、缓存状态和模型质量等价。设备实际 metadata 事件次数及算子自身耗时仍待验证，因此候选尚未采用，保留版继续运行。

原始审计 `evidence/qli-meta-perf-audit-20261030.json`，SHA256 `0f0cf2621b530fe7c32e03a8465969fbc78ba486a05d351df5e4e75d23b8b2dd`；匹配预热审计 `evidence/qli-meta-smoke-matched-audit-20261030.json`，SHA256 `b4d7e646487479471da7b8dab5d2e02fc679e5875280aa58d0dcb7e11654e6da`。保留版和候选代码均未被覆盖。

## 设备轨迹

相同 32K 输入、并发 8、32 token 输出的两次 rank 0 轨迹中，目标图的 14 个窗口均有 8 次 QLI 主算子。metadata 调用从每窗口 8 次降至 2 次，与模型两种压缩比对应；事件累计时长的窗口中位数从 0.565 ms 降至 0.179 ms，差值约 0.386 ms。两次轨迹的请求 token、实际缓存命中和 8 条 32 token 输出一致。

设备事件可能跨流重叠，profiler 存在警告，且两次采集位于不同服务实例；因此该差值不是端到端节省。轨迹审计 `evidence/qli-meta-trace-comparison-20261030.json`，SHA256 `d7c4eca2afcb894e269fccd6a488711bfd7e6f5159aa6c292cd7a3a96500462c`。

## 反向顺序的预热输出差异

反向顺序复测时，精确路径 8 条完整 512 token 输出一致；256 路径中 7/8 一致，1 条从零起始索引 277 开始不同。该请求首次 EOS 位于索引 9，但测试设置 `ignore_eos=true`，因此后续差异仍是实际输出差异，不能忽略。两次保留版及第一次候选该请求的完整输出相同，第二次候选不同；第二次候选的 DP0 草稿接受计数也不同。仅凭这些记录不能确定元数据复用是否导致差异，也不能排除跨次运行的数值或调度波动。保留该候选，不作为已通过全部正确性的版本。

## 反向顺序的两轮性能复测

先测保留版，再测候选，其他正式负载与预热条件相同：

| 轮次 | 版本 | 平均 TTFT | 平均 TPOT | 输出吞吐 |
| --- | --- | ---: | ---: | ---: |
| 1 | 保留版 | 587.8 ms | 12.3 ms | 613.033 token/s |
| 1 | 候选 | 611.5 ms | 12.2 ms | 615.854 token/s |
| 2 | 保留版 | 610.2 ms | 12.2 ms | 607.673 token/s |
| 2 | 候选 | 613.6 ms | 12.1 ms | 611.783 token/s |

候选吞吐分别高约 0.46% 和 0.68%，TTFT 分别高 23.7 ms 和 3.4 ms；两轮主负载的 8 条完整 1,024 token 输出均与保留版一致，缓存命中及 16 rank 控制标志通过。两次顺序不同的对照均使用不同服务实例，TTFT 波动不能单独归因，但实际退化必须保留在结果中。

结合预热检查中的完整输出差异、反向复测的 TTFT 退化和较小吞吐收益，候选暂不采用。单次 rank 0 轨迹证明该次调用次数和事件累计耗时减少，并不能证明所有运行的端到端收益或输出一致性。反向复测审计 `evidence/qli-meta-repeat-perf-audit-20261030.json`，SHA256 `daf8dfd5f94636ee27f209c5c024b897002e0f35bb204f398a72a47dfa89cd0e`；预热输出审计 `evidence/qli-meta-repeat-smoke-audit-20261030.json`，SHA256 `6ce60b9d0d5d3c9e4a3266ffe30b99b2f13fbc947540bdb6565a2b2c4767a563`。

## 单卡算子与图重放检查

使用 910C 上真实的 QLI 算子，以合成数据对照元数据复用关闭和开启：覆盖固定 4×6 查询及 5 slot、8 行变长图，两种压缩比和 source/consumer 索引路径。每种图改变序列位置，变长图还改变各 slot 查询长度，各重放三次；每次 8 组索引及 1 组候选块输出均逐元素一致。压缩比 2 的元数据经三个算子消费前后逐元素一致；此项检查不涵盖压缩比 1 的元数据原地变化。

该试验排除所测形状中一部分图输入和元数据复用问题，但使用合成数据、单卡，不能证明全部真实模型数据或多卡路径等价，也未解释上述继续生成的输出差异。审计 `evidence/qli-meta-operator-probe-20261030.json`，SHA256 `5dafd3bc7245fd4d09ac059b1826d8f72cee3b026c039b474a9e69ae23c9ae49`。

本目录的 `qli-metadata.patch` 仅供独立候选复现。应用前确认原 `deepinfer/npu_ops/dsa910c.py` 的 SHA256 为 `f849edeaeb14f10428c52b715f5ed8c4a812aac6c9379b416e430f743912cd89`；补丁应用后的 SHA256 为 `49f66a1a9a0f14f4bca97d4646d2b9607085932e5ca2fb747c6e37ea17ccdbd9`。在独立源码副本中应用后，设置 `DEEPINFER_910C_QLI_METADATA_REUSE=1` 并重启服务，才会在图捕获时启用复用。回退时使用原源码与原启动配置重启；仅在运行中的进程中修改环境变量不会改变已捕获的图。本候选目前不用于正式部署。
