# 910C ZOS 状态投票计时诊断

## 范围

在已接受的 910C W8A8 DeepInfer 代码基础上，独立增加可选主机分段计时，保留投票缓冲复用、DSpark、Engram 和 256 token 有界重放。该诊断在 172 使用 16 个逻辑设备、DP2×TP8/EP16；8 条请求各 32,768 输入 token、256 输出 token，实际前缀缓存命中合计 235,904 / 262,144。主干 CPU prefetch 关闭。

每个 DP 的 TP rank 0 记录主机时钟；诊断代码不新增设备同步，但记录本身会改变主机时序。此项不是 1,024 token 正式性能测试，也不产生 TTFT、TPOT 或吞吐改进结论。

## 结果

| 指标 | DP0 | DP1 |
| --- | ---: | ---: |
| 稳定阶段投票次数 | 56 | 56 |
| 投票累计主机时间 | 174.762 ms | 174.615 ms |
| 单次投票平均主机时间 | 3.121 ms | 3.118 ms |
| 单次投票最大主机时间 | 7.533 ms | 7.680 ms |

两组各 4 条输出的前 256 个 token 与固定参考逐 token 相同；所有 16 rank 的投票缓冲复用、设备 hash、DSpark 草稿预发及有界重放执行记录通过检查。缓存命中数与参考一致。以上正确性只覆盖指定请求、长度和状态，不能证明通用模型质量或精确路径等价。

投票计时包含主机填充和拷贝提交、全 rank 集体操作、结果回读以及潜在的设备和其他 rank 等待，不能将平均 3.12 ms 直接视为可消除的时间。旧版 1,024 token 诊断曾观察到约 3.6 ms，但版本、预热、生成长度和运行条件不同；两次数据不构成缓冲复用单因素耗时对照。

## 后续定位

在保留版本的独立诊断副本中，计划记录每个 rank 的投票入口、collective 调用前后和回读完成的主机单调时标，不增加设备同步、不改变任何集体操作顺序或投票逻辑。该方案能够比较主机调用区间和跨 rank 到达时间，但不能据此单独判断设备执行或网络瓶颈；需要确认所有 rank 时钟属于同一时间命名空间，且时标插入可能扰动运行。只有排除上述问题后才评估局部优化。

## 逐 rank 主机时标

在单独的诊断副本中，对上述相同 32K/256/C8 请求再次采样。16 个 worker 属于同一 Linux 时间命名空间；每个 rank 记录投票进入、发起 collective 前、调用返回以及 CPU 读回完成的主机单调时标。该实现保持原来的全 rank 投票、collective 次序与设备操作，没有新增设备同步；主机插桩仍可能影响调度。

本次核验了 58 次 collective 中每次 16 个 rank 的最终投票标志一致、各 rank 的记录数与实际投票复用调用数相同。每个 DP 的稳定阶段各 56 次投票，平均主机时间为 3.130 / 3.113 ms。16 rank、58 次的 928 条记录合并后，主机分段如下：

| 主机区间 | 中位数 | P90 | 最大值 |
| --- | ---: | ---: | ---: |
| 投票入口至 collective 调用前 | 0.053 ms | 0.067 ms | 0.202 ms |
| collective 调用至主机返回 | 0.093 ms | 0.119 ms | 4.726 ms |
| 主机返回至 CPU 读回完成 | 3.178 ms | 3.573 ms | 5.056 ms |

每次 collective 内，16 个 rank 进入 collective 的时间跨度中位数为 0.857 ms、P90 1.501 ms、最大 3.260 ms。这里是每轮最早与最晚主机时标的差，不是某个 rank 独占等待；不能与上表的分位数相加。collective 的主机返回不保证设备完成，后续读回可能等待前序设备工作、collective 和其他 rank，现有数据不足以把 3.178 ms 归因于网络、设备计算或传输。不能据此删除投票、跳过同步或将其全部作为可回收开销。

再次核验实际缓存命中 235,904 / 262,144，8 条 256 token 输出与参考一致，投票复用及 16 rank 的既有路径证明通过；限于单次短诊断，不构成端到端性能比较。逐 rank 结果 `evidence/zos-vote-ranktrace-diagnostic-20261030.json` SHA256 `26c909fe942df402facb8b286deec29e8a38ced6cdb1133c98b6e79418a9269d`；包含全部 rank 时标的原始证明保存在 `serving/zos-vote-ranktrace-run-20261030/jobs/zos-vote-ranktrace-ipc-20261030`。

## 进入顺序与读回完成时间

对 57 个 `any_busy` 为真的轮次，在同一轮内比较 16 个 rank 的 collective 进入时标与主机回读耗时：相关系数的逐轮中位数为 −0.996，57 轮均为负。每轮最早进入者的回读时间均长于最晚进入者，两者差值中位数为 0.861 ms；16 个 rank 回读结束时标的跨度中位数为 0.064 ms。57 轮中，最后进入者有 19 次为 rank 0、22 次为 rank 8，两者均为各自 DP 的 TP rank 0。

这些是同一短诊断的描述性关联，支持优先检查同步前各 rank 的工作差异，但不能证明早到 rank 仅在等待晚到 rank，也不能将 rank 0/8 的晚到直接归因于特定代码。时间均为主机时标，读回仍包含未完成设备工作。分析结果 `evidence/zos-vote-ranktrace-arrival-analysis-20261030.json` SHA256 `b974cd4ae22d6d293476bea86e9ace94c6fa29092a317ddb08c5bf73dc6fc4f8`。
