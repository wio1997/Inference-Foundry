# 解码轨迹中的激活与专家执行重叠

## 范围与方法

复用已保存的单次设备轨迹：32,768 输入 token、并发 8、32 个输出 token，rank 0，模型 ID 49 的 14 个采样窗口。未重启服务或发起新推理请求。原始轨迹 SHA256 为 `e83474741f52e503e6955c704e0d1102835804cd2566a7ab48064af0eaa0ed17`；原采集存在 profiler 警告。窗口身份依据既有事件和调用次数推断，不能直接视作端到端生成步。

每个窗口包含 40 个 `aclnnSilu_SiluAiCore_Swish` 和 40 个 `DispatchFFNCombine` 事件；激活事件位于物理流 61，专家事件位于流 68。对每个激活事件，将专家事件的时间并集与其求交，避免重复计算重叠区间。

## 结果与结论

14 个窗口中，激活事件累计时长与专家事件的时间交集占比分布为 99.22%–99.66%，中位数 99.42%。例如第一个窗口中，40 个激活事件累计 4.831 ms，与专家事件的时间并集重叠 4.801 ms，单个激活事件的中位持续时间为 1.84 μs，最大 417.309 μs。时间交集不证明激活没有关键路径作用，也不能说明其等待或执行时间的原因；不能将 4.831 ms 作为可直接回收的端到端时间。

同一采样窗口中，`aclnnSort_SortAiCore_Sort` 为 8 次，累计中位数 90.072 μs。次数与索引源的数量一致，但现有事件没有足够信息建立每次事件与某一调用的对应关系；不能断言它们全部来自 `prepare_indices`，也不能由该算子计时推算整体性能收益。

当前证据不足以证明单独改写排序或扩大激活融合的端到端收益。已有共享专家激活候选保留，继续关闭；原服务及代码不变。下一步应先用调用关系、流依赖或同条件设备事件识别实际关键路径，再选择具有可检验收益上界的局部优化；不能将本结论泛化到其他输入、并发或部署。
