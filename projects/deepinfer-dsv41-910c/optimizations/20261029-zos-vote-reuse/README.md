# DSpark 状态投票缓冲区复用

## 适配范围

910C 专用 DSpark 服务每步通过 HCCL 对请求状态、异步资格和错误状态执行三字段全局投票。该候选在原投票路径上复用固定的主机锁页缓冲区与设备缓冲区，使用异步主机到设备拷贝；全 rank 投票、阻塞式结果读取及结束判断保持不变。缓冲区在前次投票结果回读后才重新写入。

该实现是现有 910C 路径的局部改进，不代表官方 ZOS 的完整移植。其他 batch、EOS、动态调度和异常情况尚未完整覆盖。

## 验证条件和结果

DeepSeek V4.1 Flash W8A8，16 个逻辑设备，DP2、TP8、EP16；输入 32768 token、输出 1024 token、并发 8，实际 KV 命中 235904/262144。同一服务按关闭、开启、开启、关闭的顺序各测两轮，两侧均启用 DSpark 草稿预发、256 token bounded replay、Engram UVA、设备 hash 和 Recipe 原始文本分词；主干 CPU prefetch 关闭。

| 缓冲复用 | 轮次 | 平均 TTFT（ms） | 平均 TPOT（ms） | 输出吞吐（token/s） |
| --- | --- | ---: | ---: | ---: |
| 关闭 | 1 | 684.7 | 12.4 | 603.168 |
| 开启 | 1 | 599.7 | 12.3 | 612.945 |
| 开启 | 2 | 587.5 | 12.2 | 609.094 |
| 关闭 | 2 | 594.3 | 12.3 | 604.711 |

两轮合并输出吞吐：关闭 603.938、开启 611.013 token/s。两轮样本不足以证明所有负载下的稳定收益。

四轮共 32 条完整输出与参考逐 token 一致，每轮实际缓存命中及分词缓存命中均已核验；16 个 rank 在开启侧实际调用候选路径。独立 HCCL 隔离验证中，16 个 rank 各完成 128 次原路径与候选投票比较，覆盖三字段的八种全局组合和缓冲区复用。该验证不能替代更多请求类型和故障场景的验收。

## 部署与回退

1. 使用已冻结的父源码目录；当前 172 的目录为 `/data/tiankuan/wio/910c-deepinfer-172/src/DeepInfer-cache-restore-device-event-20261029`。先执行 `python3 verify.py <源码目录> base`。该目录是本次验证的前置条件，本补丁不包含完整 DeepInfer 源码。
2. 在独立副本执行 `patch -p1 < candidate.patch`，再执行 `python3 verify.py <源码目录> candidate`。
3. 作业配置字段 `zos_vote_reuse` 默认为关闭；启用需将该字段设为 `true`，并保持原有 `zos_fast`、设备映射和服务配置。只在服务空闲、设备归属明确时切换。
4. 将 `zos_vote_reuse` 设为 `false` 可恢复原投票实现。旧源码、指标和诊断记录应继续保留。逐轮数据及审核摘要见 `results.json`。
