# DSpark 目标图一致性诊断

## 问题

在独立诊断服务中，4,096 token、并发 8、关闭有界重放时，同一请求的预算 7 和预算 24 目标图在一个位置产生不同的首选 token。相应校验拒绝继续执行；默认 256 token 有界路径是否受同一输入影响没有得到证明。

## 定位和候选

两张目标图中，问题位置的 token、位置和请求编号一致。逐层比较显示第 0 层所记录的张量一致，第 1 层开始出现差异。进一步比较显示两个位置读取的 Engram 行一致；所采集的 SWA 历史窗口值一致，当前 KV 行和部分 query 有差异。该证据不能把最终 logits 差异全部归因于某一个算子。

单卡实验使用真实 Engram 投影权重及对应输入，比较 8 行和 24 行的 BF16 投影。两种形状的投影有少量数值不同，并分别逐位复现模型中观察到的对应 Engram 输出。基于此构建独立候选，仅将预算 7 图的 Engram 投影补齐至 24 行并映射回原位置；原实现保持可用。该候选通过了原 4K 失败样本的图前缀校验，但尚未完成完整正确性、质量和性能验证，未采用。

## 有界路径质量诊断

在该独立候选上，使用 64 条带自定义 32K 长前缀的 GSM8K 样本，分别测试精确、140 和 256 路径。与精确路径相比，140 和 256 的首个 EOS 前 token 序列分别有 28/64 和 24/64 条不同。仅提取明确的 `Final answer: <number>` 格式，三条路径分别有 41、40、38 条可解析，其中 36、35、34 条与参考答案匹配；未解析项不判定为答错。实际 KV 命中为每条 29,568 / 32,768 token。由于使用自定义长前缀、`ignore_eos=true` 和首个 EOS 前截取，这些数值不是标准 GSM8K 准确率。

## 数值异常

后续合成检索样本的 256 路径发生 learned confidence NaN，一条受影响请求在异常前尚未输出 EOS，故不能归因于 EOS 后继续生成。短会话中，原实现和候选对同一检索组均未再次出现 NaN；这不构成稳定性证明。

另一组独立诊断在精确路径复现同类 NaN：受影响的 8 个 rank 上，草稿隐藏状态和 logits 已非有限，而 Markov 输入及置信度权重有限。受影响 DP 的四条请求在异常前均已输出 EOS，且随后各连续输出 7 个 token ID 0。再次增加目标 logits 检查与设备同步后，同一短序列未复现。诊断会改变时序；首次出现非有限值的位置、两次异常是否同源以及与 Engram 候选的关系均未确定。
