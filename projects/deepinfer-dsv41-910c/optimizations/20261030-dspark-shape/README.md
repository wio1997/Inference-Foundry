# DSpark 目标图一致性诊断

## 问题

在独立诊断服务中，4,096 token、并发 8、关闭有界重放时，同一请求的预算 7 和预算 24 目标图在一个位置产生不同的首选 token。相应校验拒绝继续执行；默认 256 token 有界路径是否受同一输入影响没有得到证明。

## 定位和候选

两张目标图中，问题位置的 token、位置和请求编号一致。逐层比较显示第 0 层所记录的张量一致，第 1 层开始出现差异。进一步比较显示两个位置读取的 Engram 行一致；所采集的 SWA 历史窗口值一致，当前 KV 行和部分 query 有差异。该证据不能把最终 logits 差异全部归因于某一个算子。

单卡实验使用真实 Engram 投影权重及对应输入，比较 8 行和 24 行的 BF16 投影。两种形状的投影有少量数值不同，并分别逐位复现模型中观察到的对应 Engram 输出。基于此构建独立候选，仅将预算 7 图的 Engram 投影补齐至 24 行并映射回原位置；原实现保持可用。该候选通过了原 4K 失败样本的图前缀校验，但尚未完成完整正确性、质量和性能验证，未采用。

## 有界路径质量诊断

在该独立候选上，使用 64 条带自定义 32K 长前缀的 GSM8K 样本，分别测试精确、140 和 256 路径。与精确路径相比，140 和 256 的首个 EOS 前 token 序列分别有 28/64 和 24/64 条不同。仅提取明确的 `Final answer: <number>` 格式，三条路径分别有 41、40、38 条可解析，其中 36、35、34 条与参考答案匹配；未解析项不判定为答错。实际 KV 命中为每条 29,568 / 32,768 token。由于使用自定义长前缀、`ignore_eos=true` 和首个 EOS 前截取，这些数值不是标准 GSM8K 准确率。

## 数值异常

后续合成检索样本的 256 路径发生 learned confidence NaN，一条受影响请求在异常前尚未输出 EOS，故不能归因于 EOS 后继续生成。短会话中，原实现和候选对同一检索组均未再次出现 NaN；这不构成稳定性证明。

另一组独立诊断在精确路径复现同类 NaN：受影响的 8 个 rank 上，草稿隐藏状态和 logits 已非有限，而 Markov 输入及置信度权重有限。受影响 DP 的四条请求在异常前均已输出 EOS，且随后各连续输出 7 个 token ID 0。再次增加目标 logits 检查与设备同步后，同一短序列未复现。诊断会改变时序；首次出现非有限值的位置、两次异常是否同源以及与 Engram 候选的关系均未确定。

## 长会话复现

在新的独立诊断副本中，仅在设备上记录上一轮目标 logits 的有限值标志，并在置信度异常时才回读。按照原有请求组和模式顺序完成 26 组 32K 请求，每组 8 条、每条生成 512 token，实际缓存命中均为 29,568；本次未再次出现 NaN。该检查仍会影响设备执行，一次未复现不能证明问题已经解决。

与此前 25 组完整参考比较，所有请求的 DP 和槽位一致；200 条输出中 186 条完整一致，199 条在首个 EOS 前一致。唯一一条 EOS 前差异发生在精确路径，两次生成到 512 token 均未输出 EOS，第一个不同位置为零起始索引 383。该请求所在 DP 的记录显示两次验证长度均为 6、均使用完整目标图；草稿接受数不同，不能据此判断因果，也不能直接归因于先前预算 7 图问题。此前失败的检索请求在本次完成，但原失败输出不完整，不能作为完整参考。

审计 `evidence/nan-async-history-audit-20261030.json`，SHA256 `1d8ccc97e8361bd30a705f55b93c5ea936b60d6a22b83bc834b6efd0dc5b5e5e`。保留基线已恢复，Engram M24 候选仍未采用。

## 固定主负载的预算使用

复核 YOCO 索引提前准备关闭时的两轮原始结果。每轮使用 32,768 输入 token、1,024 输出 token、并发 8，实际 KV 命中 235,904 / 262,144。`selected_total_queries` 对每次验证累计实际选择的四个请求长度之和；单次最大为 24。

| 轮次 | DP | 验证次数 | 选择的查询 token 总数 | 每次平均预算 |
| --- | ---: | ---: | ---: | ---: |
| 第一轮 | 0 | 223 | 5,352 | 24 |
| 第一轮 | 1 | 223 | 5,352 | 24 |
| 第二轮 | 0 | 225 | 5,400 | 24 |
| 第二轮 | 1 | 225 | 5,400 | 24 |

四条记录均达到单次预算上限，说明这些正式请求的所有验证步均选择完整 24 行图，而不是预算 7 图。对应记录的查询长度直方图只统计尚未结束的槽位，不应直接用直方图计数除以四来推断验证次数。该服务首次运行 DSpark 时的 profile 覆盖预算 4、7、24，其校验结果随后复用，并非每次请求重新校验。

因此，M24 候选对这两轮稳态验证不在执行路径上；其价值主要是修复已复现的预算 7 校验差异以及为其他调度场景保留该路径。这个结论不适用于其他输入、并发或置信度分布。候选之前出现的长会话非有限值尚未定位，不能据此采纳，也不能用本次统计证明其模型质量或稳定性。
