# 设备端 Engram 历史窗口

## 适配范围

固定四槽、每槽六个目标查询的异步 DSpark 路径中，候选复用设备状态中的历史尾部、golden 和草稿构造 Engram 原始窗口，供已有设备 hash 与 CPU 共享表的 UVA 读取使用。CPU 继续维护完整历史、位置、C2 状态、调度和输出；不满足资格时回退原路径。该改动是 ZOS 设备状态接续的局部适配，不能代表完整官方 ZOS。

## 验证条件和结果

16 个逻辑设备，DP2、TP8、EP16；输入 32768 token，输出 1024 token，并发 8，实际 KV 命中 235904/262144。同一服务以关、开、开、关顺序各测两轮；两组均启用 DSpark 异步预发、256 token bounded replay 和 Engram UVA，仅切换设备窗口。

| 设备窗口 | 轮次 | 平均 TTFT (ms) | 平均 TPOT (ms) | 输出吞吐 (token/s) |
| --- | --- | ---: | ---: | ---: |
| 关闭 | 1 | 603.3 | 12.3 | 608.299 |
| 开启 | 1 | 601.4 | 12.4 | 606.811 |
| 开启 | 2 | 587.8 | 12.3 | 604.130 |
| 关闭 | 2 | 587.3 | 12.3 | 604.567 |

两轮合并吞吐：关闭 606.427、开启 605.468 token/s；平均 TTFT：595.30、594.60 ms；平均 TPOT：12.30、12.35 ms。开启组两轮吞吐均低于对应基准，第一轮 TPOT 增加 0.1 ms；两轮样本不足以判断小幅差异的稳定性和原因。候选保留，默认关闭。

四轮共 32 条完整输出与参考逐 token 一致，每轮分词缓存命中 8/8；16 rank 设备窗口执行及既有路径已核验。独立短诊断中，每 rank 对六次 24×4 设备窗口与原 CPU 窗口逐位对照，8 条各 32 token 输出一致。审计 SHA 和逐轮证据见 `results.json`。测试没有覆盖一般 EOS、动态 remap、其他批次形状或全部缓存状态。

## 部署和回退

1. 使用 `manifest.json` 指定的服务器父源码快照，执行 `python3 verify.py <源码目录> base`；不要将补丁直接用于未经核验的其他版本。
2. 在独立副本执行 `patch -p1 < candidate.patch`，再执行 `python3 verify.py <源码目录> candidate`。
3. 作业字段 `zos_engram_window` 控制设备窗口，需要同时启用 `zos_fast`、`engram_uva` 和 `engram_device_hash`；`zos_engram_window_check` 为逐位诊断，需要启用设备窗口。性能测试时关闭逐位诊断。
4. 不满足适用条件或关闭选项时使用原 CPU 窗口路径。设备窗口状态和位置在当前输出对外发送前校验；异常终止当前作业。服务启动和切换前应核对设备归属及请求空闲。
