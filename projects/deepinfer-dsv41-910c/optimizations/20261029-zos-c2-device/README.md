# 设备端 C2 状态提交

## 范围

本候选在现有 910C W8A8 路径上，将固定四槽、每槽六个目标查询的 C2 状态选择交给已有设备端原语。模型下一轮使用设备输出；位置、Engram 历史、调度与输出仍由 CPU 管理。不满足条件时使用原路径。该改动只覆盖 ZOS 状态接续的一部分。

## 验证结果

测试使用 16 个逻辑设备、DP2、TP8、EP16，输入 32768 token、输出 1024 token、并发 8，实际 KV 命中 235904/262144。同服务按关、开、开、关顺序各测两轮；两组均开启异步草稿预发、256 token bounded replay 与 Engram UVA，只切换设备 C2 提交。

| 状态 | 轮次 | 平均 TTFT (ms) | 平均 TPOT (ms) | 输出吞吐 (token/s) |
| --- | --- | ---: | ---: | ---: |
| 关闭 | 1 | 607.3 | 12.4 | 606.798 |
| 开启 | 1 | 613.5 | 12.4 | 604.145 |
| 开启 | 2 | 590.8 | 12.3 | 600.973 |
| 关闭 | 2 | 588.8 | 12.3 | 603.632 |

两轮合并吞吐为关闭 605.211、开启 602.555 token/s；平均 TTFT 为 598.05、602.15 ms；平均 TPOT 均为 12.35 ms。设备路径在本次测试中未取得收益，不作为默认路径。两轮样本不足以判断小幅差异的成因或稳定性。

四轮共 32 条完整输出与既有参考逐 token 一致，每轮分词缓存命中 8/8。16 个 rank 的设备路径计数、状态和既有优化均已核验。另一次短诊断中，16 个 rank 各执行 6 次设备 C2 提交，所有有效 C2 状态与原路径按 FP32 位模式一致，8 条各 32 token 输出一致。各项回执摘要和原始结果见 `results.json`。测试不覆盖任意 EOS、动态请求重映射、其他批次形状或所有缓存状态。

## 部署与回退

1. 以 `manifest.json` 指定的父源码快照为输入，执行 `python3 verify.py <源码目录> base`。该父快照位于本项目服务器记录中，不能假定适用于其他版本。
2. 在独立副本中执行 `patch -p1 < candidate.patch`，再执行 `python3 verify.py <源码目录> candidate`。
3. 在该候选服务的作业配置中，`zos_c2_device` 控制设备 C2 路径，开启时必须同时开启 `zos_fast`。`zos_c2_check` 为逐位诊断选项，需要开启 `zos_c2_device`；性能测量应关闭诊断。
4. 不满足限定条件或关闭设备选项时，使用原 C2 提交。设备状态校验失败时回退当前步，并由全局错误投票终止作业。运行前须核对设备归属及空闲状态。

保留的源码与数据用于后续优化和复核，不构成其他工作负载的性能保证。
