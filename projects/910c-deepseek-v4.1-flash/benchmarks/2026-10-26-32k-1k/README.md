# 32K 输入 / 1K 输出性能基线

固定 32768 token 输入、1024 token 输出，官方 `vllm bench serve` 随机数据集，流式 `/v1/completions`，`ignore_eos=true`。服务配置为16个逻辑设备、DP2×TP8、EP16、eager、仅 Engram CPU 卸载；上下文上限34816，batched tokens 2048，max seqs 4/DP。

| 并发 | 成功请求 | 输出吞吐 token/s | 平均 TTFT 秒 | 平均 TPOT ms | 单请求解码 token/s | 平均端到端 秒 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 2/2 | 6.32 | 2.69 | 155.66 | 6.42 | 161.93 |
| 2 | 4/4 | 12.38 | 2.89 | 158.80 | 6.30 | 165.34 |

先执行2请求长输入预热（每请求输出32 token）；上述正式阶段输出均为1024 token。每个阶段固定随机种子：单并发3201、双并发3202。请求率无限，客户端并发上限分别为1和2。正式阶段完成数、输入和输出 token 数、错误列表及吞吐算术由主 Agent 独立核验。

CLI 的额外预热次数为0，独立长输入预热在正式阶段之前完成；服务端请求及 token counters 差值与各阶段正式请求精确一致。各阶段前缀缓存实际 token 命中率分别为 并发1：0.00%, 并发2：0.00%。

这是小样本初始基线，不代表高并发极限、稳定尾延迟或模型准确率。整个测量过程中容器未重启，最终健康接口 HTTP 200。完整原始结果、逐请求时延、配置和指标快照保留在本轮 wio 目录。

客户端没有覆盖 temperature/top_p 等采样参数，沿用模型默认配置。单请求时延不包括等待客户端并发信号量的时间；输出吞吐按完整正式阶段墙钟时间计算。

结果数据见 [baseline-summary.json](baseline-summary.json)。
