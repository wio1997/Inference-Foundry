## 全词表仍有读者时，额外输出获胜 ID 值多少

各 TP8 分片可随原稠密分数交付各自的候选 ID，再对八个候选做归约。行内所有改变排序的处理必须在对应比较前完成，并保留并列时的 token 顺序、掩码和异常值行为。无法局部确定最终获胜者的行沿用原读者。若外部需要完整归一化分数、原始分数或独立副本，仍须按原约定发布。

| 情景假设 | C8 首 token P90 缩短 | C8 整批缩短 |
|---|---:|---:|
| 全部 ArgMax 扫描免费，完整分数与通信照常交付 | 0.156 ms | 8.45 ms（0.045%） |
| 与原稠密包同次交付摘要，扣除打包和两级比较等成本后净省扫描的一半 | 0.078 ms | 4.23 ms（0.023%） |
| 净省一半扫描，但另付一次完全暴露的小 TP8 AllGather | 延长 0.056 ms | 延长 1.90 ms |
| 原 BF16 规范布局发布后，直到完成选词的整个区间免费 | 0.612 ms | 40.61 ms（0.218%） |
| 连同原稠密通信在内，词表矩阵乘结束至选词完成全部免费 | 1.157 ms | 75.63 ms（0.407%） |

最后两行是整段都移走的敏感性估算，包含必须保留的工作。每波选取对候选最有利的活跃 rank，将其节省传到已进入该波的所有请求，再重算请求终点。额外通信按同机 12 个 FP32 元素的 TP8 采样计价，两组中位为 26.77 和 28.79 µs。六个普通请求沿用实际验证次数，净省一半扫描时整段响应最多缩短 0.026%，即使完整目标头后区间免费也最多约 0.274%。M1 首轮在本 DP 没有样本时引用另一 DP 的单请求样本。这些都是估算。[逐请求结果和三个直接交付条件](baselines/optional-paths-and-raw-head.json)

## 两处 5,120 通道中间面

历史记录还指出两项可以按相同尺寸快速复核的交付。输入 embedding 的生产者可向持久输入缓冲写入有效前缀。DSpark 主投影的 TP8 AllGather 返回 rank-major 的八份 640 通道分片，RMS 可按该布局直接读取整行 5,120 通道，省转置写回与再读。两项均须保留现有全部读者。RMS 保留全行归约、gamma、舍入和附加输出。

冻结 7 次 eager TP8 共 56 条主投影链均绑定到实际转置和全宽 RMS。图内 446 次调用用旧 M12/M24 样本中最慢的 28.24 µs 作为小形状代理。假设输入 bank 每个活跃组都有一次完整拷贝，计入全读写并额外给 5 µs 启动成本，而且主投影转置完全免费，两项一起预计只省 **0.623 ms 首 token、8.05 ms 整批（0.043%）**。给六个普通请求的首轮统一采用本次最大 eager 转置样本，整段响应预计至多缩短 0.056%。旧归档确认三种大形状共 24 处持久缓冲拷贝；冻结图的逐次命中率未知。图内启动、短提示形状和跨步干扰仍采用上述假设。[归档分支、算子时长与联合估算](baselines/optional-paths-and-raw-head.json)
