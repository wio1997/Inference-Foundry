DSpark 三层草稿的 64 个窗口按实际请求重算。保留各 rank 的专家时间，将其它已具名计算全部免除，即使计入当前批，首 token P90 也只能提前 6.66 ms。连计算外的整段间隔也免除，若只计此前各批则为 12.93 ms，计入当前批为 15.06 ms。后者比 1% 参考仅多 0.143 ms，请求 4 还须兑现当前批剩余区间的 93.3%。暂缓这组计算及其子集的单独融合。跨卡变更若能提前专家到达，需要另计。 [保留专家执行的模型内预算](../baselines/draft-fixed-expert.json)

原版、单改 QLI、已有 CP + slot + CPU plan 三份独立 profile 各有 112 个完整相邻目标图周期。按 DP0 / DP1，末次草稿 argmax 到首次后续元数据 kernel 的中位间隔分别为 20.537 / 20.432、20.766 / 20.577、9.480 / 9.370 ms。在这段区间，原版和仅改 QLI 均有 708 个具名任务的中位数，已有准备优化为 125 个；其四层原版 QLI 仍约 1.98 ms。这些阶段可共用同一份成本表，组合方案的请求收益需在对应基线单独验证。 [三种配置下的跨迭代阶段](../baselines/qli-iteration-comparison.json)

在另一份已保存的 EP0 记录中，70 个 worker 步按顺序经过采样、Python 记账返回、DSpark 准备、合并草稿计算和采样函数返回。保持所有先前迭代不变，仅允许当前批次提前发布首 token，把草稿三层移出路径的历史 P90 上界为 6.400 ms。即使将边界放宽至最终 FFNPost 结束到草稿末端 Fill，最多也只有 12.807 ms。早发当前结果这一项跳过独立 TTFT 实验。Fill 后面的设备复制、host 投递以及能改变后续迭代的调度另行计价。 [当前批次发布预算](../baselines/terminal-sparsity.json)
