# M07 mHC FFN 后置与下一层状态

执行位置：每层结束，带 pre_mix 进入下一层。当前记录状态：`SCOPED_PRIORITY_DISPOSITIONS_RECORDED`。完整模块优化穷尽：**未证实**。

## 实际分支与排查范围

每周期 34 个直接跨层、2 个 Engram 更新、3 个辅助 mean/gather、1 个终端输出边界。

## 已有价值判断

4480 次 Post 已绑定。直接边界完整零成本筛查最高 0.538%，辅助边界 0.263%，终端 Post 到 norm 0.226%。全部联合的中位 0.971%、最高 1.042%；不能声称所有组合严格低于 1%。

## 必须保留的语义与读者

区分更新前后的 residual/pre_mix；aux mean 和下一层 Pre 可能读不同代际。终端 raw HC 仍有读者时不能用 collapse 替掉它。

## 融合之外的完整改写空间

Post/Pre 驻留；Post+mean 双输出；条件 raw/collapsed 输出；跨层公共 producer；终端归约与 norm 联合。

## 尚缺的关键证据和继续条件

更广 HcPre 算法、真实设备最后读者和驻留条件仍开放。Engram 区间是活跃计算，不能当作跨层空白删掉。

历史八请求的 1% 门槛为 14.919 ms。末端两次 TP8 收集即使连同间隙全部消除，按 16 rank 时钟包络计也至多减少 6.047 ms。在两个 TP 组独立、只在末尾汇合的条件下，最终 FFNPost 交付后到 norm 结束至多减少 14.585 ms。包含最后一层 FFN 和已绑定 head 时，相同口径给出 24.429 ms。是否能缩减最后一层 FFN 的行，取决于原始四路状态、prompt 分数及其它读者。 [八个请求和末端读者](../baselines/terminal-draft-request-costs.json)

两次同负载对照各有 96 份完整输出与归档一致。联合生成 BF16 残差和 Y 的算术在自然输入上通过逐位核对，包括原生 HcPre 延后生成的 Y 和三项 FP32 系数。首次接入时，三轮候选在首 token 窗口分别为 3、2、1 种新行数写入了编译产物。改用运行时行数后，16 个 worker 在六种守卫用例中各自复用同一二进制，三个正式候选批次的 7,072 次调用均命中已准备的内核。 首 token P90 相对前、后参照的降幅为 +0.27% / -5.53%，未通过预定门槛。整批耗时 相对前、后参照的降幅为 -0.66% / -1.77%，未通过预定门槛。 [两次模型服务对照](../baselines/attention-handoff-c8.json)

2,560 次 Attention 首读者中，1,840 次读本地 Q，400 次没有有效本地 Q 但仍须更新全局 KV，320 次为空侧。16 个 rank 的同批原生对照验证了六种排程在三个输入检查面板上的九项输出逐位相同。原生设备时间投到 34 个普通层和历史八请求时，两种联合生成残差和 Y 的方案跨过两种缓存条件的门槛。保持原 TP8 顺序的两个服务实现已完成冻结 C8。提前本地 Q 的联合排程仍缺服务证据。 若只让本地 Q 投影与 AllGather 重叠，固定实际通信时间、发射空隙与其它工作，即使每层都隐藏最慢的 Q 投影，八个请求的首 token P90 最多减少 9.011 ms，低于本轮 14.919 ms 的准入线。跳过这一项的独立 C8。 [跨层算子与保留的读者](../baselines/attention-service-budget.json)

在原有八个请求上，普通 FFNPost→下一层 Attention HcPre 想让首 token P90 缩短 14.919 ms，即使替代成本为零，也需平均按同一比例移出至少 61.04% 的原 HcPre 时间。若能移出全部原 HcPre，每个被改层、每个 DP 可容纳的统一新增暴露耗时最多 70.02 µs。首层、Engram 更新、辅助均值读者和空侧四个分支分别单独改动，均达不到该请求门槛。 [八个请求的约束](../baselines/attention-service-budget.json)

64 个 prefill 逐卡窗口中的 2,560 次 Attention HcPre 都有外部 premix。64 次位于首层、128 次使用 Engram 已修改的残差，192 次还需保留 DSpark 在入口读取的残差均值，另有 2,176 次直接承接上层 FFNPost。每次都找到随后读取 Y 的 RMSNorm、对应 TP8 AllGather，以及稍后读取系数的 Attention Post。固定对端和其余工作，最慢历史请求中只优化首层的乐观上限为 0.659 ms，即使整个 HcPre 都能从关键路径移走。覆盖所有普通直连层时，相同假设下的上限为 24.442 ms。320 次空 Attention 的路径仍执行 gather、填零与 ReduceScatter，单独让该侧提前在原 EP16 入口计价为零。 [跨层读者与预算](../baselines/attention-coefficients.json)

FFN 的完整系数保留到后置 mHC。使用第 0 层权重及两组构造输入，在 6 种真实行数上验证 9 个输出位置。若在残差就绪后立即并行生成系数，分开生成 Y 和双输出融合两种方案的路由反而变慢。推迟到真实路由分数就绪后再生成系数，两者映射到历史最慢请求的条件收益分别为 22.240 ms 和 11.578 ms。只有前者达到 14.919 ms 的筛查门槛。将 Sinkhorn 的 20 次迭代改为 1 次会改变组合系数，其配对中位耗时差映射后为 9.579 ms。 在 171 的同一服务进程内，两轮诊断对自然输入检查了 10,390,732,800 个 BF16 字，每个字均一致。三轮候选计时中，在 256–1024 行的记录范围命中 600/600 次卡组层调用，系数任务均在真实路由分数就绪后提交。P90 首 token前参照、候选、后参照的中位数依次为 1.285、1.251、1.220 秒，相对前后参照分别快 2.65%、慢 2.57%。8 请求整轮前参照、候选、后参照的中位数依次为 15.808、15.766、15.804 秒，相对前后参照分别快 0.27%、快 0.24%。两项均未通过冻结门槛。11 轮共 88 个输出文本和负载计数吻合。原服务已恢复并通过生成验证。 [系数提交时刻和服务实测](../baselines/ffn-schedules.json)

160 次自然路由重放保留专家计算及原 BF16 舍入，隔离跨卡写回后十二轮配对中位少 47.989 ms。用三个向量核分担同一目标的不同行，仍将结果送往原接收方；120 次 V1 完整算子用时的合计中位比前、后参照低 2.64%、2.17%。 首 token P90相对前、后参照的中位耗时降幅为 +6.48% / +5.09%，未通过预设判据。整批完成时间相对前、后参照的中位耗时降幅为 +0.47% / +0.03%，未通过预设判据。 [回写与冻结服务](../baselines/expert-return-native.json)

在 160 次真实 MoE 层调用上，把六路结果按原顺序放到指定芯片归约，可以保持每芯片、每卡的峰值归约行数，跨卡少传 6.491 GB，同卡两芯片之间多传 2.203 GB。其中 590,291 行形成两段有先后依赖的跨卡传输。 在历史 profile 的 2,560 组调用中，源端的 BF16 ForeachAddList 合并路由与共享专家输出，随后执行 HcPost。对齐 M、层和 16 个 rank 的有效输入行数后，可比较 120 层。假设候选最终结果在原 MoE 结束时就绪，且能用独立通信与后续工作重叠，赶在原合并开始前完成交付，最忙接收芯片所需速率的中位数为 18.73 GB/s；只保留四段共享专家计算时为 26.24 GB/s。两次采集的层几何相同，这些速率是条件门槛。 [归约位置、依赖和交付条件](../baselines/expert-ordered-return.json)

对齐四批、16 个 rank 的最终 FFN 调用、调度步和实际词表读者。最后一层共有 26,318 个有效发送行、157,908 项专家分配，立即执行的目标词表投影只选 62 行。416 行批次里 DP1 没有立即目标投影，却接收了 9,081 项专家分配，按收发守恒至少 8,937 项来自另一个 DP。原排程下分阶段计算，只改最后 FFN 的历史首 token P90 上界为 9.429 ms，只改末端收集、复制和归一化为 13.563 ms。联合改写为 22.992 ms。若四批替代路径耗时相同，每批最多能用 2.018 ms 才能达到 1% 参考。 171 在两个同进程 C8 批次中各验证 8 份完整输出。候选的 5 个真实大 DP 批次按 TP 去重共有 26,288 行，原始四路状态全量填入 NaN，最终归一化输出的 26,244 个未选行同样填入 NaN，词表 head 实际收到的 44 个向量与改写前逐位相同。16 个 worker 的运行配置均为 DSpark 辅助状态路径，所测调用的 prompt 对数概率请求数为零。按原有行归属进行 TP8 定长发送共需 304 个结果行槽，允许重分布后为 64 个，至少需要迁移 30 个输入行。该对照保留了原计算与缓冲地址。改变运算行数后的逐位一致性、联合内核耗时以及小批次、空侧和图路径仍需分别验证。 在 171 容器的 CPU 上用同一批行号执行已安装的 MC2 准备函数，保留旧批次上下文会回填到 26,288 个行槽，旧有效前缀在所测输入上把 260 个填充位误当有效行。构建紧凑上下文后是 304 个行槽，逐位掩码错误数为 0。此项尚未执行新布局的设备通信。 [最终层逐行证据、成本与服务对照](../baselines/terminal-sparsity.json)
