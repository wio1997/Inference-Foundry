# M03 Attention

执行位置：Q/K/V投影、缓存发布、QLI、稀疏注意力、输出投影。当前记录状态：`SCOPED_PRIORITY_SCREENED_CONDITIONAL_FRONTIERS_RETAINED`。完整模块优化穷尽：**未证实**。

## 实际分支与排查范围

SWA/稀疏 attention、索引源层、QLI/MLA、KV 发布、prefill/decode、rank 无本地 attention 但参与通信。

## 已有价值判断

当前 QA+index-W 完整小区间至多 0.424%，重复 QR 量化至多 0.040%；SWA 直接 join 乐观筛查最高 0.882%。大输入 OA/打包/通信按匹配频次计价也暂缓独立实验。

## 必须保留的语义与读者

保留 RoPE/量化边界、KV 和索引缓存读者、候选与长度、row ownership、TP 参与者。缺失 SMLA 记录不意味着该 rank 可删除。

## 融合之外的完整改写空间

QLI 到 MLA 的 selected-KV 交付；SMLA tile 重组；生产端布局/通信；RoPE/store 联合；跨层缓存和状态发布。

## 尚缺的关键证据和继续条件

QLI 修正版 C8 输出相同但耗时在前后参照之间；现有分支输出加 LSE 的拆分不满足统一数值合同。更广算法保留条件。

四个历史首 token 批次可定位 368 条 QLI 到同层 SMLA 的序列，其中 40 条在第 20 层多一个 TensorMove。后置索引准备连同任务间隙在四段 eager 模型体与 225 次图调用的本地时间并集上最高占 0.039%。单独消除交接的吞吐价值暂缓，首 token 和跨层读者仍有独立预算。[分层成本与边界](../baselines/prefill-f21-attention.json)

368 组共享索引的后续读者共调用 SMLA 1,380 次。Q416 的原生配对中，已选 KV 排紧后仍用同一内核；四组输出逐位一致，净时间未过预设门槛。暂缓这个独立布局变体。跨层驻留仍受权重工作集、实际选中集合和读者代际约束。[工作集与原生定价](../baselines/prefill-selected-kv.json)

同一轮 C8 的两个引擎各完成 4 个请求，排队时间合计分别为 0.159 和 0.155 ms。若请求 0、6 在前一步决策时都已入队，原来两次调度决策必须相距至多 79.45 µs。启动参数启用了异步调度，worker 入口不能代替这个时点。后续一次冻结 C8 已补齐请求交付时间线。[请求时点与负载](../baselines/prefill-admission.json)

新 C8 的 8 个请求输出均与归档一致。6 个较晚首次调度的请求在本 DP 前一次非空决策时都未完成分词。第 8 个输入在 CPU 对照上的就绪中位时间为 612.09 ms（默认）、169.68 ms（四线程）、73.70 ms（复用种子前缀）及 21.36 ms（两者合用）。四线程配置的冻结对照结果见本轮记录。[调用时点与四组对照](../baselines/prefill-request-delivery.json)

64 个历史首 token 区间共 135,592 条 native 记录。由 22,248 次矩阵与专家调用核算直接算法工作量。在 1.8 GHz 参考条件下，M416、816、817、818 的部分计算时间下限为 10.49、20.57、20.59、25.47 ms。各层本地活跃专家权重按未压缩直读、每卡起始最多驻留 192 MiB 估算。若要在各自的部分计算下限时间内搬完这些权重，需达到 2.17、1.11、1.09、0.94 TB/s。实际可达带宽、驻留与物理时钟上界仍待约束。 [条件下限](../baselines/eager-resources-and-copies.json)

在 2,240 条同层 OA → OB → ReduceScatter → HcPost 链中，1,600 条包含 OB 输出拷贝。把接口间隙和后续拷贝全部消掉，对八个历史请求的乐观预算分别仅占各自 TTFT 的 0.232%–0.389%，暂缓该单项。扩大到两次矩阵实现及其内部中间张量读写后，按 1.8 GHz 与原直接算法计算，可改时间条件预算占 1.003%–1.809%，保留联合实现。直接预乘权重使每行 MAC 从 9,437,184 增至 20,971,520，且中间 BF16 舍入可产生不同结果。M416 的 8 个 DP1 区间未定位同签名 OA，继续保留。 [按请求及实际签名计价](../baselines/eager-resources-and-copies.json)

在 2,240 条逐卡链中同时绑定了 280 组八卡 AllToAll、输出投影、ReduceScatter 和 HcPost。按 BF16 和环形 ReduceScatter 的逻辑字节，若在行所属的卡上完成 OA 与八个 OB 部分结果的归约，可省 129,024 B/本地填充行。首次取得七个对端权重分片需 126 MiB/卡/层，累计 1,024 行时收支相抵。当前每次只有 3–818 行，逐次收集两段权重会增加传输。若只获取一次并跨历史批次保留，DP0 / DP1 可覆盖 1,655 / 1,637 行，仍须支付 HBM 读取、计算和本地归约。前者覆盖四个载体，后者覆盖三个，M416 的 DP1 未绑定。原服务恢复后的显存快照，各逻辑芯片报告剩余 5,101–5,518 MB。若原分片保留且完整权重另开缓冲，40 层每卡需额外 5,760 MiB。共享或回收本地分片时，理论额外载荷为 5,040 MiB，还需核算临时工作区和分配器。保留部分层常驻，以及只复制 OB 的方案。 [逐组通信和容量](../baselines/projection-owners.json)

单次八卡实验复用同一批输入和第 0 层真实权重，同时比较只前移 OA、只前移 OB 和两段都前移。416、818 行只前移 OA 都逐位一致。按每轮最慢 rank 配对，无显式缓冲预触时每层中位省 164.92、222.28 µs，预触 224 MiB 后为 232.82、161.72 µs。416 行只前移 OB 或两段都前移均变慢；818 行的 OB 有 15,019 个部分结果改变，合并输出有 1,236 处不同。3 行原生 AIV 归约在相同诊断输入上重复运行会出现位差，不能用大尺寸归约的舍入次序推断。历史最慢请求在 DP1，首 token 为 1,491.85 ms。在同 DP 已观测且通过原生验证的行数上，把第 0 层配对中位应用到 40 层并假定全额暴露，可省 6.47–8.89 ms，占 0.43%–0.60%。这是一种情景估算。实际服务各层、跨 DP 等待和其它尺寸的收益仍待核对。先合并估价，再决定是否接入服务。 [逐项证据](../baselines/projection-owner-native.json)

四个 prefill 批次的 2,560 个层/rank 入口都已绑定。在 M416 的 DP1，320 个 Attention 前半层走填零与 ReduceScatter 路径。用前后两个目标图的 80 组短 F21 通信和 160 组 eager F21 约束各卡相对时钟偏差，并假设该时段偏差稳定。四批共 160 层有 159 层由行数较多的卡组最后进入 MoE。M818 的另一层由 419 行一侧最后进入。单靠每段 eager 内的调用约束只能确定 36 层，事件记录的缺失或时间重叠均不能证明独立。第 0 层真实权重、合成 BF16 输入、两组 TP8 同时执行。只前移 OA 时，按 Q816、817、419、818 排列，无显式预触的单层配对中位节省分别为 278.00、386.26、285.92、312.30 µs；预触 224 MiB 后分别为 162.90、329.42、129.94、159.64 µs。四组都通过逐位验收与既定门槛。把实测变化按各层最后进入 MoE 的卡组计入，历史最慢请求的条件预算为 35.36–45.63 ms，占首 token 的 2.37%–3.06%。该预算假定每层都取得第 0 层的局部改善并传播到后续环节。真实模型的输入、常驻显存、命中和回退另见本轮服务记录。 [双组原生样本和跨卡计价](../baselines/projection-joint-arrival.json)

用同一批 profile 对一整类方案做了筛查。假定对端进入 MoE 的时刻固定，只让本层行数较少的一组提前，160 个层入口中有 159 个的最晚到达时刻保持原值。仅 M818 第 0 层有空间，即使把该侧全部前置耗时清零，最晚到达最多提前 5.944 ms，约占历史最慢请求首 token 的 0.398%。加速较晚的一组、提早发布专家输入、减少共享资源争用或移除同步，均需按各自的机制核算。 [逐层筛查](../baselines/oa-service.json)

171 的两个 TP8 组、每组 40 层已装入真实 OA 权重，每逻辑设备新增权重 2.5 GiB。两轮冻结 C8 实际送入 OB 的 16,179,527,680 个 BF16 字逐位一致。第三轮的行数改变，按每组每层计的 200 次大行数调用全部回退，三轮共 24 个完整输出及负载计数均与归档一致。候选执行 0 次，按预设规则跳过 9 轮计时，真实服务提速仍未知。合并前两轮两个 DP 的行数也只能命中 0 次。即使加入两份历史尺寸资料，按 DP 也仅能匹配 80/200 次，历史尺寸只用于准备。三个服务启动尝试均已恢复原启动脚本并通过 HTTP 200 和 2 token 生成检查。第一次自动分配的总量与历史记录相差 16 块。第二次把前端合计用于单引擎，导致 KV 分配显存不足。第三次在同一服务进程对所有组别固定 DP0 的 17,302 块和 DP1 的 17,303 块，block size 为 128。历史数据只保存总量 34,605。离线把新 OA 的行数向上对齐到 32、64 或 128，三种情形都覆盖留出轮次中的 3/5 组尺寸，但额外逻辑行数分别为 3.26%、5.21% 和 13.00%。先查原算子舍入和 kernel 选择能否覆盖 16/32 行分组，再决定是否值得原生计时。 [服务验证和容量](../baselines/oa-service.json)

171 上的 19 种行数在 16 卡、40 层的 12,160 个组合内，构造输入的 pre-OB 输出逐 BF16 字一致。两次自然输入旁路比对和一次实际启用试跑完成后，三组各计时三轮。候选在记录范围内命中 600/600 次卡组层调用。P90 首 token的前参照、候选、后参照中位数为 1.293、1.205、1.212 秒，候选相对前后参照的耗时降幅为 +6.84% / +0.59%，未达到预定门槛。8 请求整轮的前参照、候选、后参照中位数为 15.892、15.937、15.801 秒，候选相对前后参照的耗时降幅为 -0.28% / -0.86%，未达到预定门槛。共 12 轮的 96 个输出与归档文本一致，负载计数吻合。所有实验臂每卡同样预留 2.5 GiB 权重，171 原服务已恢复。 [精确行数与服务结果](../baselines/oa-family-c8.json)

两次同负载对照各有 96 份完整输出与归档一致。联合生成 BF16 残差和 Y 的算术在自然输入上通过逐位核对，包括原生 HcPre 延后生成的 Y 和三项 FP32 系数。首次接入时，三轮候选在首 token 窗口分别为 3、2、1 种新行数写入了编译产物。改用运行时行数后，16 个 worker 在六种守卫用例中各自复用同一二进制，三个正式候选批次的 7,072 次调用均命中已准备的内核。 首 token P90 相对前、后参照的降幅为 +0.27% / -5.53%，未通过预定门槛。整批耗时 相对前、后参照的降幅为 -0.66% / -1.77%，未通过预定门槛。 [两次模型服务对照](../baselines/attention-handoff-c8.json)

2,560 次 Attention 首读者中，1,840 次读本地 Q，400 次没有有效本地 Q 但仍须更新全局 KV，320 次为空侧。16 个 rank 的同批原生对照验证了六种排程在三个输入检查面板上的九项输出逐位相同。原生设备时间投到 34 个普通层和历史八请求时，两种联合生成残差和 Y 的方案跨过两种缓存条件的门槛。保持原 TP8 顺序的两个服务实现已完成冻结 C8。提前本地 Q 的联合排程仍缺服务证据。 若只让本地 Q 投影与 AllGather 重叠，固定实际通信时间、发射空隙与其它工作，即使每层都隐藏最慢的 Q 投影，八个请求的首 token P90 最多减少 9.011 ms，低于本轮 14.919 ms 的准入线。跳过这一项的独立 C8。 [跨层算子与保留的读者](../baselines/attention-service-budget.json)

在原有八个请求上，普通 FFNPost→下一层 Attention HcPre 想让首 token P90 缩短 14.919 ms，即使替代成本为零，也需平均按同一比例移出至少 61.04% 的原 HcPre 时间。若能移出全部原 HcPre，每个被改层、每个 DP 可容纳的统一新增暴露耗时最多 70.02 µs。首层、Engram 更新、辅助均值读者和空侧四个分支分别单独改动，均达不到该请求门槛。 [八个请求的约束](../baselines/attention-service-budget.json)

64 个 prefill 逐卡窗口中的 2,560 次 Attention HcPre 都有外部 premix。64 次位于首层、128 次使用 Engram 已修改的残差，192 次还需保留 DSpark 在入口读取的残差均值，另有 2,176 次直接承接上层 FFNPost。每次都找到随后读取 Y 的 RMSNorm、对应 TP8 AllGather，以及稍后读取系数的 Attention Post。固定对端和其余工作，最慢历史请求中只优化首层的乐观上限为 0.659 ms，即使整个 HcPre 都能从关键路径移走。覆盖所有普通直连层时，相同假设下的上限为 24.442 ms。320 次空 Attention 的路径仍执行 gather、填零与 ReduceScatter，单独让该侧提前在原 EP16 入口计价为零。 [跨层读者与预算](../baselines/attention-coefficients.json)
