## 实际分支与排查范围

输入、embedding、有效/无效 ID、padding、prefill/decode、target/draft、图内/图外准备。

## 已有价值判断

当前 112 个 decode 窗口的入口非通信 native 工作至多占本地周期 0.127%。独立小转换暂缓；CPU 分组发布已有范围限定的服务证据，不能和其它历史收益相加。

## 必须保留的语义与读者

保留 ID 验证、填零、原始行顺序、padding、图地址和所有状态消费者；view 不能按一次 HBM 拷贝计价。

## 融合之外的完整改写空间

需求驱动消除；有效分支内查表/填零；producer 直接写目标布局；共同输入准备与所有权重组。

## 尚缺的关键证据和继续条件

只为完整 CPU/通信/行所有权重组补证。跨迭代输入共享还需相同请求、位置与状态代际。

同一轮 C8 的两个引擎各完成 4 个请求，排队时间合计分别为 0.159 和 0.155 ms。若请求 0、6 在前一步决策时都已入队，原来两次调度决策必须相距至多 79.45 µs。启动参数启用了异步调度，worker 入口不能代替这个时点。后续一次冻结 C8 已补齐请求交付时间线。[请求时点与负载](../baselines/prefill-admission.json)

新 C8 的 8 个请求输出均与归档一致。6 个较晚首次调度的请求在本 DP 前一次非空决策时都未完成分词。第 8 个输入在 CPU 对照上的就绪中位时间为 612.09 ms（默认）、169.68 ms（四线程）、73.70 ms（复用种子前缀）及 21.36 ms（两者合用）。四线程配置的冻结对照结果见本轮记录。[调用时点与四组对照](../baselines/prefill-request-delivery.json)

线程池实际宽度依次为 1 / 4 / 1。三组各有一次准入和三次计时，12 轮共 96 份输出文本逐个与归档一致。按前参照 / 四线程 / 后参照顺序，慢请求的首 token 延迟中位为 1.2496 / 0.9855 / 1.2177 秒，四线程分别缩短 21.130% / 19.064%，通过冻结门槛。整轮耗时中位为 15.6522 / 15.5043 / 15.8759 秒，分别缩短 0.945% / 2.340%，对前参照未达到 1%。 [冻结 C8](../baselines/renderer-c8.json)

1,283 个 added token 中有 1,221 个包含候选数字切点。逐个构造跨切点输入，简单拆分 1,221 次全部产生不同的 ID。新增守卫拒绝全部反例，八份冻结输入仍分别复用 28,789 个 token，全长 32,768 个 ID 逐个相同。真实 renderer 的后续验证已完成。 [边界验证](../baselines/renderer-c8.json)

在实际 DeepseekV4Renderer 的四线程 CPU 入口，四组八请求逐个保留输出结构与全部 token ID，13 项对照覆盖截断、越界错误、特殊 token、并发命中和代际回退。第八份输入就绪中位从 199.40 降到 27.97 ms，冷种子构建一次实测 65.70 ms。此前离线对照显式创建了 tokenizer 副本池，这次使用运行时选中的 renderer 及其原始 tokenizer。随后同一服务进程完成 12 次冻结 C8，四组候选各命中八次，96 份生成文本与归档一致。按四线程前参照 / 前缀复用 / 四线程后参照，首 token 的 P90 中位为 0.9844 / 0.8599 / 0.9759 秒，正式整轮为 15.5667 / 15.3725 / 15.4546 秒，从冷种子开始到正式轮结束为 17.1857 / 17.0503 / 17.3725 秒。三项均未过冻结门槛，停止这个版本的服务试验。 [服务证据](../baselines/prefix-service.json)
