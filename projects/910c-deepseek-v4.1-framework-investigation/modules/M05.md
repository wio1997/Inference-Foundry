# M05 mHC FFN 前置与 RMS/cast

执行位置：Router/MLP之前。当前记录状态：`SCOPED_PRIORITY_SCREENED_CONDITIONAL_FRONTIERS_RETAINED`。完整模块优化穷尽：**未证实**。

## 实际分支与排查范围

FFN HcPre、RmsNormCast 的 BF16/FP32 双输出、router 与量化输入的不同读者。

## 已有价值判断

FFN HcPre 中位约 1.4153 ms；norm/cast 中位约 0.1172 ms，后者最高 0.224%。Post/norm/三处间隔的联合零成本筛查最高 1.040%，并非严格小于 1%。

## 必须保留的语义与读者

需要 BF16 的消费者必须得到原舍入值；不能用未舍入 FP32 norm 直接替代量化输入。

## 融合之外的完整改写空间

完整 FFN early-Y；多输出 norm/quant；前后置联合驻留；同一输入上的必要归约共享。

## 尚缺的关键证据和继续条件

宽范围 FFN 变换需同时解释 router、shared、routed、残差与实际资源竞争；不能由 norm 小直接否定。

4 个首 token 批次共 2,560 条 Attention Post 至 MoE 入口的逐卡路径。轻载卡组走 1,280 条填充路径，重载卡组的 1,280 条对应路径直接路由。按固定对端与原调度计价，对历史最慢请求，消除全部路由 PadV3 和 MemSet 的条件上限是 0.211 ms，独立 RMSNormCast 是 5.389 ms。Attention HcPost、FFN HcPre 与 RMSNormCast 三者的联合上限为 48.480 ms。达到该请求首 token 的 1% 需要兑现这个乐观预算的 30.8%。若联合变换只少读一次 BF16 残差，全部暴露时所需的盈亏平衡速率为 313.8 GB/s。按同字节 TensorMove 的实测中位耗时估算，四段累计仅 3.933 ms。实际 HcPre 的读取、缓存与计算重叠仍需独立判断，后续 FFNPost 还需要这份残差。 [逐分支与逐请求预算](../baselines/ffn-entry.json)
