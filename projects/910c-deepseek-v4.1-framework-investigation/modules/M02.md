# M02 mHC Attention 前置、归一化与 SP 输入交付

执行位置：每层 Attention 之前。当前记录状态：`SCOPED_PRIORITY_SCREENED_CONDITIONAL_FRONTIERS_RETAINED`。完整模块优化穷尽：**未证实**。

按同一请求的逐层通信时点去重，mHC 残差交付、SMLA 压缩 KV 直读与首段 PV 直写、OA→OB 分块这四项的中间情景可省冻结 C8 首 token P90 40.40–43.03 ms（2.71%–2.88%），整批约 0.25%–0.26%。普通代码首轮及后续请求的首 token 约省 2.98–3.53 ms，依赖投影重叠。四个 QLI 消费层的排序收益另列。 [同一请求上的联合与增量](../joint-attention-frontiers.md)

固定专家和权重，mHC 残差交付、SMLA 压缩 KV 读取与 OA→OB 分块交付同时生效，三个局部节省全部兑现时，冻结 C8 首 token P90 预计省 34.48–37.09 ms，整批仅省 38.81–41.55 ms。六个普通请求整段响应最高约 0.69%。只保留长提示首 token 条件项。 [按同批各请求的产出波次重算](../joint-attention-frontiers.md)

目标先分行再展开，草稿先展开再分行。首个 HcPre 与 HcPost 共同从原始 BF16 行读取，按冻结 453 次 TP8 调用估算，C8 整批缩短 15.88 ms（0.085%），六个普通请求的响应最高约 0.081%。 两层 Engram 在 padding 行跳过 K 和部分门控计算，保留 V 与残差。只看最有利的 rank，普通请求估算最高 1.04%；按真实 TP8 就绪时点和同波时钟约束，用 B1 样本中位外推最高 0.50%，改用其中最大样本为 0.64%。 [首层四路展开与 Engram](../initial-hc-engram.md)

归档中有 2,560 处 AttentionPost→FFNPre 以及 2,176 处直接相邻的 FFNPost→下一层 AttentionPre。两处均可考虑由 Post 同时交付原 BF16 残差、供 Cube 使用的扩宽值和按外部系数归约的 Y，并保留 Y 的 BF16 舍入及后续归一化读者。每次完整目标模型前向按 40 处 FFN 和 34 处 Attention 计价。若仅省一次残差读取及 Y 的写读，C8 首 token P90 估算省 5.47–10.94 ms。若两次残差读取均省、扩宽写入等成本，估算省 9.12–18.23 ms。按有利搬运速率给扩宽写增加 25% 成本后只省 14.59 ms，已低于 14.92 ms 门槛。六个普通请求在等成本的有利估算下，首 token 最高 0.635%，响应完成最高 0.260%。 [同一批请求的两处 mHC 交付](../baselines/hc-paired-boundaries.json)

34 个普通直连层中，固定 Y 提前交付与 TP8 排程后，将 FFN HcPost 与下一层的加权归约合成一个算子。九轮原生配对投到历史八请求，原 AllGather 顺序下首 token P90 中位估算省 10.53 ms（热缓存）/ 14.02 ms（缓存受压）；本地 Q 提前时为 11.67 / 15.58 ms。四组中一组中位超过 14.92 ms，每组均有退化轮次。实际服务的动态行版本相对前后参照为快 0.27% / 慢 5.53%，尚无稳定端到端收益。 [固定排程对照](../baselines/cross-layer-hc-fusion.json)

已有动态行实现提前产出 Y，随后在辅助流又调用完整 HcPre，只把后三个系数交给下游。在固定其他设备时长的配对模型中，四种条件、每种九轮，即使完全消除系数迟到，八请求 P90 的额外改善也是 0 ms。缩短这个算子若能减少对主流的资源竞争，仍需另计该影响。 [晚读者及组间到达](../baselines/cross-layer-hc-fusion.json)

64 个首层入口没有上层 FFN Post；2,176 条直连可用上一层已交付的 premix；192 条 DSpark 分支需保留进入该层的残差均值与 gather；128 条 Engram 分支须先更新残差。两种搬运计价下，把直连两次残差读取与 Y 写读一起省掉，历史首 token P90 约省 4.21–8.42 ms。再按分支融合均值读取与 Engram 尾部，联合为 6.27–12.00 ms；六个普通请求约省 0.42–1.46 ms，最高占自身响应的 0.184%。即使两层 Engram 尾处理和三次均值全省，固定其他工作时也仅为 3.27 ms 首 token 与 32.93 ms 整批。 [分支和逐请求成本](../baselines/cross-layer-hc-fusion.json)

Attention Post 额外交付扩宽的 FP32 残差时，每行少读一份 BF16，Cube 仍需读 FP32。历史 eager 首 token P90 在两种同速计价下省 0.36–3.93 ms。只存 FP32 则另有两个读者需要读取宽残差，净省字节为零。只读核对固定 checkpoint 中 40 个 Attention 和 40 个 FFN 投影矩阵，每个矩阵都有单 BF16 权重无法保留原投影操作数精度的系数。 [残差布局与系数](../baselines/hc-workspace-delivery.json)

## 尚缺的关键证据和继续条件

QA-only 失败不否定完整 Attention/FFN 分流；新候选必须有不同可消除工作或资源利用依据。

两次同负载对照各有 96 份完整输出与归档一致。联合生成 BF16 残差和 Y 的算术在自然输入上通过逐位核对，包括原生 HcPre 延后生成的 Y 和三项 FP32 系数。首次接入时，三轮候选在首 token 窗口分别为 3、2、1 种新行数写入了编译产物。改用运行时行数后，16 个 worker 在六种守卫用例中各自复用同一二进制，三个正式候选批次的 7,072 次调用均命中已准备的内核。 首 token P90 相对前、后参照的降幅为 +0.27% / -5.53%，未通过预定门槛。整批耗时 相对前、后参照的降幅为 -0.66% / -1.77%，未通过预定门槛。 [两次模型服务对照](../baselines/attention-handoff-c8.json)

2,560 次 Attention 首读者中，1,840 次读本地 Q，400 次没有有效本地 Q 但仍须更新全局 KV，320 次为空侧。16 个 rank 的同批原生对照验证了六种排程在三个输入检查面板上的九项输出逐位相同。原生设备时间投到 34 个普通层和历史八请求时，两种联合生成残差和 Y 的方案跨过两种缓存条件的门槛。保持原 TP8 顺序的两个服务实现已完成冻结 C8。提前本地 Q 的联合排程仍缺服务证据。 若只让本地 Q 投影与 AllGather 重叠，固定实际通信时间、发射空隙与其它工作，即使每层都隐藏最慢的 Q 投影，八个请求的首 token P90 最多减少 9.011 ms，低于本轮 14.919 ms 的准入线。跳过这一项的独立 C8。 [跨层算子与保留的读者](../baselines/attention-service-budget.json)

在原有八个请求上，普通 FFNPost→下一层 Attention HcPre 想让首 token P90 缩短 14.919 ms，即使替代成本为零，也需平均按同一比例移出至少 61.04% 的原 HcPre 时间。若能移出全部原 HcPre，每个被改层、每个 DP 可容纳的统一新增暴露耗时最多 70.02 µs。首层、Engram 更新、辅助均值读者和空侧四个分支分别单独改动，均达不到该请求门槛。 [八个请求的约束](../baselines/attention-service-budget.json)

64 个 prefill 逐卡窗口中的 2,560 次 Attention HcPre 都有外部 premix。64 次位于首层、128 次使用 Engram 已修改的残差，192 次还需保留 DSpark 在入口读取的残差均值，另有 2,176 次直接承接上层 FFNPost。每次都找到随后读取 Y 的 RMSNorm、对应 TP8 AllGather，以及稍后读取系数的 Attention Post。固定对端和其余工作，最慢历史请求中只优化首层的乐观上限为 0.659 ms，即使整个 HcPre 都能从关键路径移走。覆盖所有普通直连层时，相同假设下的上限为 24.442 ms。320 次空 Attention 的路径仍执行 gather、填零与 ReduceScatter，单独让该侧提前在原 EP16 入口计价为零。 [跨层读者与预算](../baselines/attention-coefficients.json)

将已有 HcPre 的成对计时对齐 5,120 次真实调用。Attention 或 FFN 单侧即使用最有利样本，乐观首 token 收益也只有 9.96 ms，低于历史 C8 的 14.92 ms 参考。两侧合计须兑现计时中位差额的 77.6%。本次筛查的退出条件是整块 FP32 状态逐位稳定。真实激活的稳定深度仍未知，单侧和小形状 decode 暂缓独立实验。 [按真实调用估算提前退出的收益](../baselines/mhc-iteration-cost.json)
