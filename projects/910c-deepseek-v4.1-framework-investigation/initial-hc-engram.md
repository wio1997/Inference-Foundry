# 输入 embedding、首层 mHC 和两层 Engram

在 171 的冻结 C8 中，目标和草稿各有 453 次已调度 TP8 调用，分布在 227 个波次。把输入展开和首层两处消费算子一起改写，整批估算省 **15.88 ms（0.085%）**。将两层 Engram 的哈希结果和 WKV 投影结果也改成直接交付，三处合计约省 **16.19 ms（0.087%）**。六个普通请求按提示长度和实际验证次数估算，合计响应收益最高约 **0.082%**。整批参照为 18,590.77 ms，首 token P90 为 1,491.85 ms。[逐请求结果、数据指纹与模型假设](baselines/initial-hc-engram.json)

## 首层有两个读者

目标先按 TP8 切分 token 行，再用 Tile 把每行 5,120 个 BF16 值展开为四路。草稿先展开全批，再补齐并切行。首个 HcPre 消费展开值与 FP32 的初始混合系数，随后的首个 HcPost 还要用同一份残差和注意力输出做组合。两处均支持从原始行按通道读取时，整块四路临时面才可消失。原模型第 0 层没有 Engram，三个草稿检查点在第 37、38、39 层。其它配置若在首层插入额外读者，须重新核对。[逐卡任务、源版本与读者](baselines/initial-hc-engram.json)

| 比较范围 | 冻结首 token P90 预计缩短 | 冻结整批预计缩短 |
|---|---:|---:|
| 草稿改为仅物化本 rank 的四路结果，按参考搬运速率支付本地读写 | 0.16 ms | 6.85 ms |
| 两种角色均保留四路计算顺序，省展开、宽 padding、已识别的初始系数准备，并让首个 Pre 和 Post 各少读三路 | 0.46 ms | 15.88 ms |
| 假设每个 ID 的首层前缀缓存全命中，连首个 Pre 和 RMS 的旧工作都免费 | 1.48 ms | 34.74 ms |
| 只看 B4 草稿旧准备的主线程调用，相关提交全部消失且时间完全暴露 | 0.19 ms | 40.01 ms |

首层缓存情景的普通响应收益最高约 0.208%。单角色若为每个词保存 24 个 FP32 系数，129,280 个词需 12,410,880 B；再保存完整 BF16 归一化向量需 1,323,827,200 B。目标和草稿的 embedding、参数及数值模式须分别匹配。已有预算足以停止追查热词命中率。CPU 情景的 48 个 B4 样本中，每次六个设备任务只对应五个不同的主线程调用，中位合计 186.09 µs。CPU 与设备时间可能重叠。3,624 个草稿 rank 调用中有 24 个未匹配完整的四任务初始系数签名，只计已经定位的部分。

## Engram 的两个中间结果及 padding 分支

- **哈希到两个查表算子。** 两层共 48 个 INT64 索引，直接传给查表可省每个容量行 768 B 逻辑写读。按同机连续搬运参考计算，冻结整批约省 0.009 ms；假设有效速率只有参考的四分之一，也仅约 0.036 ms。即使把原哈希和两次查表的全部核耗时都算作可省，整批也只有 40.62 ms（0.219%）。独立的 mask 早发布、历史写入、两张表及通信仍各有读者。[索引宽度、调用与请求量级](baselines/initial-hc-engram.json)
- **WKV 投影到门控。** 假设每层的 25,600 个 BF16 投影元素能直接交给门控，每本地行可免一次写回和再读，保留 BF16 舍入、后续归约和残差。两层合计估算省首 token P90 0.24 ms、整批 0.30 ms。整个 WKV 和门控阶段的整批设备工作取最有利 rank 可达 219.54 ms，其中大部分计算在融合后仍要执行。
- **按行跳过失活计算。** 已知 padding 行可以跳过 K 投影、旋转及部分门控，仍需 V、原顺序的 FP32 零乘、残差相加与 BF16 舍入。用每行 80% 的原 WKV 成本及对应门控阶段作为有利估值，固定请求的 37,040 个容量行中共有 240 个超出调度前缀。本次只给这些行估价。含图像特殊 token 或其它额外失活行的负载保留条件。

对 18 次含 padding 的图模式 TP8 调用，逐卡绑定两层各 38 个设备任务，以及随后首个 RMS 和相同组、相同编号的 AllGather。按原设备时间戳，对比最迟一个 rank 在改写前后的 RMS 完成时点；另用同波 40 次 F21 交换约束时钟偏差。较长的 eager 提示段使用同批逐卡计时。已知 padding 的冻结整批估计为 **0.12 ms**，放宽跨卡时钟后为 **0–4.79 ms**。这里仍乐观地假设每一卡省下的时间可以一直传到 RMS 完成。

对六个普通请求，只挑每层省时最多的 rank，估算最高为 **1.04%**。使用实际 TP8 就绪时点和时钟区间，三个同形状单请求图样本取中位外推，最高为 **0.50%**；改用三个样本中最大的值，最高为 **0.64%**。这个差异足以把纯 padding 特化降级。两组百分数都是普通负载的情景估算。预先知道有效行后可裁去的算术单列，不能再与固定行域的 WKV 交付重复计算。[各普通请求及跨卡时点](baselines/initial-hc-engram.json)
