# Attention 融合在同一请求上能省多少

**冻结长提示的首 token 是这组融合最有价值的指标。** 在同一份 171 profile 上，把 mHC 残差交付、压缩 KV 直读、首段 PV 直写及 OA→OB 分块放回每层的执行位置。四项合计，C8 首 token P90 预计省 **40.40–43.03 ms（2.71%–2.88%）**，整批预计省 **46.06–48.87 ms（0.25%–0.26%）**。在普通请求的两次对照耗时上，普通代码首轮及后续请求的首 token 均有约 3 ms 的机会，是否达到 1% 取决于投影重叠。[逐请求估算、原始分母及证据指纹](baselines/joint-attention-and-qli.json)

| 冻结的 8 个请求，首 token P90 原为 1,491.85 ms，整批原为 18,590.77 ms | 首 token P90 预计节省 | 整批预计节省 |
|---|---:|---:|
| 四项联合，压缩 KV 选中 256 个位置，搬运差额 50% 暴露；OA/OB 较短阶段 50% 重叠，共享计算和搬运资源都达到参考速率的 90% | 40.40–43.03 ms | 46.06–48.87 ms |
| 其余相同，OA/OB 保持串行 | 30.75–31.60 ms | 36.41–37.44 ms |
| 压缩 KV 选中 128 个位置，只省一次残差读取且不收扩宽写附加成本；OA/OB 重叠 25%，资源速率 80% | 25.51–28.08 ms | 29.42–32.12 ms |
| 四项中间情景，另假设四个 QLI 消费层的 token 归并占整核 25%，归并耗时可净减 75% | 52.87–55.53 ms（3.54%–3.72%） | 140.95–145.16 ms（0.76%–0.78%） |
| 同一排程和分母，已共享候选表示的 B4 校验图改用修正版每层 QLI 耗时 | 52.87–55.53 ms | 87.69–91.27 ms（0.47%–0.49%） |

四项联合的请求节省在原关键路径上再兑现约 35%–37%，即可使首 token 降低 1%。整批要达到 1%，若其余四项已全部兑现，旧配置的四个 QLI 消费层还须各自净减原核时约 26.7%–27.6%。按修正版 B4 图耗时外推，所需比例升至 60.6%–63.5%。若归并自身耗时可缩短 75%，修正版需要可归给归并的时间占这些 QLI 核时约 **81%–85%**。已有 profile 计数没有分出这部分耗时。修正版情景只转换匹配形状的消费层持续时间，保留原客户端分母及调度。两套配置的收益不能相加。[QLI 分支与核时依据](four-mixed-fusion-edges.md#qli-token) · [门槛计算](baselines/joint-attention-and-qli.json)

## 各项在组合里贡献了多少

| 中间情景，在相同时钟对齐假设下从联合方案移除一项 | 首 token P90 损失的节省 | 整批损失的节省 |
|---|---:|---:|
| 34 个直接 Attention 入口和 40 个 FFN 入口共用残差、交付 Y | 7.29 ms | 8.97 ms |
| 38 个压缩 Attention 层少写和重读 BF16 KV 暂存面板 | 11.85 ms | 14.62 ms |
| 同一 SMLA 首块 PV 直接写后段要读的 FP32 工作区 | 5.93 ms | 7.31 ms |
| 大行 OA→OB 交付舍入后的 BF16 分块 | 17.39 ms | 17.39 ms |

另加可选的四个 QLI 消费层，按上述 25% 与 75% 情景，对齐时钟下增量为首 token **12.50 ms**、整批 **95.95 ms**；换用修正版 B4 图时，整批增量为 **42.02 ms**。各项按同一套时钟分别重算，剩余时钟不确定性的外包区间列在数据表内。[分项增量及各请求的限制时点](baselines/joint-attention-and-qli.json)

成本按 4 波 eager、40 层、16 卡的实际顺序经过 TP8 AllGather、AllToAll、ReduceScatter，再到 EP16 入口。223 个有请求的图波次中，四个 QLI 消费层共 **14,272** 条逐卡记录按任务号、通信组及随后 F21 任务核对。QLI 与 SMLA 同处一个 AllToAll 之前，先合计本卡可省时间，再判断哪张卡限制通信；压缩 KV 和首段 PV 同属一次 SMLA，共享一份保留两次矩阵计算的时间下界。其余图层沿用已有形状参照，部分满载时保留低至零的稀疏工作情景。未计入改变专家放置、减少投影乘法或取消网络传输的收益。[首段 PV 交付](smla-partial-handoffs.md) · [按波次重算](baselines/joint-attention-and-qli.json)

## 普通代码请求的首 token

普通代码首轮及后续请求各有 1,464 个输入 token，本地提示形状为 183 行。四项合计的首 token 节省按实际请求位置估算为 **2.98–3.53 ms**。其中 OA→OB 约 1.93 ms，mHC 约 0.46 ms，其余来自 SMLA。两个原服务参照的首 token 分别为 297 / 274 ms（首轮）、256 / 278 ms（后续），对应降幅如下。[六个请求的逐次分母、绝对毫秒与速率敏感性](baselines/joint-attention-and-qli.json)

| 代码请求 | 第一次对照上的估算 | 第二次对照上的估算 | 保守查询位置下使两次均达 1% 所需的 OA/OB 重叠 |
|---|---:|---:|---:|
| 首轮 | 1.00%–1.19% | 1.09%–1.29% | 至少约 49.7% |
| 后续 | 1.17%–1.38% | 1.07%–1.27% | 至少约 42.6% |

同样的 OA 与 OB 若保持串行，这四次对照上的估算都降至 1% 以下。首轮第一次对照在保守位置下超过 1% 只余约 **8 µs**，尚无额外同步成本的实测。混合代码请求同样估省约 4.32–4.99 ms，在原首 token 约 2,265 / 272 ms 的两次对照中分别只占 0.19%–0.22% / 1.59%–1.83%。六个普通请求的**整段响应**，四项联合最高约 0.77%；加上宽松的 QLI 情景，最高约 0.85%。普通结果沿用各自请求形状、两次原服务耗时和实际校验步数；本轮没有运行新内核。[普通逐请求估算](baselines/joint-attention-and-qli.json)

## 早期三项估算及单项依据

171 的冻结 C8 基线首 token P90 为 1,491.85 ms，整批为 18,590.77 ms。沿同一批请求重算，三个边界值得作为**长提示首 token**的条件候选保留。对六个普通请求，所选中间情景的整段响应收益估算为 0.031%–0.689%。原始 profile 早于后续 slot、QLI 服务对照，两套数字使用不同基线。[计算输入、每个请求和各项假设](baselines/joint-attention-frontiers.json)

| 模型顺序与实际算子 | 哪些工作有望消失 | 单项估算的 C8 首 token P90 节省 |
|---|---|---:|
| 上一处 HcPost → HcPre → Norm，在 34 个直接 Attention 入口与 40 个 FFN 入口共享残差 | 保留舍入后的四路残差、系数与 FP32 工作面，合并生成加权归约 Y，省去中间写读。计入扩宽写回的额外成本 | 7.29 ms |
| 38 层 SMLA 内压缩 KV gather → QK、PV | 按原索引读取同一批 BF16 行，减少写入及重读临时缓冲。QK 和 PV 的两次矩阵运算仍需执行 | 11.85–11.87 ms |
| Attention 输出 OA → OB | 同核分块就地交付 OA 舍入后的 BF16 结果，保留 OB 原始点积和权重分片。仅大行采用，M24 回原路径 | 15.34–17.93 ms |

三者使用相同的专家、权重放置与路由。表中单项采用与联合估算相同的资源假设。首 token 的节省还取决于另一路何时就绪，以及设备端的提前能否传到客户端。分别记录了 320 次 TP8 AllGather、280 次 AllToAll、320 次 ReduceScatter 和 160 个 EP16 专家入口。每次都按最晚参与者汇合，随后在八个请求上重算 P90。首 token 只计至该请求第一次大行 prefill 并产生目标选择的波次，整段只计至该请求最后一次验证。客户端收到数据前已进入的下一波没有计入。[分项、参与卡和请求归属](baselines/joint-attention-frontiers.json)

| 同一冻结 profile 下的情景 | 首 token P90 预计节省 | 整批预计节省 |
|---|---:|---:|
| 中间情景，256 个有效压缩位置，搬运时间差暴露 50%，OA/OB 较短阶段重叠 50%，两项资源达到参考速率的 90% | 34.48–37.09 ms（2.31%–2.49%） | 38.81–41.55 ms（0.21%–0.22%） |
| 相同假设，OA/OB 保持串行 | 24.83–25.66 ms | 29.16–30.12 ms |
| 较少有效位置及较高资源压力，128 个位置、临时缓冲访问速率加倍、OA/OB 重叠 25% 且速率降至 80%、残差只省一次读取 | 15.14–17.69 ms | 16.73–19.30 ms |

区间反映模型内跨卡时钟及非满图波次的不确定性。数值假设局部节省能传到请求端点，保留原网络耗时；重叠、有效 KV 行数和命中缓存均未实测为新内核的表现。中间情景要让首 token P90 实际缩短 1%，需兑现约 40%–43% 的估算节省。原始 profile 包含 4 个 eager 波次的 2,560 个逐层逐卡记录，以及 223 个被调度的图波次。两侧均满 24 行的有 213 个，其余 10 个在 SMLA 图成本上给出零至满容量的区间。各汇合点的时钟极值可能对应不同偏移，区间两端无需同时可达。[情景参数、图波次和 1% 条件](baselines/joint-attention-frontiers.json)

**取舍。** 普通请求整段和冻结 C8 整批都不支持优先实现这组三项。长提示以首 token 延迟为主要目标时，优先看 SMLA 的实际有效行数和 OA→OB 能保留的实际重叠。现有证据足以条件排序，整体理论上限和真实客户端收益仍未确定。
