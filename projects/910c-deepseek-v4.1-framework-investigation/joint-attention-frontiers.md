# 长提示首 token 的三个融合机会

171 的冻结 C8 基线首 token P90 为 1,491.85 ms，整批为 18,590.77 ms。沿同一批请求重算，三个边界值得作为**长提示首 token**的条件候选保留。对六个普通请求，所选中间情景的整段响应收益估算为 0.031%–0.689%。原始 profile 早于后续 slot、QLI 服务对照，两套数字使用不同基线。[计算输入、每个请求和各项假设](baselines/joint-attention-frontiers.json)

| 模型顺序与实际算子 | 哪些工作有望消失 | 单项估算的 C8 首 token P90 节省 |
|---|---|---:|
| 上一处 HcPost → HcPre → Norm，在 34 个直接 Attention 入口与 40 个 FFN 入口共享残差 | 保留舍入后的四路残差、系数与 FP32 工作面，合并生成加权归约 Y，省去中间写读。计入扩宽写回的额外成本 | 7.29 ms |
| 38 层 SMLA 内压缩 KV gather → QK、PV | 按原索引读取同一批 BF16 行，减少写入及重读临时缓冲。QK 和 PV 的两次矩阵运算仍需执行 | 11.85–11.87 ms |
| Attention 输出 OA → OB | 同核分块就地交付 OA 舍入后的 BF16 结果，保留 OB 原始点积和权重分片。仅大行采用，M24 回原路径 | 15.34–17.93 ms |

三者使用相同的专家、权重放置与路由。表中单项采用与联合估算相同的资源假设。首 token 的节省还取决于另一路何时就绪，以及设备端的提前能否传到客户端。分别记录了 320 次 TP8 AllGather、280 次 AllToAll、320 次 ReduceScatter 和 160 个 EP16 专家入口。每次都按最晚参与者汇合，随后在八个请求上重算 P90。首 token 只计至该请求第一次大行 prefill 并产生目标选择的波次，整段只计至该请求最后一次验证。客户端收到数据前已进入的下一波没有计入。[分项、参与卡和请求归属](baselines/joint-attention-frontiers.json)

| 同一冻结 profile 下的情景 | 首 token P90 预计节省 | 整批预计节省 |
|---|---:|---:|
| 中间情景，256 个有效压缩位置，搬运时间差暴露 50%，OA/OB 较短阶段重叠 50%，两项资源达到参考速率的 90% | 34.48–37.09 ms（2.31%–2.49%） | 38.81–41.55 ms（0.21%–0.22%） |
| 相同假设，OA/OB 保持串行 | 24.83–25.66 ms | 29.16–30.12 ms |
| 较少有效位置及较高资源压力，128 个位置、临时缓冲访问速率加倍、OA/OB 重叠 25% 且速率降至 80%、残差只省一次读取 | 15.14–17.69 ms | 16.73–19.30 ms |

区间反映模型内跨卡时钟及非满图波次的不确定性。数值假设局部节省能传到请求端点，保留原网络耗时；重叠、有效 KV 行数和命中缓存均未实测为新内核的表现。中间情景要让首 token P90 实际缩短 1%，需兑现约 40%–43% 的估算节省。原始 profile 包含 4 个 eager 波次的 2,560 个逐层逐卡记录，以及 223 个被调度的图波次。两侧均满 24 行的有 213 个，其余 10 个在 SMLA 图成本上给出零至满容量的区间。各汇合点的时钟极值可能对应不同偏移，区间两端无需同时可达。[情景参数、图波次和 1% 条件](baselines/joint-attention-frontiers.json)

**取舍。** 普通请求整段和冻结 C8 整批都不支持优先实现这组三项。长提示以首 token 延迟为主要目标时，优先看 SMLA 的实际有效行数和 OA→OB 能保留的实际重叠。现有证据足以条件排序，整体理论上限和真实客户端收益仍未确定。
