## 判断融合与重组的方法

先确认当前实际执行的条件、shape、dtype、行域、频次与版本，再给完整可变工作定价。只有价值仍可观或关键未知会改变结论时，才定点补源码、参数或原生实验。不能从相邻名字、空白区间或缺失字段推出独立性。

| 搜索维度 | 必须判断的问题 | 保留的约束 |
|---|---|---|
| 消除与共享 | 输出是否真正需要；重复计算能否按需求消除；多读者是否可共享同一值 | 全部读者、值代际、别名与错误语义 |
| 控制分支 | 公共前驱下沉、公共后继合并、分支内移、静态专门化、逐行mask、空/无效路径 | 只计算应走分支；RNG、状态增量、tie与NaN行为 |
| 融合与拆分 | 链、fork/join、多输出、部分结果提前交付、复合算子内部拆分后重组 | 原始舍入、所有输出、事件和完成语义 |
| 布局与量化 | producer是否直接交付consumer所需布局、量化尺度、cache位置或分片 | logical shape与physical格式、row domain、量化与BF16/FP32边界 |
| 跨层 | residual/pre_mix/aux是否可驻留，计算能否共享 | 不同层权重、不同代际与延迟读者；不能只保留紧邻消费者 |
| 跨卡 | 通信与计算如何重排、数据所有权是否改变、部分结果何时就绪 | 所有参与者、collective顺序、全局容量、真实peer readiness |
| 跨迭代 | 缓存、bank、slot、权重能否安全复用 | 设备最后读者、图地址、释放/更新时刻与请求命名空间 |
| 算法与资源 | 更换等价算法、tile、归约、资源划分能否减少必要工作或等待 | 数值合同、AIC/AIV/HBM/网络竞争、驻留和容量 |

这些是推导替代计算图的维度，不是逐个算子做笛卡尔配对。单点价值低不能自动否定更大的共同producer或算法变换；更大范围也不能把重叠收益重复相加。

## 证据分层与成本口径

1. **源码结构成立**：只能说明在列出的条件下存在合法重组方向。
2. **当前路径命中**：需要正向profile、配置或实际参数证据；有分支代码不等于负载执行了它。
3. **数值合同通过**：须覆盖被改变的全部输出、状态、舍入、alias和错误边界；BF16一项相同不够。
4. **原生实现可行及收益**：固定输入、样本和门槛；保留原始失败；合成输入结果只属于其原生范围。
5. **服务收益**：同一冻结负载、完整输出检查、前后参照、实际生效的配置；计时落在参照波动内不能声称提升。

当前主要证据包括112个当前decode窗口、64个历史首段body及其同数据库225个target调用分母，以及M06的16rank/2路由分布/12组交替AB/BA原生配对。不同cohort不混成一个总百分比，不叠加跨rank时间，不把逻辑字节当作物理HBM或链路流量。

对一个完整替代区域，先估计原本可能移除的区间并集，再扣除必要计算、布局、同步和新通信成本；只在外部工作固定等明确假设下使用零替代成本筛查。1%是当前工作排序参考，不是用户给出的绝对正确性标准，也不是所有负载的不可行界。

## 理论上限与尚缺的物理证据

全模型数值理论上限尚未建立。已知的是若干带条件的工作量与依赖界。可实现时间下界至少受必要计算、真实HBM流量、实际通信和最长依赖路径共同限制；容量、tile、量化和有限AIC/AIV资源还会收紧它。各下界不能凭峰值规格或当前task总和替代。

对于同一profile里的局部改写，当前报告提供的是假定替代成本为零、其它工作不变的优先级筛查，不是全服务可达加速。M07的所有小边界联合中位约0.971%、最大1.042%；必须明确保留这个越过1%的尾部，不能只列单项较小就宣称联合严格低于1%。

仍需完成的关键证据包括F21阶段级有效计算/peer readiness、不同消费者的设备最后读取、真实物理流量与驻留、跨卡/跨迭代关键路径，以及更广替代图的数值验收。F21历史首段包含等待的占比约5.24%–6.38%，这部分仍有价值判断空间，不能把它当成可直接删除的时间。

## 过程反思与纠错

新增[统一成本基线](baselines/README.md)：复用同一批112个本地周期的83类算子频次/区间导航、54组区域成本或频次筛查、设备容量和已有竞争反例。[通信成本表](baselines/communication.json)将16016条记录按组/count/dtype/阶段分成28类，可直接复用实际耗时；15792条绑定native，224条保留。新候选先查表，再对完整改写区域定价；只有未测成本会改变选择时才补证。算子类型汇总只作导航，不是每shape微基准；完整范围和哈希在[成本数据表](baselines/atlas.json)。

M09直接复用16份本地缓存和旧seed合同，未新增源码阅读、profile导出或NPU探针。完整seed/count+padded免费最高0.082894%，因此暂缓独立实现；包含score最高0.608161%。联合到context copy最高1.049986%，仍交给M10完整定价；这些重叠区间不能相加。复用产生了明确处置，未声称已量化分析速度倍数。

M10的64组匹配eager/mixed区间整段免费，相对同库225个已选目标调用耗时仅0.573%–0.593%，因此也在实现前暂缓。单请求与多请求分别绑定原生序列，32条未归类draft保留；含M08/M09的区间不重复计收益。这些是具体节省工作量的处置，未声称分析速度已提升某个倍数。

通信、HBM/L2/host-UVA、计算及调度成本按实际用例共享准备，具体准入与停止规则见[集中补测清单](baselines/calibration-plan.json)。通信消息与实际时长已整理；纯传输带宽、内存和通用调度曲线仍未完成；已完成的固定caller批量对照单独记录，不能把等待区间、实测吞吐或设备容量当成物理上界。基线准备不阻塞可用已有证据推进的M08–M11，原冻结实验门槛不变。

本次服务接入暴露了另一处低效：完成3条基线计时后，才发现候选批量写入没有启用。随后用有界记录定位ratio1标志误拒绝，并复用48个真实序列核对语义。下一次准入在计时前发现Triton起始行号导致缓存失配；11.15秒私有验证完成旧缓存命中和单改行号的反事实验证，未增加原生性能样本。完整调用选择、启用和输出验收必须先于计时。详见[决策与复用流程](baselines/decision-workflow.md)。

此前候选之间跳转、先研究接口后计算频次、逐个配对、反复读相同代码，都会消耗低价值工作。现在以模型模块顺序推进，同族合同引用已有证据，先算完整变换的价值，再决定最小补证。

M06新探针接入经历9次启动/接入失败后才完成一次正式对照；原因涵盖进程表解析、挂载、HCCL设置、只读编译目录、vendor路径和NZ逻辑形状。它们属于接入质量问题，不是优化机制的失败证据。完整CPU导入检查、原运行环境核对和可复用接入已固化；所有运行回执留档，样本数、计算范围和收益门槛未因性能结果而调整。

本轮还修复了旧M04/M05台账中4480条ReduceScatter记录编号被变量复用覆盖的问题。成本在覆盖前已计算；修复前后逐字段比较及下游重生成证明原数值和其它绑定不变。旧哈希、来源提交和修正哈希见证据摘要。后续不能只验证汇总数字，也要检查关键绑定的类型与对应任务。

## F21 的长调用、输入就绪与空专家分支

16个rank的既有profile共含4480次目标F21和336次草稿F21。按层和周期分成301组，每组的16条记录在导出时间上均有共同区间，相邻组互不穿插。达到1毫秒的调用集中在6组，涉及目标首层的5个周期与草稿末层的1个周期。若保持最后进入的rank的结束时刻固定，这6组的全部rank完成时刻最多提前4.292微秒。这一判断依赖导出时钟，设备间的误差界仍未知。

草稿末层该次最长调用为2.971毫秒。rank 11最后进入，距全部rank完成仅余153.64微秒。在进入之前，rank 11从上一层F21退出起的3.327毫秒中，2.817毫秒没有记录到原生计算或DMA覆盖；其余部分rank已在等同组通信。具体到同一次AllToAll，rank 8原生记录约1.502毫秒，rank 11约8微秒。CPU activity关闭，无法给这段差异指定主机原因。将整个异常区间按实际出现次数计入每rank七个周期，即使整段耗时消失，本地占比也只有0.868%–0.875%。暂缓该单点实验。[按rank和周期的证据](baselines/f21-readiness.json)

## 首 token 的跨卡到达差异与 Attention 交付

四个 eager 批次的 2,560 次 F21 已按真实来源层、专家计数、同层快照和 native task 对齐。在 M816/M817 的 400 次零发送 rank 调用中，每次仍有 19–12,445 行专家任务。跳过整个 F21 会漏算。固定 171 host tiler 的 11000 分支在 M816/817/818 上分别执行 836/837/838 次整行量化，每卡仅 20 次来自核心边界的重复。最大核心负担均为 21 行，已经达到按 40 核均分全部行的下限。单独去重暂缓，mask 分支的源端准备、收端专家运算及返回仍须分别定价。

从上一层 F21 在本卡结束到下一层 F21 在本卡开始，三个大 M 批次共 117 个相邻层间隔。每个间隔中，发送行较多的 DP 组里最快的 rank 都比另一组最慢的 rank 耗时长。这项比较只使用本卡时长。按相同 TP 位置配对，39 层前置时长差的中位数分别为 159.10、164.31 和 65.84 ms。双组交换轻重角色后仍观察到这个规律。差额内含 SMLA、QLI、矩阵计算、通信和未归属区间；其中可优化的部分仍需单独证明。

在四个批次中，368 个同层 QLI/准备/SMLA 区间含 328 条三任务序列和 40 条带额外 TensorMove 的序列。额外搬运都位于第 20 层，输出形状不能证明它是生产模型必需的拷贝。已逐 rank 核实 225 次图调用和四段 eager 模型体时间互不重叠。在合并后的本地时间并集上，QLI 结束到 SMLA 开始的区间占 0.032%–0.039%，包含两端运算的整段同层区间占 0.498%–0.573%。即使把同四段内其它层全部 SMLA 也免费移除，固定其它工作时合计只占 0.894%–0.987%。在单个输入较多的首 token 模型体里，整段区间占比最高 11.40%。首 token 延迟、跨层 KV 共享和更广的 Attention 重组保留独立判断。[分组结果、时间口径与算子分布](baselines/prefill-f21-attention.json)

## 选中 KV 的跨层读者、首字时间与原生布局对照

在 64 个 rank 本地模型体中，46 个执行稀疏 Attention。第 2、8、14 层各产生一组供六层使用的压缩 KV 和索引。第 20–39 层共用第 20 层的压缩 KV，索引每四层更新一次。368 组索引覆盖 1,748 次稀疏 SMLA，其中 1,380 次是同组后续读者。把这些后续 SMLA 全部计入，在前述 229 段本地时间并集上占 0.386%–0.419%。

8 个请求均由实际 worker 首次调度记录对应到同轮客户端首个非空文本，历史首字时间为 449–1,492 ms。Q416 的请求首字时间为 448.846 ms，若仅靠该批次的后续 SMLA 改善 1%，需省 4.488 ms。这是局部筛查门槛，其他请求的等待和跨卡路径另计。

单独为每个查询打包 512 行 BF16 KV，Q416 需 208 MiB，Q818 需 409 MiB。按请求的页表容量和已调度行数收紧后，同组所有查询共同选中的物理行数对应的数据量最多 74 MiB，实际选中集合未导出。每卡报告 L2 为 192 MiB。相邻读者之间经过非空专家，在普通稠密 INT8 实现中，1,378/1,380 个间隔触及的专家权重单独就超过 L2。具体缓存替换和 HBM 字节仍未知。

171 单卡的 Q416 原生对照保持 SMLA、选中值和各查询内的顺序一致，分别使用分散页和预先排紧的字典。两种压缩比例、1,024/8,192 个不同行的四组输入均通过完整 BF16 输出逐位比较，更改所选 KV 后全部 416 行输出均变化。预热与每次计时前另触及 256 MiB 两种条件下，配对中位差为 −0.16 至 +3.52 µs/次。按 15 次比例 2 和 15 次比例 1 的后续调用折算，四种情形为 0.009–0.069 ms，尚未计入构建或重映射。暂缓该布局变体。原生输入为合成历史，不作为实际服务加速。

相邻的 M816/M817 两步另有跨迭代候选。若在原 DP 上让请求 0 和 6 提前一步进入 prefill，同时保留请求 7 的两步 decode 和另一 DP 的前后因果关系，两步有效行总数仍为 13,080。按相同 CP 分配推演，每层载体从 26,128 行减为 13,120 行。原计数在同层同接收卡逐项合并的最大值为 24,738，原容量为 65,536。客户端发起时间不能证明提前时请求已可调度，输入分配、实际专家忙时和步间状态也可能改变。该候选尚无实测收益。[工作集、8 个请求、原生实测与排程条件](baselines/prefill-selected-kv.json)

## 首 token 的请求交付与合批价值

同一轮 C8 的引擎指标显示，两个 DP 各完成 4 个请求，零抢占，队列等待合计 0.159 / 0.155 ms。若请求 0、6 在第三步调度时都已入队，则到共同的第四步首次调度，它们各自至少等待了两次决策之间的间隔。因此原排程的间隔必须 ≤79.45 µs。服务使用异步调度，约 269 ms 的 worker 入口间隔不能用于这一判据。两个 DP 的每组首 token 时间总和扣除引擎排队和 prefill 后还分别有 1.625 / 2.219 秒；这部分覆盖多个端点，无法单独归因给 tokenizer。[引擎指标、端点和时点判据](baselines/prefill-admission.json)

## 四线程在真实服务中的收益

线程池实际宽度依次为 1 / 4 / 1。三组各有一次准入和三次计时，12 轮共 96 份输出文本逐个与归档一致。按前参照 / 四线程 / 后参照顺序，慢请求的首 token 延迟中位为 1.2496 / 0.9855 / 1.2177 秒，四线程分别缩短 21.130% / 19.064%，通过冻结门槛。整轮耗时中位为 15.6522 / 15.5043 / 15.8759 秒，分别缩短 0.945% / 2.340%，对前参照未达到 1%。 首 token 的 P90 在本轮固定八请求下取最慢请求，每组仅三次计时。三次四线程整轮都快于前后参照样本，前参照的相对差值仍低于冻结门槛。每轮缓存计数和生成长度一致，原服务恢复后健康检查 200 并生成两个 token。[逐轮计时与预设门槛](baselines/renderer-c8.json)

## 从同一份 profile 复用计算、权重与拷贝成本

64 个历史首 token 区间共 135,592 条 native 记录。由 22,248 次矩阵与专家调用核算直接算法工作量。在 1.8 GHz 参考条件下，M416、816、817、818 的部分计算时间下限为 10.49、20.57、20.59、25.47 ms。各层本地活跃专家权重按未压缩直读、每卡起始最多驻留 192 MiB 估算。若要在各自的部分计算下限时间内搬完这些权重，需达到 2.17、1.11、1.09、0.94 TB/s。实际可达带宽、驻留与物理时钟上界仍待约束。 [计算与内存假设](baselines/eager-resources-and-copies.json)
