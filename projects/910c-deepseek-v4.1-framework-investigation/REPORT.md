# DeepSeek V4.1 Flash 推理框架整体算子优化排查报告

本报告记录固定模型、版本、硬件和负载下的优化排查。目标是识别真正能减少执行时间的计算、数据移动、通信和调度变换，覆盖分支、拆分重组及跨算子、跨层、跨卡、跨迭代组合。推理框架是定位实际调用、状态和算子的依据，研究对象仍是这些优化是否正确、是否有价值。

**整体分析尚未完成。M00–M11 已完成一轮当前范围的顺序价值筛查，正继续 M00/M11 联合准备与发布。** 重要条件机会和证据缺口仍明确保留；这些处置不等于穷尽全部优化。全模型数值理论上限仍为 `null`。

## 判断融合与重组的方法

先确认当前实际执行的条件、shape、dtype、行域、频次与版本，再给完整可变工作定价。只有价值仍可观或关键未知会改变结论时，才定点补源码、参数或原生实验。不能从相邻名字、空白区间或缺失字段推出独立性。

| 搜索维度 | 必须判断的问题 | 保留的约束 |
|---|---|---|
| 消除与共享 | 输出是否真正需要；重复计算能否按需求消除；多读者是否可共享同一值 | 全部读者、值代际、别名与错误语义 |
| 控制分支 | 公共前驱下沉、公共后继合并、分支内移、静态专门化、逐行mask、空/无效路径 | 只计算应走分支；RNG、状态增量、tie与NaN行为 |
| 融合与拆分 | 链、fork/join、多输出、部分结果提前交付、复合算子内部拆分后重组 | 原始舍入、所有输出、事件和完成语义 |
| 布局与量化 | producer是否直接交付consumer所需布局、量化尺度、cache位置或分片 | logical shape与physical格式、row domain、量化与BF16/FP32边界 |
| 跨层 | residual/pre_mix/aux是否可驻留，计算能否共享 | 不同层权重、不同代际与延迟读者；不能只保留紧邻消费者 |
| 跨卡 | 通信与计算如何重排、数据所有权是否改变、部分结果何时就绪 | 所有参与者、collective顺序、全局容量、真实peer readiness |
| 跨迭代 | 缓存、bank、slot、权重能否安全复用 | 设备最后读者、图地址、释放/更新时刻与请求命名空间 |
| 算法与资源 | 更换等价算法、tile、归约、资源划分能否减少必要工作或等待 | 数值合同、AIC/AIV/HBM/网络竞争、驻留和容量 |

这些是推导替代计算图的维度，不是逐个算子做笛卡尔配对。单点价值低不能自动否定更大的共同producer或算法变换；更大范围也不能把重叠收益重复相加。

## 证据分层与成本口径

1. **源码结构成立**：只能说明在列出的条件下存在合法重组方向。
2. **当前路径命中**：需要正向profile、配置或实际参数证据；有分支代码不等于负载执行了它。
3. **数值合同通过**：须覆盖被改变的全部输出、状态、舍入、alias和错误边界；BF16一项相同不够。
4. **原生实现可行及收益**：固定输入、样本和门槛；保留原始失败；合成输入结果只属于其原生范围。
5. **服务收益**：同一冻结负载、完整输出检查、前后参照、实际生效的配置；计时落在参照波动内不能声称提升。

当前主要证据包括112个当前decode窗口、64个历史首段body及其同数据库225个target调用分母，以及M06的16rank/2路由分布/12组交替AB/BA原生配对。不同cohort不混成一个总百分比，不叠加跨rank时间，不把逻辑字节当作物理HBM或链路流量。

对一个完整替代区域，先估计原本可能移除的区间并集，再扣除必要计算、布局、同步和新通信成本；只在外部工作固定等明确假设下使用零替代成本筛查。1%是当前工作排序参考，不是用户给出的绝对正确性标准，也不是所有负载的不可行界。

## 主要实验与已改变的决策

| 具体机制 | 正确性与适用性 | 性能裁决与后续 |
|---|---|---|
| CPU计划/发布组合 | 已有冻结负载的范围限定接受证据 | 引用原比较，不与历史其它收益相加；当前profile用于看剩余工作 |
| 修正版QLI | 既有C8输出一致 | 候选耗时位于前后参照之间，尚无已证实服务收益；不重跑同版本 |
| QA-only early-Y | 4组动态原生输入及完整输出合同通过 | 每入口配对节省中位0.8765μs，未过13.8934μs门槛；无追加C8 |
| shared overlap flag-only | 当前fused MC2配置强制关闭该flag | 未生效不能当作已验证新调度，更不能证明所有并行不可能 |
| 显式共享专家/F21 fork | 16rank、两种合成路由，eager/captured serial/fork与输入检查通过 | 配对节省中位4.076/5.924μs，均低于13.893μs；关闭该具体版本，不追加样本或C8 |
| F21分段12/12及wait-frontier版本 | 既有冻结C8输出检查通过 | 未证实端到端收益；不做未改机制的分段盲扫 |
| merge+HC Post | 原生及实际前缀数值检查通过，已有冻结C8 | 未证实服务收益；小kernel很快不能替代端到端判断 |
| 大形状共享/router/merge | 复用同数据库频次，没有新设备任务 | 即使全部相关计算免费，采样区域占比约0.660%–0.765%；暂缓独立吞吐优化，TTFT与联合设计保留条件 |

M06短profile包含512条同设备绑定。共享投影与F21的任务区间相交，但投影任务持续时间明显拉长，例如均匀路由的up中位区间由34.19μs变为541.63μs。区间可能含等待，不等于同时完成了等量有效计算；性能裁决来自独立的无profile配对计时。该实验使用合成权重和路由，不能直接证明模型输出或C8收益。

## 理论上限与尚缺的物理证据

全模型数值理论上限尚未建立。已知的是若干带条件的工作量与依赖界。可实现时间下界至少受必要计算、真实HBM流量、实际通信和最长依赖路径共同限制；容量、tile、量化和有限AIC/AIV资源还会收紧它。各下界不能凭峰值规格或当前task总和替代。

对于同一profile里的局部改写，当前报告提供的是假定替代成本为零、其它工作不变的优先级筛查，不是全服务可达加速。M07的所有小边界联合中位约0.971%、最大1.042%；必须明确保留这个越过1%的尾部，不能只列单项较小就宣称联合严格低于1%。

仍需完成的关键证据包括F21阶段级有效计算/peer readiness、不同消费者的设备最后读取、真实物理流量与驻留、跨卡/跨迭代关键路径，以及更广替代图的数值验收。F21历史首段包含等待的占比约5.24%–6.38%，这部分仍有价值判断空间，不能把它当成可直接删除的时间。

## 过程反思与纠错

新增[统一成本基线](baselines/README.md)：复用同一批112个本地周期的83类算子频次/区间导航、十五组区域成本或频次筛查、设备容量和已有竞争反例。[通信成本表](baselines/communication.json)将16016条记录按组/count/dtype/阶段分成28类，可直接复用实际耗时；15792条绑定native，224条保留。新候选先查表，再对完整改写区域定价；只有未测成本会改变选择时才补证。算子类型汇总只作导航，不是每shape微基准；完整范围和哈希在[成本数据表](baselines/atlas.json)。

M09直接复用16份本地缓存和旧seed合同，未新增源码阅读、profile导出或NPU探针。完整seed/count+padded免费最高0.082894%，因此暂缓独立实现；包含score最高0.608161%。联合到context copy最高1.049986%，仍交给M10完整定价；这些重叠区间不能相加。复用产生了明确处置，未声称已量化分析速度倍数。

M10的64组匹配eager/mixed区间整段免费，相对同库225个已选目标调用耗时仅0.573%–0.593%，因此也在实现前暂缓。单请求与多请求分别绑定原生序列，32条未归类draft保留；含M08/M09的区间不重复计收益。这些是具体节省工作量的处置，未声称分析速度已提升某个倍数。

通信、HBM/L2/host-UVA、计算及调度成本按实际用例共享准备，具体准入与停止规则见[集中补测清单](baselines/calibration-plan.json)。通信消息与实际时长已整理；纯传输带宽、内存和通用调度曲线仍未完成；已完成的固定caller批量对照单独记录，不能把等待区间、实测吞吐或设备容量当成物理上界。基线准备不阻塞可用已有证据推进的M08–M11，原冻结实验门槛不变。

此前候选之间跳转、先研究接口后计算频次、逐个配对、反复读相同代码，都会消耗低价值工作。现在以模型模块顺序推进，同族合同引用已有证据，先算完整变换的价值，再决定最小补证。

M06新探针接入经历9次启动/接入失败后才完成一次正式对照；原因涵盖进程表解析、挂载、HCCL设置、只读编译目录、vendor路径和NZ逻辑形状。它们属于接入质量问题，不是优化机制的失败证据。完整CPU导入检查、原运行环境核对和可复用接入已固化；所有运行回执留档，样本数、计算范围和收益门槛未因性能结果而调整。

本轮还修复了旧M04/M05台账中4480条ReduceScatter记录编号被变量复用覆盖的问题。成本在覆盖前已计算；修复前后逐字段比较及下游重生成证明原数值和其它绑定不变。旧哈希、来源提交和修正哈希见证据摘要。后续不能只验证汇总数字，也要检查关键绑定的类型与对应任务。
