# 验证后的分数输出与五步草稿投影

171 的两组归档回答不同的问题。16 个 worker 的 1,104 条成对元数据明确给出 `no_penalties=True`、`all_greedy=True`、`max_num_logprobs=None`、`logprob_token_ids=None`。这批调用无需执行对外 logprobs 收集或惩罚。另一份冻结 C8 提供 227 波、453 次 TP8 目标调用的真实组批，其中 428 次是 4 个请求、20 个待验证行加 4 个 bonus 行。以下启用分支的估算使用后一份的行数与轮数。普通请求另用各自归档的校验轮数。[配置、逐请求结果与源文件指纹](baselines/score-readers.json)

## 一个额外的融合位置

请求有限 Top-K logprobs 时，拒绝采样器已经分别持有 target 与 bonus 分数。它先创建 FP32 的完整零张量，把两组分数分别写入，再按接受位置收集成矩形词表张量，最后计算 log-softmax、Top-K、所选 token 的分数及排名。可以把原索引直接映射到对应的分数行，再把归一化结果交给最后三个读者。这项改写保留词表投影与 TP8 收集，作用在验证完成之后。

以 4 个请求、每个 5 个待验证 token、词表 129,280 为例。把两个分数面直接交给后续算子，省下清零、两次 scatter 合计的原读写和接受行张量的写读，共 62,054,400 个逻辑字节。若归一化还能就地交付给 Top-K 与排名，同时为原分数再读一遍付费，可再省 24,821,760 字节。

混合组批时要分别使用输入行数和输出槽数。归档中有一次 3 个请求、5 个待验证 token，实际输入只有 8 行，矩形输出有 18 槽。必须按原请求偏移、clamp 和占位 ID 映射，按原顺序先筛分数、再丢弃 token。Top-K 按原舍入后的 FP32 对数概率求，所选 token 的排名统计所有 `>=` 的值，选中 ID 与 Top-K 中的同一 ID 也允许重复。仅交换最大分数和 ID 无法满足这条输出合同。

| 同样的组批和轮数下，假设相应功能每次都启用 | C8 整批预计缩短 | 六个普通请求整段的最高估算 |
|---|---:|---:|
| 验证后直接读 target/bonus，省去重新拼行 | 5.70–11.41 ms | 0.021% 以内 |
| 再融合有限 Top-K 与排名的归一化交付，已扣一遍额外扫描 | 7.99–15.98 ms | 0.029% 以内 |
| 从已经读取的 output counts 推导惩罚所需的 membership | 1.71–3.42 ms | 0.007% 以内 |
| 前两类共同启用，再假设 prompt membership 每次均命中并省去其稠密构造 | 12.27–24.53 ms | 0.044% 以内 |

每行惩罚可省的 output membership 接口为 `6V` 字节，prompt membership 全命中再省 `9V` 字节。保留对 prompt mask 的最终读取、输出历史的独立代际和原惩罚算术。表中共同启用行按每波重算，没有重复计入前三行。最大的联合情景约占原 18.59 秒整批的 0.132%，首 token P90 约省 0.15–0.29 ms。以同一组逻辑字节达到整批 1%，有效速率需降至约 159 GB/s。计算采用同机连续搬运的 1.20/2.41 TB/s 两种计价口径。真实非连续访问、提交和算子计算可能改变结果。[分项字节、临界速率与估算](baselines/score-readers.json)

这项判断只给所列中间读写计价。全词表返回有稠密输出，prompt logprobs 还可能需要所有提示行，两者要按各自的读者与行数计。可选负载下的实际吞吐、整理长历史的 CPU 时间、直方图原子操作均未实测。独立实现和专项采样降级。

## 草稿 W1/W2 的可省时间

当前 DSpark 依次用前驱 token 做 W1 查表、W2 投影、BF16 校正加法和选词。下一步使用上一步的 ID。对冻结 C8 逐波取已调度卡中最大的可省任务时间，并假设全部提前量都能传到请求端。

| 在相同权重、布局与组批下的假设 | 首 token P90 | 整批 |
|---|---:|---:|
| 五步 W2 点积都免费 | 0.80 ms | 36.86 ms（0.198%） |
| 连同五步 W1 查表都免费 | 0.86 ms | 39.57 ms（0.213%） |
| 五步 W2 及其后已记录的切片、分数写回、加法和 ArgMax 全免费，保留 W1 | 1.82 ms | 88.82 ms（0.478%） |
| 四行形状的五步均兑现已有全命中原生样本的差额，其它形状走原实现 | 0.20 ms | 21.43 ms（0.115%） |

即使 W1 与 W2 都免费，六个普通请求中最高也只省整段响应的 0.269%。因此对这组负载，无需估计缓存命中率，就能将前驱 bias 缓存与只消除 W2 的胜者证明移出优先队列。全命中的实际命中率未知；表格各行是替代情景。动态 confidence、survival 与预算分配在归档 EP0 配置上由 `dynamic_spec_config.method=None` 直接筛掉。[逐波估算与既有原生样本](baselines/score-readers.json)
