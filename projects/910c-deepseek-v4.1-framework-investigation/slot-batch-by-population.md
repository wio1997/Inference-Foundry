# B1–B4 的 slot 批写该覆盖哪些卡

**只扩展 26 组写入的路径，可以从普通请求的优先候选中降级。** 在冻结 C8 的三个 B1 通信组上，同样的单卡节省传到 TP8 汇合点后差别很大。把这三个已见时序分别用于六个普通请求，即使 26 组的卡每步净省 0.961 ms、全部兑现，整段响应估算最高也只有 0.93%。把 13 组全局写入一起融合，普通对话仍可能过 1%；它取决于这条较短路径能省多少时间。[逐请求结果和假设](baselines/slot-batch-by-population.json)

## 正常验证分支的写入

171 的既有冻结 profile 有 223 个实际调度的目标图波次，其中 10 个出现未满 4 个请求的 DP。读取这些波次和 2 个满图对照的 16 个 rank，得到 192 个逐卡窗口。每个窗口都用上一轮 sampler 的最后一个任务与本轮目标词嵌入查表定位，按同一条流的算子类型、输入输出形状和 dtype 匹配。压缩写入命中带有效位置判断的 38 个连续任务；另外 12 次全局写入均命中各 17 个连续任务的原始链。非空本地写入各有对应的 3 行链。由此可以把正常更新与先前记录的跳过 ring 更新分支分开。[逐卡任务编号、证据哈希与成本](baselines/slot-batch-by-population.json)

| 每个 DP 的真实请求数 | 匹配的 TP8 组 | 每组执行 26 项的 rank | 每组只匹配 13 项全局写入的 rank | 原写入 kernel 累计时间中位数，26 项 / 13 项 |
|---|---:|---|---|---:|
| B1 | 3 | 0–1 | 2–7 | 0.989 / 0.511 ms |
| B2 | 9 | 0–3 | 4–7 | 0.988 / 0.515 ms |
| B3 | 6 | 0–5 | 6–7 | 0.989 / 0.513 ms |
| B4 对照 | 6 | 0–7 | 无 | 0.992 ms / — |

本表的 rank 为 DP 内的 TP 编号。每笔 26 项由 13 个全局 writer 与 13 个非空本地 writer 组成。这里定位了正常分支的设备工作。改为一次提交仍须保留无本地行时原 fallback 的可见行为、迭代代次、缓冲区别名检查以及各读者的就绪顺序。[分派条件与读者合同](ordinary-input-and-slot.md)

## 单个 writer 与跨 writer 的融合

将每个 writer 的坐标和扁平索引合为双输出，已有另一组 112 个逐卡窗口可提供成本参照。融合后，13 个全局 kernel 合计中位为 0.068 ms，全部 26 个合计 0.121 ms。与上述正常分支的原任务成本配对外推，在这 10 个非满波次中，C8 整批估算省 4.87 ms。已完成的单项服务对照另有自己的基线。[原生记录与单项服务比较](baselines/slot-batch-by-population.json) · [已有服务对照](fusion-candidates.md)

在已有双输出、且满 B4 已经批写的基础上，扩展 B1–B3 改变的是跨 writer 的提交次数。下表借用 B4 原生配对的整次调用中位节省 0.961 ms，为两类 rank 指定不同的净节省。在每个波次先重算图外目标查表 SUM 的最后参与卡，再重算第一层 EP16 专家入口的最后参与卡，最后按每个请求实际结束的波次重算整批。原通信服务时间和后续执行顺序固定。局部提前量能否传到客户端仍是估算条件。[时钟约束和逐波次结果](baselines/slot-batch-by-population.json)

| 13 项 / 26 项假设净省 | 冻结 C8 整批预计缩短 | 后续对话普通请求整段预计缩短 |
|---|---:|---:|
| 0 / 0.961 ms | 2.88 ms | 0–0.89% |
| 0.480 / 0.961 ms | 5.28 ms | 0.64%–1.37% |
| 0.961 / 0.961 ms | 7.69 ms | 1.28%–1.37% |

冻结 C8 的 10 个非满图波次均在八个请求交付首 token 后，故三种扩展的首 token P90 增量均为零。即使两种 rank 都省 0.961 ms，7.69 ms 也只占冻结整批 18,590.77 ms 的 0.041%。该估算评价的是新增的小批量分支；已有 B4 批写仍保留原服务对照的结论。[冻结 C8 与普通负载参考](baselines/slot-batch-by-population.json)

上述 0.961 ms 是整次调用参照。只消除双输出 kernel 的设备执行时间，六个普通请求的响应估算最高约省 0.183%。[设备时间和所需额外净节省](fusion-attribution.md)

## 普通请求的取舍门槛

设 26 项与 13 项参与卡中最晚到达的时刻分别为 T₂₆、T₁₃，融合各省 S₂₆、S₁₃。TP8 输入能提前的时间为 max(T₂₆,T₁₃) − max(T₂₆−S₂₆,T₁₃−S₁₃)。这一关系也覆盖融合后换了一张卡最后到达的情况。

后续对话的两个原服务参考要求每个可用图步净省约 0.70–0.75 ms 才能带来整段 1%。以 0.75 ms 为例，在两个由 26 项 rank 最后到达的 B1 组，13 项分支分别还需净省 **0.31–0.49 ms** 和 **0.13–0.32 ms**。第三个组由 13 项 rank 最晚到达，这条分支本身必须省足 **0.75 ms**。这些范围来自各波次的跨卡时钟约束。机器台账另列出假设零时钟偏移的数值；个别波次的通信先后关系已排除零偏移。三个冻结组出自两个波次，不能据此推算普通生产流量的频率。[各组临界值](baselines/slot-batch-by-population.json)

普通小批量保留同时处理全局与非空本地写入的候选。只有 13 项的路径能获得足够净节省、正常分支缓冲区允许延后提交，且较慢 DP 和客户端消费端能同步提前时，才采用超过 1% 的估值。已有 profile 足以作此排序。

## 普通请求的 Attention 与 slot 批写能否共同改善整段响应

对同一请求，只计本次 prefill 的四处 Attention 融合，以及此后验证迭代中的 slot 批写。前者包括 mHC 残差共读、压缩 KV 直读、首块 PV 直写和 OA→OB 分块，沿用每查询 256 个有效压缩位置、搬运差额暴露一半、较短投影重叠一半、共享资源达到参照速率 90% 的情景。后者只计 B1 的 13 项全局或 26 项全局加本地写入。从同一轮对照取请求耗时和验证次数。这样可以直接判断短代码请求的约 3 ms prefill 节省，能否与随后几步写入共同达到整段 1%。[Attention 分项](joint-attention-frontiers.md) · [逐请求计算和来源](baselines/ordinary-attention-and-slot.json)

两个 DP 的 16 个 worker 在同一台 171 上使用单调时钟记录图调用入口。按各卡第一波匹配的完整 40 层 prefill 对齐后，四个普通阶段共 **153 个**目标图波次，135 个只有一个 DP 拥有请求，18 个两组各有请求。两组始终都进入这些图。一次后续请求开始时，某卡还记录了上一段的一个图入口，已按 prefill 锚点排除。两个请求共用的图在全局只计一次，在每条请求上只计至它自己的最后一次验证。[阶段、波次、请求及两组的到达时间差](baselines/ordinary-attention-and-slot.json)

下表给一个可检验的时序情景。假设每个有请求且命中批写的 DP 在本组 TP8 汇合后都能提前 **0.961 ms**，取自三个 B1 时序样本中的有利值，原始速度参照为 B4。同一波先让对应 DP 按这个量提前，再取两组最晚的主机图入口，假设两组从这里到下一处共同设备依赖的耗时相同。只给有请求的 DP 计收益。实际请求用自己的步数，DP 相对时序沿用观测世代的各波样本。下表数值均为整段响应的条件降幅。

| 普通请求 | 首次原服务参照 | 恢复后原服务参照 | 对筛选的影响 |
|---|---:|---:|---|
| 独立对话 | 0.36%–0.37% | 0.92%–0.95% | 两轮在此情景均低于 1%；组间后续时延改变 1 ms 时第二轮可过线 |
| 独立短代码 | 1.21%–1.33% | 1.26%–1.38% | 只有 3 个验证图。要在两轮和两个查询位置估值下都达到 1%，每步净收益需达约 0.618 ms |
| 混合到达的对话 | 0.87%–0.90% | 1.26%–1.30% | 两轮的排序不同，应保留排队和请求分母 |
| 混合到达的代码 | 0.57%–0.60% | 1.59%–1.66% | 观测的 14 个图都与另一条请求同波；只让代码所在 DP 命中时，第二轮降至 0.57%–0.63% |
| 后续对话 | 1.16%–1.21% | 1.11%–1.15% | 按当前入口和两种位置估值，全部过线需每个活跃 DP 约省 0.857 ms；组间时延很敏感 |
| 后续代码 | 1.43%–1.53% | 1.34%–1.43% | 全部过线需每个活跃 DP 约省 0.588 ms。实际观测 4 个图，两轮原服务各有 6 次验证 |

若用较小的 **0.480 ms** 组内收益，独立短代码两轮分别为 0.91%–1.03%、0.94%–1.07%，后续对话两轮都低于 0.66%。归档没有普通 B1 批写的整次调用计时，也没有这些波次从主机入口到 EP16 设备汇合的实际尾部耗时。机器记录分别给出完全传递、组间后续耗时相差 ±1 ms，以及只有本请求所在 DP 命中的情景。这些数据支持把独立短代码和后续代码列作条件候选，无法证明线上已达到这个速度或推断它们在流量中的比例。[每步门槛与敏感性](baselines/ordinary-attention-and-slot.json)

冻结 C8 的 10 个非满波次都在首 token 之后。即使每波有请求的参与卡都省 0.961 ms，并让这份增量完全传给最慢请求，新增 slot 收益也至多 9.61 ms。再给全程四处 Attention 融合的中间情景 48.87 ms，整批合计仍仅约 **58.48 ms（0.315%）**。冻结首 token 沿用 Attention 单组的 40.40–43.03 ms。这个判断用于筛选已有满批优化之后的小批量扩展；满批 slot 的历史服务增量另有原基线。[C8 与普通负载的不同结论](baselines/ordinary-attention-and-slot.json)
