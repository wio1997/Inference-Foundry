# V1 编码器缓存到解码输入交付判断

## 介绍

从冻结 V1 scheduler 的输入特征和 encoder 预算追到 worker `_preprocess`、缓存和 V4.1 decoder 的词嵌入、注意力及后续读者。以原始 C8、平衡 C8 和六组普通负载决定调优范围。合法图像、软嵌入、EC connector 与分层 encoder cache 分别核对执行条件。每个替换原语逐位一致。

## 到了哪里

| 交付 | 实际代码与读者 |
| --- | --- |
| 冻结文本入口 | V4.1 仍是启用 MM 的 decoder-only 模型。原 C8、原形状 profile、平衡 profile、逐函数 profile 和六普通客户端均经 `/v1/completions` 交文本/词 ID，无图像或软嵌入 payload。`enable_prompt_embeds=False`，EC transfer 与自定义 cache manager 都未配置。`scheduled_encoder_inputs` 为空时 encoder 直接返回，但 `_gather_mm_embeddings` 仍分配 CPU bool mask、扫描请求窗。实际 V4.1 `embed_input_ids` 先做原词嵌入，见空 MM 列表便直接返回，merge 不读 mask。之后仍写原 `inputs_embeds` bank，保留原 raw IDs、padding、位置、Engram 和 decoder 读者。 |
| 有图像时的 scheduler | `_try_schedule_encoder_inputs` 按原请求窗口和 prefill look-ahead 找 span。相同 hash 已在本步选中或 cache 命中时可跳 encoder。禁止 chunk 时在未完整图像前回退，容量/预算不足则缩到 span 前或阻塞已在 span 内的请求。原顺序先问容量、再查子窗口是否有嵌入，两个条件的交换有回退反例。命中 EC 时保留 cache 预算并登记外部加载，计算预算不扣 encoder。`strip_covered_mm_data` 对前缀已覆盖的 span 只可丢 payload，仍需保留 M-RoPE 所需 CPU 字段和共享内存地址确认。 |
| 编码与完整输出 | `_execute_mm_encoder` 忽略缺 payload 的记录，软嵌入用 H2D 直入 cache。按相邻 modality 和字段兼容分组，V4.1 内部仍按各图像的 ViT/LLM grid 迭代，grid 在 CPU，patch 和类型按原字段布局交付。ViT 走 PatchEmbed、32 个 RMS/Attention/MLP 残差块和末尾 RMS。已核同 SHA 的历史加载回执，`AscendApplyRotaryEmb` 为 FP32 NeoX 中间计算后 cast 回原 dtype，`AscendMMEncoderAttention` 走 FIA。固定 16/16 heads、D64 的图像原语没有 GQA 展开或 D64→128 padding 可省。Aligner 在 ViT 之后做边界补零、`unfold`、GELU 和双投影。随后按原类型写 start/end/newline 与图像行，完整 span 按 hash 交给 cache。原编译设置关闭 encoder 图，原生对照未覆盖改造后的图像分支。 |
| NPU / CPU 缓存 | 默认 `EncoderCacheManager` 以 hash 管请求引用，引用为零可回收且仍能被命中，真正 eviction 通过 `free_encoder_mm_hashes` 交 worker。合法 score manager 用独立 metadata 发布 NPU/CPU evict、promote、临时 H2D。worker 在提交 H2D 后记录当前 stream event，保活 pinned 源直到队头事件完成，device 结果 `record_stream`。命中顺序为常驻、临时、score CPU 同步 fallback。miss 时产生的 D2H staging 和后续 H2D 若移到不同流，仍需证明生产完成和 pinned 源末读。`reset_encoder_cache` 在本地暂存/CPU cache/pending copy 非空时先同步。 |
| EC 生产与消费 | 冻结 `ec_transfer_config=None` 时初始化短路，mixin 是 `nullcontext`。合法 consumer 在 gather 前绑定本轮 metadata 并加载，producer 在编码前可先发布已有命中，冷结果由 `_cache_encoder_output` 的 save hook 发布。只有 producer 的 worker 从 encoder 分支返回空的 decoder 结果。`finally` 收集完成标记和 worker metadata，再清本轮 connector metadata，scheduler 更新状态和处理不可用请求。已核通用 ABI 和工厂分流。可配置 CPU、Mooncake、example 和外部实现各自的 transport 完成语义需要选定实现及同负载，不能沿用普通 cache 的设备事件。 |
| 选行、merge 和退役 | gather 用实际 `InputBatch.req_ids` 顺序，原窗口交集经 `PlaceholderRange` 前缀计数转为 cache 子切片，mask 用原相对坐标标位。空子片跳过 lookup。target 已在处理窗内缺 cache 会报错，支持 MM 的合法 drafter 可对只被 `+1` 看见的未就绪图像退回 token embedding。实际 DSpark 的 MM draft gate 已关闭。原 merge 把有序片段拼合、按 decoder dtype cast 后原地更新词嵌入，校验 mask 与数目。scheduler 到 `computed−placeholders ≥ span_end+lookahead` 才能解除读者，清理引用和实际释放设备/主机存储分开。 |
| decoder、跨层与图像条件 | `_prepare_mm_inputs` 同时交 raw IDs 与持久 `inputs_embeds`，V4.1 以外部 embedding 进入 SP/首层 HC。Raw IDs 仍供 Engram 的 dead-mask/history 和 A3 原生 vision/hash router。缓存命中可以没有新 `scheduled_encoder_inputs`，但仍需 gather 和 merge。当前 `skip_compiled` 由新 encoder 输入及模型类型决定，不能用这个位判断没有图像读者。原 FULL 纯文本图捕获内部 lookup，eager 用外部 embeddings，沿用旧输入交付定价。 |
| decoder attention 的图像 span | worker 仍生成 `mm_req_doc_ranges` 和 `mm_prefix_range`。旧 `dsa_v1` sibling 确实读前者并构造双向 image SWA。冻结 V4.1 target PCP 通过 `get_v41_cp_classes` 选 V4.1 builder/impl。已核当前 V4.1 基类与 PCP/CP 源码不读这两个字段，target `causal=True`，原 `ori_sparse_indices` 走该 builder 的显式输入或内部默认，不能把 sibling 的 image SWA 列为 V4.1 已生效。真实图像请求的 eager、cache-hit/FULL 和最终 attention mask 仍缺原生证据。 |

核对 29 份当前磁盘源码。24 组原 Python 条件/行映射控制覆盖空请求、同 hash 冷 miss、cache/EC 命中、预算回退、batch 行序、`+1`、原 merge 和 score fallback。控制使用 CPU 替身，无新增数值或事件验收。[源码身份](encoder-delivery-dependencies.json) · [归档与控制](encoder-delivery-review.json) · [旧输入 bank 与首层价](词嵌入实际派发与首层静态计算整段判断.md) · [退役](请求归还到下一轮缓存映射判断.md)。

## 结果

- **已停止 · 冻结文本负载的独立 encoder/cache 设备优化。** 本次核对的请求里 ViT、aligner、image merge、encoder cache payload 设备搬运和 EC transfer 的可省设备工作为 0，故同边界的请求收益为 0。初始化和模型驻留单独有旧账。
- **已停止 · 同预算独立空 MM mask/gather。** 旧平衡 C8 16 卡×11 闭合周期内，整段 `_preprocess` 平均 **7.120 ms/卡**，任一卡全免最多为对应窗口 **0.752%**。这个范围已包含必要的词嵌入、clamp、copy 等。整批诊断单 worker 最多 **121.160 ms**，相当于批次墙钟 **0.687%**，只给本地量级。空 mask 的独立端点收益未测。保留大输入/图/Engram 联合交付的旧价。
- **待确认 · 图像存在时的完整交付与跨 TP 共享。** 同一原 ViT 的分图注意力域必须保留。先比较原样子图中共享各层 FP32 RoPE 系数、Aligner 直接按原补零/Unfold 坐标给投影、把原类型转换和 cache 片段直接写进 decoder bank。跨 TP 单 owner 还要验证原每 rank 的位模式、所有 span 读者、连接器与 score-cache 寿命，并计全 span 传输。BF16/5120 每行有效载荷 10,240 B。若原 8 卡并行重复计算，省掉 7 份总工作也可能被广播和等待抵消。没有匹配图片负载的 hit/miss、实际矩阵 shape 或关键路径时间，当前不启动设备对照。
- **待确认 · 冻结文本的跨阶段输入交付。** 沿用原 C8 输入到首 SMLA/早期 HCPost 的更大估算。guard 需覆盖原 raw IDs、真实 mask/尾部、eager 和 FULL 两种读者、Engram history、持久 bank 首写/末读与原 fallback。只计能真正暴露的等待与搬运，图像零人口不用于裁去这个大范围。
- **已确认可实现 · 本轮没有新增替换准入。** 未运行新 NPU、请求或 profile。171 操作限于只读核对自有容器源码。
