# S02 本轮输入共同发布

本段已形成首轮价值判断/阈值，未完成全模型。入口是 `NPUModelRunner._prepare_inputs:1281–1694`，包含继承的 `_prepare_input_ids:1790–1924` 和spec metadata生产；出口交给图模式/metadata、Engram、目标模型及本轮验证器。具体表几何和性能参数在形成可删工作之后取历史观测匹配，不导入旧候选集合。

## 从出口需求反推

| 下游读者 | 必须得到的结果 | 可消的生产/交付，不可删的结果 |
|---|---|---|
| 本轮模型/词嵌入、Engram history/hash | 正确请求代次的raw ID及规定的model清理后ID；mask、lookback和padding合同另有读者 | seed与draft的四份索引向量、临时gather/cast/scatter可由一个请求owner直接覆盖；新/混合prefill的CPU补集仍要交付 |
| 所有attention cache组、RoPE、compressor | corrected INT64 positions、INT32 seq_lens/qsl、各组physical slot、CPU长度/位置镜像 | 一次请求计划可共用req row、query offset、修正位置；position buffer还有独立读者，不能只生成slot后删它。现有13组fused slot mapping已经是基线 |
| 下一轮状态与本轮host builder | 上轮位置映射、old computed/accepted/draft与CPU fallback，正确的host请求状态 | 合并同侧δ与共同读者计划；不能把host镜像等同于device位置后直接取消 |
| 本轮head与拒绝验证、后续padded draft准备 | logits/target/bonus/cumulative draft等typed索引与raw draft ID | 仿射索引可共用计算/常驻模板/packet；raw token内容必须来自本轮。模型clamp不能提前改变给验证器的raw draft |
| 各group builder、cache读写及Engram物理history | 正确的每组block表与slot银行、未使用尾部的规定值 | 未变表/行可免重复H2D，变化可发delta；形状未变不能证明内容未变，捕获地址和reader epoch保留 |

## 数学上共同的请求计划

对当前行r，令 `p_r` 为前轮行映射，`s_r` 为本轮scheduled token数，`q_r=Σ_{i≤r}s_i` 为inclusive query末端。活动谓词为 `p_r≥0 且 d_old[p_r]>0`：

- `c_r = c_old[p_r] + int32(v_old[p_r])`，活动行成立；其它行使用CPU fallback。
- `accepted_r = v_old[p_r]`，活动行成立；其它行保留规定初始化/原有fallback值。
- `position[r,j] = int64(c_r)+j`；`seq_len[r]=c_r+s_r`；qsl是s的前缀和。
- 对共同请求，seed写在 `q_r-d_r-1`，其d_r个draft写在之后的连续位置；prev row决定读取上一轮哪一行，不要求请求映射恒等。
- 令 `D_r=Σ_{i≤r}d_i`，`S_r=D_r+r+1`。bonus索引为 `S_r-1`；第j个target索引为 `D_{r-1}+r+j`；logits取行为 `q_r-d_r-1+j`（0≤j≤d_r）。因此spec五平面共享(q,d)；原两次draft gather可直接使用 `q_r-d_r+j`。

固定B4验证轮s=6、d=5时，五个索引平面都是确定的只读模板，逻辑上传量320B；用(C,D)描述为32B。模板不包含ID、修正长度或block内容。混合prefill、零draft/不齐draft仍要用原通用布局或等价descriptor。保持int32/int64索引ABI。

数学可共用不自动变成一次全模型kernel。B≤4的state remap可先快照所有old computed行再写，避免换序/重复映射的原地覆写；大T位置/slot展开宜并行。将整个8192-token展开硬塞进一个小state program可能变慢，属于同一机会的不同实现组织，不额外计价。

## C01：block表未变内容的重复上传

代码每轮 `commit_block_table(num_reqs)` 遍历所有组，`BlockTable.commit_block_table`直接copy当前行前缀，没有dirty判断。当前保存几何是12张[4,272] INT32普通表和1张[4,1]环表，B4合计 **52,240B/轮**。同一个表会被后面多个模型层读取，但它们共享表，不是每层都上传一份。

可删的是未变表/未变行的H2D及提交，不是block表这个结果。append/add/clear/move/swap、condense/reorder、图padding尾部写都属于状态变化；如果价值值得再追，必须由这些真实mutator建立dirty/epoch，不能只比较shape。若把13表打包一次上传再scatter回原地址，新packet、fanout和同步成本须扣除。

**先定量筛字节，再留提交条件。** 用旧C8的453个TP8调用作参考，把两DP调用全部串行、每次都按B4最大字节给足信用，并显式按1GB/s估价：全部payload免费仅 **23.66472ms，整批0.1273%**。这是有利参考，不是实测H2D速率或硬件上界。

所以纯字节减少不作为高优先项。要达旧整批1%，还需净省 **162.24297ms**。即便13×453次提交全可跳过，平均每个被删提交仍需净关键路径省 **27.55µs**；真实dirty比例、两DP重叠和新成本会收紧门槛。**先取得这个净提交量是否可能过线，再决定是否追每个mutator；不在此枚举多种copy拼接方案。**

## C02：统一请求计划与多输出输入发布

当前流程分开做prev remap、接受数/位置/长度、seed/draft索引上传与overlay、spec索引计算/五次typed上传、raw draft gather。可共享请求映射、qsl、draft长度及old状态读，减少提交和中间索引面；保持所有对外结果和状态，不需要删除字段才能融合。

匹配历史参数之前先确定了这个工作集；随后找到同shape state remap与ID overlay原始任务记录：72次，B2/T12、B3/T1688、B4/T24、B4/T6540。按profile+remap任务ID一一配对确认state/position/seq与overlay任务不交叠。最大观测任务并集 **136.279µs/次**。

给453个参考调用全按此最大值、两DP都串行、候选执行时间为0，已定价设备部分仅 **61.734387ms，整批0.3321%**。所以这些已定价小kernel的逐对实现整组降级，不继续拆remap→add、cast→scatter等小方案。

但这还**不能排除整个共同producer**：spec五平面的物理DMA/提交、raw gather、host构造及大跨度输入前缀并未都在上述任务并集内。联合方案要达到整批1%，这些其余工作扣新成本后至少还需净省 **124.17331ms**；若453次全命中，约 **274.11µs/参考调用**。若净额达不到这个范围，整个联合输入发布降级。host span中的等待和观测开销不直接当作可删量。

TTFT需要沿请求端点重新计适用次数；不能把这两项的整批参考百分比改名成TTFT收益。C01与C02若同用packet、共用host遍历或删同一submit，必须扣重，不能把未知提交节省相加。

## 会改变取舍的读者/同步条件

1. **raw ID观察点**：spec raw draft gather在模型前清理和 `_preprocess.clamp(min=0)`之前。若把clamp并入早期overlay，要保留单独raw输出；例如把draft=-1提前变0，可能把greedy本应拒绝的位置变为接受。这不是可以忽略的padding。
2. **老状态原地复用**：换序/重复prev row下，old computed所有活跃读者需在当前prefix覆写前快照；accepted有独立初始化与尾部合同。只为省一个小中间面而多加全局屏障可能抵消收益。
3. **跨迭代bank**：template只读可共享；可变packet的backing必须等最后sampler/draft读者退休。目标图release并不自动覆盖其后的验证器和drafter。
4. **CPU侧仍有读者**：当前压缩metadata在模型前读取修正后的CPU长度/位置；用device-only计划替代它属于S03联合方案，需要另算其真实省量。仅因同一δ不能删镜像或计数D2H。

## 适用分支归属

无前轮样本/新批：原CPU ID前缀交付与fallback；全部共同decode：原代码已跳过无用ID H2D，不能再计一次；混合prefill：原CPU全前缀copy+overlay保留，若只传补集须有覆盖证明；无draft：不用spec平面；有draft但不齐：通用仿射descriptor；固定均匀：模板；DCP/PP/M-RoPE/prompt-embeds不是当前请求路径，保留边界不计收益。模型padding尾部和mask不因实际token数小而自动无读者。
