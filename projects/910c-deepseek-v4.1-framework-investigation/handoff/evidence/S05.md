# S05：目标embedding、SP与第0层入口

2026-11-08，首轮判断完成；下一个待扫是decoder body，不宣称模型已走完。

真实纯文本请求仍实例化V4.1多模态wrapper（`vl_model.py:54,190,261`）。GPU runner `_preprocess:3513–3588`先clamp speculative占位ID，再为文本算embedding并copy进固定bank；`requires_raw_input_tokens=True`使raw ID与embedding一起交给模型。Engram/history读取raw ID，不读embedding bank。模型 `model.py:1519`使用传入embedding，否则从ID查表；FULL wrapper实际重放capture而不重跑Python条件，原capture有内部ID lookup，故存在图外与图内重复。eager/mixed只算一次，不可一起删。

执行次序补核：S05a的runner `_preprocess`在S04 `prepare_engram_inputs`之前；S05b的模型内部lookup/SP/repeat在它之后。S04/S05是审阅分段编号，不代表把全部embedding挪到Engram准备之后。runner:2530虽调用通用`update_cos_sin`，此wrapper有vision/text子配置，`is_vl_model=True`使通用`_cos/_sin`不初始化，`rotary_embedding.py:174–181`直接guard返回，当前无这次通用RoPE gather可融合。实际V4.1位置表由`rope_dsv4.py:107–191`按配置/position group取行，共享及固定输出银行已在S03 CP cache范围；当前`torch.gather(...,out=...)`已消除原index后copy，不重复认领。不同config/位置组不能共用数值，稳定地址和bank末读者保留。

下游第0层要SP本地token的H5120向量及四路HC初值；不需要每rank保留全部token的完整词表embedding。可从词表owner直接交付本地SP行，或将AllReduce换ReduceScatter；有效ID仅有一个owner出非零值，但仍保持SUM、无效ID、padding、原dtype/图地址。目标与草稿词表权重不同，无跨模型embedding共用；与Engram的ID→hash→表也不同，不能共用查表数值。两条路可以共同发布/打包，仅节省重复遍历/提交而非权重读取本身。

**价值先于追小读者。** 相符旧C8端点估价，整个named embedding全免费也仅TTFT最多5.957ms（0.399%）、整批93.115ms（0.501%）；ordinary相同路由历史上界低于1%。因此单独删重复图外lookup、lookup+mask/ID算式、SP交付替代及其内部逐对变体整组低值排除，不为证明某个alias再逐一追。这个排除只覆盖embedding本身；如果共同输入publisher改变更大的host关键段，归C02/C03，重新只算新增净省。原外部host至下一提交间隙含通信或其他工作，不能全当查表提交开销。

模型随后SP切分hidden/ID/mask，`hidden.unsqueeze(1).repeat(...,hc_mult=4,...)`、FP32 `pre_mix=[1,0,0,0]`进入第0层。数学上四路初值相同，可给第一HcPre虚拟广播，某些Gram/投影公共项可因相同输入合并；只适用该初始化，不可推广到后续已不同的四路。draft还存在repeat后的SP pad，可在本地行直接构造。相关small-shape repeat/pad/premix按保存最大任务时间、453个全串行参考caller全部免费约40.80ms（旧整批0.219%），这是T24/T20小形状参考，**不当作prefill大shape上界**。与embedding合并也无明显1%空间；若大shape入口另有≥约51.995ms/整批的新增净省才改变这个组合取舍。仅payload/布局变化无此证据，首轮停止入口局部实现；第一HcPre公式仍在下一段与所有80次pre统一判断，避免用初始化小范围排除整段mHC。

固定无多模态内容/soft prompt、PP1；上述fallback未被当前请求命中，但代码保留MM/eager/capture合同，不把可删图外文本lookup推广到其他请求。raw ID clamp、lookback、mask、metadata和银行代际均有后续读者；这里不能因embedding低值而删除状态更新。
