把准备工作追到数据和实际读者

设备空着时，框架在准备什么？

主要在构造本轮输入、缓存地址、每卡局部长度和原生算子参数。历史 KV 数据本体由后面的设备算子读取。

先分清三种东西

地址：去哪读、往哪写

block_table 把序列逻辑页映射到实际缓存块。slot_mapping 指明新 token 写入的位置。

参数：读多少、怎样计算

QSL 区分请求，seq_lens 限定有效历史；CP、压缩信息和原生 packet 规定本次执行方式。

数据：真正参与计算的值

Q、历史 KV、index K 和 ring state 在设备上。参数就绪后，算子仍要读取这些值并执行计算。

如何判断能不能提前、隐藏多少

先删掉没有读者的重复值，再把仍需执行的工作按真实输入拆开。QSL 的结构信息可以早准备；精确长度要等有效 token 数；本层 top-k 还要等实际 query。

最早开始 = max(输入就绪, 缓冲可安全写入, 执行资源可用)
暴露等待 = max(准备完成 − 消费者其余依赖就绪, 0)

必须把多个任务连成依赖图，比较最后交付时刻。不能把观察到的空档、单字段耗时或单项覆盖量直接相加成吞吐收益。
