# 异步输出跨进程交付与等待

## 介绍

从 target 已采样 ID、可选分数和请求行映射，沿 worker 输出线程、EngineCore 回复、调度消费及前端解码走到实际读者。先分开设备完成、进程内对象、进程间拷贝和请求交付。每个替换原语逐位一致。

## 到了哪里

| 交付 | 实际路径与合法条件 |
| --- | --- |
| 设备结果到 worker 线程 | 冻结 PP1、DSpark、async 先提交草稿，再构造 `AsyncGPUModelRunnerOutput`。copy stream 等默认流，发起 D2H、记录事件，持有设备源。实际回复 rank 在独立线程执行 `get_output`，等待事件后按单 token 或拒绝采样结果解析，保留无效行、ID 顺序、可选分数/NaN 和失败语义。另有下一轮 history 读者，经当前 req ID 映射到旧行并等同一事件。 |
| worker 到 EngineCore | 单机每 DP 的 TP0 回复 `ModelRunnerOutput`。普通 `execute_model` 的中间回复与 `sample_tokens` 分开，`FutureWrapper` 按提交顺序排空。KV/EC 聚合存在时允许多个 rank 回复，原 aggregator 在指定结果上合并。同步模式直接 enqueue，异步模式先入线程队列。失败以原状态和错误字符串回复，超时及进程失败仍各走原出口。 |
| 本机 ring、溢出与远端 | 冻结回复 queue 为 `MessageQueue(1, 1)`，24 MiB/槽、10 槽。协议 5 pickle 对满足条件的 CPU tensor 取连续字节，单个 buffer 小于 1 MiB 时 inline，至少 1 MiB 时交 OOB。总字节达到槽上限走 overflow 标志和本地 ZMQ；跨机 reader 直接走远端 ZMQ。ring 写完后再公布 flag，reader 解码后在 finally 标记本 reader 已读，之后才允许 writer 覆盖。tensor 从 ring 重建时拷出，具独立存储的 ZMQ Frame 可由 tensor 持有。空、非常规 tensor 及 timeout 保持各自原分支。 |
| 调度到前端 socket | Scheduler 消费后由 EngineCore 主线程把 per-client `EngineCoreOutputs` 入队。专用线程按原 array-like schema 编码。复用首 frame 的 bytearray 只在首帧 tracker 完成后回收，其余 OOB frame 由 ZMQ 持有。coordinator 小消息走独立编码，`ENGINE_CORE_DEAD` 广播后退出。可选 tensor/ndarray 走 inline 或 aux frame，阈值来自 env，源码默认 256 B；输出端未接 tensor IPC provider。 |
| 前端实际读者 | `AsyncMPClient` 用 `recv_multipart(copy=False)`、存活校验、typed decoder。inline tensor clone，aux tensor 默认保持 frame 存储，ndarray 保留原 view/copy 条件。utility 与故障走单独分支，DP 路由先移除 finished request，再把输出或 stats 入队。AsyncLLM → OutputProcessor 消费原序列、stop 及流式增量。默认输出是小整数 ID 列表和状态。可选 prompt tensor、pooler、expert 路由等分支另保留。 |

冻结原始 C8 与普通 payload 未请求生成或提示词分数，路由专家、采样 mask 和 KV/EC connector 在归档配置关闭。固定批次每 DP 最多 4 行，DSpark 最多 6 个候选 ID/行。普通 token 内容不形成大 tensor 交付。压紧包结构仍须保留 req ID 和当前/旧行代次、空回复、完成/中止次序和持有到最早读完的存储。

## 结果

| 同负载归档 | 整段允许全免的筛选价与边界 |
| --- | --- |
| 平衡 C8，完整轻量请求 | 按原 FIFO 对齐 DP0/1 的 226/227 个 sample 回复，worker 返回到 EngineCore 取结果中位数 22.24/22.79 ms。这个大包络包含晚到设备事件，单凭它无法给 pickle、共享内存或线程通知计价。 |
| 平衡 C8，11 个闭合 decode 周期 × 2 回复 rank | 非主线程 ACL event wait 中位数 9.03/10.22 ms。源码、唯一线程和时序匹配，归档缺 event handle。`sample_tokens` 结束至 wait 开始的中位数约 0.83/0.82 ms，已经早于事件完成。在保留同一晚到事件的条件下，再提前唤醒也无法提前完成这些回复。 |
| 同 22 条，事件完成到 EngineCore 取到结果 | 包含解析、线程调度、pickle/ring/反序列化的全部尾段。双 DP 并集 6.17 ms，逐边加 10 µs 的时钟敏感性后 6.39 ms，占较短稳态窗 0.623%。这是原观察窗全免筛选，适用于该稳态窗的独立子方案。 |
| 原形状 C8 前端完整 trace | 458 次输出 decode，decoder 全免 6.60 ms/整批 0.038%，P90 TTFT 宽松信用 0.203 ms。含 `process_outputs_socket` 与 `get_output_async` 的全部可见接收活动并集 57.94 ms/整批 0.331%，P90 1.256 ms/0.087%。九个前端 encode 调用属于输入和 utility。EngineCore 发送线程在这份 trace 的范围外。 |
| 原始 C8 非回复 rank | 63 个可匹配的 late copy/record，设备区间中位 3.54 µs，主机 copy API 到 record API 中位 73.45 µs。读者为空才有资格移除，不能把 14 张并行卡的计时相加到一个请求。 |

[定价、22 条匹配与归档 SHA](output-ipc-price.json)。

- **已停止。** 平衡 C8 已测稳态窗内，以独立 1% 为工作排序参考的 worker 事件后序列化、ring 布局、重复拷贝和接收小方案。原形状 C8 独立前端 Msgpack decode/接收小方案也停止。两份 trace 的信用各自使用。
- **待确认。** 提前输出连同下一输入所有权。真正的大项是晚到数据事件。原始 C8 已有保留原草稿、拷贝与 CPU 交接代价的首次回复情景，最短请求可省 15.239 ms，整批 P90 TTFT 情景可省 8.016 ms。只挪 D2H 的旧补丁继续停止。合格设计要把 data-ready 与必须保留的 work-done、晚到 H2D 读完及下一代写入分开验证。[提前输出和代次证据](early-output-generation-protocol.md)。
- **待确认。** 整个跨进程输出/下一轮提交联合交付。若继续评估，需要 EngineCore 发送线程的可见编码/发送、实际跨进程代次 join 和六普通的端点分母。非回复 rank 省掉 D2H 可跟随大方案，必须验证 `sampling_metadata.output_token_ids` 空、无多回复聚合及源的最后读者。大 tensor 分支按实际命中和 buffer 生命周期另算。
- **已确认可实现。** 本段未纳入替换原语。复核来自原源码与归档，未执行设备逐位验收。
