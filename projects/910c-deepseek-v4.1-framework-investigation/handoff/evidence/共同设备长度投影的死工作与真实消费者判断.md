介绍：继续同代 metadata 的较大交付。此次沿设备权威长度经过 CP suffix/sub/clamp/where，追到 base 持久坐标、C2 长度、原生 metadata 回调及最终 SMLA/QLI/压缩器消费者。每个替换原语仍要求逐位一致。

到了哪里：171 统一 hostname 核对通过；同 owned 容器/image 的 17 份当前源码 SHA 全匹配。11 份限定 body、18 个行段，穷举原 base 两个函数中 common 对象的 39 个读取/传递点。复用已完成诊断的 16 份 trace 与 CPU 日志，4576 次目标 CP 调用均匹配唯一投影序列；176 个 frame 各 26 次。另在本机用标准库抽取执行原完整 base build/publish 函数，960 个符号控制流用例对新长度输入设置“只能读 shape、读值就报错”的哨兵，并执行延迟回调。所有命中用例保持 canonical 输出别名，miss 负对照确实读取输入值。这是读取与逃逸证据，不是 Torch/NPU 数值或逐位验收。

结果：发现可独立于 CPU helper 缓存开发的删减：**原首个 CP 投影及 base903 的持久复制不变；已有 local batch 缓存命中后，后续 25 次新投影的值没有消费者。** 原 build945 只读取新输入的 shape，值从 batch968–969 的原 canonical 坐标继续流向后续各处。候选补丁仅在已有显式 batch 字典命中时沿用其 seq_lens；无字典/miss 完整回退。补丁已生成供审查，尚未安装到服务。
