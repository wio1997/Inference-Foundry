# 请求归还到下一轮缓存映射

这次走读覆盖请求结束、抢占与迟到结果处理，经 KV 页归还和重新取得，直到 V1 worker 交付下一轮 block table、slot mapping 和 C2 环形状态参数。冻结配置为 910C、CANN 9.2.0、V1 runner、异步调度、前缀缓存开启及 DSpark 五候选。两个源码清单共核对 15 份容器磁盘文件。已保存的同容器源码用于核对相关构造器和消费者。见 [源码与分支](scheduler-retire-path-review.json)。

## 请求状态与物理页

- EngineCore 按队列取最早 future，在处理该结果前消费 abort。Scheduler 先扣本次在途份额，排除已结束请求和应丢弃的 stale 份额。普通抢占归还请求页并清空 optimistic 状态，迟到结果可继续交付 token，同时跳过旧拒绝计数的回滚。强制 reset 的 drop 模式可丢弃这份结果。正常拒绝会回滚 computed tokens 和 placeholders，AsyncScheduler 发布已扣除 placeholders 的可缓存前缀。EOS、停止 ID、长度上限和重复检查保留原顺序及 stop reason。
- Scheduler 构造器只在多批在途且存在 KV consumer connector 时设置 `defer_block_free`。冻结配置走 `KVCacheManager.free`。合法 connector 路径可以先移除请求的页簿，再把页列表挂到 fence 队列。处理有 token 的步骤才推进 `processed_step_seq`。原队列遇第一个未完成 fence 就停，保留释放顺序。EC hook 在 encoder cache free 之前执行。
- HybridKVCacheCoordinator 按 group 调用 manager，manager 逆序交付请求的 blocks。BlockPool 对引用减到零的非 null 页分两种入队次序。可复用前缀的带 hash 页继续保留内容。命中方 `touch` 先取引用，随后才分配新页。再分配会通知 reuse watchers 并移除旧 hash。窗口回收使用 `max(0, total_computed_tokens - num_in_flight_tokens)`，缓存发布保留 finalized token 上限。C2 的 A3 CircularBufferManager 每请求持有一个环页，前缀查询为空且无窗口裁减。此前的 [前缀与归还合同](prefix-retirement-frontier.json) 与本轮选中源码的 SHA 一致。

## 下一轮读者与复制边界

- Worker 在 `synchronize_input_prep` 内读入 SchedulerOutput。清理 finished ID 与原 batch 行先于安装同 ID 新请求。连续请求追加页，恢复请求替换页列表并重新加入 batch，随后允许移动和交换物理行。prepare event 在修改复用的 CPU staging 前等待，在退出 prepare 时记录。GPU metadata 提交另由 `_model_forward` 的 finally 退役。大原语若改变提交时序，需要分别保存 pinned 源读完、旧设备读者完成和新页读者获准三个条件。
- `MultiGroupBlockTable.commit_block_table` 已在 CPU 后续准备之前提交 H2D。它提交当前请求前缀的每个 group。raw block table 和 slot mapping 随后供 attention metadata 消费。图路径在设备上把 padding 行清零并把 token 尾部设为 PAD。仅凭两帧 CPU 行内容相等跳过 H2D，会漏掉设备端 padding 写入改变的行。按差分提交的较大方案至少要带行迁移、有效范围和设备端覆写记录。
- DCP1 多组路径已融合 slot 生成。多请求且 tile 小于 1024 时进入 adaptive kernel，其余由普通 fused kernel 处理。fused 路径仍给 circular group 计算一列页的环槽和 PAD 尾。C2 builder 自己交付 PAD 槽，环状态地址来自 `block_table[:, 0]` 与本轮有效行。DSpark setter 会登记各组的 raw view，执行期只从 draft attention groups 取对应的 table 和 slot。删除 circular raw slot 工作要以该值在完整交付中成为内部死值为前提，并保存实际读者需要的 padding、地址和 C2 ring 参数。
- MRV1/DSpark 的初始化条件排除了 Mamba+Eagle3 zeroer。现有 C8 MXFP scale 恢复列表不含 V4.1 的 MLA/SWA cache。zero/copy 字段仍保留原调度和 worker 调用条件。C2 ring 写入、普通 Fill 及生命周期边界仍属于原交付。

## Encoder 与采样分支

V1 runner 的 encoder 清理先查询 pending copy 队头，再处理普通释放或 score-cache metadata。设备 copy 用 pinned source 和 event 持有源，缺 staged cache 时可走同步 fallback。冻结文本请求和无 EC connector 的配置不给这条链独立搬运信用。

普通与诊断 C8 的归档客户端使用 temperature 0。目标采样的 all-greedy 路径在调用随机 sampler 前返回。合法混合或随机路径保留共享 RNG 的整批抽样及逐行 seed 覆写。Ascend 的随机分支等待 global stream 并记录噪声张量的消费 stream。batch-invariant 路径委托上游，需同时保留噪声 dtype 和原 `div_` 或 `reciprocal_` 加乘法分支的舍入与原地更新。DSpark rejection 的抽样顺序沿用此前的实际调用证据。见 [目标输出与采样主体](target-output-source-excerpts.json)。
