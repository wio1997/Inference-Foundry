## 当前顺序与两条真实消费链

目标sample/rejection完成 → `_bookkeeping_sync:3010–3149`（当前async只建立CPU占位与上一代row map，复制req顺序）→ seed/count → DSpark context/body/Markov → draft ID → 更新accepted state → 构造`AsyncGPUModelRunnerOutput` → engine等输出 → scheduler更新请求/停止/回收 → 下次schedule → S01请求/slot变更 → S02请求映射/接受修正/ID overlay → S03 metadata → 下一target。

采样后有两条不同链：

1. **设备迭代链**：完整GPU sampled平面、seed及valid count给padded drafter；draft `[B,5]`留在设备。`_copy_draft_token_ids_to_cpu:2163–2203`当前async、无structured/penalty-output-ID/PP条件下直接返回，因此没有每轮draft D2H可删，仍先保存`prev_num_spec_tokens=5`。下一轮按上一代req map/width直接读GPU draft/seed修正输入，不能换成客户端过滤后的列表。
2. **host/客户端链**：Async输出持有GPU tensor引用，copy stream `wait_stream(default_stream)`后D2H IDs并record event；`get_output:345–385`先等event，再parse/filter无效请求、sentinel和vocab，释放引用。scheduler `update_from_output:1874–2033`据此滚回被拒token数、处理stale/finished/stop与deferred free，发EngineCoreOutput。CPU仍需要输出和count，不因GPU已有状态就可删除D2H。

`_copy_valid_sampled_token_count:1876–1896`的独立copy stream发布count到CPU/event，并将seed留作prev_sampled IDs。`_update_states_after_model_execute:999–1036`在sampling_done后另一stream计算`(output!=-1).sum`、D2H accepted count/event，保持**上一轮row顺序**直到S02消费，不能随input batch reorder改掉。seed路径额外屏蔽discard/vocab，状态count/客户端过滤的需求并非一般同一个值；只能共同读原平面、分目的发布，不能强行alias三种count。

## 数学/执行可以消失的工作

**C02共同请求producer闭环。** 从rejection的首不匹配/有效输出count直接产生seed/count、拒绝数、上一代row map以及下一轮ID/位置/长度/spec仿射索引，可以消掉重读ID、重复归约和clone/索引planes；保留discard fallback seed、原CPU镜像、typed ABI和生成代际。K5不变时qsl/bonus/target索引有共同仿射模板，token值与请求slot仍动态。next target的拒绝修正用上一代count，不读刚覆盖的新代。

**C04 DP packet到回环已覆盖。** 固定K5/padded eager query数由当前B与dummy角色决定；正常既定长度不会碰drafter max_len guard，故可以考虑把target/draft count共同协调。若任一rank角色/shape不可预测则全DP fallback，不能一端单删collective。去掉第二次CPU协调只算真正缩短的关键时间；原EP最后跨rank同步及必要dummy参与仍保留。

**银行/迭代流水。** target与draft metadata有不同输出banks，不能因一次全局wait就认为它们相同。可按角色last reader退役、提前构造下一代共同plan；但原positions、seq、input-ID/block表views可能跨角色共享，in-place改写会竞态。若要重叠，先保留输入快照/独立generation，输出地址和ExternalEvents仍稳定；no alias/old reader完成才可覆盖。不能凭两个输出bank不重叠就删输入ready/reuse fence。

**C15输出ready与写入退役分离。** sampled ID在draft之前已最终确定，理论可在sampling milestone发D2H，与后续draft并行，避免客户端等无关草稿。现constructor在draft之后wait主流，engine的完成边界也用于scheduler的安全回收（源码明确此前GPU写完成才drain deferred frees）。因此必须分开`sample-copy-ready`与`draft/cache-write-retired`，并将stop/abort的页回收、bank覆盖和下一轮复用挂到后者；不能只把wait挪早。还要保持GPU sampled tensor引用、req映射快照、接受count事件以及输出顺序。减少的是客户端无关依赖的等待，不是假称减少draft计算。
