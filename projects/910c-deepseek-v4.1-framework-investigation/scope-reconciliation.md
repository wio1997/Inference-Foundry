# 哪些改写值得按融合继续排查

固定 171 的模型、路由、专家分布和权重位置。对每条改写先写出生产算子、消费算子和可以少做的一份工作，再用已有 profile 的分支命中次数、层数、关键路径和替代开销折算到请求端。同一个中间张量被多个方案消除时，只用一次这笔预算。本文沿用现有报告的 1% 排序参考，分别看首 token、整批和普通请求。[逐项归因与证据指纹](baselines/fusion-scope.json)

| 175 条已登记改写的处置 | 条数 | 后续动作 |
|---|---:|---|
| 具名部分有可复用的估算、对照或局部实证 | 80 | 直接引用匹配的形状与分支，同条中其余机制保留条件 |
| 混有调度或放置 | 22 | 只为独立消除的计算、中间读写或提交计价 |
| 仅改变权重分布或分片 | 4 | 从融合队列移出 |

| 具体实现已出现数值反例 | 2 | 查新机制时保留反例 |
| 已有源码合同，本表尚未单列收益判断 | 45 | 先找超过请求收益门槛的整组，再判断是否值得定点补证 |

G13、G14、G16 共 21 条历史改写复用了同一批形状和分支证据。动态 confidence 的判断只针对保存了开关的 EP0 配置，私有 penalty 分支的判断只针对明确关闭它的 1,104 条记录。另登记一条验证后直接从 target/bonus 输出有限 Top-K 的具体融合，独立于 175 条历史改写的计数。[分支与普通请求](score-readers.md)

## MoE 里哪些工作仍值得算

- G20.A04 复制热门专家，G10.A05 把共享 Down 的权重列放到另一张卡。两项均移出融合队列。调整路由、冷热分布或一个 rank 的等待时间，无法说明某个算子少读写了一份数据。
- 固定 EP16 和原权重时，GMM1 → SwiGLU/量化 → GMM2 有两份中间数据。每个分派行先写 4,608 个 FP16 值，再写 2,304 个 INT8 值。FP32 行 scale 有后续读者。按 1.203 TB/s 连续搬运参考、每层取行最多的卡、两处写读都完全暴露且替代交付免费，冻结 C8 首 token P90 分别省 8.10 和 2.02 ms，整批合计省 14.17 ms。对应 0.68% 和 0.076%。六个普通请求的响应情景估算最高约 0.135%。这组融合降级。[固定路由的数据流、假设与估算](baselines/routed-expert-handoffs.json)
- G20.A01–A03 的批次聚合、满块早发和队列调度不单列融合收益。若上游能直接写给原顺序的归约消费者，才对消掉的返回缓冲和仍须读写的部分单独计价。空发送 rank 也可能接收。[返回读者与端点](baselines/expert-ordered-return.json)

4,472 次已索引的路由任务均为 INT8 权重的 DispatchFFNCombine。G10.A10–A11 属于未量化 modular 分支的可选乘法和 bias 转换，本次采样中无该项工作。固定权重时仍可成立的共享／路由结果合并已覆盖到下一层直接 premix。[FFN 输出合并的请求估算](ffn-merge-premix.md)

G13.A05–A06 的贪心 4+1 分块沿用已有整段筛查。112 个窗口中，从 head 输入选行到词表校验的整个阶段最多占本地周期 0.7042%。G14.A01、A02 的 raw 副本和行拆分共享已有 head 分数交付预算。G14.A04 的 count/seed/padded 完整区间最高占当地周期 0.082894%。在这组窗口内可批量降级，跨出该阶段的融合仍可计其额外消除的读写。[逐项证据](baselines/fusion-scope.json)

## 用有效行数判断 Attention 融合价值

长提示下，SMLA 的 Vector 根据压缩索引取 BF16 行并写入 GM 临时面，Cube 的 QK 和 PV 两次消费该面。在归档的 64 段逐卡 eager 和 128 个逐卡图窗口上，保留必要矩阵乘、舍入和各层注意力。假设稀疏访问与临时面同速、搬运差额有一半落在关键路径上，按统一有效行数重算冻结 C8 的首 token P90。

| 每个查询的有效位置 | 首 token P90 预计缩短 |
|---:|---:|
| 256 | 11.861–11.886 ms |
| 321 | 14.873–14.904 ms |
| 322 | 14.9191–14.9504 ms |
| 512 | 23.722–23.772 ms |

1% 对应 14.91855 ms。322 是这个统一长度模型的临界点。真实形状混合时须按每个查询所在的批和请求端点重新聚合。八个冻结请求首段调度的后缀为 3,200 或 3,328 个 token，无法据此直接读出每行 SMLA 取了多少 KV。六个普通 prefill 源索引的末行采样可见 128–274 个键，另两个三行调用中的采样分别可见 1,022 和 1,027 个。历史长行原生样本里，候选块列表为空也可交付 512 个有效索引。长提示条件项继续保留。[请求敏感性与原始样本定位](baselines/smla-panel-occupancy.json)

G08 的 10 条改写均已有分项处置。两份 BF16 Attention 输出及 LSE 的既有归并在 C1/C2 有数值反例；已测是该具体归并。G09 的固定专家表仅允许命中它的文本行提前确定 ID，归档原生路由有视觉 bias、无该表，仍需计算 384 个分数。两条 MC2 掩码复用共享原前缀准备预算。[OA、OB 与接收端判断](oa-ob-shared-cube.md) · [各条证据](baselines/fusion-scope.json)

## 输入、分支与重复预算

- 冻结负载是八个字符串请求。六个普通负载覆盖两条单请求、两条混合到达和两条后续请求，提交的是文本 token ID。归档客户端、请求协议和 workload 哈希确认两组均使用贪心生成，没有图像或外部 prompt embedding。G21 的九种图像专属改写、G14 的两种纯随机改写在这些请求上直接跳过。未量化专家路径另由固定 W8A8 排除。文本请求经过多模态包装器时仍可执行模型内部的词嵌入，446 次双查表已独立计价。图像请求仍可考虑 32 层复用旋转系数，每 N 个 patch 条件性少写 3,968 × N 个 FP32 元素，尚无图像请求时延。[范围和视觉合同来源](baselines/fusion-scope.json) · [文本查表与读者](baselines/embedding-engram-fusion.json)
- 51 个历史工作单位和 95 条组合关系用于查重复预算。典型交叉包括 Post→Pre 的残差与 Y、三个检查点归集与草稿输入拼接。QLI 的成员转换和 SMLA 私有面是不同的工作。跨层 KV 驻留与直接读取涉及同一笔访问时只能计一次。slot 双输出与 26 项批写的服务基线也不同。[按分支查看工作单位和关系](baselines/fusion-scope.json)
- 12 个执行模块关联 21 个分支族和 210 条原始分支说明。2,968 个原始控制点、1,008 个新增控制点和 290 个数据谓词已有逐项源码记录。360 条历史语义记录中有 198 条缺后续证据链接。记录数量不能证明运行时命中、两个算子独立、数值等价或整体完成。空白项保持待定。[执行顺序和历史记录](branch-coverage.md)
