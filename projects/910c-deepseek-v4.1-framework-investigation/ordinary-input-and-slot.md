# 单请求下的词嵌入、Engram 和 slot 批写

同一个 24 行图可以服务 1 个真实请求或 4 个真实请求。词嵌入要分别看图外、图内和草稿实际读几行。slot 要看生成坐标和扁平索引时传给 writer 的真实请求数。本页使用 171 已有的普通请求计数和冻结 C8 设备记录，新增性能测量为零。

<a id="independent-input"></a>

## 普通请求该优先哪条输入融合

**B4 的 26 项 slot 批写保留已有服务结论。普通 B1 中，后续对话最值得条件保留。** 假设一个有请求的 DP 上，做 26 项的两个 rank 每步都能在主机图入口提前 0.961 ms，做 13 项的其余六个 rank 只提前 0.480 ms。按 153 个实录图波次重算 16 个 worker 的最晚图入口，两组 DP 到后续公共依赖的时延相同时，六个请求在两轮参照中都未达到整段 1%。冻结 C8 在满批已优化的基础上再覆盖小批分支，沿用设备汇合模型，首 token 增量为零，整批有利估计也只再缩短 0.041%。[同轮 B4 服务对照](fusion-candidates.md) · [冻结图分支与设备到达](slot-batch-by-population.md)

| 普通请求 | 13 项省 0.480 ms、26 项省 0.961 ms，首次 / 恢复后参照的整段降幅 | 26 项保持 0.961 ms，13 项要省多少才能达到整段 1% |
|---|---|---|
| 独立短代码 | 0.57% / 0.59% | 两轮各仅 3 个验证图，即使所有活跃卡都省 0.961 ms，仍不足 1% |
| 独立对话 | 0.21% / 0.55% | 两轮的 16 卡入口模型均未过线 |
| 混合到达的对话 | 0.56%–0.57% / 0.81%–0.82% | 恢复后参照需 0.677–0.694 ms，首次参照按 0.961 ms 仍不足 |
| 混合到达的代码 | 0.30% / 0.83% | 恢复后参照需 0.700 ms，首次参照不足 |
| 后续对话 | 0.76%–0.78% / 0.73%–0.74% | 首次参照需 0.778–0.812 ms，恢复后需 0.845–0.880 ms |
| 后续代码 | 0.82% / 0.77% | 两轮按 0.961 ms 仍不足 |

组内 rank 分工来自冻结 B1 正常更新分支。主机入口来自普通请求的逐 rank 记录，135 个图波次只有一个有请求的 DP。表内把未持有请求的 DP 提前量设为零；两轮原服务各用自己的验证步数和时间，沿用观测世代相对请求所有者的时序。若允许每波各 rank 从主机标记到公共依赖的尾时延相差 0.25 ms，13 项省 0.480 ms 时，后续对话两轮的降幅区间放宽为 0.73%–0.82% / 0.69%–0.79%。真实 B1 单次批写的节省和设备汇合时刻仍未知。[16 卡模型、各组时延敏感性和逐请求结果](baselines/input-fusion-by-rank.json)

112 个已有 B4 窗口将 2,912 个双输出 writer 与各自的启动 API 一一对应。把其中 13 个全局 writer 的设备时间与其启动时间按串行全额相加，每窗最大 0.179 ms；26 个全算时最大 0.308 ms。借用这两个参照，即使完全传到客户端，六个普通请求整段最多缩短 0.459%。后续对话对 13 项的 0.880 ms 门槛中，约 0.70 ms 必须来自这些记录之外，例如合并调用确实消除的上层提交。B4 原生整次调用的 0.961 ms 为敏感性参照。[绑定证据与假设](baselines/input-fusion-by-rank.json)

### 图外重复查表的独立预算

目标图使用原始 token ID、图外 embedding bank 无其它读者时，复用图内结果可以省一次图外词表查找、掩码和 TP8 SUM。446 个活跃图调用逐组用四个通信的参与时刻约束卡间时钟，按每个请求的终止波次计价。已知设备工作全额兑现时，冻结整批估算省 **68.44 ms（0.368%）**；再串行计入 14 个具名启动 API 是 **89.55 ms（0.482%）**。连第一个到最后一个启动之间的整段主机时间都免去，整批也仅 **110.08 ms（0.592%）**。这些图工作位于冻结首 token 之后。[各请求的阶段与端点](baselines/input-fusion-by-rank.json)

普通 B1 只匹配这条查表的物理形状。三个匹配组均为 6 行，DP0 两个、DP1 一个，其中一个随后草稿是 10 行；它仍是有效的查表样本。给足设备和各自启动 API，按两轮请求实际所属 DP 外推，六请求最高为 **0.667%**。在 DP1 的一组样本上，若再把启动间隙算入，独立对话第二轮、混合对话第二轮、后续对话第一轮才可能承载 1%，且分别需消去可用间隙的至少 **91.7%、74.5%、84.0%**。3,568 条逐卡记录中，随后首个已绑定的非通信设备任务是 3,424 个 Fill 和 144 个 ZerosLike。把其提交前的空档整段归给图外查表，缺少因果依据。具名工作降级，额外主机预算仅保留上述条件。[同形状三个组、启动区间与过线条件](baselines/input-fusion-by-rank.json)

### 更换通信协议的两个候选

- 词嵌入按 SP 行交付涉及查表端所有权判断和 ReduceScatter。复用原估价，按调优通信与常见 24 行组估计，六个普通请求的整段最高约省 0.083%；沿用稀少的六行组为 0.257%。
- 两层 Engram 按 SP 行定向交给 WKV，涉及预清零、重排与 AllToAll。相同两种样本口径下，各普通请求最高分别约省 0.085% 和 0.929%。缺少同负载原生增量时，两条协议改写均降级。历史最高 1.85% 是多处改动在稀少组上的合计。[原协议估值、调优与默认校准](baselines/embedding-engram-fusion.json)

## 词嵌入与两层 Engram

六个普通请求各自独占一个 DP 的活跃请求名额，验证时每个请求对应一个当前 token 和五个草稿 token。在有 hook 的那次运行中，逐请求、在所属 DP 的八个 rank 上对齐后，共有 **171 次请求验证走 24 行目标图，另有 2 次并入另一请求的 eager prefill**。两个同时段请求可能经过同一物理波次。两次原服务参考各用其自己的验证次数和耗时。普通请求 hook 观测了图描述符和 eager 层记录，图里图外各执行了哪次查表只能从冻结 profile 比照。冻结 C8 的 446 个有效 TP8 图调用都出现了图外、图内两次目标查表。[每请求的计算波次与来源](baselines/ordinary-embedding-fixed-route.json)

此前用来估算单请求的三个冻结样本，图外目标查表都是 6 行，图内目标与两层 Engram 都是 24 行。草稿查表分别为 10、5、5 行，后两个恰是同一波的两个 DP。按物理形状重估时，图内目标与 Engram 可另用 428 个同为 24 行的常见组。图外和草稿仍用那两个匹配组，发生归约等待的时间也可能与普通请求不同。[按阶段划分的形状与样本数](baselines/ordinary-embedding-fixed-route.json)

| 固定 TP8 协议的改写 | 冻结 C8 首 token P90 / 整批预计节省 | 六个普通请求中估算最高的整段降幅 |
|---|---:|---:|
| 词表查找同时确定本 rank 是否拥有该行并屏蔽无效值；两层 Engram 减少预清零、重排与 gate 临时写读；保留图外查表 | 0.69–3.90 / 16.32–22.93 ms | 0.14% |
| 上述改写加上共用图内查表，省去图外的整次重复查表和 SUM | 0.69–3.90 / 27.28–49.88 ms | 0.62% |
| 同一改写，将两个 gate 的向量阶段节省放宽至一半，以容纳减少启动等额外收益 | 1.01–4.80 / 59.40–82.57 ms | 0.84% |

第二行要求目标模型在图内使用同一代原始 ID，且图外写入的 embedding bank 没有其它读者。第一、二行按能够省掉的片外读写估算 gate，均保留 WKV、旋转矩阵乘和规定的数值语义。此前的 **1.85%** 还依赖改用 ReduceScatter、定向 AllToAll 以及三个尾部组的通信耗时。固定通信协议后，这组写读和重复计算在普通整段响应上降级；改变通信协议的组合保留其单独条件。[固定协议的分项与时钟假设](baselines/ordinary-embedding-fixed-route.json) · [包含通信变更的原估算](baselines/embedding-engram-fusion.json)

## slot 写入的单请求分支

已实测的 26 项批写要求全局和本地 writer 均传入 4 个实际请求。普通单请求即使图描述符写着 4，本地 metadata 仍接收实际请求数 1，当前 26 项专门版本会回退。逐项的坐标与扁平索引双输出支持动态请求数，但这六个请求未单独记录它的命中和耗时。[真实请求数的传递、分派谓词与源文件哈希](baselines/single-request-slot-batch.json)

冻结服务中已有 48 个单请求形状的逐卡 metadata 记录，全部开启了跳过 ring 更新的分支。12 个记录有 13 个全局和 13 个非空本地写入，36 个记录有 13 个全局写入且本地行数为零。前者 26 个原 writer 均返回成功；后者 13 个本地调用均转原 fallback。这批记录只覆盖跳过更新的调用。后续已在冻结 C8 的全部非满目标图找到正常更新分支并绑定 13/26 项，普通服务的批写命中率仍待定。[正常更新与汇合点](slot-batch-by-population.md)[完整 26 项的参数与回退](baselines/single-request-slot-batch.json)

**保留一个条件候选。** 真实 B1 下同一代的 slot 可批量生成坐标和扁平索引。要保留全局/本地各自的有效行上限，正常压缩分支读实际请求末端的 query_start_loc，跳过更新的压缩分支仍写无效哨兵。零本地行要保留原回退的语义和顺序。现有 B4 kernel 的索引和别名检查均固定读第 4 项，仅放宽入口不能复用。

以 B4 原生 12 轮配对的整次调用中位节省 **0.961 ms** 借估 B1，假设每个可用图步都完整命中且节省传到用户。表中区间用每次原服务各自的验证数和响应时间。数值用于筛查 B1 版本的价值，已有 B4 的服务实测另存。[逐请求收益与每步所需开销](baselines/single-request-slot-batch.json)

|---|---:|
| 单轮对话 | 0.52%–1.33% |
| 单轮代码 | 0.60%–0.62% |
| 混合到达 · 对话 | 0.97%–1.43% |
| 混合到达 · 代码 | 0.43%–1.18% |
| 后续对话 | 1.28%–1.37% |
| 后续代码 | 0.89%–0.94% |

后续对话在两次原服务参考中都需要每个可用图步净省约 **0.70–0.75 ms** 才能缩短整段响应 1%。假设每步只能兑现 B4 原生中位数的一半，六个请求的最高估值降到约 0.72%。确定长期优先级还取决于正常更新时 13 项或 26 项能否合并，以及最晚就绪的参与卡能兑现多少。现有数据支持把 B1 专门版本列入候选，尚无普通服务的实测加速。[按模型顺序的候选清单](fusion-candidates.md)
