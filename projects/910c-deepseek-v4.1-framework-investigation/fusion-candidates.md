# 融合候选与请求收益

固定模型为 DeepSeek V4.1 Flash W8A8，含 Engram 与 DSpark。171 使用 910C、16 个 rank、CANN 9.2。C8 的 32K 输入、1K 输出与普通单请求分别计价。下表的百分比均指相应指标的耗时降幅。

在相同基线上能归给设备算子融合的整批收益，已有 slot 双输出和 26 项批写的实测。跨层 QLI 共用一次转换另有固定负载证据。专家布局、任务重排、页驻留及仅裁剪工作行的收益归入历史模块记录。

## 批量排除与覆盖

在全部 3,632 次逐卡目标图回放和 64 段逐卡 eager 主体中，观测到 60 类命名计算或通信任务。69 个数据库本地编号按每卡字符串表还原为 10 种运行时任务，其中 25 个编号跨库有多种含义。冻结其它工作和调度，21 类命名任务各自全部归零仍无法让两个请求指标中的任一项改善 1%。其中 13 类（含 LogicalAnd、Rsqrt、Tile）合起来，最多省 5.82 ms 首 token P90 与 167.29 ms 整批时间，对应 0.39% / 0.90%。此上界甚至允许把并行卡上的时间相加，首 token 额外留 100 ms 的时钟余量。若嵌入大算子还能改变主机提交、通信或其它读写，应按新增的可省工作重新估算。事件、拷贝和模型执行区间在各自生产者与读者处计价。[逐类及联合上界](baselines/target-family-filter.json)

12 个模型执行模块都有首轮价值判断。既有统计中，decode 的 405 个阶段/形状签名有 381 个在每个已测本地周期都低于 1%，prefill 的 663 个签名有 591 个在每个已测主体区间都低于 1%。这两组数据用于过滤孤立小改。共同生产者能消掉多次写回或改变通信交付时，以整个组合重新计价。历史末层 FFN 及读出有 7 段，128 个可变范围中已有 94 个即使全省也达不到历史首 token P90 的 1%。这 94 个范围可一次排除，无需逐对补测。[按阶段筛查](baselines/fusion-priority.json) · [128 个组合](baselines/terminal-stage-screen.json)

按输入、Engram、Attention、FFN/MoE、读出/采样、DSpark 和下一轮交付顺序推进。M08–M10 的词表选词与三层 context KV 已在同批同卡上联合计价。M11 的有效计数等待与下一轮设备入口已核对。已完成随机采样双阈值初筛，保留不同分数读者的条件。[按模块的读者和口径](module-value-map.md)

## 估算口径

先按请求终点聚合命中次数，只计可省的实质计算、提交、搬运及可提前的等待。并行 rank 每批只取一份时间，重新计算八个请求的 P90。末层和草稿两项窄范围各有两种发布假设，分别给此前批次计收益，以及同时给当前批次计收益。25% 与 50% 表示假设的净消除比例，实际能兑现多少尚未知。普通 QLI 采用单卡既有配对设备计时，并假定局部收益全部传递到响应完成，按两轮原服务响应时间报告占比。各项的负载、分母、基线和重叠范围不同，收益不得相加。[计算数据及来源哈希](baselines/profile-fusion-estimates.json)
