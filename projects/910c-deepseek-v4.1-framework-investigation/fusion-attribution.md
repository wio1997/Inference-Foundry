# 哪些收益能归给算子融合

之前把 MoE 的模块总耗时当成可优化预算，沿着专家冷热与权重放置做了深查。模块占比只适合定位。把路由、专家位置、权重分片、输入行和输出合同固定后，能指明哪一次计算、读写或提交会消失，才有可估算的融合收益。以路由专家为例，GMM1 → SwiGLU/量化 → GMM2 在当前实现中有两处中间结果可以尝试少写少读。按归档带宽、假设这些搬运全部暴露，冻结 C8 首 token P90 约省 10.12 ms，整批约省 14.17 ms（0.076%）。这一项已降级。[原形状、流量和计价条件](baselines/routed-expert-handoffs.json)

## 37 条混合提案如何处置

- **21 条归档。** 按提案现有描述，收益来自缓存、裁行、改变放置、调度或捕获方式，没有指明独立的算子工作消除。对应分支合同仍在原台账内。
- **12 条复用已有结果。** 例如三种 DSpark 词表分片方案共用各步 W2 输出 → 加 bias → ArgMax 的同一份交付估值。不同的权重分布不会产生三份可相加的融合收益。原记录只证明已覆盖的分量。
- **4 条保留条件。** 下表列出每一条的算子边界和最便宜的判断办法。当前没有一条可以据此列为新增高收益候选。[37 条原提案、来源、逐项决定](baselines/mixed-fusion-screen.json)

| 在模型中的位置 | 可能消掉什么 | 从已有 profile 判断是否值得继续 |
|---|---|---|
| M01，两层 Engram 同 TP 组交付 | 若两层输入及时就绪，合包省一次独立提交 | 比较两个生产时刻与第一层消费期限。若延后交付吃掉节省，停止 |
| M03，分块打分 → 局部 Top-K → 最终归并 | 局部列表的写回与重读 | 先确认现有路径物化了哪份列表。最终集合确定前的并行时间单独计 |
| M04，OB 尾部或规约交付 → 零行恢复 | 由实际 writer 生成原输出，可消除独立的零行重建 | 先找真实重建任务与读者。变长通信少发的字节另计 |
| M06，同卡同权重的两次 GMM | 横向合并两次已就绪的调用，有机会少一次提交或重复读取 | 先确认原来有两次独立调用，且第一次的读者可以等。已处于同一批 GMM 的行没有这份收益 |

## 用普通请求核对 slot 估价

这次评估的是已经把坐标与扁平索引融合为双输出后，再把 13 或 26 个 writer 合在一起的增量。112 个归档逐卡窗口里，这 13/26 个 kernel 的设备执行时间之和，最大分别为 **0.06918 / 0.12272 ms**。即使每个普通请求的每个适用图步都按较大的值估算、替代执行成本为零、节省全部传至客户端，六个请求的整段响应最多约缩短 **0.183%**。这些窗口作为普通形状的参照，尚无 B1 批写服务实测。[逐请求估值与适用步数](baselines/request-fusion-budgets.json)

两次原服务的后续对话各要约 0.70 / 0.73 ms（按各自最有利的可用步数）才能达到整段 1%。即使设备净省 0.12272 ms，仍缺约 **0.578 / 0.611 ms 每步**。B4 原生配对的 0.961 ms 测的是整次调用至完成，包含提交等多项开销。普通小批量只保留能把这些额外开销从请求关键路径消掉的条件方案。B4 的冻结服务实测仍按原配置引用。[普通请求分支](slot-batch-by-population.md) · [已有 B4 服务对照](fusion-candidates.md)

## 共同计算基线能回答什么

用同一批 8 个请求、4 波 eager 与 223 波有请求的目标图，复用 16 个 rank 的已有记录。按执行顺序统计目标主体的矩阵乘和原路由专家 GMM、目标词表投影、三层草稿 WKV、草稿主体、词表及五步 W2。草稿只计入仍有请求在该 DP 下一波继续验证的分支。未为并发卡累加时间。首 token 只计本请求产生首个 token 的目标主体和目标词表头，批尾不收取随后无消费者的草稿工作。[每个请求的波次、MAC 和去重规则](baselines/request-fusion-budgets.json)

固定原乘法和行数，以 1.8 GHz 为参考，每个逻辑设备每等效周期 BF16 / INT8 分别按 98,304 / 196,608 个 MAC 计。对各卡、各模式的累计工作取最大值，得到首 token P90 约 **25.47 ms**、整批约 **88.86 ms** 的条件性计算下界。原端点分别为 1,491.85 和 18,590.77 ms。这一界过宽，无法区分 1% 量级的候选。FP32 的耗时、Attention 内部乘法、部分额外投影、内存、网络及主机时间均未定价，频率也未经认证为上界。后续排序直接用相应算子边界的可省成本，普通请求沿用自己的形状与分母。[同批算术和局限](baselines/request-fusion-budgets.json)
