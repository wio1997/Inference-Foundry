## 2. 本轮找到的具体边界

139的正式C8共有12次纯prefill调用：8次复用，4次重算。4次重算在全部8rank上具有相同结构：

```text
普通prefix缓存先命中640 token；每个1024-token请求还剩384 token。
本步token预算1792，当前调度填入：

请求A  [640 → 1024]  384  完整尾段
请求B  [640 → 1024]  384  完整尾段
请求C  [640 → 1024]  384  完整尾段
请求D  [640 → 1024]  384  完整尾段
请求E  [640 →  896]  256  非末尾片段
合计                     1792

状态复用的规则：只有整批每个请求都到prompt末尾，且各自状态可用，才能跳过forward。
E尚未到1024 → E的复用key为None → 整批条件失败 → A到E一起执行模型。
```

这个失败条件由源码直接确定：`_records()`仅在`stop == len(prompt)`时给出key；`forward()`用`all(...)`决定整批复用。有一个非末尾片段就必定回退。这个条件在4次重算中全部出现，不能归咎于底层CANN算子精度。

量化结果：这4次回退共计算7168个token，其中6144属于完整尾段、1024属于被切开的尾段。**6144是完整尾段的token数，不是已证明可以省掉的计算量。** 事件没有逐请求prompt哈希和逐请求命中原因，尚不能证明那4个完整尾段都已有兼容状态；重新分批也会改变形状和时序。

各rank这4次原始forward的host范围合计约1.15–1.31秒。它包含异步提交或等待，既不是设备耗时，也不是严格可回收上限；不能据此宣布足够补齐1.81118秒，更不能按token比例推算吞吐。

**优先设计：在确认状态可复用时，让原生调度按完整剩余尾段分批，避免把非末尾片段混入可复用批次。** 不直接把共同的1792参数改成某个有利值；不按C4/C8名称、数据集身份或固定prompt做特判。状态不可复用时应保留普通计算路径，避免牺牲冷请求的批处理效率。

这属于框架调度与缓存的协同特性。它需要正确传递状态可用性、全rank一致决策、请求进度和资源归属，不能只在forward里伪造“已经算完”。

## 3. 为什么这还不是完整30%方案

| 已有事件 | C4 | C8 |
|---|---:|---:|
| 纯prefill调用 | 25 | 12 |
| 复用 / 回退 | 1 / 24 | 8 / 4 |
| 含非末尾片段的回退 | 16 | 4 |
| 全部到末尾但仍回退 | 8 | 0 |
| 跳过 / 调度的纯prefill token | 768 / 31488 | 5120 / 12288 |

C4即使全部到末尾也有8次回退；仅消除非末尾混批条件不会自动使这些调用命中。C4中的缓存条目还在逐渐增加，不能把C8的温状态当作C4已经拥有的状态。

另外，当前GLM适配在`Worker.execute_model_step()`中提前转入GLM适配器，绕过通用Worker后续的ZOS执行分支。现有异步提交已经发生，但**原生入口接通不等于原有ZOS优势已经接通**。双方使用大量相同SDK模型计算和NPU算子，共有图、异步和MTP优化匹配后，要再领先30%，必须真的少做工作、减少关键路径等待或改善批处理效率。

输出前回调/簿记的已测小范围，全部72请求合计39.78毫秒，单独删除不足以补齐任何一档。不能用`execute_host_elapsed_ns`的等待时间冒充CPU纯开销，也不能用pending次数证明设备没有气泡。

因此C4的下一项问题应限定为：**逐步准备、MTP接受数量反馈、输出回收与下一步提交之间，是否有累计足够大的未重叠关键路径等待？** 目前缺少回答它的设备关联时间线；这不是已确认的根因，不直接据此重写ZOS。

## 4. 对此前安排的修正

1. **先做机制对照，再谈框架优势。** 已完成139/140，保留真实C8成果，也承认C4无稳定机制收益证据。
2. **性能调查只保留一个具体实现候选。** 优先完整尾段分批契约；不再同时扫算子、缓存容量、图尺寸、精度和并行策略。
3. **C4证据收集与C8实现可以独立开展，但共享设备的计分必须串行。** 由本主会话推进，不恢复cron或子代理；源码设计和已有日志分析可重叠，不并发争抢计分资源。
4. **每次测试必须改变一个决定。** 已知输入、状态、版本和必要输出约束继续检查；不恢复CPU/NPU逐位追差，也不把文本不一致自动判成算子错误。
5. **失败要关闭分支。** 形状变化没有带来关键路径改善，就拒绝该路线；不以另一个编号重置同一预算。
