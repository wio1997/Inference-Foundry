## 1. 本轮关闭了什么解释

上一轮发现129的C4纯prefill调用25→35、单请求分段调用2→17。本轮进一步对齐客户端状态：

- **17次中的14次**，当时确实只有1个请求尚未收到首token，另3个已经进入生成区间。不存在另外3个尚待prefill的客户端请求可直接填进去。
- 只有3次是4个客户端请求都在等待首token，但服务端HTTP→C++队列的实际时间没有被记录，不能据此断言调度器漏选。这3次的主机区间合计0.909秒；即使静态账目上全部删除，也不足以覆盖129距历史门槛的3.829秒。动态调度效果不能由这个静态减法预测。
- 5次“唯一等待请求从0开始prefill”的记录中，后续客户端请求分别在约0.887、2.768、0.957、2.865秒后才开始，最后一次没有后续请求。它们是原运行的到达记录，不是改策略后的预测；但说明几毫秒的固定收集等待不能自然凑齐所有这些小批次。

因此，**重复实现“检查点后填充其他等待请求”没有价值；仅调整HTTP瞬时收集，也没有足以过线的依据。**

源码另确认：原生入口将prefill尝试间隔固定为1；NORMAL引擎选择prefill或decode整个步骤；有新等待prompt时可能打断原有生成。异步decode重叠已经启用并在128/129执行，不能当成缺失特性再补一次。

640位置的检查点用于保存可重用的中间KDA状态。直接取消它不是无害的调度优化，会改变共有前缀缓存契约，本候选不这样做。

## 2. 唯一原型：在请求组边界接纳新工作

新增显式开关`--native-admission-cohort`，默认关闭，仅允许在既有HTTP、async和混合状态复用配置下启用。

```text
已有HTTP队列 → 接纳当前可用请求 → 原生prefill
                                      ↓
                              首次进入原生decode
                                      ↓
新HTTP请求继续排队 ← 暂缓新接纳；当前组继续正常decode
                                      ↓
                              当前组全部结束
                                      ↓
                          立即开放下一组接纳
```

组边界由原生scheduler的真实步骤状态和活跃请求集合决定。没有固定等待毫秒数，没有硬编码C4/C8，没有识别benchmark题目，也不缓存答案。prefill阶段仍可接纳已经排队的其他请求；首次decode后，组成员只能完成退出，不能不断加入新成员延长该组。空组和已在prompt阶段完成的短请求不会阻塞后续接纳。

所有已接纳请求仍由DeepInfer C++ scheduler、Worker及现有状态所有权协议处理；HTTP线程不操作模型。新请求保留在既有有界HTTP队列中。共同优化、MTP5、输入/输出长度、内存及图配置保持原样。

**这是可选的吞吐优先准入策略，开启后不应再称为原连续接纳模式。** 服务回执明确记录`continuous_batching=false`和新开关状态；关闭开关保留原模式。不能把该模式下的结果外推成所有在线负载都更好。

## 3. 因果假设、代价和停止条件

干预：让后续到达的请求等待当前decode组结束。

预期机制：少发生“一个新请求的prefill插进几个老请求的生成”；下一组有机会形成更集中的prefill，已有请求的生成也更连续。

必须观察到：组内没有新接纳、组退出后及时接纳、所有原请求完成，正式C4的分批/生成交错和整批耗时按预测方向变化。只有原始端到端时间能回答是否值得采用。

**代价：新请求的首token等待可能增加。** 当前没有证据承诺吞吐改善，更不能把已观察到的4.134秒单等待请求主机区间全算成可回收时间。一次新候选如连性能筛选也未通过，不继续扫组大小、等待阈值或prefill interval。即使吞吐通过，也必须如实报告TTFT/TPOT及输出差异；不能只挑有利指标。

此前捕获的vLLM调度源码支持在token预算内处理运行中和等待请求、并有prefill节流逻辑。**不能因为新增了一个DeepInfer参数名，就宣称这是一项普遍独有技术。** 本任务的已有特性差异仍是完整目标混合状态/hidden复用；132是它在原生入口上的吞吐策略候选。最终仍须共有优化一致的新强参考，以及同源码特性关闭控制，不能以旧117或两个不同版本拼接验收。

本轮没有重新读取参考运行时源码；vLLM描述仅对应已捕获且哈希核验的源码，不冒充新参考现场审计。
