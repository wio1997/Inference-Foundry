# 失败记录与未验证范围

## 质量

完整模型质量与 G29/G30 数值等价性 **未验证**。相同的 64 条长随机输入中，32K 有 0/32、64K 有 1/32 的完整预测文本完全相同。随机输入的整段文本差异不能单独证明质量失败，但也不能忽略或作为精度通过。两个短自然问题返回 4 / Beijing，仅是功能冒烟，不能覆盖整模型质量。见 [输出对比](../evidence/G29_G30_output_comparison.json)。

DSpark RoPE 的实数 FP32 展开相对原复数乘有一个 BF16 末位差异，CPU 对照出现相同局部差异；没有把它外推成全部输出变化的根因。当前没有 logit、acceptance、真实任务质量或重复测量来回答数值影响。

## 性能结论

G30 只表明该固定配置能完成四档指定负载。没有证明最优性能、跨引擎优势或开启融合的因果收益。G30 在 64K 和 128K 的吞吐低于 G29，不隐藏这些数据。没有同臂重复、噪声底、跨时间漂移标定；不能仅凭两次运行判定融合导致提升或退化。

## 主要失败及修正

| 观察 | 后续处理 | 证据边界 |
|---|---|---|
| 错误 retry0 配置没有发 HTTP | 改为实际版本的一次尝试 retry1；失败轮次不计入结果 | 请求发出不等于性能验收 |
| DeepEP normal prefill 超过通信缓冲区 | 固定全局 chunk16384 → 每 DP1024，HCCL512MiB；对应 normal 估算 461MiB | 16-rank 组件验证和完整四档成功；不推广到其它 chunk |
| 较大 chunk 下 Engram 临时张量申请 OOM | 保留上下文270336、KV600000和输出合同，缩小每 DP prefill chunk到1024 | OOM 失败未当作成功结果 |
| 旧 A3 算子与当前 CANN 的广泛 host 注册冲突 | 保留 device/opapi/AICPU 字节，重建限定 host 注册与隔离解析 | 仅证明当前组合可运行；不能作为通用 ABI 兼容承诺 |
| 每次调用保留约4.20GiB workspace | G8 按 stream 等维度复用容量池，保留捕获图仍引用的 owner | 改的是 workspace 生命周期，未作为独立加速量化 |
| 首次 DeepEP/metadata 的顺序失败 | 私有 metadata 之前先完成实际 eager 通信 | 底层一次性初始化原因仍未确定 |

以前的失败轮次没有混入 G29/G30 正式数据。G29 由任务主动停机后切换到 G30，容器的受控退出不解释成模型崩溃。原始 task 报告和组件验证文件保留必要指针；本分支没有伪造缺失的失败运行数据。

## 原生不支持或不适用的优化

- prefill graph 经框架解析禁用；draft metadata glue 不具备 host-free capture，但 draft 模型自身图已捕获。
- chunked prefix cache 经框架解析禁用；普通 radix Full/SWA 保持开启。
- 当前 DSpark + ModelSlim 组合不支持共享专家融合。
- CUDA DeepGEMM、CUDA/TileLang/hashTopK、FP8 专用路径不适用于当前 A3/W8A8 路径。
- `NPU_BF16_WO_A` 快路要求 local group1；当前为 8，不满足条件。
- QKV 原生融合只作用于目标模型；draft 使用框架原生独立 loader，不擅自加入新融合。

“开启所有优化”在本次归档中指打开当前模型/硬件/框架组合适用的原生选项，不等于强开不支持的分支。

## 归档与运行边界

源码和原始性能数据对应已完成的真实运行。便携脚本是根据实测命令整理的交付物，只做离线验档；没有再次部署、上板、压测或质量评估。历史服务有 6 小时守护上限，当前存活状态不属于本归档的在线承诺。
