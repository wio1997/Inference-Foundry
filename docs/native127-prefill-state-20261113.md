# DeepInfer 混合 prefill 状态复用候选127

2026-11-13。源码 `605a4bb403eda35acfec700ae0d43854af21616a`，以保留实现114（`c4ec8e0`）为基线。默认发布实现保持114。本文是实现与试验设计记录，**不是新增性能成绩或NPU验收结果**。

## 这一轮解决什么

固定参考与原生路径均开启适用的共同优化后，现有单批C4/C8优势为34.28%/20.60%。C8仍需净省1.18198秒才达到固定强参考117的1.3倍。此前metadata图与MTP缩行虽然减少了部分主机或输入工作，却没有改善目标吞吐；本轮不再延长这些分支。

127只尝试一件事：同一服务实例收到完全相同的token序列时，恢复已计算的目标模型末段状态和隐藏激活，省掉一次完整目标prefill forward。DeepInfer继续管理请求与调度；正常正长度输入准备、logits、采样、实际MTP草稿和decode仍执行。缓存不保存采样结果、生成token或答案。

## 实现边界

- 开关 `--native-prefill-state`，默认关闭；修改4个文件，复用114的模型数学、算子和图配置。
- 仅作用于纯prefill、eager、所有请求均到达prompt末尾且全部命中的批次。混合批、decode、图捕获、未命中或隐藏激活覆盖不足时走原forward。
- 身份是完整prompt token IDs；模型、权重、dtype、TP映射固定在实例内。条目记录可覆盖的起点，允许同一输入采用不同的prefill切块，但不补造缺失的隐藏行。
- 覆盖34层KDA的卷积和递推状态、11组主注意力KV、11组压缩indexer和11组私有压缩尾部。KDA只恢复当前实际使用的状态行，不把5步draft预留行当成已计算状态。
- 恢复前核验实际block映射、私有引用计数和活动KDA列；8个rank必须一致决定命中。完成事件保障缓存复制和复用的流依赖。
- MTP缓存由原SDK路径照常更新。恢复的目标隐藏激活继续提供给实际draft forward，不用历史草稿替代计算。
- 固定runner的device-metadata释放契约保留；不使用新执行器、跨进程缓存或通用快照系统。

## 内存与成本

总缓存预算仍为每rank **4GiB**：普通SDK池3GiB，状态复用arena1GiB。arena使用有界LRU，所有保存状态和隐藏激活计入；普通池启动时必须仍满足声明的8请求容量。实际底层分配去重后核对总payload，SDK对齐额外storage单列。

按固定源码和模型维度计算，单条末段状态为27,607,040字节，加384行BF16隐藏激活后30,752,768字节，1GiB约容纳34条；每条保存或恢复需要102次复制调用。这是**源码推算**，实际布局、容量、复制和同步成本均待NPU验证。不能把理论减少的token数直接换成速度提升。

已有122观察的C8有14次纯prefill调用，其中8次完整批、合计6528个token在条目齐全时具有复用条件。其他批次正常执行。该观察不保证127的调度形状、命中率或净收益。

## 与固定vLLM能力的区别

固定参考的通用前缀缓存仍按640-token混合状态边界命中，并保留最后token计算入口。源码中的细粒度Mamba hash能力要求更细hash对齐；本次TP配置的group和hash均为640，其启用谓词不成立。

127新增的是一个正常正长度调度步内的完整目标forward替换：恢复私有混合状态及可用隐藏激活，随后走原采样和draft。它不是把已有共同开关只在原生侧打开，也不声称其他vLLM版本无法实现相同机制。结果的适用范围是重复输入的温缓存负载，不能外推到全新prompt或冷缓存。
