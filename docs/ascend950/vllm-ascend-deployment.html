1. 部署方案

在单台 8 卡 Ascend 950DT 服务器上部署 DeepSeek-V4.1-Flash，提供 OpenAI 兼容 HTTP 接口。使用官方 vllm_cann:ds41 镜像、原始 Hybrid FP8-MXFP4 权重，以及 DP8 / TP1 / EP8 并行配置。

官方 950 vLLM 示例采用双机 PD 分离。本指南以该软件发布为基线，给出本机的单机 PD 混部实施配置；单机启动参数及兼容修改见第 6、7 节。官方来源：CANN DeepSeek-V4.1 部署说明。

项目配置
服务形态单机 PD 混部；Prefill 与 Decode 共用 8 张 NPU
模型与量化DeepSeek-V4.1-Flash；原始 Hybrid FP8-MXFP4；deepseek_v4_fp8
并行方式DP = 8；Attention TP = 1；开启 Expert Parallel，MoE EP = 8
主要特性DSpark 5、Engram FP8 与 CPU 卸载、前缀缓存、异步调度、Decode 图模式、静态 Kernel、共享专家多流重叠
接口/health、/v1/models、/v1/completions、/v1/chat/completions、/metrics
默认监听0.0.0.0:8000；服务模型名 DeepSeek-V4.1-Flash-1017

实施顺序：环境核验 → 准备镜像、权重和拓扑 → 创建容器 → 编译算子并应用补丁 → 启动服务 → 验收与归档。

6. 算子构建与兼容补丁

6.1 MoE 路由算子接口对齐

本镜像的 custom_ops 绑定包含 additional_bias、additional_token_mask 等参数，需要匹配 20 参数的 aclnnMoeGatingTopKHashGetWorkspaceSize 接口。重建官方 moe_gating_top_k_hash 算子，并安装到本部署独立目录，使运行时优先加载该实现。

源码：CANN recipes infer 官方仓库；固定提交 6d060311ae75f6105fe4216e20566875da5a8838。构建参数采用官方 ascend950 目标，参考 自定义算子编译说明。

6.2 DSA 混合批次排序初始化

在 DeepseekV41MetadataBuilder.__init__ 中初始化 Decode 优先排序协议，使 DSpark 与私有循环池在混合 Prefill / Decode 批次下使用一致顺序。补丁只增加下面一行：

容器内 · dsa_v41.py
self._init_reorder_batch_threshold(supports_spec_as_decode=True)

目标文件为 /opt/vllm-ascend-dsnext/vllm_ascend/attention/dsa_v41.py。脚本校验原文件 SHA256、保存备份，并检查修改后的 Python 语法；文件版本不符时中止。

容器内 · patch_dsa.py
#!/usr/bin/env python3
"""Apply a version-checked DSA metadata initialization patch; no NPU calls."""
import hashlib
import pathlib

TARGET = pathlib.Path('/opt/vllm-ascend-dsnext/vllm_ascend/attention/dsa_v41.py')
BASE_SHA = '47cfb57d13143ed56f7eb0c76511f80d28af3deeb6477c1380c9845345782ef2'
ANCHOR = b'''class DeepseekV41MetadataBuilder(AttentionMetadataBuilder[DeepseekV41Metadata]):
    def __init__(self, kv_cache_spec, layer_names, vllm_config, device):
        super().__init__(kv_cache_spec, layer_names, vllm_config, device)
'''
ADDITION = b'        self._init_reorder_batch_threshold(supports_spec_as_decode=True)\n'

def patched(base):
    assert hashlib.sha256(base).hexdigest() == BASE_SHA, 'Unexpected source SHA256'
    assert base.count(ANCHOR) == 1, 'Unexpected metadata builder layout'
    out = base.replace(ANCHOR, ANCHOR + ADDITION, 1)
    compile(out, str(TARGET), 'exec')
    return out

def main():
    backup = pathlib.Path('/workspace/deploy/backups/dsa_v41.py.original')
    current = TARGET.read_bytes()
    if backup.exists():
        desired = patched(backup.read_bytes())
        if current == desired:
            print('DSA patch already applied'); return
        assert current == backup.read_bytes(), 'Source differs from backup and patch'
    else:
        desired = patched(current)
        backup.parent.mkdir(parents=True, exist_ok=True)
        backup.write_bytes(current)
    TARGET.write_bytes(desired)
    print('DSA patched SHA256=' + hashlib.sha256(desired).hexdigest())

if __name__ == '__main__':
    main()

7.1 运行参数

参数基线值含义
data-parallel-size / size-local8 / 88 个本地 DP worker

8.2 八卡与特性检查

检查项验收标准
NPU 状态8 卡健康；8 个 worker 均成功加载模型，无 worker 退出或持续重启
图捕获当前启动日志中 DP0–DP7 均出现 Graph capturing finished；结合 rank 日志确认完整性
静态 Kernel记录编译汇总、失败项与是否回退；存在失败项时单独确认受影响路径
DSpark生成请求后，相关 draft / accepted token 计数增长；仅配置为开启不足以证明执行
前缀缓存相同 token 前缀预热后发送新请求，检查命中 token 计数增量；90% 命中需以实际 token 数核验
CPU 绑定图捕获结束后检查 worker 主线程亲和性：卡 0–3 位于 CPU 288–383，卡 4–7 位于 CPU 96–191
内存记录负载前后各卡 HBM、主机 RSS 与剩余内存；不能用启动快照代替运行峰值
