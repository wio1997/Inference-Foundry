# 鲲鹏950比上一代好多少

截至2026-10-21，现有公开资料和本机观测不足以给出一个适用于所有负载的“快X%”。需要区分规格、单核执行、多核吞吐以及整套超节点系统。

## 可以确认的量化信息

华为公开的鲲鹏950方案有96核/192线程和192核/384线程两档，使用双线程灵犀核，并支持通用计算超节点及机密计算。来源：[华为官方主题演讲](https://www.huawei.com/cn/news/2025/9/hc-xu-keynote-speech)。

以旧鲲鹏920的64核型号作为明确比较对象，物理核数量变化如下；这是算术规格比较，不是benchmark：

| 比较 | 物理核心数量变化 | 能否直接推出业务速度 |
|---|---:|---|
| 64核920 → 96核950 | 1.5倍，即增加50% | 不能 |
| 64核920 → 192核950 | 3倍，即增加200% | 不能 |
| 若上一代实际是80核新型号 → 96核950 | 1.2倍，即增加20% | 不能；还需核对具体SKU/线程 |

旧920存在不同核心数及后续新型号，不能把“上一代”统一当作64核。64核/80核的产品资料参考：[鲲鹏处理器产品页](https://www.hikunpeng.com/zh/compute/kunpeng920)、[鲲鹏官方硬件配套中的80核型号](https://www.hikunpeng.com/doc_center/source/zh/boostmedia/hw265/kunpengcps_hw265enc_28_0005.html)。比较前应记录双方真实SKU。

SMT提供更多可调度线程，但两线程共享一个物理核的部分执行资源；线程数翻倍不能直接当作计算吞吐翻倍。单线程Python调度、CPU内存带宽限制的查表、可并行编译和多进程服务的收益也会不同。

## 两个常见数字的适用范围

- 公开演讲中的“单核性能提升50%+”属于后续2028年产品规划，不能据此说当前950比920单核快50%。
- TaiShan950配合GaussDB多写架构的2.9倍表述属于完整数据库/超节点方案，不能当作CPU通用性能或DeepSeek推理倍数。

本手册不把这些系统级和未来路线图数字写成当前单机实测。

## 这台服务器实际查到了什么

| lscpu项目 | 观测 |
|---|---|
| Architecture / Vendor | aarch64 / HiSilicon |
| Socket(s) | 2 |
| Core(s) per socket | 96 |
| Thread(s) per core | 2 |
| CPU(s) | 384，在线0–383 |
| CPU min/max MHz | 1200 / 2300 |
| NUMA node(s) | 4 |
| NUMA分布 | 0–95、96–191、192–287、288–383 |
| Model name | `-` |
| MIDR | `0x00000000480fd060` |

这些规格与950的96核档相符，但DMI型号还未确认。不能把ARM implementer/part编码单独作为商品SKU认证。准确识别可由管理员读取 `dmidecode -t processor`、BMC硬件清单或设备交付资料。

鲲鹏950是CPU，昇腾950DT是NPU，二者名称都含950，但承担不同工作。本次DeepSeek主要计算在NPU上；CPU负责请求/调度、输入准备、采样相关主机工作、文件加载及编译等。提高CPU性能能否改善推理，取决于这些工作是否暴露在关键路径。

## 与本次部署的实际关系

1. 本机虽有384逻辑CPU，历史模型容器只配置了16 CPU配额，OMP_NUM_THREADS=2。不能把整机核数当作进程实际可用算力。
2. NUMA亲和可能影响主存读写、pinned buffer及host offload；应结合实际NPU/网卡拓扑测量，不能盲目把线程全部绑到某个node。
3. NPU空隙与CPU schedule/metadata/launch对应时，才优先研究CPU路径。若CPU工作已被NPU计算覆盖，更快CPU未必降低TPOT。
4. 从源码编译可能受多核、内存和磁盘共同影响，MAX_JOBS应适配容器CPU/内存，而非直接设置384。

若要得出“比上一代快多少”，建议在明确的旧SKU服务器上，保持代码、编译器、线程/NUMA策略和输入一致，分别测单线程、多线程、内存带宽及实际调度路径。当前没有进行这种跨CPU实测，所以不提供推测百分比。
