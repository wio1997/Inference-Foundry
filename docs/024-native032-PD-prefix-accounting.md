# vLLM 0.32 四档本地和连接器前缀计数

从原生 G630 的正式冷测和同输入首轮重放的八组前后快照独立复算。每组都是 32 条请求，实际峰值并发 16，每条输出 1024；同档冷测和重放使用同一输入 SHA。仅提取 engine 0 的 `ds41flash` 计数，并复核原请求审计。 [原始运行和缓存资格](016-native032-four-tier-first-matrix.md) [逐阶段计数及源文件 SHA](../evidence/native_cache_G1382/G630_PD_native_formal_prefix_accounting.json)

| 输入长度 | P 重放本地命中 | D 重放本地命中 | D 冷测连接器命中 | D 重放连接器命中 |
|--:|--:|--:|--:|--:|
| 32768 | 1044480 | 1044480 | 1048544 | 4064 |
| 65536 | 0 | 50432 | 2097120 | 2046688 |
| 131072 | 0 | 0 | 4194272 | 4194272 |
| 262144 | 0 | 0 | 8388576 | 8388576 |

四档冷测的 P/D 本地命中均为零，P 在两种阶段的连接器命中也均为零。每个阶段中，D 的外部查询量等于总查询减去本地命中，本地与连接器两类命中之和恰为总查询减 32 个 token。32K、64K 重放时连接器命中各减少的数量，与该档 D 本地命中的增加量相等。128K、256K 重放仍保持完整的外部前缀命中。 [计数复算脚本](../code/native_PD_cache_accounting_G1382/audit_native_PD_cache_accounting.py)

这些值是逻辑 token 计数，跨节点字节、传输等待和实际缓存淘汰仍需独立证据。长档低命中和现有容量估计一致，当前原始快照支持复核缓存命中及连接器记账。跨框架热态比较需报告 P、D 本地以及连接器计数的来源与适用性。 [64K 容量边界与单请求检查](012-native032-first-65536-cold-replay.md) [128K 复算和限制](014-native032-first-131072-cold-replay.md)
