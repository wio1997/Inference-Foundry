# 新性能比较合同 v1 — 独立前缀，自然暖缓存

适用于新 Flash 及原 GLM-5.3 比较，但两种模型分别出结果，不合并吞吐或收益。旧共享前缀、RDMA、80,012 服务 tokens 的历史数据不进入新框架收益计算。

本页默认是文本输入合同。Flash 多模态按 [专项方案](MULTIMODAL_TEST_PLAN.md) 扩展：使用支持媒体的接口，80K核验视觉展开后的实际模型位置，预热边界不得截断媒体块/混合状态检查点；同样排除预热、保持独立前缀和自然缓存。多模态能力和成绩尚未验证。

## 请求与预热

| 客户端并发 C | 独立长前缀数 | 每前缀正式变体 | 正式请求数 |
|---:|---:|---:|---:|
|16|16|4|64|
|32|32|4|128|
|64|64|4|256|

每个 prefix 是自身独立的 74,400 token 文本；不设计共享长公共段。tokenizer 固有特殊 token/短格式前缀允许，但审计跨前缀 LCP 分布，不能藏入共享的 74K。每个 prefix 对应四个全新后缀，后缀起点即分歧，使四条完整请求在指定边界之后不继续共享。连续闭环补满客户端并发，不在四轮之间插入预热或清缓存。

每条正式请求服务侧实际输入严格 80,000、输出严格 600，固定 temperature、seed/采样、ignore_eos/最低输出约束并保存完成原因。优先统一 `/v1/completions` 的已 tokenized 输入或预渲染文本，避免两个聊天模板额外加 token；先验证 AISBench 对两框架的支持。若一侧无法实现统一封装，不启动比较，修复适配后重冻结合同。80,012 不悄悄视作 80,000。

先按固定 run namespace 清理仅本任务缓存，生成 C 个不同前缀，并逐个真实预热；等待写入完成、查对象/读回已知键。只对指定前缀做短输出，不预热完整 80K 正式请求。预热路由覆盖与正式亲和政策两边一致且记录。预热之后**不清 L1/L2**，允许正式请求利用自然 HBM/DRAM/L3 驻留。新档使用隔离命名空间；先核对池实际可容纳独立前缀，不为凑命中改为共享前缀。

每个完整文本/输入 IDs 有 SHA；同一模型的两个框架使用完全相同 input IDs，逐条核验服务 tokens 与缓存来源。Flash 与原模型分别按各自 tokenizer 构造相同长度/独立性类别，不能声称两个模型 token IDs 相同。

74,400 是逻辑预热前缀；实际可命中取决于页、MTP bigram 边界、缓存状态和后端定义。当前旧 SGLang page128/MTP 路径曾确认 74,368（92.96%），**这不是强行写给所有框架的常数**。运行前计算每个后端理论边界，运行后取真实 cached/storage/device/host 明细；字段缺失保持 null，不能填成期望命中。各层/target/draft/逻辑位置与物理 bytes 分开，不能把重叠计数相加。自然 HBM 命中不是失败，也不能强行称 L3 命中。

## 计时与报告

- 所有预热、冒烟、健康请求与 token 单列，完全排除正式吞吐；正式的 KV 查询/加载、网关与调度排队、P/D 计算/交接全部计入 TTFT/E2E。
- 全程时钟：第一条正式请求发出到最后一条终结（含超时/失败）；输出吞吐=sum 实际成功输出 tokens / 全程时长。另报 goodput=sum 通过正确性/输出/SLA gate 的输出 tokens / 全程时长，不能用成功幸存窗口缩分母。
- 输入逻辑吞吐=sum 正式实际输入 tokens / 同一时长，明确包含缓存命中；另报未命中/重算 tokens 与计数来源。不能把 P、D 输入相加。
- TTFT 是每请求发出到首个有效输出 token；TPOT 为同请求后续 599 个 token 的时间定义，统一 AISBench 版本和 reasoning/text 合并规则。不把角色 compute 时间或响应体结束叫 TTFT。
- 同时报全程 P50/P90/P99、E2E、TPOT、成功/超时/取消/缺字段及原始请求记录。四批是最低快速比较，不冒充长稳态证明；收益接近噪声时做有界配对重复。
- 原生 AISBench 稳态独立报窗口/样本/选择规则；不足以形成稳态即 N/A。服务端 D running 平台、客户端实际在途与 SSE 接收 token 窗口另列，不能冒充 NPU 生成时刻或原生稳态。
- Client C64 不等于 64 条同时解码。记录每 DP 的 HBM token capacity、真实运行/等待/transfer/bootstrap/host buffer 占用与峰值；D 155,648 tokens/DP 的旧布局装不下两条独立 80K，不能靠名字掩盖。

## 完整性与 SLA

先正确性再性能：权重/量化/输出、缓存状态、PD 数据、图与 MTP 实际执行通过；请求数、token、SHA、run namespace、无重复、失败全部审计。发生死等/缓存失效/缺证据时保存原始数据，不能报合格框架收益。

历史引用的门槛为 TTFT P50<4s、P90<12s、P99<30s，TPOT P50<18ms、P90<40ms；另有历史包使用 TTFT5s 的注记，保留其原文。新报告完整原始分位数与上述 4s gate 同时报，部署前确认用户若有更新的 SLA 则另版本冻结，不能为通过临时放宽。

单次四批结果不是全部场景最优证明。基线后用少量保护用例覆盖并发、复用间隔/命中层、取消和长上下文边界；无复用用例仅作功能保护或后续另授权性能范围，当前主报告不计冷启动成绩。未知业务文本不提交公开仓库，公开保存 SHA/统计与可复现生成器配置。
