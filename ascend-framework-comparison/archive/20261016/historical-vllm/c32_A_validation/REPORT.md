# 快速配置筛选：baseline、候选 1、候选 2 与四格组合

结论：三个候选组合均未显示优于 A 对照的性能，四组 C64 均未通过全部 SLA。保留 A 的服务参数后，C32/N1024 验证 TTFT P50=3.559s 已通过，但 TPOT P50=22.482ms 仍超出 18ms，完整 SLA 仍失败。本轮没有找到满足 SLA 的配置，也没有证明最佳参数。

全程 input/output TPS 是全部成功请求的对应 token 总数除以从第一条请求发出到最后一条请求结束的时长。native 稳态沿用冻结 AISBench 选择器，以选定请求的 token 总数除以选定窗口时长；它不等于对该时间段实际流出的每个 token 重新计数，有限窗口仍有边界效应。窗口条件通过不代表 SLA 通过，也不是某个百分比置信水平的统计认证。输入 TPS 包含缓存命中的逻辑输入 token，不等于新增 prefill 计算速度。

原始私有归档保存逐请求记录、时间数据库、前后 counters、六机设备采样和分析脚本，公开这里只发布聚合结果与哈希。全程复算入口见[基线脚本](../../verify_results.py)，稳态定义见[指标说明](../../METRIC_DEFINITIONS.md)，兼容性见[机制说明](MECHANISM.md)，归档身份见[来源清单](PROVENANCE.json)。仅凭公开聚合文件不能完整重建私有逐请求结果。

本稿汇总四组单轮 N=384、C=64 筛选，不是重复容量认证，也不能据此认定最优配置。A 是四组 C64 筛选的 best observed arm；独立 C32 validation 见下节，不据此认定最优。候选2和四格组合的配置以 sidecar 记录为准，原 manifest 的 UNASSIGNED/陈旧标签均保留并在来源清单中说明。

## 观察与限制

候选1相对 baseline 的 native 稳态 TPOT p50 +1.87%、TTFT p50 +0.56%、输出吞吐 −1.13%；未显示明确收益。候选2的 TPOT p50 为 24.9428 ms（相对 baseline +5.83%），稳态 output TPS 为 1,862.78（−3.59%）。四组均为单轮，没有重复运行误差估计，不能判定统计显著性。候选1/2的 MTP accepted-plus-bonus 分别约4.013442/4.012348，baseline约4.042453；draft-token接受率约60.2688%/60.2470%，baseline约60.8491%。accepted-plus-bonus 观测相差约 0.7%；输入盐值、批形状和配置的影响尚未分离，因此不能把吞吐差全归因于配置。

候选2同时把 fused MC2 设为关闭并启用 overlap；如果 baseline 实际使用 MC2，观察到的差异还可能包含失去 MC2 收益。当前聚合没有 step/event 时序，不能拆分 overlap 窗口、stream成本、MC2或padding的贡献。TP=2 对某个 scheduled token count 最多补1个 token；均匀 MTP5 验证 q=6×request 为偶数，不能由平均 running 2.5推断 padding 常见或昂贵。q1、draft、mixed batch 需要独立数据。

四格组合的 native 稳态为 3/6，full-run 样本 SLA 也未全部达标。其相对 baseline 的稳态输出 TPS 为 −3.67%、TPOT p50 为 +1.38%；这是 FC/shared-DP/fused-MC2/overlap 组合变化的单轮观察，不能归因于单个开关，也不能据此判断配置最优。该组合源码路径的 W8A8 事件等待点与 shared-DP all-reduce 跳过范围见 MECHANISM.md。四组结果不证明最佳参数、q1 占比或实际 overlap 程度；C32 validation 已完成，见下节。原始归档哈希和标签更正见 PROVENANCE.json。

## 当前决定与下一步

保留 A：P 预算 12288、D MTP5，D FlashComm1/shared-DP 关闭、fused MC2 请求配置为 1、共享专家 overlap 关闭。恢复依据是四个同 C/N 筛选结果，不是默认回退习惯，也不是参数最优证明。恢复后六个主进程实际参数已复核，代理健康且在途为零；本轮设备采样已停止，诊断 gate 关闭。本阶段没有新增代码级性能 KEEP。

C32 全程和稳态均仅 TPOT P50 未通过；稳态超门槛 4.482ms（24.90%），要到 18ms 边界仍需从观测值下降约 19.94%，严格通过需更低。因此解码阶段延迟是当前直接的 SLA 限制。六机均有活动，D 持续高活动、P 也并非空闲，但这些指标不能证明六机均达到计算峰值，也不能证明 P 普遍等待 D 或 D 普遍等待 P。

本轮停止新增重启和配置组合，不增加 C70/C80。已有数据不支持通过增大 max_num_seqs 解决问题：C64 采样中的 P/D 活跃请求量未显示该上限是主要限制，且离散采样也不能排除短暂触顶。预算、MTP、图模式和上述通信组合的历史测试结果分别保留，不将不同 N 的吞吐拼接为收益。

下一阶段优先取得当前 4P2D 的短时同步执行证据：区分 q1/q6、最终图模式、跨 rank 进入时差、CPU 发起空档与通信/kernel 时间，再决定图路径、通信或调度的优化方向。旧 2P2D 的 q1 机制不能直接证明当前 4P2D 的发生率；本轮也没有证明 all-dynamic 或长间隔全部来自图回退。这项深度诊断尚未执行或自动排期。
