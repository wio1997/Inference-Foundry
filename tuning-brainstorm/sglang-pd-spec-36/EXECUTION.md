# 执行方式与任务接力

主控：GPT-6.1 Sol，推理强度 xhigh。简单工作：本地 ZCode，通过用户现有 DeepSeek provider，任务配置模型别名 `deepseek-flash`。配置别名不能证明服务端实际模型发布版本；请求元数据缺失时保留 UNKNOWN。

## 完成计划后继续做什么

1. 读取本目录合同和 36 点清单，恢复任务状态。核对安装源码、真实模型、PD 与 MTP 支持，以及可用设备归属；不沿用其他研究线的基线。
2. 先得到 36 点路径/支持性表。随后为实际走到的路径建立可重复基线；不适用项记录源码、配置或探针证据。
3. 将延迟拆到真实依赖图，计算必要计算量和必要搬运量，并用同硬件、形状、dtype、布局的 probe 校准可达速率。先定位目前距可达边界最远、且暴露在关键路径上的工作。
4. 每轮只冻结一个可证伪候选。ZCode 执行主控审核的脚本或有限补丁，主控独立检查命令、退出码、产物、正确性和性能证据。
5. 结果分为接受、否定、不确定、不适用或具体阻塞。接受后重测瓶颈迁移；有剩余空间就继续下一轮。不要只扫配置，也不要将一次局部加速当作任务终点。
6. 按条件保存当前最好实现、选择条件与回退。将讲解、原始证据索引、结果与否定理由逐轮提交到当前 GitHub 分支，保留相互独立的历史结果。

## 首轮顺序

延续 CPU overlap 课程，先分析 M015 / M016 / M018 / M019 的真实 relay、缓冲和同步依赖；其次 M035 的 P→D 交接与已有 PD-CHUNK；再根据 profile 进入 M017 / M021 / M022 或更大的 Attention / MoE / 网络瓶颈。教学顺序与实验优先级可以不同。

不同机制可能指向同一条关键路径，但不能把同一个改动算成多个独立收益。已有开关、已有 fast path、兼容性限制要先识别，不能重新包装成创新。

## 主控与执行器的边界

ZCode CLI 已核实版本为 0.16.9，支持 `--prompt`、`--json`、`--cwd` 与 `--mode yolo`。本地任务启动器使用独立配置，明确禁用 Browser / ComputerUse；不修改用户全局模型与权限设置。`cwd` 是工作目录，不是操作系统沙箱。

用户已授权本任务所需非交互执行、隔离依赖、候选修改、测试、任务自有容器启停和 GitHub 提交。主控负责把每轮授权范围写进受控脚本；遵守平台实际权限机制，不反复让用户审批已授权普通步骤。

服务器只操作确认属于本任务的资源。其他对话正在使用的服务、进程、模型研究状态不能接管。资源不足时完成源码审计、CPU 等价测试和其他独立工作，明确记录阻塞；不能换成单引擎或关闭 MTP 来冒充主线通过。

## 本地状态与公开证据

本地 Task/Loop/Run 状态保存完整运行上下文；公开仓库保存经过检查的规格、代码、命令、环境摘要、产物哈希及结论。密钥、provider 配置、密码、认证日志和其他任务会话不进入 GitHub 或第三方模型 prompt。

每个 Run 至少包含冻结合同及代码哈希、唯一变量、执行命令、退出码、正确性、重复与噪声、设备/主机计时和有效输出统计。用实际接受长度分布解释 MTP 成本。跨节点单调时钟不直接相减，异步操作不能仅用主机提交时间冒充设备耗时。

本地清单检查通过只表示准备完整。当前没有本任务的服务器运行基线、可达带宽/算力校准或优化收益；这些必须在后续真实实验中补齐。
