## 它干什么

DSA indexer/Top-K 是模型决定看哪些历史位置的算法；HiSparse 是把完整 KV 放主机、设备保留热点的管理办法。减少 Top-K 数量会改变算法，不能当等价优化。

## 当前怎么做

先确认模型是否 DSA、目标和草稿各用哪个索引器。固定 NPU 源码已有短序列跳过 Top-K 的路径；HiSparse shared-index prefetch 文档明确排除推测解码。

## 成本在哪里

Top-K 与 gather 花计算和访存；HiSparse 还需主机内存、换入和同步，不能把节约 HBM 当自动加速。

## 这次考察的优化思路

保留相同 Top-K 语义，查短序列“全选”能否直接生成连续索引且实际已生效；已有短路径不再重复实现。HiSparse 预取不纳入本 MTP 主线。

## 什么条件下可能适用

仅针对实际 DSA 路径；Ascend HiSparse 基础支持也须独立确认。

## 新增成本与回退场景

长序列不能跳过选择；相等分数的 tie 顺序也可能影响结果。

## 不能破坏的语义和生命周期

位置集合、顺序、mask、草稿与目标的各自状态一致；不擅自缩 Top-K 或跨层复用。

## 最小实验

**基线**

记录 K 与实际序列长，目标/草稿分别检查。

**唯一改动因素**

先只探测 L≤K 的已有 fast path 是否命中；仅发现未覆盖路径才补。

**用例**

- 2/3 并发，L=K-1、K、K+1
- c3-long 作为不能跳过的保护用例

**预测**

短序列不执行多余选择，长序列保持原算法。

**指标**

- Top-K 调用/耗时
- 索引一致性
- accepted length
- D 每 token 时间

**否定条件**

fast path 已覆盖则记已有；非 DSA 或 MTP 不兼容路径记不适用。

**第一个可执行动作**

读模型 config 与 NPU 分派，输出 DSA/HiSparse/预取三项独立支持结论。

**最低执行层级**

先核验路径与兼容性；通过后做局部实验；最后验证 PD 端到端

## 逼近物理极限的分析

**必要工作**

模型规定的 indexer、Top-K 位置集合和这些 KV 的读取必须保留；L≤K 时选择可退化但索引仍须正确。

**资源与依赖边界**

以 indexer→选择→gather→attention 的真依赖建界；HiSparse 若支持还需主机链路，不与 DSA 计算混算。

**怎样校准可达上界**

同 NPU 实际 K/L/heads/dtype 测选择、索引生成与 gather 可达时间；HiSparse 未支持则该项 N/A。

**怎样判断剩余空间**

先扣除已有短路径收益，再看真实重复选择/布局准备；长序列优化不能靠擅自减 K。

**条件特化与回退**

短序列连续索引仅 L≤K 且 mask/tie 语义匹配时使用，跨阈值回 Top-K；测判断与图桶切换。

**何时停止当前方向**

现有 fast path 已覆盖，或额外判断超过节省即停；MTP 不支持的 HiSparse prefetch 明确排除。
