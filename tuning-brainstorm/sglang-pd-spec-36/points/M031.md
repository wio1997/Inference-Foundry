## 它干什么

MTP 先便宜地提出若干候选，再由目标模型验证，接受的连续 token 一次提交；目标是每次昂贵验证换来更多有效输出。

## 当前怎么做

SGLang 将模型 MTP 接入推测流程，参数控制草稿深度、分支数和验证 token 数。最终成本包括草稿、验证、接受判定、状态提交及 rejected KV 处理。

## 成本在哪里

候选越多越贵；接受长度不随深度等比例增长。平均接受率还会隐藏大量“只接受很短”的轮次。

## 这次考察的优化思路

保持 MTP 开启与采样规则不变，只比较当前深度和一个相邻合法正深度，寻找每个有效输出 token 的总成本更低者；最低深度时不降到零。

## 什么条件下可能适用

目标模型 MTP 权重与 Ascend 实现有效，PD 交接包含需要的推测状态。

## 新增成本与回退场景

高接受负载变浅可能变慢；参数变化可能触发不同图桶和内核，须同时归因。

## 不能破坏的语义和生命周期

不降低接受阈值冒充等价加速；冻结采样、seed 合同和质量指标，按算法要求检验分布/greedy结果。

## 最小实验

**基线**

固定 MTP 算法、top-k、采样、权重及请求集。

**唯一改动因素**

优先试深度减一但保持合法正值；已在最低深度则只试加一。如候选数由合法性要求派生，明确记录联动。

**用例**

- c2-short、c3-long
- 自然高接受与低接受各一组固定提示词

**预测**

较浅时检查减少无效工作是否覆盖接受数损失；较深时检查新增接受是否覆盖新增成本。

**指标**

- draft/verify/commit 时间
- accepted length 全分布
- 有效 token/s
- HBM 与质量

**否定条件**

单位有效 token 成本未降、质量失败或差异来自请求集变化。

**第一个可执行动作**

确认实际算法别名与参数规范化，记录当前 accepted length，先不改深度。

**最低执行层级**

先核验路径与兼容性；通过后做局部实验；最后验证 PD 端到端

## 逼近物理极限的分析

**必要工作**

保持接受规则下的 draft、target verify、状态提交与必要 KV 工作；每轮有效输出长度是实测随机量。

**资源与依赖边界**

依赖图给每轮可达总成本，再用总成本/总有效输出 token 评估，不用平均接受率简单相除各段。

**怎样校准可达上界**

同 NPU、dtype、长度、树形和接受分布校准各阶段可达性能；当前 UNKNOWN。

**怎样判断剩余空间**

分别估计可省的 rejected 工作、launch 与提交成本；更深草稿只有新增接受收益覆盖新增成本才继续。

**条件特化与回退**

仅在已测业务/长度/批次区域选深度，未知区域用当前稳定深度；计图切换与策略判断成本。

**何时停止当前方向**

相邻合法深度均无单位有效 token 改善且阶段接近可达界则停止本区域；不能外推全部文本。
