# M007｜Mixed batch 与 ragged / packed 输入

[任务目录](../README.md) · [执行合同](../CONTRACT.md)

- 教学课程：第 2 讲。
- 审阅状态：条件不适用。
- 类型：not_applicable。
- 主线：PD 分离 + 推测解码保留；Ascend 实际配置待运行合同确认。
- 本文是用途、假设与最小实验设计，不是已取得加速的报告。

## 它干什么

这里有两个概念：同一 worker 混合 P/D 阶段，以及把多条变长输入紧凑排在同一数组。只有前者与专用 PD 目标冲突。

## 当前怎么做

本任务 P、D 使用独立资源，因此不试 mixed prefill/decode。P 仍会把每请求的有效 token 展平，并用长度和前缀边界还原；D 的 MTP 验证也有自己的形状和边界。

## 成本在哪里

紧凑输入能避免一部分 padding，但长度/偏移准备及后端对齐仍有成本；不要把所有 padding 当成可直接删除。

## 这次考察的优化思路

同 worker 混 P/D 优化在本任务排除。保留一个适用性探针：量出 P packed 输入和 D verify 的实际/对齐 token，后续归入元数据与图形状点研究。

## 什么条件下可能适用

mixed 部分条件不适用；packed 部分须按实际 Ascend attention 与 verify 后端逐条核验。

## 新增成本与回退场景

强行改变 batch mode 会偏离 PD；删除对齐可能退出图或违反算子布局。

## 不能破坏的语义和生命周期

各请求边界、位置编码、mask 与 MTP 树关系保持正确；不把未接受草稿当输出。

## 最小实验

**基线**

读取 P/D 角色与每轮 forward_mode、有效 token 和实际输入形状。

**唯一改动因素**

不改代码；增加一次低开销形状记录，确认是否存在可归因的冗余。

**用例**

- P 输入长度差异大的 3 请求
- D 的 3 请求接受长度不同
- 请求结束后批次缩小

**预测**

专用 PD 不出现计划中的混 P/D 执行；packed 与 verify 对齐各有独立成本。

**指标**

- 实际/对齐 token
- metadata 时间
- forward_mode
- 图命中

**否定条件**

没有该模式就关闭混批实验；padding 是后端必需或无需等待则不能据数量推断收益。

**第一个可执行动作**

核对角色和调用路径，输出“混批不适用、packed 另查”的证据。

**最低执行层级**

适用性探针；不执行 mixed 配置实验

## 逼近物理极限的分析

**必要工作**

每请求有效 token 与 attention/verify 边界必需；专用 PD 角色不因优化而改变。

**资源与依赖边界**

packed 理想有效工作量按真实 token/验证树计；padding 的最小值受 NPU kernel 对齐和捕获形状约束，不能假设零。

**怎样校准可达上界**

在实际支持形状中测有效/总 token 与单算子时间，区分必需对齐和因图桶过粗造成的额外计算。

**怎样判断剩余空间**

将可删 padding 空间交 M021 图形状或 M017 元数据，不在本点强行 mixed；若后端支持更紧凑布局可独立建 loop。

**条件特化与回退**

按 P 输入长短差、verify 树宽、每请求接受长度、批次变化和图桶特化；混 P/D 区间在本任务排除。

**何时停止当前方向**

角色不适用的子题以路径证据关闭；packed 子题达到后端合法形状的有效工作下界或转交明确记录，不能误称整个机制无空间。
