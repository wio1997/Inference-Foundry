# M015｜CPU / 设备 overlap 调度

[任务目录](../README.md) · [执行合同](../CONTRACT.md)

- 教学课程：第 3 讲。
- 审阅状态：待路径核验。
- 类型：existing。
- 主线：PD 分离 + 推测解码保留；Ascend 实际配置待运行合同确认。
- 本文是用途、假设与最小实验设计，不是已取得加速的报告。

## 它干什么

CPU 在设备计算当前轮时准备下一轮，让两边尽量少互相等待；计算依赖仍必须遵守。

## 当前怎么做

D overlap 循环先提交当前 batch，再处理上一批 CPU 结果；遇到不支持组合有回退。推测解码接受结果通过实际同步/relay 路径交接。

## 成本在哪里

隐藏 CPU 工作但不消除它；队列、event 和额外在途状态也有成本。若 CPU 太慢或设备很短，仍留空洞。

## 这次考察的优化思路

先验证现有 overlap 是否真的隐藏了 CPU。只在当前 MTP 与后端支持的情况下做 overlap 开关对照，不以关闭推测解码换取可比性。

## 什么条件下可能适用

专用 D、实际 MTP 算法与后端明确允许这两种调度；不支持的组合改做单模式时间线。

## 新增成本与回退场景

非 overlap 会显著退化；混入 grammar 等功能可能触发回退，导致名义开关与实际模式不一致。

## 不能破坏的语义和生命周期

输出 token 合同、接受长度、EOS/取消与槽回收正确；记录每批真实 disable_overlap 状态。

## 最小实验

**基线**

保留 MTP，采样 CPU prepare、device start/end 和 result-ready 三组边界。

**唯一改动因素**

支持时只切 overlap；不支持则仅测现有模式的暴露时间，不强行构造基线。

**用例**

- 1 路低批次
- 3 路并发
- 频繁请求结束与接入；固定输出预算

**预测**

有效 overlap 将 CPU 准备覆盖在设备工作内；剩余提交空隙才是后续候选。

**指标**

- CPU 准备及暴露时间
- 设备空洞
- ITL
- 实际回退次数

**否定条件**

只看到两个线程同时忙不能证明收益；开关改变 MTP 或执行后端则对照无效。

**第一个可执行动作**

先跟踪 event_loop_overlap_disagg_decode 和实际回退原因。 源码明确不支持的 overlap＋spec＋grammar 等组合排除，不为对照关闭 MTP 或移除请求功能。

**最低执行层级**

模式核验 → 时间线 → 条件允许才 开关对照

## 逼近物理极限的分析

**必要工作**

上一轮必须产生下一轮实际输入与长度；部分 CPU 事务也必须在对应结果之后完成。

**资源与依赖边界**

理想稳态轮次间隔不小于 max(必要 CPU 服务,设备依赖链)，另加无法重叠的串行段；资源竞争会把实际下界抬高。

**怎样校准可达上界**

分别量固定批最短 CPU 准备与设备依赖链，再用时间线验证可重叠范围；不能把所有 CPU/设备总和或最大值直接当真实轮时。

**怎样判断剩余空间**

把实际间隔减去校准边界，逐段归因晚提交、event 等待、数据回传或资源竞争；首个开关对照只是验证模型。

**条件特化与回退**

按并发、context、MTP 接受长度/草稿配置、批次 churn、图命中和输入输出功能分区，记录实际 fallback。

**何时停止当前方向**

可解释空洞消失或只剩必要依赖，重复测量的剩余差距不支持进一步候选；仅报告指定场景接近可达流水效率。
