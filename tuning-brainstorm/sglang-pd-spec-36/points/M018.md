## 它干什么

pinned 主机缓冲便于异步搬运。异步的意思是 CPU 可以先走，不代表它已经把数据读完，因此源缓冲不能立刻被改写。

## 当前怎么做

P prepare_for_extend 生成 pinned 输入，H2D 延后到 forward 的 resolve。缓冲复用必须等消费者完成；NPU 是否使用这条路径要实际确认。

## 成本在哪里

反复分配/填充主机张量与 H2D 有成本；多缓冲占主机空间，event 与回收也要维护。

## 这次考察的优化思路

若实际每个 chunk 都新建 pinned token staging 且分配占显著时间，可研究按容量复用有完成标记的少量缓冲，避免每轮新分配。

## 什么条件下可能适用

只针对确定生命周期的 P token staging；不把 CUDA 私有流行为直接套在 Ascend，也不改 MTP 状态缓冲。

## 新增成本与回退场景

额外容量与同步管理；过小的环复用会写读竞态，过多的环只占内存。

## 不能破坏的语义和生命周期

H2D 完成之前源内容不变；取消、异常、尺寸增大时安全退出或扩容，不绕过现有 WAR barrier。

## 最小实验

**基线**

记录 pinned allocation、填充、H2D 与最终读完边界；排除 allocator 已有效缓存的情况。

**唯一改动因素**

只复用一种 token staging 缓冲，槽位凭完成事件回收；不足时回退原分配。

**用例**

- 连续等尺寸 chunks
- 尺寸交替与突然变长
- 人为延迟 copy 时取消并接入新请求

**预测**

分配次数下降且 copy 内容一致；只有被暴露的准备时间减少才有 E2E 价值。

**指标**

- pinned 分配次数/时间
- 主机峰值内存
- H2D 字节和等待
- 输入 checksum 与 TTFT

**否定条件**

旧数据污染或读写交叠立即失败；已有缓存消除分配成本则不新增缓冲池。

**第一个可执行动作**

先核验实际 NPU copy 完成语义并画出一块缓冲的生产/读取/复用时间。

**最低执行层级**

生命周期 → 延迟拷贝竞态 → P 分块

## 逼近物理极限的分析

**必要工作**

每个输入字节必须在设备消费前正确就绪；缓冲在最后读完前保持有效与内容稳定。

**资源与依赖边界**

输入搬运下界受实际 host-device 路径的有效带宽与启动成本限制；可隐藏量受依赖窗口限制，pinned 分配本身可通过安全复用减少。

**怎样校准可达上界**

对真实字节量和 NPU API 测独立 H2D 的稳定最好值，再测与计算/PD 通信同跑；区分分配、填充、拷贝和等待。

**怎样判断剩余空间**

缓冲复用之后继续检查多次中间复制、过大容量、散小拷贝和不必要等待；若内存带宽已饱和则减少字节比增加 stream 更有意义。

**条件特化与回退**

按 chunk 字节量、形状变化、可重叠窗口、NUMA 放置、并发与 MTP 后端压力分区；需要图固定地址时专门验证。

**何时停止当前方向**

主机准备无重复分配/复制，H2D 接近竞争条件下校准能力且未隐藏尾巴有依赖解释；不能用空载 PCIe/NPU 标称带宽宣布物理极限。
