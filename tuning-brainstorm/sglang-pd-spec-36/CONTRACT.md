## 每点固定交付

1. 用途：输入是什么，输出是什么，解决哪个问题。
2. 当前实现：步骤、关键数据、所有权、先后依赖和已有优化。
3. 成本：CPU、算子启动、HBM、互联、同步、队列、额外状态分别是谁付出。
4. 候选：具体改哪一步、减少哪项工作、增加什么成本。
5. 适用条件和反例：请求长度、并发、缓存状态、后端、并行、接受长度、布局和资源压力。
6. 最小实验：基线、唯一变量、Case、预测、指标、正确性保护和否定条件。
7. 结果：运行 commit、实际命令、环境/数据摘要、退出码、产物哈希、重复次数与噪声、局部与端到端结果。
8. 白话结论：为何有效/无效；只在什么条件下保留；下一步是否值得继续。
9. 上界地图：必要工作、资源下界、校准方式、剩余空间、条件特化和停止依据；未知数字写 UNKNOWN。

## 物理极限与剩余空间

本任务追求硬件约束下的最好可行实现，不能用“配置已经调过”“GPU看起来很忙”或一个局部加速作为终点。分别建立：低并发时延前沿、冻结延迟目标下的有效吞吐前沿、内存容量边界。三者可能需要不同实现，不能混成一个全局最优数字。

对每个 Case 把工作分成：语义必须完成的工作、可共享/可融合的工作、重复或无效的框架工作。计算必要 FLOPs/算子规模、HBM及主机必要字节、互联必要字节、真实串行依赖、最慢rank和尾块。先记录理论峰值上限，再在相同芯片、dtype、形状、布局、功耗/频率条件下测可达算力/带宽；两种上限不得混写。

可以用 `必要操作量 / 可达算力`、`必要字节 / 可达带宽` 形成带条件的资源时间估计。只有同一阶段且可充分重叠的资源项才可取 max；必须串行的阶段沿依赖路径累积。多rank按实际collective依赖与最慢rank分析，不能简单把所有kernel时间相加，也不能只算单rank均值。校准得到的是可达性能参照，不是已证明严格数学下界。

每个点报告理论/校准模型、假设、测量值、模型不确定性、估计可消除空间、profile证据和置信度。目标是把冗余、同步气泡、低效内核与负载不均逐项消掉；模型无法解释的差距优先作为下一次诊断Loop，而非硬凑到100%。

推测解码用一段实际运行中的“总草稿+验证+提交+搬运成本 / 总有效输出token”评价，并保存接受长度分布。不能把target单次更快或接受率更高直接当成最终更快。

允许按batch、context、实际未缓存长度、稀疏度、专家分布、MTP接受长度、拓扑选择不同实现。条件特化必须有可观测触发条件、正确回退、阈值维护和切换成本测量；离线知道正确答案的oracle选择只能作为上界参考，不能当线上结果。

一个机制被改进后重新评估瓶颈迁移。停止该方向的依据是：剩余可行空间低于模型/测量不确定性；额外维护或切换成本抵消收益；高价值候选已被逐项验证/排除；或瓶颈已转移到另一个机制。报告“当前证据下最佳/达到所建模型附近”，不得声称有限实验已证明所有条件的绝对物理最优。

## 证据与实验阶梯

- E0：规格、真实调用路径和支持性探针。先证明“当前配置会走这里”。
- E1：正确、可重复运行，但没有稳定基线。先建立基线与自然波动。
- E2：已有同条件基线，机制不明。做最小 trace / 计数诊断。
- E3：真实证据支持机制。仅实现并比较一个候选。
- E4：已有接受/否定的证据，再讨论跨 Case 迁移与组合。

每一项从能回答问题的最低成本层开始：静态调用/支持性 → CPU 或字节/索引等价测试 → 局部 NPU probe → 短服务对照 → 必要的正式 benchmark。失败点保留原始错误与资源回收证据，不能不断叠参数尝试掩盖。

局部测试先验证语义与生命周期；真实服务测试同时确认成功率、输出语义、EOS、取消、重试、引用/页回收。对数值路径不保证 bitwise 时，事先冻结适合该改动的精度/质量界限；不能看一两个回答相同就宣布正确。

同一个 Case、同一 MTP/并行/模型合同下，先 A/A 重复估计波动，再 A/B 交错重复。默认至少三组配对作为起点，若波动遮住差异则记录 INCONCLUSIVE 并按剩余信息价值决定补测；不要用固定百分比替代统计与业务目标。单次改动后不得顺手叠其他候选。

指标拆开报告：局部 CPU / device 时间、启动次数、暴露空隙、HBM/通信字节、P/D 容量积分、TTFT、ITL/TPOT、端到端有效输出吞吐、各长度组 p50/p95/p99、接受长度和重试。主机 wall-time 可能包含等待；异步搬运的数据量与计时窗口须一致；不同机器单调时钟不能直接相减。

## 状态与完成条件

点位状态：`PLANNED` → `PATH_CONFIRMED` → `BASELINE_READY` → `TESTING` → `ACCEPTED / REJECTED / INCONCLUSIVE / NOT_APPLICABLE / BLOCKED`。阻塞必须写具体缺失资源和可继续的独立工作。

- ACCEPTED：正确性/回归通过、同条件收益超过噪声、适用边界明确，主控审查后保留。
- REJECTED：正确性失败或收益不成立；撤回候选，保留反证。
- INCONCLUSIVE：已有实验但无法区分收益，不能包装成通过。
- NOT_APPLICABLE：用源码/配置/最小支持性探针证明此场景不走该路径或不支持。
- BLOCKED：具体外部条件缺失，分析与探针已尽可能推进；不等于实验完成。

36 点都有教学解释、独立最小实验、真实结果或有证据的不适用结论，剩余阻塞明确可追踪，才可声称覆盖完成。仅写完 36 个实验计划不等于测完。Task 控制工具使用 accepted/rejected/inconclusive/pivoted；点位 NOT_APPLICABLE 映射为带不适用证据的 rejected 或 pivoted，不能伪造性能 Run。
