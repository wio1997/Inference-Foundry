# 怎样避免重复无效工作

## 一次形成、按变化失效

|层|保存什么|下次怎样复用|何时重做|
|---|---|---|---|
|语义合同|数值/舍入/RNG/错误、全部消费者、alias/state/通信规则|直接查证据和条件，不重读同一源码|相关实现、输入域或接口合同变了|
|静态图与条件|qualifiedsymbol、函数/依赖哈希、分支效应、模型角色|沿用未变子图，只复扫变化邻域|source/config/backend或依赖变化|
|运行映射|当前cohort的stack/connection/task/row/owner/flags|沿用映射方法，重新绑定新ID和时段|每份新profile都重新绑定|
|统计与代价|次数、shape、时间、活动率、匹配工作量|复用计算器和单位定义，仅换输入|新case/profile/shape/并行/硬件参数|
|候选与反例|原图footprint、变换、数值/状态域、失败条件|同义方案返回原编号，不另起一轮|有新的变换或原反例不再适用|
|待证问题|claim、缺证据、影响哪种结论、状态|相同问题/相同输入沿用答案|新证据或需要升级的结论出现|

## 查询键和判重

候选键 = 语义原子/输入输出关系 + 变换类型 + 数值域 + 所有权/状态协议。不要用标题、函数行号或两个kernel名字作为唯一键。

证据键 = 模型/sourcecommit与dirty指纹 + 相关配置/量化/后端 + shape/dtype/数值域 + graph/并行/owner + 度量口径。涉及内容复用时再加入参数/输入/请求/状态代际。一次确认的源合同，不因对话恢复而失效；一次运行的pointer/taskId/flag/耗时，不因源合同未变就变成新观测。

保留完整archive，但默认恢复包只放：当前摘要、候选/问题索引、相关事实和最后一次决策。不要每轮通读或全量rehash一万份历史。Git blob/commit和已验证来源可复用；仅对改变的输入和受影响证据重算hash/校验。下载或发布归档时才运行全量完整性检查。

## 三个实际例子

1. **F21已经融合**：同路径不再问“能否把dispatch/GMM/激活/combine首次融合”。下一问题只能是有新依据的内部流水/资源/协议变化。
2. **DSpark三路KV**：输入相同不等于结果相同，这个约束按参数归属缓存。新profile只更新shape、耗时和读写映射，不重复证明三套权重关系。
3. **batch更新顺序**：三gather先于computed写，acceptedELSE后读，固定成有条件合同。只有状态plane/函数顺序/允许alias域变了才重开；未知alias不扩散成全模型所有私有字段的取证任务。

## 未决项也要缓存

UNKNOWN、CONDITIONAL、UNSUPPORTED、RULED_OUT都是有价值结果。记录适用范围和缺哪条证据。相同输入下重复读代码/跑同一探针不会提高证据等级。

同一问题连续没有新增信息时，停止该重复动作，换来源或保留明确缺口；不能伪装成仍在推进，也不能因此把未分析范围标完成。未来实施需要的数值/性能验证与当前分析归档分开。

## 每轮开始前的五个检查

1. 当前真正要改变的决策是什么？
2. knowledge/旧候选/旧反例是否已经回答？
3. 这次输入或假设哪里变了？只会让哪些证据失效？
4. 本次最小读取/探针能产生哪种新信息？得不到时何时停止？
5. 本轮结束新增了什么结论？若只是计数、换标题或重写相同报告，就不启动这一轮。
