# Warmup graph capture candidate, gated replay

`selective_recorder_next_graphgate.c` is a separate CPU-tested draft. The existing running service, capture and logs have not been changed. It extends the earlier gated draft by observing the program's existing same-thread nested `aclmdlRICaptureGetInfo` during an already recognized candidate launch even when PROFILE_ACTIVE is absent. The observed modelRI is retained in a bounded in-process set, with no warmup capture event output. If an observed `aclmdlRIExecuteAsync` uses that modelRI while PROFILE_ACTIVE is present, a candidate replay record is emitted. Duplicate modelRI observations are deduplicated; eviction of an occupied slot marks `graph_evicted` and sticky `state_incomplete`. `aclmdlRIDestroy` removes observed handles.

The relation is `candidate_model_only`, not a graph-to-task or graph-to-kernel proof. It relies on the existing runtime actually calling the intercepted capture API inside the same thread and nested within an already recognized launch wrapper. Hidden/static/different APIs, cross-thread capture, handle reuse, unobserved graph destroy or out-of-process execution can produce missing or misleading associations. The memory cache is not persistent between worker processes. Window checks, API hooking and hashing can perturb execution. Lost events, capacity eviction, `gate_unknown`, an absent final statistics record or a missing replay event cannot establish absence of the target. Launch/mutation overlap detection remains conditional on intercepted intervals and does not prove handle lifetime or runtime-loaded bytes.

CPU-only mock inside the user's stage container: `next-selective-revision7/next-selective-tests/gate.k7b4tk`. Warmup capture followed by active-window-only replay produced a candidate; 12,000 repeated captures of the same modelRI did not evict it; limiting the cache to two slots and generating three distinct modelRIs raised `graph_evicted=1` and `state_incomplete=true`. Window gating, missing-gate handling and launch/unload overlap tests also passed. These tests do not validate NPU runtime behavior or the real vLLM code path. No service was started or injected.
