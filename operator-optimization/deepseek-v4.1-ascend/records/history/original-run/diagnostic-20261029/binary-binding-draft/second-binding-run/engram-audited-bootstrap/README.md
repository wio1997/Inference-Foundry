# Engram metadata bootstrap — CPU-reviewed draft

This is an independent, opt-in diagnostic draft. It has not been installed into a running inference worker and no NPU run has been performed. Do not use without reviewing the separate container isolation, ownership, recovery, and workload adapter.

Files: `sitecustomize.py`, `engram_bootstrap.py`, `audited_observer.py`, and the offline `audit_window.py`. Put these in one dedicated directory and put that directory on the diagnostic worker's Python import path before interpreter startup. Do not combine it with the earlier high-overhead profile sitecustomize. The hook does not itself import the target model; it intercepts natural import of the exact verified installed source and class. It refuses a source hash, origin, method signature, or canonical code-object mismatch. A missing installation status is UNKNOWN, never evidence that the class was unused. Bootstrap/source injection and the supplied PID/rank manifest need independent verification by the controller.

Set only in the dedicated isolated workers: `WIO_ENGRAM_META_ENABLE=1`; `WIO_ENGRAM_RUN_ID=<32 lowercase hex>`; `WIO_DIAG_DIR=<absolute dedicated directory>`; `WIO_ENGRAM_META_PATH=<WIO_DIAG_DIR>/engram-metadata.jsonl`. These are absent by default. One observation window is supported: write `PROFILE_ACTIVE` as a bounded JSON file with matching `run_id` and a 32-lowercase-hex `window_id`; remove it after the frozen workload has completed. The controller must separately establish expected workers and wait for each worker's close checkpoint; missing, abnormal, stale, mismatched or incomplete checkpoints mean UNKNOWN. Closing gate/checkpoint is a conditional snapshot, not an absolute barrier against threads stalled before entry. Rank environment and controller PID/rank map are unverified by the observer. An inherited fork without reverified installation is UNKNOWN.

The observer writes a shared 1 MiB capped JSONL, at most 64 per-process status files each capped at 4096 bytes, plus an advisory lock and transient status replacement file. Nonblocking contention, limit reached, metadata failures, malformed gate, unknown initialization, unmatched pairs, and other observed losses taint the result. Statistics are lower bounds under concurrent drops. `audit_window.py <directory> <manifest.json>` checks one externally supplied `run_id`, `window_id`, and list of `{pid, rank}`. `NO_LOSS_DETECTED_CONDITIONAL_SNAPSHOT` only means the available checkpoint and record pairs matched at the instant read; it is not proof of complete calls, accurate rank identity, no perturbation, or absence of events after that instant. Zero matched events or a missing log is not proof no invocation occurred.

Only Python calls observed by the wrapper can be recorded: NPU graph replay without Python execution is invisible, as are native/internal operations. `storage_wrapper_instance` is an anonymous weak Python wrapper token, not a physical-storage alias or lifetime proof. No tensor elements, physical addresses, prompt or generated text are intentionally collected. Measurement does add metadata calls, file writes, a per-worker polling thread and lock contention; overhead and production throughput impact are not established. Capture alone cannot prove async tensor lifetime or device timeline causality.

ZCode CPU test: `stage-cpu-v4-result.json` and `zcode-cpu-v4-verified.json`; model was deepseek-flash. All five tests passed, including injected observer initialization and post-patch startup failures with method rollback and invalid path rejection; PYTHONOPTIMIZE is removed for tests and optimized execution rejected. The tests include, including genuine torch CPU slices with `[13,24]` shape, `[48,1]` stride and offsets 0/24, with `torch_npu` absent. Earlier v2 results are retained: the exit cleanup race was corrected before v3 by stopping/joining the watcher. These are unit-level tests, not model/NPU/throughput validation.

Directory policy: the isolated metadata directory must be a real path without symlink components, owned by the worker effective UID and mode 0700; any existing event log and lock must be regular single-link files, owned by that UID, mode at most 0600. Parent-path validation is not protection against hostile concurrent parent renames; the containing tree must remain exclusively operator-controlled throughout capture. Failure during installation restores the original method if it is still the wrapper installed by this attempt. An independent concurrent method replacement cannot safely be overwritten and is an UNKNOWN condition.
