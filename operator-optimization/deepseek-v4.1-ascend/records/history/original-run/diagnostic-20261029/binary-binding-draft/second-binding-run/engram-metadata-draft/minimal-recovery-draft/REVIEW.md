# 最小恢复链草稿：待独立审查，所有入口禁用

此目录是独立副本，不修改旧脚本或生产环境。为审查准备，未在 169 执行，不启停容器、服务或 NPU。

控制器启动独立监督器，监督器写入原停放脚本要求的 lease 并持续核验控制器 PID/出生身份；控制器消失、身份不可证或总时限到达时开始恢复。不读取心跳文件、不发送本机进程信号；控制器正常结束也通过同一恢复程序收尾。恢复重试使用原共享 `owner-fence.lock`，先在持锁时为唯一 run 写入不可逆撤销标记，再检查本次容器确切 ID、标签与历史身份、停止自己容器、依据原经验 HBM/进程释放检查恢复 baseline，HTTP health 200 才可报告健康。

启动、负载 CAPTURE、常规 RESTORE 三个会改变容器或任务状态的远程块，均在获取同一 fence 后检查撤销标记；持锁期间无法与撤销并发，其原 `ensure_owner_fence` 检查继续有效。健康 STATUS 和 SUMMARY 为只读；不能因为读到健康就跳过 CAPTURE 内再次持锁和撤销检查。已在途且持锁的旧操作先完成或因锁持有者失效而失败，撤销等待取得锁后持久化；在此之前恢复尚未开始，因此不能声称已恢复。撤销后后来的写路径都拒绝，防止原控制器或其孤儿子进程之后再次停基线。本方案未通过实际 SSH/容器故障试验；需要独立审阅所有远程写路径和锁语义后方能考虑启用。

本机 CPU 模拟覆盖：已有写操作与撤销按同一 flock 串行；撤销后新的写入被拒绝；脚本结构中三个远程写块及恢复撤销位于同一持锁区；监督器不发送信号且不读取心跳。只验证模型和结构，不证明远端 Docker/SSH 进程生存期、权限、NPU 或锁可靠性。

限制：Mac 断电/离线时控制器和监督器均不可用，无法保证自动恢复；stage、SSH 或 fence 故障也会推迟恢复。若 HBM/设备归属无法确认或其他人已占卡，仍只等待，不停止他人任务。共同锁只约束参与协议的代码，无法阻止外部用户在检查后占卡；仍有锁 holder 失效与后续操作之间、外部占用变化等现实竞态。总时限 7500 秒为草稿配置，不能推导性能，也不能代替实际负载完成情况。缺少身份记录、标记写入失败或资源归属不明会阻止安全恢复，不能报告健康。

`build.py` 从当前硬化并禁用的 adapter 生成副本；bootstrap 清单仍 PENDING。仅解析 `STATUS/SUMMARY` 中当前代码为只读，若日后改代码必须重新审计。`controller.py`、`watchdog.py` 及生成的三份 adapter 均硬禁用。请审阅具体源文件，不应仅凭本说明启用。

## 已发送 Docker 操作与恢复后的持续观察

现有锁是 stage 的单独 holder，Docker 命令由另一进程发出：holder 失效释放锁后，已提交给 Docker daemon 的 stop/start 不一定取消。`docker stop --time 45` 的 45 秒是停止信号后的等待时间，并非整个请求的端到端上界：[Docker 官方 stop 文档](https://docs.docker.com/reference/cli/docker/container/stop)。因此，撤销标记和 flock 只能约束仍遵守协议的后续写入，不能保证锁丢失前已经发送的请求不会迟到。

按用户授权，草稿监督器在完成一次带 fence 的幂等恢复后，不因控制器写了 done 就立即退出：对同一 baseline 精确 ID 做 5 分钟健康观察，若再次发现已停止，则重新运行原有恢复检查（精确 ID、仅停止本 run 容器、他人 PID 不动、经验 HBM 和健康检查）。运行中健康未就绪只观察，不能因健康检查失败就对服务发停止/重启。若设备已被他人占用则恢复检查暂缓。5 分钟是有限监控策略，不证明之后绝不会出现迟到操作；Mac/监督器离线也不具备该监控能力。该代码仍为禁用草稿，尚未经过远端故障注入或独立审查。当前只增加周期检查的源码和 CPU 编译/结构测试，**并未实现 pending 操作日志**；日志未来只可作为 UNKNOWN 排查线索，不得根据等待或 timeout 宣称后台操作必然终结。

补充 CPU 行为模拟：对真实监督循环 AST 使用假的 inspect、恢复和时间序列，验证首次恢复在健康观察之前执行，基线先健康再停止时调用第二次恢复，之后完成有限观察；累计 4 项 CPU 检查通过。模拟不证明远端进程或 Docker 请求完成。
