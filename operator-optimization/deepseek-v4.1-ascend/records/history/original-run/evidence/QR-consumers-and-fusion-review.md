# Q归一化、量化与双消费者：具体边界复核

本条只分析结构和允许消除的中间流量，不实现内核，不声称提速。来源：`attention/dsa_v41.py:320,367,375,394-431,567-611`，`models/deepseek_v41/indexer.py:165-179`，`attention/context_parallel/dsa_v41_cp.py:196-207`，本任务冻结config。

## 当前真实路径

主Q路径为 `Wq_a → q_norm → Wq_b动态INT8量化 → Wq_b GEMM → RoPE`。Wq_a和q_norm的输出遵循既有BF16契约，不能把FP32归一化值直接交给量化并声称等价。

`qr=q_norm(...)` 在 index source 层还供给 indexer 的 `project_query(qr)`；它是实质的第二个数值消费者。CP的非source分支还使用`qr.shape[0]`，这是元数据消费者，不意味着必须读qr的全部数值。

40个target层中，index source IDs为2、8、14、20、24、28、32、36，共8个。其余32层不执行本层indexer query projection；它们可以复用先前source的索引。这个结论仅针对已保存的target配置，不推广到其他模型/分支。

## 具体流量机会

令本rank查询行数为M，qr宽度1280，BF16中间大小为2560M字节。以下是**有条件的可移除流量**，不是必要HBM流量下界，也没有假设原实现真的从HBM读写这些字节。

| 边界 | 独立qr数值消费者 | 可能省掉的qr物化流量 | 必须保留 |
|---|---|---|---|
| 只融合norm+quant，source层indexer仍独立 | quant和indexer | 可以避免quant一侧2560M字节读取；qr写出仍可能需要 | 给indexer的BF16 qr、主路径INT8值和scale |
| norm+quant，非source层无其他qr数值用户 | quant | 在允许改变内部边界的域内，最多省掉qr的一写一读，即5120M字节 | qr逻辑shape、已有舍入和量化语义 |
| norm同时接入主Q和indexer两条投影 | 两条消费路径都进入候选子图 | 允许更大范围内消掉qr物化，但需联合考虑多N tile、liveness、共享与重算 | 两条分支输出、全部量化scale、独立的RoPE/缓存依赖 |

若再将量化与GEMM接合，INT8激活及scale也可能少一次写/读。但多个GEMM的N tile需要复用相同激活；不能在没有容量/布局证据时直接宣布中间张量永不落地。当前Q/KV交错执行和indexer query量化已使用异步流，扩大融合也可能损失重叠。

## 数值约束

归一化、BF16舍入、量化scale归约和取整必须按现有语义保留。不能只用代数约分取消RMS因子，因为中间BF16舍入一般不与乘法、最大值归约及量化取整交换。量化scale依赖整条约定行范围；分块实现必须先满足其真实归约依赖。未知舍入模式和scale布局继续查实际实现，不用一个自选round函数代替。

## 对理想model的影响

允许融合的理想model从开始就可以放宽这些中间物化开销为零。发现此机会不能把它重新加成“不可避免成本”，也不证明当前耗时能下降对应比例。独立算子冷权重模型与这个双消费者融合域须分别保留，不能把二者下界直接求和。

结论：F05存在明确的source/consumer差异；“把norm和quant合并就能全部消除qr”这一笼统说法不成立。是否有性能收益仍未知。

## 双消费者共享信息：联合输出不能按两份独立输入相加（2026-10-30）

上文的两个消费者来自冻结源码中的条件路径：index source 层的 `qr=q_norm(...)` 同时供主 Q 路径与 indexer query 投影使用；非 source 层的 shape 用户不是第二个数值读取。配置中的 8 个 index source 是静态模型角色，不能证明历史每次设备调用采用该分支、两个任务读取同一 storage 或都具有相同的有效行。输入记录和源码边界见上文，模型配置 `evidence/model-config.json` 的 SHA-256 为 `43d3b2bc55626893d59275b32e04068c0fc916f5c382eb91de73bdbade9c88f7`。

以 `M=3`、宽 1280、BF16 为形状算术，一份未压缩 qr 为 `3×1280×2=7680 B`，两次各自完整读取为 `15360 B`。若某候选确实把一份 qr 跨指定边界读出并让两支共享，便不能因为两个消费者而把同一份读取算成两次；若结果已在目的侧、可直接由生产者消费，或被正确重算/融合，额外跨该边界量也可能为零。相反，能否实际共享取决于张量身份、数值语义、片上空间、并发和生命周期；这不是声明历史实现真实只读一次，或 7680 B 一定必须跨 HBM。不能因有 8 个 source 层就无条件将任意必要流量乘 8：各层输入、权重、共享和缓存状态是否具有独立信息，尚需证明。

### 联合函数像及通信记录条件

固定一次实现域内的接收侧初态 `σ`、固定权重和所有其他相关状态；令 `X_σ` 是与此初态相容的**有限**输入族，接收侧最终必须按指定精度观察两路输出 `(f(x),g(x))`。令

`K_f=|{f(x):x∈X_σ}|`，`K_g=|{g(x):x∈X_σ}|`，`K=|{(f(x),g(x)):x∈X_σ}|`。

由于同一个 x 同时决定两路，`max(K_f,K_g)≤K≤min(K_f K_g,|X_σ|)`；不能把 `K_f K_g` 直接当 K，除非独立组合的可达性已证明。假设所有可将 x 的相关信息带给接收侧的路径均包含在同一 cut 中，固定初态不含相关副本或摘要，窗口前已交付的数据不得再算窗内工作；每种输入都要正确得到这对输出，且分帧、长度、终止、交互、时间或静默信号均纳入完整有限离散 transcript，不存在免费旁路。不同的输出对必须对应不同 transcript。

- 对任意变长有限二进制 transcript，若所有输入的记录长度均小于 `floor(log₂ K)`，可用字符串不足 K 种。因此在 `K≥1` 时，至少存在一个输入需要不少于 `floor(log₂ K)` bit；`K=1` 时下界为 0。这是最坏输入界，不是每个输入或平均值。
- 若对所有输入强制发送同一固定长度 `L`，则 `2^L≥K`，故每次发送均为 `L≥ceil(log₂ K)` bit。若要求无免费侧信道的可即时解码前缀码，其最坏长度也至少 `ceil(log₂ K)`；平均长度另依输入分布与编码规则判断。
- 如果只统计 payload、但免费使用无限精度的到达时间、任意分帧次数或长度信号区分输入，以上完整 transcript 界不能直接称为 payload 字节下界。可变长度通信及随机协议都不得据此假定某个固定输入在每次运行中均达到最坏长度。

若另行证明此同一 cut 的短窗口累计 transcript 容量 `I(t)≤β+B t`，`B>0` 且 β 覆盖该计数口径的在途/突发信用，且最坏输入的上述输出必须在该窗交付，则 `T≥max(0,floor(log₂ K)−β)/B`。其它计算、通信和分块可重叠；若同时对同一窗口与实现域证实其他独立下界，只能依据资源及依赖关系组合，不能重复把同一份信息作为两份必需传输。真实 `X_σ`、f/g 的可观察契约、K、β、B 和历史任务绑定均未知，因此该式不生成 169 的数值 TPS 界。

### 可以复算的共享与独立反例

一位动态输入 `b∈{0,1}`，令两路 `f(b)=b, g(b)=b`，则 `K_f=K_g=K=2`；按完整固定长度记录只需 1 bit，而把两个单路界相加会误得 2 bit。另一接口的输入为 `(a,b)∈{0,1}²`，令 `f(a,b)=a, g(a,b)=b`，则 `K=4`，固定长度最坏需 2 bit。两种结构都有两个消费者，但联合信息量不同；这个抽象例子不是断言真实 qr 的两支是恒等函数或互相独立。

本地纯 CPU 复算，不读取 tensor 值或访问设备：

```sh
python3 - <<'PY'
from itertools import product
m, width = 3, 1280
print('one_qr_bytes', m*width*2, 'two_raw_reads_bytes', 2*m*width*2)
x1 = [(b,) for b in (0,1)]
x2 = list(product((0,1), repeat=2))
for name, xs, f, g in [
    ('shared', x1, lambda x:x[0], lambda x:x[0]),
    ('independent', x2, lambda x:x[0], lambda x:x[1]),
]:
    print(name, len({f(x) for x in xs}), len({g(x) for x in xs}), len({(f(x),g(x)) for x in xs}))
PY
```

输出依次为 `one_qr_bytes 7680 two_raw_reads_bytes 15360`、`shared 2 2 2`、`independent 2 2 4`。本次未新增 NPU 负载或修改目标实现。
