# 第一版算子理想上界（未填造硬件速率）

状态：SYMBOLIC_CEILING；基线为169实测519.8441 token/s。

## 已核对事实

- 实际板卡名称9382；对应SDK平台配置24 Cube、48 Vector、cube_freq=1800。该配置值暂不视为物理最大频率保证。
- Q投影实际INT8权重为[32768,1280]，共41,943,040字节（40MiB）。当前enable_dsa_cp=true时源码使用ReplicatedLinear，不能把N直接除以TP8；查询行按CP分配，实际M待采集。
- 一个专家的三块INT8权重为[2304,5120]、[2304,5120]、[5120,2304]；常规稠密计算每行35,389,440 MAC。每层路由top-k=6，共享专家1个。

## 第一条独立算子上界

在上述标准稠密算法域内，Q投影处理M个查询位置：

    必要计算 = 41943040 M MAC
    L0 = 41943040 M / P8
    U0 = M/L0 = P8/41943040 查询行/秒

P8是相应资源集合的有效硬件容量上限，尚未有足够依据填数。MMAD.s8存在和SDK的MKN粒度都不足以独自证明每周期吞吐。

冷权重、A已为INT8且输入/输出位于HBM的独立边界下（省略scale等流量以保持乐观）：

    必要HBM字节 >= 41943040 + 66816 M
    L1 = max(41943040 M/P8, (41943040+66816M)/B_HBM)
    U1 = M/L1 <= U0

若权重可以已驻留缓存，不能继续添加这40MiB的HBM必读量；若允许融合，也必须重新定义输入输出边界，不能照搬独立算子流量。

## 框架级最初两层（只保留选定INT8乘加）

在声明的标准目标前向验证域内，prefill至少处理26240个未命中位置；再加入每请求至少1023个已生成位置的目标计算，共至少34424个主干位置。

    每个主干位置选定INT8工作 = 11586764800 MAC
    C0: T >= 304036708352000/P8_all_devices
    C1: T >= 398862791475200/P8_all_devices
    输出吞吐 <= 8192 / T_lower

这里只统计Q投影、六个路由专家和一个共享专家的常规乘加，其他计算/访存/通信/调度均明确松弛。它允许达不到；也不声称覆盖所有可能推理算法。数值参数未知时只保留公式。

## 已登记的分析候选

1. 当前CP路径的低查询行数与完整Q权重复制：需要实际M、GEMV/tiling和设备耗时验证，尚不能称最大瓶颈。
2. Q侧归一化→动态量化→INT8投影的中间张量：融合候选；必须保留数值与舍入语义，尚未证明可消除。
3. 已融合的MoE MC2：通信、计算、等待共处一个算子，不能按名称将整个耗时归给GEMM或网络。
4. Engram等待与小算子/元数据：只在关键路径暴露时计入当前差距，不能把可隐藏成本强加进理论极限。
