# 理想上界模型与本次适用域

本模型的验收是界的方向、前提和证据可复核；不要求找到可达排程、改代码或跑出提速。没有使用形式化证明器。

## 从理想松弛开始

固定硬件资源集合 H、模型数值语义 M、工作负载 W、有效输出 Q 和允许实现域 D。初始模型允许理想融合、重排、共享、分块流水及不同资源的重叠；先去掉 Python/launch/通知成本、可避免的中间物化和当前实现选定的屏障。这样允许的执行集合只会扩大，不会把真实合法实现排除。

对每种资源 r，只在证明同一计时窗口和允许实现域中，至少有 `F_r,min` 个相同计量口径的工作单位需要在窗口内完成，且所选资源的全部可用路径对任意窗口前缀满足硬包络 `W_r(t) ≤ β_r + P_r,max t` 时，才能加入 `T ≥ max(0, F_r,min−β_r)/P_r,max`。这里 `β_r` 是按同一工作单位计量、包络允许的初始突发或在途信用，`P_r,max>0`；已被快侧初态消除的工作不能再重复计入 `F_r,min`。只有额外证明 `β_r=0` 的短窗包络时，才可以简写成 `F_r,min/P_r,max`。因此

`L = max((F8_min−β8)_+/P8_max, (F16_min−β16)_+/P16_max, (Fvec_min−βvec)_+/Pvec_max, (D_HBM_min−β_HBM)_+/B_HBM_max, (D_L2_min−β_L2)_+/B_L2_max, (D_link_min−β_link)_+/B_link_max, L_causal_min)`

其中 `x_+=max(0,x)`；对在相同窗口交付的固定有效输出 `Q`，仅当 `L>0` 时有 `TPS ≤ Q/L`。各项的必要量、信用和硬容量须分别证明；未知量保持 UNKNOWN，不能赋值为零。若 `L=0`，该公式不给出有限吞吐上界。

新增有证明约束使 L 不减、U 不增。同一资源上的必要工作可累计，但必须先证明共享同一个容量池且没有重复计数；不同资源的总时长不能默认相加。短路径可与其他路径重叠，通信的当前暴露时间不能直接变成不可避免时间。

## 分块、依赖和容量

数据按允许的最小粒度生产/消费；一条依赖边只约束实际需要的值或子块。当前 kernel 的整阶段 SyncAll、tile 大小、expert 顺序、通知粒度不自动约束所有合法实现。若引入依赖链下界，必须证明边存在且给出适用的最短延迟上限/下限来源，不能把某个可行排程的时间倒数成吞吐上界。

行量化需要约定归约域的 scale；归一化、BF16 舍入及量化取整不能凭代数约分消掉。但这些数值依赖不自动证明整块投影或所有 rank 必须等到整个算子完成，允许部分归约、准备工作和分块流水的域仍须覆盖。

共享输入及多个消费者必须完整保留。Q 归一化后的 qr 在 8 个 index source 层有第二个数值消费者；32 个非 source 层的 shape 消费不要求读取所有 qr 数值。详见 QR-consumers-and-fusion-review.md。候选流量是可能省掉的流量，不是必要 HBM 字节。

## 本次可复算的条件数值界

Wq_b 独立算子域：一般稠密输入，所有 M 行输出均需计算，固定当前常规 dense GEMM 算法族，所有所计 MAC 必须由声明的 INT8 Cube 容量池执行，必要 MAC 为 `M*1280*32768`。不是允许快速矩阵算法、稀疏、答案缓存或忽略 padding 输出时的无条件算法下界。对应实测来自相同独立 kernel 边界；target/draft 标签不改变该张量级计数，不能将其每行吞吐直接当返回 token/s。

官方 msprof-analyze 的标称 INT8 公式为 `16*32*16*2 OPS/周期/核`。16 个采样设备均记录 24 AICore、1800 MHz，故标称值为每逻辑设备 707.7888 TOPS、353.8944 TMAC/s。

这只是 **CONDITIONAL_CEILING**：该标称公式适用于本机 9382、执行域频率不超过 1800 MHz、计算池对计时窗口内所有前缀的严格容量不超过该公式且对应初始信用为零，都是显式前提。profiler 元数据记载 1800 MHz；尚未证明该字段是运行时实时频率，也不证明它是物理最高频率；官方 MFU 分母也不自动构成独立硬件证明。快照、commit 和 SHA 见 conditional-nominal-capacity.json。没有独立证明本机不可超越的物理数值上界。

端到端 C8 的选定 target INT8 必要工作：未缓存 prefill 26240 个位置，加每个请求除最后输出外的 target 输入位置 `8*1023`，共 34424 个位置。每位置选取 40 层的 Q_b、6 路专家和 1 共享专家，MAC 为

`40 * (1280*32768 + (6+1)*3*5120*2304) = 11586764800`。

总计 `398862791475200 MAC`。此约束域要求标准 dense target 验证、全部计数 MAC 在窗口内由声明的 INT8 Cube 池执行，且每个请求、每个未命中位置及生成位置都独立计算，不允许额外跨请求/位置结果复用、记忆或等价计算绕过。当前缓存命中计数只说明当前实现口径，不能证明宽松共享域需要这么多不同计算；观测基线是否严格属于该窄域也未全部核实。理想模型忽略额外复制、draft/rejected 工作、BF16/FP32、attention、访存、通信及调度。因此用全部 16 设备标称 INT8 容量得到的 116294.745 token/s 只是这个窄域、上述物理容量及**零初始信用**假设下很松的条件计算上界；对于允许共享及不同计算资源共同执行的宽域，没有得到数值上界，也不是预计能达到的整机极限。519.844 token/s 的实际基线与它的差距不证明存在相应可消除开销或提速空间。

历史文件 `fixed-output-conditional-bound.json` 及一次性生成器 `../tools/summarize_output_bound.py` 保留原始证据，其 `D/B` 和 `8192B/D` 必须另证零初始信用才成立，不是普遍公式；不要将旧生成器的输出直接作为当前界。历史集成脚本 `../tools/integrate_g4_clock_bound.py`、`../tools/integrate_diagnosis.py` 也包含旧式，重新生成时须改写推导而不能覆盖当前结果。当前完整推导及接口条件见 `../agents/bounds/baseline-client-count-provisional.md`、`../agents/bounds/actual_causal_bound.md`。旧 JSON 的文本长度与原始 SHA 保持不变，本次仅更正活跃模型解释。

`../bounds/*.input.json` 与 `../calculations/` 的既有 `work_lower/rate_upper` 条件数值沿用零信用算法，保留作为历史算术结果；其中的资源工作/速率式及相关实测比值不构成一般公式，也未证明本机零信用。要得到一般数值界，需要新证实各项窗口信用并用上面的形式重新计算；原始算术文件不因报告修订而被静默覆盖。

## 不能编造的收紧项

- Wq_b INT8 权重为 40 MiB，单设备 L2 的 SDK 容量为 192 MiB；只凭大小不能强制每次从 HBM 读入全部权重。初态、层间复用、其他占用和新实现分块需另证。冷的独立算子可以另设初态，但不能混入暖的整模型比较。
- checkpoint 大小、当前 workspace、实际 trace 流量都不是融合域的普适 I/O 下界。HBM/L2/互连的适用硬容量上限仍未知，不用测得峰值替代上限。
- 每模块的有效 unpadded 路由/专家计数尚未恢复；3 行物理输入不等于 3 个有效输出 token。40 层及 MC2 的更细数值界暂留符号。
- 更正（2026-10-29）：MC2 源码存在数据就绪与同步机制，但现有采样没有证明跨设备时钟误差界及同次 collective 身份，不能据跨卡开始时间差断言到达不齐或等待；低 PMU 比例也不能证明原因或收紧通用理想上界。

计算器只检查精确分数算术，不检查必要性、硬件容量、单位或语义。bounds/ 保存各对象输入，calculations/ 保存原始输出；未知项为 null，不能解释为已证明零成本。


## 客户端输出界的条件收紧

若固定两轮每条结果的非空文本、1024 output_tokens、已核验客户端 JSON 解析和计时窗，且不允许在该客户端接口旁路交付，既有输出文本界可加入必须传递的 usage 字段，得到每轮最少 33108 / 33504 字节，而非此前仅文本+choices 骨架的 32828 / 33224 字节。仅当同一接口的 `B_out,max`、`β_out` 包络已被证明时才带入 `(D−β)_+/B`；并与其他已证界取最大值。这是接口条件界，不能解释为 NPU 硬容量或允许不同客户端的无条件界；详见 `../agents/bounds/baseline-client-count-provisional.md`。

## 联合容量：计算、通信重叠与共享资源（2026-10-30）

前面的 `max(计算下界, 通信下界)` 是只知道各自容量时的安全组合；它不保证两者真的能同时达到各自上限。要在允许融合、重算、分块、预取和全程重叠的实现域中进一步收紧，必须先对**同一计时窗口、同一输出契约和全部允许实现**证明：计数口径分别为计算工作 `F≥0` 和通信工作 `D≥0` 的必要量，且已扣除窗口前已完成并可复用的工作。这里 F 可用 MAC、D 可用 bit；若允许某种算法绕过这些工作，须把它纳入必要性证明，不能用现有内核或 trace 的工作量代替。

设 `Q_F(t)`、`Q_D(t)` 是该窗口内按对应口径完成的累计工作，`β_F≥0`、`β_D≥0` 是对可能在途或离散突发的**已证明上界**；计入初态信用和计入必要量的窗口边界须一致。令 `S` 是覆盖所有允许状态和并行方式的联合服务速率集合，定义其支持函数

`H(λ,μ) = sup{ λf + μd : (f,d) ∈ S }`，其中 `λ,μ≥0`。

`λ` 与 `μ` 带有对应的计量换算单位。必须另行证明对于所有选用权重的每个窗口前缀，累计服务有联合硬包络

`λQ_F(t) + μQ_D(t) ≤ λβ_F + μβ_D + H(λ,μ)t`。

不能仅因两个独立的测量峰值就认定 S 的形状或其支持函数；真实硬件的不同工作状态、可用路径、速率变化、并发以及短窗批量完成均须覆盖。对 `H(λ,μ)>0` 且上述必要量均须在窗口内完成，可得

`T ≥ [λ(F−β_F) + μ(D−β_D)]_+ / H(λ,μ)`，`x_+=max(0,x)`。

对所有**已经证实**的非负权重取最大；若证书包含两个坐标轴且其单项容量与所比较的单资源项一致，该最大值至少不弱于这两个单资源项。零权重或 `H=0` 的退化情形要单独处理，不能除以零。对每个权重都成立的共同资源限制可以使用；不同窗口或不同实现域的必要量不能拼入同一不等式。若同一次操作同时产生计入 F 的计算结果和计入 D 的数据，两个指标可以各自如实计数，但 H 必须覆盖这次操作对两项**同时**作出的贡献；不能假设它占用了两次互斥资源，更不能把未经证明独立必要的工作重复累加。

### 可并行与争用的算术对照

只作为抽象、零信用示例：令 `F=100 MAC`、`D=100 bit`。若硬件可同时维持 `f≤10 MAC/s` 和 `d≤10 bit/s`，且联合速率集合为矩形，则 `H=10λ+10μ`，已知这两个工作量得到的下界最大为 **10 s**；例如允许 `(f,d)=(10,10)` 同时运行，两个工作在 10 s 完成。

若另有独立硬件证据证明两种工作共享同一个容量池，联合速率只能满足 `f/10+d/10≤1`，则 `H=max(10λ,10μ)`。取 `λ=μ=1/10` 得到 **20 s**；速率 `(5,5)` 可同时进行两类工作并在 20 s 完成。后者并非断言计算和通信必须先后执行，而是证明它们在这个假设资源池内不能同时各用满额容量。两种机器各自单项最大率都是 10，单项峰值和两个区间重叠本身不足以判断究竟属于哪种联合容量模型。

纯 CPU 算术复算：

```sh
python3 - <<'PY'
from fractions import Fraction as F
f = d = F(100)
p = b = F(10)
lam, mu = F(1, 10), F(1, 10)
need = lam*f + mu*d
h_rect = lam*p + mu*b
h_shared = max(lam*p, mu*b)
print('rectangle_seconds', need / h_rect)
print('shared_seconds', need / h_shared)
print('shared_concurrent_rates', p/2, b/2)
PY
```

输出 `rectangle_seconds 10`、`shared_seconds 20`、`shared_concurrent_rates 5 5`。这些是人为设置的抽象值，不是 169 的算力、通信带宽或实测值。[共享带宽条件审计](../agents/bounds/hardware-source-and-shared-bandwidth-20261028.md) 已讨论 HBM 读写共池的特例；此处推广到不同工作类别。已有 [F17 样本](../agents/fusion/F17-COMPRESSOR-DUAL-PROJECTION-PIPELINE.md) 中投影和量化的导出区间有重叠，但实际资源身份、饱和度、张量关联和时钟语义尚未闭合，不能从这项重叠选定矩形或单池模型。

目前对 169 的实际目标工作量 F、跨指定 cut 的 D、联合集合 S、所有相关初态信用和精确物理资源边界均未证明，故 H 与数值 TPS 上界仍为 UNKNOWN；不使用已测峰值代替硬容量，不把观察到的等待或理论差距称为可实现提速。

### 多资源共享初始信用：不能把单项上限都当成可同时存在

上节以分别证明的 `β_F`、`β_D` 组成信用矩形，是保守形式；如果同一计时窗的初始在途或离散突发额度在多种工作之间存在**经证明的共同容量约束**，这两个上限可能无法同时达到。令 `C` 为覆盖所有允许初态和该计数口径的联合信用集合，并定义信用支持函数 `Γ(λ,μ)=sup{λb_F+μb_D:(b_F,b_D)∈C}`。在上节相同 F、D、S 和窗口范围下，若对全部合法前缀还独立证明

`λQ_F(t)+μQ_D(t) ≤ Γ(λ,μ)+H(λ,μ)t`，

则对于 `H(λ,μ)>0`：

`T ≥ [λF+μD−Γ(λ,μ)]_+ / H(λ,μ)`。

只有 C 和联合前缀包络确实覆盖**所有可用初态、计数边界与实施方式**，才可替换原先的 `λβ_F+μβ_D`；不能因为两个缓冲名称相似或任务在一张卡上，就假设它们只能共用一个信用池。计算与通信的计数若由同一操作同时完成，其计入方式及对 C 和 H 的联合贡献必须一致；多个资源可并发、同一输入可共享，不能凭标签加倍工作。已在窗口前完成并留在缓存的可复用结果，应先从必要的窗内 F/D 剔除；β 或 Γ 只覆盖按此计数口径允许的窗内在途/突发，不能把先前完成的工作同时算作必要工作与信用。

**可证伪的抽象例子**：假设 `F=D=100`，服务资源具有已证 `f+d≤10`，其支持函数在 `λ=μ=1` 时为 `H=10`。假设每一类单独的在途信用都不超过 10，但另有可证明的共同初始槽约束 `b_F+b_D≤10`。只用各自单项上限相加，得到 `T≥(200−10−10)/10=18 s`；使用联合信用集合得到 `Γ(1,1)=10`，界收紧为 **19 s**。忽略信用会错误给出 20 s；在此抽象模型里，初始已有共 10 单位在途、窗口开始后分别完成剩余 90 与 100 单位并合计以每秒 10 单位服务，即可在 19 s 完成；两类工作可按照容量同时进行。这只说明已证相关信用可收紧计算，既不声明 169 有该槽约束，也不把 19 s 称为真实机器性能。

CPU 复算：

```sh
python3 - <<'PY'
from fractions import Fraction as F
work_f = work_d = F(100)
h = F(10)
b_f = b_d = F(10)
gamma = F(10)  # 已证共享信用 b_f+b_d≤10 的假想例子
print('independent_credit_seconds', (work_f + work_d - b_f - b_d) / h)
print('shared_credit_seconds', (work_f + work_d - gamma) / h)
print('zero_credit_seconds', (work_f + work_d) / h)
PY
```

依次输出 `18`、`19`、`20`。本机现有资料仅有 [AIC/AIV 架构与带宽审计](../agents/bounds/hardware_sources_audit.md) 中不同执行单元和理论单指令线索、[共享带宽审计](../agents/bounds/hardware-source-and-shared-bandwidth-20261028.md) 中可能的读写竞争提示，以及 [F17](../agents/fusion/F17-COMPRESSOR-DUAL-PROJECTION-PIPELINE.md) 的部分任务时间重叠；它们均未证明 169 的初始队列、in-flight 归属、全部可用路径或某个联合信用集合 C。AIC 与 AIV 架构独立也不推出各自所有访存/通信路径完全独立。若只有单项容量与各自信用上限，沿用前一节保守矩形，不采用这个假设的更紧界；实际 F、D、S、C 与物理容量仍为 UNKNOWN。

### 用已有同设备窗口排除一组联合假设：不是测量硬上限

[EP8 邻接证据](../agents/diagnosis/TENSORMOVE-EP8-NEIGHBOR-DATAFLOW.md) 保存同一设备轨道、stream 47 中投影 task 43440 与 copy task 43441 的导出时间：以前者起点到后者终点，窗口长度为 `320.933 + 37.0995 = 358.0325 µs`。两条各自有 host flow 关联；这**不证明**两个任务操作同一 tensor、实际执行了下述逻辑工作、它们单独占用设备，或这个设备时钟窗有多小的误差。采集开启 profiler。相关输入输出、trace 和来源哈希见该邻接证据与 [host 绑定](../agents/diagnosis/TENSORMOVE-EP8-PROJECTION-HOST-BINDING.md)。

定义一个可被证伪的**窄域联合假设**，不把它当作实际已成立的事实：

1. 选中 BF16 投影在该窗口内完整完成传统稠密 `[8184,1024] × [1024,5120]` 的 `F=42,907,729,920 MAC`；全部工作被下面 P 的计量资源覆盖。物理 shape 不能单独证明有效行、权重语义或实际指令。
2. 同一个完整窗口须通过某一明确的数据 cut 完成 `D=167,608,320 B` 的互不重复的读写服务；这只是两份完整 BF16 `[8184,5120]` 的一次原始读和一次原始写的条件算术。缓存、融合、别名、压缩、直接输出到目标、上游重算或跨窗预取可能破坏这个必要量。此处不要求这整个 D 一定落在 37.0995 µs copy 子窗口内。
