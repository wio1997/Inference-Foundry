# F20：分块 TopK 的排序语义和精确性边界

## 可确认和未知

在冻结 [without-group 源码](frozen-source/csrc/moe/moe_gating_top_k_hash/op_kernel/moe_gating_top_k_hash_without_group.h) 中，正常路由先计算每个专家的 `xNorm`，叠加 text 或 vision bias 得到排序 score；`ArithProgression(..., 0, 1, expertCount_)` 对有效专家按原输入位置产生 ID；`Sort<float, true>` 排序，`GatherMask` 提取 ID，随后按 ID 从**未加 bias**的 `xNorm` 取权重，再归一化和缩放（约 129–140、144–213、244–309 行）。

华为 [CANN 8.0.0 Sort 文档](https://www.hiascend.com/document/detail/en/canncommercial/800/apiref/ascendcopapi/atlasascendc_api_07_0842.html) 描述该签名中 `isFullSort=true` 为全量降序，score 相同时保留输入顺序，输出包含 score 和传入的 index。**这是按输入位置稳定，不是 API 根据 index 数值排序。** 因这个冻结源码的有效专家 ID 恰为原始位置，在该文档及普通可比较数值适用、源码与历史实现一致的条件下，等分数时有效专家的原始 ID 小者先出。不同版本/产品的精确语义、历史 binary 及运行时 kernel 与此源的对应关系尚未绑定。

该 Sort 文档未给出 NaN 顺序，不能把其他 `TopK` 接口的 NaN 说明移植为本调用的行为；signed zero、非有限值和溢出等边界亦未通过同版本约束与实际 binary 证实。源码按 `ONE_REPEAT_SORT_NUM` 对齐 score 并将尾部 padding score 设为 `FLOAT32_NEG_INF`，但 ID 的显式初始化只覆盖有效专家数，不能断言 padding ID 的值。若排序行为满足上述稳定条件、K≤E 且所有有效 score 可比较，尾部 padding 即便与有效 `−inf` 同值也应排在有效位置之后；这是条件推论，不能用来证明含 NaN 时的行为。拆块方案须显式处理每块的 padding、有效掩码和 K 大于块长度的情况，且最终输出 ID 对应全局专家，而非块内偏移。

## 条件定理与证明

假设一行共有 E 个有效专家，1≤K≤E，所有排序 score 固定且存在与原调用**一致的严格全序** `≺`：score 较大者优先，score 相等时原始输入位置小者优先。专家集合被分成不重不漏的块；每块保留该全序的前 `min(K, 块大小)` 个候选，再用同一全序对候选集合求全局前 K。此时输出 ID 序列与一次全量排序前 K 完全一致。

证明：若全局前 K 中某个专家在其块内排在 K 名以后，则块内已有至少 K 个专家在它之前；这些专家在全体中也在它之前，故它不可能属于全局前 K，矛盾。因此候选集合包含所有全局前 K；候选集合按相同全序排序的前 K 与原序列相同。这个证明是数学条件结论，并不证明实际 A3 Sort 的 NaN 域存在相同全序，也不证明重新计算 score 逐位不变。

更一般地，给定一次具体输入，要精确复现原输出 ID：**候选集合必须包含原排序前 K 的每个 ID，且最终合并输出序列必须等于原排序前 K 序列**；这两项是该具体结果的必要且充分条件。使用同一全序和每块保留前 K 是保障所有输入的充分方法，不能称为唯一必要实现：例如可通过有证明的排除界保留更少候选。相同 ID 还不足以证明最终权重或模型结果一致：需保持各选中未加 bias 的 `xNorm`、顺序、规约与缩放的浮点结果以及下游语义满足所要求的精度；不同 GEMM 分块、算子实现、舍入、无穷/NaN 可改变 score 或权重。

## 最小反例：稳定 Sort 也可能合并错

令 K=2，原输入中专家 0、1、2 的 score 全为 1；原排序按输入次序选 `[0,1]`。专家块为 A=`[0,2]`、B=`[1]`，分别保留全部候选后，按块拼接为 `[0,2,1]`。若最终只对拼接后 score 做一次稳定排序，tie 保留的是**拼接顺序**，得到 `[0,2]`，不等于原结果。要使此策略正确，合并须用原始全局位置打破相等值，或让稳定排序的输入保持原始相对顺序。此例是文档规定的抽象排序语义推演，不是假装执行了实际 CANN kernel。

即使 final merge 正确，如果 K=1 的块内专家 0、1 分数相同却错误保留 1、丢弃 0，而其他块均较低，原结果为 0，新结果为 1；局部 tie 也必须一致。若 K=2 时块 A 有全局前两名，只留一个局部候选也会丢掉真实结果。

复算 `python3 agents/fusion/f20_topk_stable_order_witness.py`：输出上述稳定拼接反例，并对 6 个专家的离散分数和 K=1–6 验证 4,374 个固定交错分块实例。脚本 SHA-256 `5f32b4152fefeaab7b42308b16b22d1c84a70ae14ea9775bf143ce61e01eea1b`。ZCode 和主控分别运行均通过；这只是抽象整数例子，不能代替上面的数学证明，也不能验证部署的 CANN Sort、NaN 或浮点精度。

## 后续验证边界

在当前只读数据限制内，可继续寻找版本匹配的 Sort NaN/inf/稳定语义、加载 binary 与调用版本的可信绑定，以及实际计算生成的 score；不得用另一个 API 或 Python 的排序当作已部署 kernel 的证据。对候选块的排列、全局 ID、有效尾部、未加 bias 权重和归约顺序分别列出约束。没有逐调用 score 或权重和历史 binary 的绑定，就无法证明该请求是否存在 tie、候选实际等价或性能收益；不启动 NPU、不修改目标实现。

## 可证明排除：未完成 gate 列的区间证书

这是对无表动态路由的一个可研究重组，不是假设已有运行实现。冻结 without-group 源码先由 gate logits 计算未加 bias 的 score，使用 score 加 bias 排序，再取**未加 bias**的被选 score 归一化；模型中的外部 gate 路径和样本绑定限制见 `F20-A3-NO-HASH-ROUTER-BOUNDARY.md`。在一个特定 token 上，对专家 j 设其原实现的最终排序值为 s_j，并已得到经证明包含该值的闭区间 [L_j,U_j]。假设有效 score 有与原排序一致的确定全序，且这些界都包含 bias 和原实现的浮点误差、处理好有效专家掩码；那么：如果有至少 K 个**不同于 j** 的有效专家 i 满足 L_i > U_j，则 j 不可能进入原排序的前 K。证明是这些 i 的实际分数均大于 j，故至少已有 K 个专家排在 j 之前。此条件是充分条件，不是必要条件；如果上界相等，必须用同版本的 tie 规则判断，不能套用严格大于的结论。

可选的证书构造，在**理想实数 dot product**且相关矩阵输入允许提前取得有界信息时，将专家 j 的 gate 权重列按 hidden 轴拆成已处理部分 A 和余项 B，logit 记为 p_j + x_B·w_j,B。柯西–施瓦茨给出 `p_j−||x_B||₂||w_j,B||₂ ≤ logit_j ≤ p_j+||x_B||₂||w_j,B||₂`。例如可预先保存权重分块范数，并为每 token 求输入余项范数；然后使用**有证明**的原评分实现区间传播，把偏置放入最终 score 边界。其他经过证明的合法界也可以使用。若前 K 的下界已共同超过某未完成列的上界，可研究不再完成该列；得到最终专家集合后，对所有选中项仍须完成符合原顺序和 dtype 的 gate、原始未加 bias score、K 路归一化与 scale、ID 和后续映射。实际门控算子输入/权重类型、矩阵乘精度与舍入、`Exp→Adds→Ln→Sqrt` 的误差和溢出行为、bias、NaN 与排序版本均未绑定；实数公式本身**不是**这些浮点输出的区间证书。若要求逐位等价，应基于真实指令的误差上下界或外向舍入证明；没有证书则必须继续计算，不能把估算阈值当正确性保证。

等号反例：K=6，已有专家 ID 1–6 的实际值均为 1，尚未完成的专家 ID 0 也恰为 1；在本报告前文的稳定排序条件下，ID 0 排在这些专家之前。如果把“已有 K 个下界 **≥** 待排除上界”直接当作排除条件，就会错误丢掉 ID 0。反例只适用于前文明确的 tie 合同，不证明历史任务出现相等值。
