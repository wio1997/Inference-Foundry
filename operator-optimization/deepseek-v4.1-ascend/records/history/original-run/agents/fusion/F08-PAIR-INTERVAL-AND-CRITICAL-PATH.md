# F08：写入与矩阵乘的两事件跨度和关键路径边界

## 结论

对已有 640 条选中记录，每个 scatter 从其同一 layer scope 中的已匹配 QuantBatchMatmul 中，选择**时间距离最近者**；距离相同则选择交叠最长者，再按时间与 flow id 确定。实际这 640 个选择均没有距离并列。这里的配对只按时间，**不证明同一张量、事件依赖或同一请求**；它不是独立无 profiler 的对照。取两个事件的最早开始到最晚结束，称为“**两事件记录跨度**”：这不是模块耗时、关键路径、性能收益或全设备 makespan。

| 全部短组 | 31 | 17.70 | 289.38 | 0 | 330.48 | 41.48 |
| 全部长组 | 609 | 258.935 | 306.83375 | 241.415 | 324.414 | 17.34 |

| 同 EP3/db852 长组 | 11 | 261.08 | 306.48 | 243.0 | 324.50 | 17.78 |

每列分别计算中位数，最后一列先逐对相减再取中位；不可用表内中位数之间相减替代。短组选择的 MatMul 全部在 scatter 之后，中间还包括 10.96–37.56 µs 的记录间隙，故最后一列大于 scatter 时间并不代表 scatter 实际贡献更多。长组 609 条全部交叠；各对 `跨度−MatMul 时长` 为 15.10–27.86 µs，来源于**被选记录端点**，不代表可节省时间。短组与长组的两事件跨度中位数接近，即使对应 scatter 记录时长差距很大，也不能从单一算子时长推断端到端谁更快。

## 为什么不能称为关键路径或预测收益

- 只要两个事件的时间区间重叠，其全部区间时长相加就会重复计时；两事件跨度包含两事件之间的空隙，但不覆盖 scope 以外其他必要工作，也不证明发生等待，不能替代严格 DAG。
- 即使固定矩阵乘记录端点并从图上删除 scatter，长组两事件跨度可能只减少约 15–28 µs；但这是假设其他事件不变的图形反事实。删除或融合可能改变下发、资源争用、event join 和后续任务，无法从当前记录推算真实性能。短组先写后乘的记录顺序也不证明强制依赖，不能据此断定融合串行或可完全重叠。
- 能构造相同两事件时序的不同依赖：其一，后续算子必须等 scatter 和 matmul 都完成，则两者均可能约束后续；其二，后续只依赖 matmul 而另一路独立消费 scatter，则 scatter 不一定约束后续。还有可能存在未导出的前驱或 join，导致同一个两事件跨度对应不同全局耗时。两事件的时间和范围信息本身不能区分这些 DAG。
- 即使两个被记录区间相交，也未证明其都同时执行、争用相同资源；区间可能包含排队和等待。先前 F08 报告记录的源码流依赖和条件性 cache 写读关系只在其指定分支和对象条件下成立，不能通过近邻配对反推。
