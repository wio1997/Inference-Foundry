# F23：一个可证明的数值依赖，以及通信结论的边界

## 结论先说

对下述**单独 F23 接口的受限语义域**，可以严格证明：每个输出位置在某些输入下分别依赖 routed 值和 shared 值。再附加独立的输入放置与信息通道条件，可证明**至少有一种输入**需要跨指定 cut 传递不少于 N bit 的信息。

这些是数学命题，**不是本次 169 的通信量、时间下界或 TPS 上界**。当前未证明 169 的该分支被执行、候选输入在模型中可独立出现、该中间输出是外部可观察接口，或其值只存在某个远端 cut。结论不能直接填入 169 的资源窗口模型。

## 域 D：定义精度、输入和可见结果

设 `N≥1`；两个长度 N 的输入向量 `x,y` 各坐标独立取 `{0,1}`。需要提供精确输出

`z_i = 1.5 × x_i + y_i`，`i=1,…,N`。

接口的结果 `z` 必须在本域中可观察，而非仅影响某个之后可能将它消掉的计算。数值精度要求输出逐元素与上述结果 bit-exact 一致；这里可能的数值只有 `0,1,1.5,2.5`，均可由 BF16 精确表示，因而这些特定输入不会因 BF16 舍入或乘加合并而改变所述结果。输入也均可精确表示。这个特定小域不声称确定一般输入下 Triton 的中间精度、舍入或 NaN 行为。

实现域允许任意融合、重排、查表、编码、分块和预计算；不要求执行单独乘法、加法、特定指令、特定张量或 kernel。初态允许关于函数及固定 scale 的任意预计算，但**不能依赖本次在线选择的 x 或 y**。不同调用可以共享关于固定函数的状态，但所规定的可变输入仍须被区分。若已有状态按输入不同而变化，就不属于此初态条件。

对应现有代码的依据仅是 `agents/fusion/frozen-source/vllm_ascend/ops/triton/mul_add.py` 写出 `x * scale + y`，`sources/vllm-workspace/vllm-ascend/vllm_ascend/models/deepseek_v41/model.py:300-315` 条件性调用，而冻结配置中 `routed_scaling_factor` 为 1.5。**尚未证明实际样本命中该 tuple/shared 分支；也未证明真实两个分支输出在上述二元集合中能独立变化。**这里固定 scale 只是研究这个源码分支的条件例子，不是模型的已实测输入。

## 可证明的共同数值依赖

任取位置 i，固定所有其他位置为零：

- 固定 `y_i=0`，令 `x_i` 从 0 变为 1，则 `z_i` 从 0 变为 1.5。因此能区分这两种合法输入的正确实现，其输出信息必须取决于 `x_i`。
- 固定 `x_i=0`，令 `y_i` 从 0 变为 1，则 `z_i` 从 0 变为 1。因此同样必须能区分这两种 y 输入。

证据是函数的输入输出可区分性，适用于域内任何正确等价实现，包括融合和查表；**不证明**每个调用都需显式读取两个 BF16 tensor、单独运行乘加、访问 HBM 或消耗特定数量的 MAC。比如合法输入恰好 x=0 时，`z=y`；知道该条件后不必执行乘法。数值依赖也不证明任意一次固定真实请求对两个量都敏感。

`python3 agents/scheduler/f23_binary_witness.py` 用有理数精确检查 N=1..4，每个坐标的上述区分对，并列出固定 x=0 时不同输出个数；脚本 SHA-256 为 `c87fc56624b9ffc76241b1724c3a4fea2896fd839fb7f6472bb0a70721910361`。穷举仅自检有限例；前述一般 N 的证明不依赖穷举或设备。

## 加强假设后：跨 cut 的最坏情形信息量

进一步限定子域 C：

1. 固定 `x=0`，`y` 仍可独立取所有 `2^N` 个二元向量；最终结果须在接收侧 R 得到。
2. 开始时 `y` 仅在另一侧 S；对所有可能 y，R 的初始状态、固定函数预计算、x 和随机种子（若有）都一样，也没有有关本次 y 的缓存、复制品或可替代结果。y 可先在 S 准备好，不要求 S 内部计算。
3. 从 S 到 R 的唯一信息通路为指定 cut，其所有有效信号（数据、包信息、是否发送、轮次、时间编码和其他可能旁路）都计入通信模型；本例把一个完整可区分的信号 transcript 表示为二进制串，禁止免费时间／隐含终止符携带额外信息。允许任意分块、编码和交互。讨论确定性协议；若随机协议要求每个固定随机种子下对所有输入零错误，同样可固定种子适用该论证。

因为 x=0，必须有 `z=y`。不同的 `y` 需要 R 得到不同输出；若两种 y 对应同一个完整接收 transcript，R 的初态又相同，R 的确定性结果也相同，矛盾。因此至少需要 `2^N` 种可区分 transcript。长度严格小于 N 的所有二进制串仅有 `1+2+⋯+2^(N-1)=2^N−1` 种，故至少一种输入的 transcript 长度 ≥N bit。

这是**最坏情形**：并不证明每一个 y、某个指定真实 y，或平均请求都传了 N bit；也不证明传输了 N 个独立 BF16 值、消息包数量、方向带宽已经饱和或通信不可被其他计算隐藏。若再独立证明对每一种合法执行、从窗口开始到输出 z 完成的每个时刻 t，该 cut 可传输的全部有效信息满足 `B(t)≤C_cut·t`，且计时窗包含在线 y 信息的全部传输，则存在某种输入使完成时间 `T≥N/C_cut`。若允许初始突发且只能证明 `B(t)≤b+C_cut·t`，相应下界是 `T≥max(0,(N−b)/C_cut)`；一个长时间平均速率不能自动满足逐前缀容量约束。这不是单次特定请求或整机稳态平均吞吐上界，也没有给 `C_cut` 数值。

**宽域反例**：如果允许 R 在窗口开始前已有当次 y 的有效副本，或者允许 S、R 两侧角色重新放置而把 x、y 与输出放在同一侧，那么不必有前述跨 cut 传输，所选 cut 的必要流量下界可以是 0。若最终只观察 `hc_post` 或模型 token 而不是 z，还可能存在后续不敏感／消除；于是 z 的区分性也不能自动推广为最终 token 的区分性。这说明放置与观察契约是上述通信命题的关键条件。

## 不能代入 169 的缺口

需要分别证明真实该分支、相关中间值的独立可变性、最终接口可观察或后继对该值敏感、在线初态无副本或等价结果、唯一通信 cut 的实际物理边界及包含所有旁路的硬速率上限。当前这些在 169 上均未完整证明。尤其是模型 routed 与 shared 分支可能共享上游输入并有相关性；把它们当任意独立二元输入会扩大语义域，不能据此反推每个真实执行必需传输。对于固定真实采样，可用的正工作量、正时间和跨 cut 下界维持 **UNKNOWN**，理想放松中相关项可取 0。

独立审查见 `F23-INDEPENDENT-REVIEW.md`：量词是“每个在全输入域正确的合规协议，存在至少一个输入”，不是每个输入；时间界必须截止于输出完成，并计入协议的全部侧信道及允许的初始突发。
