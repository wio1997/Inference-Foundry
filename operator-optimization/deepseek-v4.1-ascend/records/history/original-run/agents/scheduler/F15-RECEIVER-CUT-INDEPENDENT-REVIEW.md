# F15 单接收端通信界：独立审查

审查对象 `F15-RECEIVER-CUT-INFORMATION-BOUND.md` 和 `f15_receiver_cut_bound.py`。对文中明确的**抽象 BF16 全域、接收端必须恢复完整交换中间张量、无免费旁路**的条件，索引、计数与最坏情形信息论证成立；其数值不能直接套用到本次 169 推理的所有等价实现。需要明确两个时间公式的边界条件，见下。

## 映射与数值

冻结 `dsa_cp.py:77–91` 的 view → permute → contiguous，再按 `all_to_all_single` **等分、按发送 rank 顺序**接收时，`recv[r][sL+t][h][c] = input[s][t][r(H/P)+h][c]` 与 `restore-tp-heads-witness` 检查的索引一致。脚本只模拟索引，等分 collective 语义、实际 rank 对应、历史运行 branch 与硬件 dtype 并非脚本证明的事实。

P=8、H=64、D=512 时，7 个非本地源一共 `7×L×8×512 = 28672L` 个远端元素，按 16 原始位/元素为 `458752L` bit = `57344L` byte。每接收端输出 `8L` 行，对应 `7168` byte/接收行。L=3 的 `86016` 元素、`1376256` bit、`172032` byte、`168 KiB` 算术复核正确。原脚本本地运行通过并复核源码 SHA；它没有执行硬件通信。

## 可变长计数与量词

固定接收状态 z 后，远端自由 raw bits 共有 `M=2^N` 个可区分输出。若不同输出不能共享同一完整接收 transcript，则最多 b bit 的可变长二进制串至多 `2^(b+1)−1` 个。取 `b=N−1`，数量少于 `2^N`，所以对**每个全域正确的合规协议**，必有至少一个输入的接收 transcript 长度 ≥N。固定长度 N-bit 原样发送是抽象协议可达上界，故在此模型中最坏值为 N；这不证明硬件能达此值。

实际可达集合的形式 `ceil(log2(M_r(z)+1))−1` 是宽松变长计数下界，要求 z 可达且 `M_r(z)≥1`。它允许长度可辨时短消息，也不要求 prefix-free；若 termination/长度是免费渠道，需把这类可区分状态一并计数而不是仅计 payload。禁用或付费记录时间、空消息、帧界、轮次等侧信道，是该界的必要前提。比如如果不同输入可通过 N 个可区分发送时刻编码，只有固定内容的一个短数据包，单独的 payload 位数就不能给出原先的 N-bit 下界；原证书已写明禁止这一免费渠道。

最坏输入可随协议变化；不等价于每个输入、平均长度、真实一个请求或共同触发所有 receiver 界的输入。接收端 z 可能含副本、上游相关状态或可重算结果，压缩真实 `M_r(z)`；看最终投影而非完整中间张量时，发送端投影与重排也会改变必须区分的集合。原文已正确排除将 full raw BF16 自由域当作真实模型可达集合的推断。

## 时间 / 行率需补充的条件

1. `T≥57344L/B_r,max` 必须计到**接收端拿到该次所要求完整结果的完成时刻**，并保证证书的有区别信息都在窗口内输入到接收端；不能以输出完成后的协议收尾位数推导输出时延。所计 transcript 的 bit/byte 数也必须和物理 cut 上按速率计的实际信息量一致；把一个自定义较长的描述编码称为 transcript，不会自动证明硬件真的传了这些比特。
2. 需要对所有允许输入及每个窗口前缀 t 满足 `B_phys(t) ≤ B_r,max × t`，且包含所有并行链路、协议信息和可辨侧信道；平均值、长期标称值和单链路速率都不足以单独推出此式。若协议有未计的初始突发 b 字节，则只有 `T≥max(0,(57344L−b)/B_r,max)`。若只给长期平均带宽，可用短暂突发在窗口开始几乎瞬间送完数据、随后长时间空闲构成反例。
3. 对行率 `8L / T_worst ≤ B_r,max / 7168`，应显式限定 **L≥1、T_worst>0**，且 T_worst 是在同一固定 L、固定接收初态/协议和完整输出语义下对该输入域取最大或上确界的完成时间。如果 L=0 且无需执行，`8L/T_worst` 可能是 `0/0`，表达式无定义；这个边界不影响 L≥1 的计数结果。流水、跨轮预发和复用改变窗口/状态时应重证。

这些是对使用条件的补充；原证书将 B_r,max、实际语义域与真实数据量均标为 UNKNOWN 的限定应保留。本次无新 profiler、通信或 NPU 操作。
