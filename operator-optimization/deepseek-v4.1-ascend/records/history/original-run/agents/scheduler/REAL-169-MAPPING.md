# 理论资源窗口如何映射 169 的 F05、F21、F23

## 使用边界

本记录只把已冻结源码、配置和已有 trace 映射成**待证明的语义节点与资源问题**，不宣称得到 169 的算子时间界或 TPS 数值。宽域允许融合、拆分、跨层复用、预计算和改变分片；观察到的 API、通信原语、设备任务、缓存写出、屏障和 MAC 次数均不自动是宽域不可避免工作。

先固定：请求及可变输入集合、有效输出及精度／舍入契约、可使用的固定模型权重与编码、预计算／缓存及初态、设备和通信拓扑、运行窗口与有效输出计数。下面的“语义依赖”通常只说明当前模型函数的某种值关系；要成为**所有合法实现**的任务或正的时间／通信下界，还需证明输入可变、输出对该值实际敏感、没有已存等价结果或替代算法，以及必要工作无法绕过所选资源。极端输入、未激活专家、零行、共享缓存和空 query 都会影响可否把工作记为必做。

冻结设置见 `evidence/frozen-serve.sh` 和 `evidence/model-config.json`：采样为 16 个逻辑 rank、DP/TP/EP 与 DSpark 配置；注意 rank 数不是资源独立证明。`captured-layer-attribution/module-call-metrics.json` 中的 target 层窗口由源码顺序和角色归属，**不是逐 tensor 身份证明**。本记录不把资源窗口公式代入具体采样时间或名义硬件参数。

## F05：Q 归一化 → 动态量化 → Wq_b

源码：`sources/vllm-workspace/vllm-ascend/vllm_ascend/attention/dsa_v41.py:320-324,350-389,440-495`；条件 wrapper 来源和哈希见 `agents/fusion/WRAPPER-REVIEW.md` 与 `hotspot-wrapper-provenance.json`；双消费者核查见 `evidence/QR-consumers-and-fusion-review.md`。`agents/fusion/QUANT-CONSUMER-REVIEW.md` 描述了 checkpoint 描述文件哈希一致，但历史实际加载对象尚不能仅凭此断言。

| 候选节点 / 边 | 当前实现的观察 | 宽域中的必要性与可分块边界 |
|---|---|---|
| Q 前投影得到 q_norm 输入 | 代码有 `wq_a` 后 `q_norm`；多流分支可与 KV 相关工作交错。 | 所需是可观察模型结果符合精度契约；单独 `wq_a` 节点、调用或全部标准 MAC 是否必要 **UNKNOWN**。只在证明某个具体值用于最终结果且不可由初态替代时，才建该值产生节点。 |
| `qr` 归一化语义 | 源码先求 `qr=q_norm(...)`，主 Q 用 `qr`；index source 层另将它送 query projection。输入为空走另一条分支。 | 如果契约要求现有结果和中间 BF16 舍入，应保留其数值效果；不强制 `qr` 独立物化，也不强制所有层存在第二个数值消费者。完整 row 的必要归约范围、可分层次归约、及数据敏感性须由实际 norm 语义与输入域证明，不能仅由 API 名称当硬边。 |
| 动态 scale 与量化值 | `CVLinearWrapper` 在无通信且识别为 W8A8 Dynamic 时调用动态量化、然后量化矩阵乘；实际运行对象、是否无通信及 trace 一一绑定未完全证实。 | 若合同规定输出等价于该动态量化，需保持 scale、舍入和溢出效果；但单独 scale buffer、两次 kernel 与常规量化算法不是必做。先证明某一个有效行实际 scale 的归约输入范围及变化会影响结果；在证明它必须依赖全部相关元素之前，不能强加整行屏障。 |
| Wq_b 投影 → Q 消费者 | 配置／checkpoint 描述支持 Wq_b 的 W8A8 动态标签；源码有投影及 RoPE，source 层 indexer 另消费 qr。trace 有匹配类型与 shape 的候选，未证明逐 tensor 对应。 | 在指定的观察输出域下必须保持影响到最终结果的 Q／indexer 数值，但不证明完整矩阵输出、逐乘加或该执行顺序普遍必做。只要 scale 与具体输出依赖允许，可以对行、输出通道和 K 方向部分工作分块；跨 K 部分累加及浮点结果顺序需符合约定，最终哪个块最早可被下游消费 **UNKNOWN**。 |

**资源与初态：**归约可能运行在 AIV、AIC 或其他合法路径；不能预先把每个语义节点固定到某类单元并把工作加总。若仅限定某种实现才可分别构造逻辑计算、HBM→片上存储、片上搬运资源，但 Wq_b 权重、scale 和激活的实际必要跨 cut 数据量、缓存可用空间、驻留／编码、外部预取、各方向硬速率均 **UNKNOWN**。权重是否分片或复制、是否已在快存、数据是否由其他消费者共享、每层 qr 是否实际写出 HBM 均未证明。`a_i/b_i` 应来自已证明的细粒度必要依赖，而非多流 event、函数调用边界或当前一次整张量 GEMM。额外的 indexer 消费者只在相应角色和有效 query 的条件下建图。

## F21：路由、分发、专家计算与合并

源码 `sources/vllm-workspace/vllm-ascend/vllm_ascend/ops/fused_moe/moe_comm_method.py:563-611` 中，`enable_fused_mc2==1` 仍可能分为 MegaMoE 与自定义 `dispatch_ffn_combine`。已有归属窗口实际采到 `DispatchFFNCombine`；自定义 kernel 的 AIC/AIV 分支、专家标志和当前同步点见 `evidence/MC2-known-dependencies.md`。同窗出现不证明每次实际路由、专家数据或跨 rank 一一对应。

| 候选节点 / 边 | 当前实现的观察 | 宽域中的必要性与可分块边界 |
|---|---|---|
| 路由与选中专家 | 源码有 router / top-k 输入，MC2 调用带 `expert_idx`、`probs` 与 mask；配置有 routed expert 和每 token 的专家数。 | 应保持声明契约下最终被选值、权重及并列／精度效果；不自动强制独立 top-k、全专家扫描或规定条数的设备消息。路由是否对某次输出敏感、是否能在初态预知或共享，需单独证明。 |
| token / expert 交汇、数据发送 | 当前 MC2 接收 EP group、专家索引和输入，kernel 含 dispatch/combine 及按 expert 的数据就绪 flag。 | 若固定专家仅在远端且既无副本、缓存、足够替代编码与共享结果，并可证明输出依赖远端独有数据，可推某一资源 cut 有信息流；其最低字节、方向、路径及哪些 rank 参与 **UNKNOWN**。允许复制权重、移动计算或预计算的宽域不能直接使用现有 all-to-all 数量。 |
| GMM1 → 激活／量化 → GMM2 | 当前 fused kernel 有 GMM1、激活/量化以及 GMM2，内部存在分块发布和多个同步点。 | 需保持该模型专家的数值函数，包括 scale、激活限制和舍入；不能默认现有中间张量、操作计数与同步步骤都必做。在证明某 expert/token/tile 的真实计算依赖后，可允许已就绪的 tile 进入后继；部分归约、分块粒度和输出误差契约未证实前不能要求整轮 dispatch、所有 GMM1 或所有 expert 完成后才进行下步。 |
| combine／回传 → MoE 可观察输出 | 当前 op 接收专家概率并输出 routed result；模型后续还可能进行 shared 合并及归约。 | 如果固定的输出分片确实依赖多个远端专家贡献，必须保证这些贡献的信息能影响对应输出；但当前全量 combine、barrier 和具体 reduction 算法不是宽域必然。需先证参与集合、非零/可变贡献及最小合并粒度。不同 expert/token 可以独立推进，仅共享资源容量会造成潜在竞争。 |

**资源与初态：**候选池包括本地计算（AIC/AIV 或其他路径）、HBM/片上搬运、不同方向的互联及可能共享的通信引擎。要为某个池给 `C_r`，必须核实实际设备映射、所有可并行替代路径、所选 cut 的双向与并发共享、以及对该 SKU 的硬速率上限；当前均 **UNKNOWN**。把通信与计算当可重叠资源是乐观放松，只有证实共享同一硬资源才收紧；反之不能以任一单链路速率限制全机。若把多个 token 或多个专家的字节相加，先证明数据与计算互不重复，不可忽略缓存、复制、压缩或同一次传输服务多个消费者。当前内部 `SyncAll`、flag 等是现有实现的事实，不是宽域的必然同步或可直接计入的 d_i。

|---|---|---|

**资源与初态：**可条件建立合并计算、必要 cut 的信息流、后续输出 tile 的数值节点；各节点适用的计算资源、缓存占用、传输带宽与最终 placement 目前 **UNKNOWN**。同一个物化数据若能供 shared、routed 和后继多个消费者复用，不得重复计费；另一方面若存在多个不同 rank 的必需贡献，也不能在没证明复用之前直接忽略。若理想域允许在片上保持中间值，单独的 `2×bytes(x)` 物化只能作为当前实现的条件候选，不能作为必要流量下界。

## 把节点送进资源窗口公式前必须补什么

1. **域和初态**：实际被测输出、误差容限、可接受重排、量化中间舍入、缓存和预计算预算，以及窗开始时已有权重/KV/共享结果。宽域和固定执行分支域分开建模。
2. **共同必要工作**：对每个候选节点给可追溯的函数语义和有效输入条件，证明不能由共享状态、其他算法或替代路径消除；仍未证明者标 UNKNOWN 或在理想放松里取 0，不能把 profile 次数直接转为必做量。
3. **细粒度依赖**：对每条跨 tile、expert、row、rank 的边证明必要性并明确端点；区分数值归约的完整依赖与现有同步实现。输入可在任意合法时间准备，只有确证的 d_i 才可大于 0。
4. **资源和共享**：明确每项工作对某一资源的必要量 `w_i`，确保证明可加且互不重复；查实际硬件能力与资源 cut 的硬上限 `C_r`。若工作可选择路径，要将所有替代能力纳入宽域，而不能强行约束到一条路径。各资源 `C_r` 未证时保留符号，不用实测最好值或单一指标填数。
5. **同一窗口与输出**：同一合法 DAG 定义上求每个非空选择集的资源窗口下界并与必要路径界取最大；不要将各资源可能并发的时间直接相加。最后只有同一计时窗的实际有效输出数 Q 才能用于 `Q/T_lower`；当 `T_lower=0` 或必要量和容量未知时，不给有限 TPS 数值。

此映射并不证明完整系统已有共同必要任务图，F05/F21/F23 跨越多个样本或调用可能彼此重叠；因此本文件没有把三处局部任务的工作或时间加总，更没有把当前热点时间当作理论极限或可实现收益。
