# F09 数值和访问量证书：独立审查

审查对象为 `F09-NUMERIC-DEPENDENCY.md` 和 `f09_single_coordinate_witness.py`。结论：**在文中声明的 129 个输入、scale 可见、特定浮点语义和受限原始数组访问模型下，数值区分和 128 bit/128 字节地址的全零输入访问证明成立。不能由此直接得出 169 的 HBM 流量或时间下界。** 本审查没有改动原证书。

## 数值见证

冻结 helper 的 SHA 为 `6065b79f0f764e99bafae71347c8c8dfd0625ad52b0d695639c47e71338d0bba`；CPU 脚本执行成功，独立复算结果如下：

- 全零输入，`max_abs=0`，在假设 subnormal 无 flush 的前提下 `max(0,2^-24)` 产生 FP16 `0x0001`。
- 单个 2 输入的假设 FP32 `2/127` 舍入值是 `2113665/134217728`；它到 FP16 `0x2407`、`0x2408`、`0x2409` 的距离分别为 `2177/134217728`、`129/134217728`、`1919/134217728`，所以最邻近的是 `0x2408 = 129/8192`，并非依赖二者恰好相等。`2/(129/8192)=16384/129=127+1/129`，经所设 FP32 取整、nearest-even 和夹紧得到该坐标 INT8 127。其他坐标是 0。
- 因 max 对位置对称，这一见证适用于任意 j，共 128 个坐标。两个 scale 明确不同，因此即使只观察 scale 也可区分；量化输出是额外观察，并非依赖证书必须的输出。

结论依赖证书给出的 IEEE 舍入、`2^-24` 保留等前提。CPU 的 `struct` 自检与数值证明不确认目标 Triton 编译结果、设备 flush 行为、运行时输入 dtype 或最终 token 对该 scale 的敏感性。

## 对抗式访问论证

在原证书的 129 个输入中，BF16 `0x0000` 和 `0x4000` 在每个坐标恰有一个不同 bit，且这 128 个不同 bit 位于 128 个不同的字节地址；端序不影响不同地址的数量。对每个 j：如果确定性算法执行**全零输入**时从未检查该差异 bit，那么在只改变 j 的输入上，按执行步骤归纳，算法每次读到的值及随后选择都相同，于是输出也相同，和两个不同 scale 冲突。故该全零执行至少检查全部 128 个差异 bit；如果探测接口按 byte 收取，至少访问其所在的 128 个不同 byte 地址。

量词是：对**每个对全域正确的合规算法**，其**全零输入执行**至少检查这些位置。可提前知道输入域，但不能提前知道当前这次输入是全零。该证明不需所有 2^128 种组合可达，也不暗示最终 scale 承载 128 bit 信息：在本 129 输入子域，scale 只有两种结果。读取完整 BF16 值可能涉及更多逻辑字节，但不能据此把 128-byte 下界升级为 256-byte 下界。

如果得到输入的机制包含 input-dependent 元数据、事先得到的结果、持久 cache、memory-side OR/max、内容索引、producer 提供的全零标志或免费旁路，单点改变可先经其他位置/信号暴露；归纳前提就失效。正确实现也可融合生产者并在生成时算 max，而不重读单独的 raw query。这些反例原文已明确排除，适用时不能仍使用该访问下界。

## 从逻辑探测变成物理通信和时间：应更严格

原证书已经将实际 cut 与带宽保留为 UNKNOWN。若今后要使用 `T≥128/C`，还需给出单独证明，不能只凭“128 个 probe”推导：

1. 计时窗口从输入在线变化后开始，接收结果完成时结束；开始时接收侧及可达 cache 没有本次输入的预知/副本，producer 先算出的摘要和事件等不能免费穿越窗口。
2. 所有实际可利用路径（计算侧已知信息、旁路、内容编码/压缩、共享 cache line 或广播、预取、memory-side 聚合及控制/时序）均纳入模型。必须证明它们在该具体 cut 上对**这个全零执行**带来至少 128 bit 的总计费量，或至少 128 byte 的总计费量；128 个不同逻辑地址本身并不证明这两个物理流量命题。尤其该子域的输入信息可压缩，不能把读取 bit 数直接等同通信信息熵。
3. 所谓硬速率 `C` 要适用于全部被计费通道和窗口的任意前缀累计传输：`B(t)≤C·t`；若存在允许的突发 `b`，则只可得 `T≥max(0,(B_required−b)/C)`。真实运行中其他任务或阶段可重叠，不能将该单接口耗时下界直接逐项相加。

即使条件全部成立，结论仍只适用于该固定全零执行、该访问协议及指定 cut；不是本模型所有输入的单 token 时延、平均吞吐或端到端 TPS 上界。实际 169 的上述条件没有证明，保持 UNKNOWN。
