# F09 单 head 数值依赖证书：全零与单坐标 2

## 结论和范围

对下面明确定义的 **128 维、BF16 查询值、scale 作为可见输出的独立接口域**，冻结 F09 的 scale 对每一个输入坐标都存在可区分性；正确实现必须能区分全零 head 与任意一个坐标变成 2 的 head。融合、重排、查表和提早归约都允许，只要保持该接口结果。

若**额外**把输入限制为不可预先总结的原始 BF16 地址数组，并只允许逐位／逐字节直接读取来获知在线输入，那么对全零输入，一个对该域所有输入都正确的确定性算法必须在最坏情况下检查 128 个不同的指定 bit 位置；若以字节为最小访问单位，它必须读取 128 个不同字节地址。这是**受限数组访问模型**下的访问数量，不是实测或必需的 256 字节 HBM 流量，也不是 169 的端到端下界。

## 冻结代码和域定义

证据为 `agents/fusion/frozen-source/vllm_ascend/ops/triton/quantize_indexer_query.py`，SHA-256 `6065b79f0f764e99bafae71347c8c8dfd0625ad52b0d695639c47e71338d0bba`；双容器匹配来源在 `agents/fusion/indexer-helper-provenance.json`。源码中每行求 `max(abs(query))`，`div_rn` 除以 127，结果转 FP16 再转 FP32，取至少 `2^-24`，用 scale 做归一化和 `nearbyint`，并输出 INT8 与 FP16 scale。每行在该 helper 对应一个 token/head，维度由包装器断言为 128。

为了使数值结论严格，定义语义域 D：

1. 指定单个有效 head，128 坐标输入均为有限 BF16 值；本次证明只需覆盖全零向量，以及 128 个分别只有第 j 坐标为 BF16 `2.0` 的向量。输入值在本次在线执行开始后才确定，允许其他固定代码/常量预计算。
2. `max` 与绝对值按有限数值精确比较；除法按 IEEE binary32 round-to-nearest ties-to-even，FP32→FP16 按 round-to-nearest ties-to-even；最小正 FP16 subnormal `2^-24` 得以保留而没有 flush-to-zero。INT8 归一化按 binary32 round-to-nearest、`nearbyint` 为 ties-to-even 后限幅到 [-127,127]。
3. 逐 head scale 输出须 **bit-exact 可观察**；若还观察量化向量，也须与同一语义一致。允许任何算法和布局、融合生产者/消费者、表查或分块，只要对域内每个输入满足该接口契约。初态可以含任意与当次输入无关的权重和代码，但不能预先知道本次 query 值或存有基于该 query 的 scale 摘要。

这组 FP 语义是明确的**证明假设**：本次没有运行 169 设备核验编译器 lowering、实际输入 dtype、subnormal 行为或该 helper 在历史窗口确实被调用。Python 源码不能独立证明这些运行事实。若只要求最终 token 或有误差容限而不观察中间 scale，本域的接口契约不自动成立。

## 精确见证及每坐标依赖

对全零向量，`abs_max=0`，FP16 舍入后取最小值，因此 scale 为 `2^-24`，FP16 bits 为 `0x0001`，全部 quantized 值为 0。

对任意 j，将第 j 个输入改为 BF16 `2.0`：`abs_max=2`。按 D 的两次舍入，FP32 `2/127` 为 `2113665/134217728`（bits `0x3c810204`），FP16 scale 为 `129/8192`（bits `0x2408`），大于最小值；第 j 个输出 INT8 为 127，其他为 0。两种输入仅在坐标 j 不同，且输出 scale 的 bits 不同，因此每个 j 都有一对可区分输入。所有 128 个坐标均满足此命题。

该命题的量词是：**每个坐标存在一对输入会影响 scale**。它不声称在任意一次输入、坐标或所有非最大值上改变数值都会改变 scale；并列最大值、量化舍入和限幅均可能使某些微小变化无影响。

对应 CPU 自检 `f09_single_coordinate_witness.py` 会核对源码 SHA，并用 `struct` 的 IEEE 格式检查全零与全部 128 个单坐标见证及 INT8 输出；它不是执行 Triton/NPU。该小程序对这些样例的检查可重复；上面的任意坐标结论直接由 max 与全零／单点构造得到，而非以抽样推广。

ZCode stage `operator-ceiling169-v2-100-f09-witness` 退出码为 0，执行模型凭据验证为 `deepseek-flash`。结果保存于 `f09-single-coordinate-witness.json`，SHA-256 `2e89e4961c9320aa85531d9f2766eeb19c36e39337a0a846449e1714676f3177`；脚本 SHA-256 `7098bc789bf20ba3af1a01940262c1474ac2bc10be2270b3bfe307130c15e88a` 及源码 SHA 与结果记录均吻合。结果仅核验上述 CPU 参考算术，不增加真实 NPU 执行或历史分支的证据。

## 条件 bit / 字节访问下界：它到底证明了什么

将 D 进一步限制为数组访问子域 A：

- 128 个 BF16 原始编码分别保存在 128 个互不重叠的两字节槽位；在线输入仅为上面的 129 个向量。全零为 `0x0000`，单点 2 为 `0x4000`。同一格式下每个坐标存在一个固定位置的不同 bit；每个该 bit 所在的字节地址互不相同。端序只改变这个字节在槽位中的偏移。
- 输入数据是唯一随本次选择改变的在线状态；scale、max、非零标记、别名副本、压缩数据、producer 传入的摘要等都不能在窗口开始前提供，也不能从输入以外的旁路获知。算法所见历史及初态对这 129 个输入完全相同，直到它访问不同的输入存储位置。
- 为观察输入，算法只能通过有地址的 **单 bit probe**，或另一模型中的 **单 byte probe** 读取原始槽位；不可调用内存端 max/OR、对整个输入计算的 oracle、基于内容的跳读或携带免费输入信息的事件。允许并行请求、读未对齐数据、缓存代码、重排和自适应决策；probe 只计不同 bit 位置或 byte 地址，不把某个访问计成一条总线事务。
- 算法确定性、且对 A 内所有 129 个输入给出可见 scale 的正确结果。若无误差随机实现要对每个固定随机种子都对这些输入正确，也可以固定种子后应用同一证明；有概率出错或弱化观察契约不在此命题内。

设算法在全零输入上没有访问第 j 坐标中 `0x0000` 与 `0x4000` 不同的那一 bit；两输入所有已读内容相同，所以它的下一次访问与最后输出也相同，无法同时给出 `0x0001` 和 `0x2408`。因此每个 j 的差异 bit 都必须被读取。128 个不同坐标各有不同 bit，得到至少 **128 个不同 bit 位置**的全零输入访问。若最小读取单位是字节，每个不同 bit 又位于不同地址，至少访问 **128 个不同字节地址**。这是对全零执行的对抗论证；算法必须对全域正确，而不是提前被告知当前向量全零。

注意，以上说的是**被检查的 bit 位置和字节地址**，不是“输出携带 128 bit 信息”：此受限输入集的 scale 只有两种结果。BF16 槽位虽占 256 字节，`0x0000` 与 `0x4000` 只在每槽一个 bit 上不同；该证明不要求读取每槽两个字节。若有允许读取整 BF16 槽位的实现，则可能读取 256 字节的逻辑值，但这是访问方式的结果，不能由本证明推出为任意实现的最小值。

只有**再**证明这些全部 probe 必须在线从某个明确硬件 cut 的慢侧跨到快侧、每个被计 bit 不会被任何其他共同传输或缓存覆盖，并且该 cut 的硬上限为 `C` bit/s，才可在 A 的全零执行上写 `T≥128/C`；byte 模型同理使用该 cut 可计的至少 128 字节及同口径带宽。初态、替代通路、内存侧计算、并行共享和时间窗有任何变化，都要重新证明。当前 169 的 cut、硬容量及这些前提均 **UNKNOWN**，不代入时间或 TPS。

## 反例与流水边界

- 若 producer 在线逐元素产生 query 时，同时计算 max 或传递经过认证的非零/scale 摘要，量化节点可以不重新读取原始 128 个 BF16 坐标；计算可能完全融合。这不违反 D 的结果语义，但不属于数组访问子域 A。
- 若 scale 及输出已按本次 query 在窗口开始之前算好，窗口内的相关读取/计算下界可为 0；这不满足 D/A 对在线初态的限制。权重热缓存与本次 query 相关的预计算也应分别建模。
- 如果可并行地按 tile 收集局部最大值，再规约局部结果，块间计算和数据准备可以重叠；不能因为全零时每个坐标都需可区分就宣称必须有一次完整 tensor 落地或全量搬运后才开始计算。对本二元输入域，一旦看到 2 又知道上限为 2，scale 可以提前确定；只有全零输入的正确性仍需排除其他坐标为 2。
- 即便 `quantize_indexer_query` 的 scale 在其接口中可见，真实 QLI 或模型最终输出能否区分上述两种状态还需证明。实际模型的 query 是否覆盖独立的 129 个输入也未证实；因此本证书不对 F09 在 169 的实际必做 HBM 流量、硬件时间或整个模型 TPS 作数字判断。
