审查对象：`RESOURCE-WINDOW-BOUND.md` 和 `resource_window_bound.py`；脚本 SHA-256 为 `1267d47056335f9db3c7b51de13c8ef64a551f43582fabea8e989e9bd8aa1ee2`。本审查未改原脚本，也未操作设备。

## 结论

**数学证明思路在限定任务图和非空任务集合下成立，但文档目前漏写了非空条件；字面公式不成立。**脚本已用 `if selected:` 排除空集合，因此这个问题不影响脚本所给的两个示例值。脚本的调度检查器还有独立的验证缺口；当前手写示例经人工核对是有效的，但不能把该检查器当作对任意调度的完整验证。

**这还不是 169 的理论上界。**适用 169 的共同必要任务图、每任务必要工作量、各资源硬容量、图粒度和初态尚未证明。本审查不提供数值 TPS。

## 必须修正的量词：`S` 非空

文档原文写“对任一资源 r、非负阈值 a、b”，并对所有这样的 a、b 取最大值。若 `S(r,a,b)` 为空，则不能从“集合内任务都在窗口里”推出 `T ≥ a+b`。反例：一个必须完成的任务，资源容量 1、工作量 1、跨度 1，无前驱后继；合法调度 `T=1`。取 `a=b=100`，选择集为空，而字面右侧为 `100+0+100=200`。因此原命题和无限阈值上的最大值写法是假的。

应把陈述限定为 `S(r,a,b) ≠ ∅`，并在所有这样的集合上取最大值；不存在任何非空选择集时，资源窗口项按 0 处理。若 S 非空、所有该集合成员确实必须执行并在计时窗内完成，则至少存在一个任务，其最早可开始时刻不早于 a，完成后必经跨度至少 b，故 `a ≤ T−b`。所有所选任务的资源工作发生在该时间窗内，且每时刻总处理量不超过 C，便有 `Σw_i ≤ C(T−a−b)`；公式成立，允许抢占、分块后建图和跨资源并行。

脚本 `bound` 中 `if selected:` 已避开空集合。它只枚举各资源节点的 `earliest` 和 `tail` 值（另加 0）：在有限 DAG 和非空选择集下，这是充分的。对于任意非空选择集，分别将阈值提升到该集合内 `a_i` 的最小值与 `b_i` 的最小值，不改变选择成员，且右侧不减；这两个值均来自枚举集合。

## 前提及可构造的反例

- **必要任务和工作必须对整个声明域普遍成立。**实际实现图只证明某一次执行做过，不能证明任意允许的融合、缓存、代数重排或预计算都要做同样的工作。把图当共同必要图而没有证明，会把合法方案排除，可能得到虚假的通用上界。
- **分块和依赖要对粒度成立。**若完整读完才能开始完整算并非必要，不能把当前同步点作为全局必然边。文档的 10 个 tile、11 对 20 时间单位反例是有效说明；但在某个 tile 粒度下依赖是否必要仍需单独证明。
- **同一资源的工作量必须在所选任务间互不重复，且所有工作都在各任务起止区间内。**例如两个算子共享一次读取或两次计数指向同一硬件操作时，重复加总会高估必做量。输入定义未能排除则不能带入。
- **`C_r` 必须在整个声明域和计时窗内是所选资源合计吞吐的硬上限。**可共享物理通路才可合并字节；如果两个独立的 1 单位读写端口被错误合成单个容量 1 的端口，那么两边各处理 1 单位可同时在 `T=1` 完成，但错误加和会得到 `T≥2`。平均值、单次观测峰值或未适配当前 dtype / 单位的参数均不能自动充当硬上限。
- **`d_i` 是任务起终点跨度的经证明下界，不是独占资源时间。**模型允许其它资源或其它任务在其间交错；如果将一段可融合消去的 host launch 延时直接作为 d，则约束的是固定实现而非理想域。
- **计时窗边界及初态必须包含并允许所有合法的历史状态。**热权重、KV／前缀缓存、预取、已有输出及持续请求都可能跨窗存在；把窗前已完成的工作重复计入会得到无效的下界。
- **把时间下界转成吞吐上界要使用同一个统计窗、同一有效 token 定义。**推测解码的草稿 token 不能一律按最终生成 token 计数；批处理的 8192 token 与整个批次耗时需对应，不能拿单轮 kernel 窗口做分母。要声称稳定流 TPS 的上界，还需定义窗口族和可允许的首尾初态；一次批次界不能自动推广。

## 脚本与示例核查

在只载入 Python 定义、不执行文件底部输出语句的情况下，复算示例得到：第一个路径界 5、IO 工作界 8、计算工作界 12、窗口界 14；第二个共享 IO 工作界 64。给定的第一个手写调度逐项核对，四个 `in` 均为 1、四个 `calc` 均为 3、四个 `out` 均为 1；依赖和同资源不重叠，最后完成于 14。故这两组特定示例的算术与所列证据一致。**这个可达示例只是自检，不是建立下界的必要条件，也不是其他图能够达到下界的证据。**

`validate_witness` 只检查固定四组名称的依赖与按声明资源分组的时间区间不交叠，**没有验证每个节点的持续时间／工作量、应使用的资源、非负起点、区间顺序、节点名唯一或确切集合**。将 `in0..3`、`calc0..3`、`out0..3` 的所有起止时刻都设为 0，并分别标为 `io`、`cube`、`io`，函数返回 `0`，尽管此例要求每个计算持续 3 个时间单位。当前 14 单位实例经上述独立人工检查有效；不要将该函数推广为任意调度合法性证明。审查没有修改原脚本；建议如需要机器验证 witness，另行补充节点与工时一致性校验。

脚本运算用 `Fraction`，只要输入以整数或有理数字符串表示即可精确复算。直接传 Python 浮点数时 `Fraction(float)` 会精确表示该浮点近似值，未必是人想要的十进制有理数；真实实例应保存明确单位和精确字符串。
