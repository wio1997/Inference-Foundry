# F15：单接收端跨 cut 的信息下界（条件证明）

## 明确的对象与映射

对应 `agents/fusion/F15-CP-PROJECTION-REVIEW.md`，在选用 DSA-CP、等分 all-to-all 的条件下，P=8、总头 H=64、每头 D=512、每源 L 行且 `L≥1`，接收 rank r 的完整中间结果满足

`recv[r][s*L+t][h][c] = input[s][t][r*(H/P)+h][c]`，

其中 `s,r∈[0,7]`，`t∈[0,L-1]`，`h∈[0,7]`，`c∈[0,511]`。参见冻结 `sources/vllm-workspace/vllm-ascend/vllm_ascend/attention/context_parallel/dsa_cp.py:77-91` 和 F15 的索引 witness。实际配置是否在历史每个层/步走此分支、L 的实际值及激活 dtype 仍未被运行时证明；L 在这里是符号。padding 中预先已知为零的行不具备完整自由度。

选一个 receiver r，将它的可计算资源和初始本地状态放在 cut 一侧、其余七个源放在另一侧；只统计其余侧到接收侧的通信。必须在所考察时间窗开始时确定接收端已知信息 `z`，包括本地数据、权重、共享随机数、预先复制的中间值和可观察控制状态。若另有跨边界来源、外部共享存储或其他旁路，都必须计入同一个信息通道；否则下界不成立。

## 抽象 raw BF16 全域的最坏输入界

假设：

1. 每源 L 个行均为独立有效行，没有已知零 padding；s≠r 的目标头组共有 `(P−1)L(H/P)D = 28,672 L` 个元素。接收侧的既有状态 `z` 不含这些元素的信息，固定 z 时它们可独立取任意 16 位 BF16 **原始比特模式**；要求接收端在窗口内逐 bit 得到映射指定的完整 `recv[r]` 中间张量。所有 NaN payload、符号位等也都作为可区分位模式，而不只是数值等价。
2. 跨 cut 的每条区分信息均计入二进制 transcript，协议规范预先固定；收发消息边界、长度、顺序、运行时间、无声等待等不能作为免费侧信道。允许通信与计算重叠、交互编码、发送端内部任意计算；交互中 receiver 发出的消息只由其既有状态和已收到的 transcript 决定。若用随机协议，要固定双方已共享的随机种子并要求该种子下零错误。接收端持有的本源 s=r 部分不计跨 cut。
3. 所有可能输入必须在相同语义和协议下精确恢复，且不是只要求后续投影的结果。

在固定 `z` 下，可区分远端原始比特组合数是 `M=2^N`，其中

`N = 16 × 28,672 L = 458,752 L bits = 57,344 L bytes`。

如果有两个不同组合得到完全相同的入站 transcript，receiver 因状态相同而无法对两者输出不同且正确的相应元素，矛盾；因此 transcript 与这 `M` 个输出必须可区分。若 transcript 最多 b 位且长度本身可辨识，长度 `0…b` 的二进制串至多 `2^(b+1)−1` 个。取 `b=N−1` 时这个数小于 `2^N`，因此**至少存在一个**合法原始输入需要 `≥N` 位入站信息。固定长度编码恰好发送 N 位，说明该抽象通信复杂度下界紧；这不证明硬件、软件可达到它。原始 BF16 容纳任意位组合只是证明域假设，不由算子实际数学输出证明。

若变长编码带前缀自由/自定界且位流边界不免费，可由 Kraft 不等式得到最坏 `≥ceil(log2 M)` 位；以上较弱的无前缀枚举论证对 `M=2^N` 已同样给出 N。单个输入可压缩到少于 N 位；这里结论是**完整输入域中的最坏输入**，不是所有输入逐次都必须传 N 位。若免费公开消息长度、帧边界、无限细时间、发送次数/静默或者其他控制信道，接收侧可能从这些信道获得信息，上述单独的 payload bit 界不成立；应把该信道容量和时延纳入模型，或在接口约束中显式禁用。

## 真实模型可达集合和已有信息

实际模型的输入、权重、inverse RoPE、运算舍入、路径和 BF16 NaN 处理可能限制元素之间的组合；padding 和缓存也可能让远端元素已知或关联。因此 `2^(458,752L)` 不自动等于真实可达状态数。固定接收端侧信息 `z`，定义 `S_r(z)` 为所有符合模型、工作负载、状态和精度规则时，receiver 必须区分的**远端目标输出组合**的集合，`M_r(z)=|S_r(z)|`。若 `M_r(z)` 有限且 transcript 不利用免费侧信道，则固定 z 的任意零错误协议的最坏入站比特数至少

`b_r(z) ≥ ceil(log2(M_r(z)+1)) − 1`。

这只是长度可辨的宽松计数下界；若只已知空集之外有一个可能输出，则仅为 0 位。某个输入分布和前缀码的平均消息长度可用条件熵约束，但必须先确定概率分布，且平均界不等于每次或最坏物理界。实际 `S_r(z)` 的非平凡大小、对应历史请求域及 bit-exact 语义目前 **UNKNOWN**。

若 receiver 已经持有远端副本、相同信息可从共享 HBM/CPU/缓存取得、计算可在本地重做，或源/接收侧在窗口之前协商和预传，那么 `z` 或可用边界发生改变，必须以条件可达集合重新计算；如果外部读取穿越本 cut 也需要计入相应信息，不可把通信消失只算在别处。固定已经经过训练的权重亦可能通过函数约束降低可达集合大小，不能把训练激活直接当自由的 16 位向量。

特别注意：F15 当前源码物化 head 交换后调用投影，但若优化允许在发送侧先投影、只向 receiver 交付最终投影输出、对中间值融合/重算，要求 receiver 区分的集合可能大幅改变，且归约和浮点舍入规则可能限制可行方法。此时 `57,344L` **不是**对所有语义等价端到端实现的必要通信量；必须另证明下游函数的可区分输出、矩阵秩/量化映射或 bit-exact 行为，才能收紧。

## 由信息到条件时间及行率

若进一步证明对每一种允许执行、从窗口开始到接收端完整结果完成的每个时刻 `t`，该 receiver cut 的所有入站信息（包括并行路径、协议和侧信道）满足累计物理量 `B_phys(t)≤B_r,max × t`，且计入的 transcript 位与实际穿越该 cut 的物理信息可比较，并且所有必要信息都在窗口开始后、完整输出前跨越，则存在上述最坏输入满足：

`T_cut ≥ 57,344 L / B_r,max` 秒。

若允许初始突发 `b` 字节且只证明 `B_phys(t)≤b+B_r,max×t`，对应下界改为 `T≥max(0,(57,344L−b)/B_r,max)`。长期平均带宽不自动满足逐前缀容量约束。

这里 `B_r,max` 是对实际指定边界、方向和可用所有并行通道成立的**硬上限**，不是测得吞吐、带宽采样、链路标称双向值，当前为 UNKNOWN。把通信与计算重叠后，全操作仍至少需要满足这个界；不能把该界与计算总时间盲目相加，也不能由某个平均延迟断言所有请求达到。

接收端本次完整结果有 `P×L=8L` 行，在 **L≥1、T_worst>0**，并固定上述 raw 任务域、接收初态及协议、输入均要求正确且同一窗口按最坏输入计时的条件下，其行率的最坏情况满足

`8L / T_worst ≤ B_r,max / 7,168` 接收行/秒。

这不是模型输出 token/s：每行的含义、padding、层数和端到端 token 归属不同；也不是每个请求的逐次吞吐上界。多轮流水若预先传输或复用数据，需扩展状态和窗口重新证明。

## L=3 纯算术例

若人为设定 L=3、三行都有效、完整 BF16 原始域和上述条件均成立，则某个最坏输入对一个 receiver 要区分 `86,016` 个远端元素，即 `1,376,256` bit = `172,032` byte = `168 KiB`；receiver 的结果共有 24 行。L=3 **不是**本次运行的实测分片长度，168 KiB 也不是实测流量。

对其他 receiver 单独均可写自己的最坏情形，但每个 receiver 的最坏输入可能不同、cut 也可能重叠；没有证明一个共同合法输入同时触发各界、总拓扑资源对应及不重复计数前，不能把这些逐 receiver 最坏值直接相加当真实整机界。

## 复现及证据

运行 `python3 agents/scheduler/f15_receiver_cut_bound.py`：先重算 F15 索引 witness 所引用四份源码 SHA 并匹配，再输出 P/H/D、符号每 L 字节数、L=3 算术及 2-bit 玩具集合的穷举计数。它是本机 CPU 上的整数/文件哈希复核，不运行任何集体通信、NPU 或模型，也不证明历史运行时 dtype/分支或理论容量。

独立复核见 `F15-RECEIVER-CUT-INDEPENDENT-REVIEW.md`：L=0 时行率可能为 0/0；时间下界需要完整输出完成前的物理 transcript、逐前缀带宽和允许突发的说明。此修正不证明这些条件在 169 上成立。
