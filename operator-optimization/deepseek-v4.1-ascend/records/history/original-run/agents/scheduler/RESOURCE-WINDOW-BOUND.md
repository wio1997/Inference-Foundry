# 算子、通信与调度的理想时间下界：依赖 + 资源窗口

这是一个**严格限定了执行域的通用模板**，不是 169 的 TPS 结论。它说明怎样比“分别算访存、计算、通信再取最大”更紧，同时仍然允许可行的重叠、分块流水、抢占、异步调度和不同请求并行。

## 1. 必须先约定什么

固定计时窗 `[0,T]` 和有效输出 `Q`，假设已经证明：

1. 对该执行域内每一个合法实现，某个共同的任务图中的任务都必须发生，图的边代表**完成到开始的必要依赖**，任务可以细分到实际允许的 tile 粒度。不确定的边不要加入；允许改变算法、复用或预计算时，不能直接把现有实现的算子图当共同任务图。
2. 每个任务 i 在明确的资源 r 上必须消耗不少于 `w_i` 的**互不重复**工作量；资源 r 的总处理速率任何时刻不超过 `C_r`。例如严格定义的存储 cut 字节数及该 cut 的读写合计速率上限。必须证明各任务无法用另一条资源通路、共享一个结果或消除工作；资源或工作无法证明就保留 UNKNOWN，不能把实测最好值当硬上限。
3. 每任务有效执行的起点和终点之间有已证实的最短跨度 `d_i ≥ 0`。可令未知 d_i 为 0 以放松模型；不能把测得平均值、软件启动耗时或完全可被融合消除的实现边界当不可避免时延。
4. 计时起点之前已经在缓存、预取、预计算和已有输出中的内容要在模型初态中允许；`w_i` 只能包含进入窗口后仍不可避免的工作。资源可以在任务间任意分配和抢占；不同资源可同时工作。

对应合法调度集合称为 D。若从更宽的用户理想域到这个图的包含关系没有证明，得到的只是在 D 中的条件界，不是全体实现的通用上界。

## 2. 如何算

在图中使用每个 `d_i` 忽略资源争用，得到：

- `a_i`：从时间 0 开始，到任务 i 能开始之前的最长必要前驱路径最短时间。
- `b_i`：任务 i 结束后，到完成所有输出仍必须经过的最长必要后继路径最短时间。
- `L`：从输入到输出的最长必要路径的最短时间。

对任一资源 r、非负阈值 a、b，选出 `S(r,a,b) = {i | resource(i)=r, a_i≥a, b_i≥b}`。**仅当 S 非空时**，任何属于 D 的合法调度都满足：

`T ≥ a + [Σ(i∈S) w_i]/C_r + b`。

证明：集合内每项工作不可能早于 a 开始；每项工作结束后离最终完成至少还需 b，所以所有这些工作只能占用 `[a,T−b]`。该资源在任何时刻总速率不超过 C_r，而每项工作量互不重复，所以 `Σw_i ≤ C_r(T−a−b)`。整理即得公式。此证明允许集合中的任务交错、抢占，以及与其他资源并行。

求所有使 S 非空的 r、a、b 的最大值（若没有非空集合，该项取 0），再与路径界取最大：

`T_lower = max(L, max_(r,a,b: S≠∅)[a + Σ_(i∈S)w_i/C_r + b])`。

这包含普通资源总量界：令 a=b=0 就得到 `T ≥ Σw_i/C_r`。资源容量、任务量、依赖或精度约束只有在已证实且适用时才允许代入；**可证明的下界越大，其对应 TPS 上界 `Q/T_lower` 越小、越紧**。模型不需要找到达到该值的调度。若 Q=8192 仅限合同中一次完整 8 请求、各输出 1024 token 的计时窗，分母须使用同一个窗，不能套在单次 kernel 或 profiling 窗口上。

## 3. 小例子：为什么依赖和共享资源要一起算

4 个 tile，每个都需要依次搬入 1、计算 3、搬出 1 个时间单位；搬入和搬出共享一个 IO 资源，计算使用另一资源，各自容量为 1。假设这些工作和 tile 边确实都是不可避免的。

- 单条 tile 依赖路径是 5；IO 总工作是 8；计算总工作是 12。单纯取最大得到 12。
- 所有计算至少在首次搬入之后开始，所有计算结束后还要至少一次搬出。取计算资源窗口的 `a=1, b=1`，得到 `T≥1+12+1=14`。
- 示例脚本给出一个合法的 14 单位调度作为算术自检；**理论上界成立不依赖找到这个调度**。不是所有图的下界都能被达到。

换成每 tile 搬入和搬出各 8、计算 3，共用同一个 IO 资源，则仅 IO 的总必要工作就给出 `T≥64`。首搬入 + 所有计算 + 末搬出为 `8+12+8=28`，在此例是更松的下界而非真实最优时间：不能假定全部搬运总能藏在计算后面。

反过来，如果实际提供独立读写路径，必须分别建资源，不能把双向字节强加到单一资源上。若 I/O 和算力共享某个中间硬件，还需有证据才能建立该共享资源 cut。没有证明共享就不做强制相加。

## 4. 一个重要反例：过粗的依赖边会高估下界

如果一个 10 单位读操作可以拆成 10 个 tile，每个读 1 单位后对应计算 1 单位立即开始，读和算资源不同，则流水只需 11 单位。把整个读取和整个计算画成不可拆分、全完成后才能开始的两个节点，会得到 `T≥20`，这是错误地排除了合法流水。对 169，`全量通信→全量计算`、`一整层→下一整层` 等边只有在确实无法逐块就绪时才可加入；同步点和 chunk 粒度应由源码、接口和真实数值语义分别证明。

## 5. 对当前 169 基线怎么使用

候选是从已冻结的 F05 Q 量化/投影、F21 MC2、F23 MoE 输出与残差等边界建立**多种逐步放宽的图**：

1. 先定义实际观察图与理想图；标出已融合的 MC2 内部哪些工作、scale/精度及每个状态写确实需要，保留分片和所有消费者。
2. 不把 graph replay、kernel launch、当前屏障、一次调用的全部输入、通信等待直接画成必然边。对于存在多条实现路径或跨层复用的节点，先证明共同必要子图，不能为方便算数固定现有实现。
3. 每个资源填写**可追溯的硬能力上限**，每个节点填写已证明的最低工作；不知道就写 UNKNOWN。现有 `agents/bounds/` 的条件量和产品规格不能直接当硬上限。
4. 对每个细化版本重新算公式，结果标明合法实现域、初态、时间窗和计量单位。只有证明新的约束对该域内所有实现都成立，才能用于收紧上界；域变窄就只能标“条件界”，不得与宽域无条件界混为一谈。
5. 与基线比较时明确端到端 Q=8192 与实际测量窗；局部 40 层或 profiler 数据不能直接替代端到端时间。

## 复现

在任务根目录执行 `python3 agents/scheduler/resource_window_bound.py`。它采用有理数精确计算拓扑路径和有限阈值资源窗口，生成同目录 `resource_window_bound.v2.json`，校验两个示例及一个合法调度。脚本计算的是输入模型的数学结果，**不会证明输入图、工作量或硬件能力符合 169**。

## Q / Indexer 输入量化：逐行必需信息与末尾因果时延的条件资源窗口（2026-10-30）

已保存 EP3 layer36 中两次分别归属主 Q 与 Indexer 的动态量化 host→设备 flow，其物理输入均为 BF16 `[1023,1280]`，输出 INT8 同形和 `FLOAT [1023]` scale；源码条件下两分支消费变量 `qr`，但尚未绑定同一 tensor、有效行、实际量化数值和每条 buffer 的生命周期，见 `agents/fusion/F05-F09-SHARED-QR-QUANT-REVIEW.md`。下述将这个**观测形状借作条件接口**，不是称采样就是所定义的输入或执行域。

定义一个可复现的限制域：1023 行、每行 1280 个 BF16 原始槽，行首固定 `1`，其他 1279 个坐标在全 `0` 与“任意一个坐标改为 `2`”的输入族中变化，各坐标独立可寻址；全部行的 scale 均在选定窗口内作为可观察输出，按 `max(abs(row))/127` 定义，要求足够精度以区分 `1/127` 与 `2/127`。对这一输入族要求确定性正确（也可固定无误差随机实现的随机种子）；不假设历史请求覆盖该族，也不假设实际最终模型输出能观察所有 scale。取基准输入为所有行第一坐标 1、其余全 0，则任取其中某行一个非首坐标，将该元素由 BF16 `0x0000` 改为 `0x4000`，仅这一 bit 变化，但该行 scale 由 `1/127` 变成 `2/127`。因此每个此类坐标都是该行输出的可区分信息源，逐行融合、分块、预先处理**与本次输入无关的**常量都不能取消这一语义区分。

进一步限制为原始数组在线探测域：该 bit 只在窗口开始后确定、每个坐标的不同 bit 均位于不同的原始字节地址；初态及允许的其他途径不含关于这次变化的副本、max/scale 摘要或预计算结果。观察输入只允许检查原始 bit/字节，不允许带有输入信息的额外 oracle、旁路、内存端规约或压缩摘要；地址／控制流也不携带免费输入信息。只要算法对全域正确，在上述基准输入执行中就必须检查每一个该差异 bit：若漏掉某个，翻转它之后所有已观察信息和输出仍相同，无法同时输出两个不同 scale。于是这一次基准输入至少涉及 `1023×1279 = 1,308,417` 个不同 bit 位置；如果观察以原始字节为单位，则至少涉及同样数量的**不同字节地址**。这不是有 1,308,417 bit 的输出信息，也不是默认的 HBM 流量或所有真实输入的读量；宽域若允许上游生成时顺便提供归约摘要，该独立数组探测限制就不适用。

这两个逻辑消费者若确实读取相同输入、需要相同的确定性量化结果，且允许在指定 cut 的同一接收域共享一次探测及其结果，那么一次满足上述条件的探测即可供两者共享；**不能**仅因为观察到两个 DynamicQuant 任务而将 1,308,417 再乘 2。若分支的输入、语义或初态实际不同，或两个消费者位于不同接收域而所有可用传输路径、广播和副本未证可共用，则各 cut 的通信与必要量必须分别证明；既不能无条件翻倍，也不能保证没有额外信息传输。该界不要求生成中间量化 tensor、两个 kernel、整 batch 完成后才启动投影，也不要求数据访问、各行归约、其他 token、通信或其他模块互相串行。

进一步给出一个可放入资源窗口计算的、带初态和尾部依赖的条件式。仅在下列条件都另行成立时：

1. 这些 `W=1,308,417` 个不同原始字节地址的观察都必须在窗口内通过**同一个指定 cut**，并计为相互不同的字节；不能由已缓存信息、广播重用、压缩、另一路径或上游摘要满足。选定 cut 的累计完成字节对每个窗口前缀满足 `Q(t)≤β+B t`，`B>0` 为其全部并行路径合计的严格速率上界，`β≥0` 是短窗突发或已在途计数信用；信用不代表输入可在窗前已知。
2. 对这 `W` 个观察中的每一个，能够独立证明：从其信息进入接收侧，到关联行的 scale 正确、可观察地最终发布，至少还有 `δ≥0` 秒的物理因果传播时间；这一证明必须覆盖并行提前计算、推测、查表、重排和逐行/逐块输出，不能把现有 kernel、barrier 或实测时间当作 `δ`。该信息在窗口内进入，相关行输出均在 `T` 前发布。

选出**最后一个**完成上述必要观察的时刻 `t_last`：由容量包络，`W≤β+B t_last`；由所选信息到对应可观察 scale 的必要传播，`T≥t_last+δ`。因此

`T ≥ δ + (W−β)_+ / B`。

计算不同于直接把各阶段时长相加：只有最后一个必要信息到其相应最终发布所需的 **已证明因果传播下界** 才能加上，所有其他行的计算、访存和主 Q/Indexer 分支均可并行与流水。与无尾部假设的 `T≥(W−β)_+/B`、单独 `T≥δ` 相比，若 `W>β` 且已证 `δ>0`，此式更紧；若所有分支预先算好、信息到达后可即时选择且没有正的已证传播下界，应令 `δ=0`。该论证在没有已证明 cut、byte 必须跨 cut、`B`、`β`、正 `δ`、scale 可观察契约和输入族可达性的真实情况下不能代数代入。它也不表明 `1023` 是实际有效 token 数，不能与单个 profiler 任务的 19.580 / 19.300 µs 比为性能差距，更不能输出真实硬件 TPS 上限。

CPU 复算输入族和计数：`python3 -c 'r,d=1023,1280; print(r*(d-1),hex(0x0000^0x4000),1/127,2/127)'`。源接口公式及主 Q/Indexer 调用位置见上面的 F05/F09 分析；CPU 算术不是 NPU correctness 测试。

### 独立复核：量词、时间和实际样本的区别（2026-10-30）

上述决策树论证的量词是：一个固定的确定性算法须对输入族的全零其余坐标和每个单坐标为 2 的变体都正确；在**同一次全零其余坐标执行**中，如果任何一个对应的差异 bit 没有被观察，则该执行与只翻转该 bit 的执行具有相同已见信息、控制选择和输出，矛盾。故该次执行须观察所有 `1023×1279` 个不同位置；不要求在一次输入中同时出现 1,308,417 个数值为 2 的元素，也不要求输入族包含全部可能的 BF16 数组。该对抗论证不以各行值在真实模型中独立可达为前提，但应用到真实模型时必须另证相应输入族及可观察 scale 确实属于合法合同。

在字节模型里，数量针对包含差异 bit 的 **不同原始字节地址**；整 BF16 值、缓存行、总线事务或 HBM 控制器物理字节的个数均未由此证明。一个读取动作可覆盖多个地址，其覆盖的必要字节可用于容量账；但不能把动作数量、bit 位置数、去重后源地址数、压缩后的链路字节数混作同一个量。只有附加证明这些不同原始字节都在本窗口经过指定 cut，且以同一原始字节口径计入该 cut 的包络，才能使用上面的 W/B 式。

时间证明还需要：`t_last` 是这 W 项**全部完成进入对应接收域**的最后时刻；`δ` 是该最后项的信息变化到关联行 scale 最终发布的跨实现物理因果下界，不是完成整个 batch 的同步耗时。若把“从最后字节到 scale”置于同一位置、允许用输入到达时同步选择已预计算结果，并不能单靠逐行数据依赖证明 `δ>0`；缺证时取 0。若满足上述假设，逐行、跨行、Q/Indexer 两消费者和其他资源的提前计算与重叠均已包含在放松域中；最后一项不能在 `T−δ` 后到达是结论，不是额外规定全 batch 栅栏。

这个条件模型确实排除了两类**在其限定域内**的错误界：把共用输入的两次设备任务自动记为两份必要探测，以及已经证明正 δ 后仍把“最后必要字节到达”和该字节的因果传播当成完全可互相覆盖。它不排除现实中两分支实际需要不同数据或不同传输，也不能证明真实 169 有上述输入、scale 对外可见、指定 cut、正 δ、速率上界或任何可量化的性能差距。尤其允许上游 producer 在数据流中融合归约并交付摘要、输入已驻留或改变可观察合同的宽域，数组读取证书本身不再适用；未知只限于这些结论，不能推广成全模型无法分析。
