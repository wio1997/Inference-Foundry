## 绑定与计数解释

对 EP0、EP3 各层四条样本，用各自历史 rank 下数据库的 `streamId/taskId/modelId/startNs` 精确联合匹配 `TASK`，各一条，globalTaskId 分别为 2574、3392、2380、3198，且各自在该 rank 的 TASK 表唯一，每条查出 28 个 PMU 条目。对应 PMU 时间戳比 TASK 结束分别早 1、20、20、20 ns；结合唯一性支持关联，但导出器契约及采集误差仍未独立证明。对于 L36，若只用 ±1 µs 而不是精确开始时间，EP0 和 EP3 各有 2 个候选；避免错误归属。

EP0 L15 和 L36 的 `aic_total_cycles × aic_mac_ratio` 数值分别约 18,407,052 和 20,014,813，条件为 PMU 归属正确及所存值算术有效，故可以排除“这两条数值乘积完全相等，差异仅是分母变化”这一精确假设。该乘积**不是 MAC 数量或实际工作量**，不能排除相同有效工作，也不能据此说明性能瓶颈。EP0 L15 的 AIV MTE2/MTE3 比例约 1.92%/0.51%，L36 约 3.46%/2.73%；这些字段不等价于整体设备利用率或有效带宽，互相不可简单相加。

## 任务前后时间线及限制

在各自本地记录中，对每条 L15 MC2 只检查**同一 scope 内已唯一关联、同流、开始时间在 MC2 之前的记录**：最近一个都是 `MoeGatingTopKHash`，其结束到 MC2 开始间隔 EP0 为 1.340 µs，EP3 为 2055.040 µs。近邻判定仅限已关联记录，不保证覆盖全部同流任务、同步事件或图运行时活动，因此间隔不是空闲、排队、同步等待或调度耗时的证明。

跨 rank 设备时钟同步、同一次具体集体通信、peer 执行依赖均未证实：不能从某 rank 的相对时间推断其他 rank 等待它，不能断定低比例由通信、主机下发、专家不均衡、缺少矩阵计算或者插桩扰动导致。既有源码和元数据清点未发现这些选定历史调用绑定的逐专家值或容量：shape `[1023,6]` 不能替代实际路由分布。

下一步应先查 EP3 的这段 2055 µs 在已保存**完整同流 TASK 和同步记录**中的覆盖与事件，而不是只查 scope 命中的算子；若存在空隙，仍需核对采集完整性及同流调度/同步记录，空白不等于未执行。若缺乏可绑定的阶段标记及逐专家值，应保留多种解释，不推断根因。
