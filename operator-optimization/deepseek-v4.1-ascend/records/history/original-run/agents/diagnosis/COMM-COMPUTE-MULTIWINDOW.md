# 既存 EP0/EP8 多窗口通信与计算区间对照

对照既存 `rank_gaps.csv` 中 EP0、EP8 各 ordinal 1、6、7 六个互不重叠的本卡窗口：上一目标层 39 MC2 结束到下一目标层 0 开始。窗口是锚点间隔，不等同于完整 forward、请求或某模块。前序层角色归属和同请求关联仍有限。逐卡核对导出 CSV SHA-256；输入摘要、完整窗口起止和各字段记录在 `comm-compute-multiwindow.json`。脚本 `query_comm_compute_multiwindow.py` 读取原 CSV 和原锚点，断言输入哈希、窗口不重叠与并集等式。基于同一设备同表时间戳，Decimal 微秒转纳秒，每窗口独立计算，不做跨卡时钟相减。

锚点沿用历史文件的层标签，其中 ordinal 1 和 6 的前序 eager 层角色尚未独立验证；因此这些窗口以保存的锚点为准，不能把名称直接提升为已证实的目标层边界。

规则与 `EP8-WINDOW7-COMM-COMPUTE-OVERLAP.md` 相同：只取正时长、与窗口相交、stream/task 非 N/A 的行；`Type` 前缀 `hcom_` 为通信，`Accelerator Core` 为 `AI_CORE`、`AI_VECTOR_CORE`、`MIX_AIC`、`MIX_AIV`、`AIC`、`AIV` 且非 hcom 为计算。分别按窗口裁剪求区间并集，交集用两并集与合并并集计算，并独立遍历所有通信/计算对交叉校验。

所有窗口各有通信及计算记录，选中行均未跨越窗口边界；六窗口内选中通信和计算流无相同 stream，逐对交集也均为零。EP8 ordinal 7 精确复现原报告结果。未发现有重叠的选中窗口；不应为了凑有/无对照扩大范围或推断不存在任何重叠。

这些只是已导出行的时间戳交集，时钟对设备执行区间的误差、采集完整性和真实任务覆盖未核实；hcom 记录可能为汇总或有嵌套，融合 MC2 的内部通信和计算无法拆出；未选定类型、AI_CPU 和 stream/task 为 N/A 的汇总行被排除。它不能证明设备所有通信与计算不重叠、任务依赖、通信不可隐藏、关键路径或预期收益，也不能直接与线上无 profiler 的吞吐等同。本结论无新 NPU 工作、无目标实现改动。
