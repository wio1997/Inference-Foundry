# 最低比例榜：不同任务和同名不同形状的可比性

## 发现

原排名在 AIC、AIV 之间分榜是必要的，但即使都落在 AIV 或 AIC 内，**单一流水比例的大小也不能直接作为不同任务或模块的整体 NPU 利用率排名**。TensorMove 是名称所标识的搬运类任务，观察到其 vector 显示为 0.0%；同一已核验 EP8 任务的数据库 vector 为非零约 0.0231%，MTE2、MTE3 相关字段分别约 42.0%、46.6%。这已经排除“vector 显示 0 就意味着此任务所有硬件流水均为零”的解释；数据无法证明具体数据流、实际带宽、整体空闲程度或根因，也不能把这些不同流水比例直接相加。参见 [原始 PMU 精度核验](TENSORMOVE-EP8-PMU-PRECISION.md)。跨任务比较同一计数器作为定位线索可以，但做“最低模块利用率”结论需要任务应使用哪些单元、各单元分母和可重叠关系，不能由名称单独决定。

此前榜单每个原始名称所列的值是**不同物理签名中各层组的最小值**；这对发现异常有用，但不代表该名称所有任务具有同一形状，也不对应模块总体水平。以 digest `8c18c293…` 的 `aclnnMatmul_MatMulCommon_MatMulV2` 为例：

| 已有八卡可比组 | 每卡输入及权重形状 | 八卡周期加权的显示 AIC MAC 比例 |
|---|---|---:|
| 同名所有合格组的最小值，层 14 | BF16 `[643,5120]`、`[32,5120]`；输出 `[643,32]` | 6.8381% |
| 同名出现最多的固定物理签名，40 个层组 | BF16 `[643,5120]`、`[1280,5120]`；输出 `[643,1280]` | 最低 42.3807%，最高 50.9477% |

两种输入和输出形状明确不同；仅凭算子名或物理形状不能绑定其逻辑模块、有效工作量或可优化空间。最低组不代表主形状，也不是该模块平均值。全部合格组中此名称共有 135 个组、7 种物理签名；40 是出现最多签名的层组数，而非 40 次独立端到端试验。

## 固定相同原名和物理签名后的筛选示例

`DispatchFFNCombine` 在四个 digest 各自有 40 个合格层组，且组内同 digest、原名、CSV Type、芯片核心类型、输入输出 shape/dtype/format 及每卡任务数相同。每个层组均是八卡周期加权显示 AIC MAC 比例：

| digest 前缀 | 40 个层组的最低值（层） | 最高值（层） |
|---|---:|---:|
| 1b826883 | 0.4891%（14） | 18.0086%（36） |
| 7ddf7ae9 | 1.6268%（14） | 7.2453%（36） |
| 8c18c293 | 0.1372%（0） | 4.6667%（28） |
| db852bff | 2.7863%（15） | 27.5324%（36） |

这是更有意义的**同一记录签名内变动**，不是证明同一实际专家路由量、内部工作构成、层之间可交换，或归因于调度/通信/计算。不同 digest 不保证形状相同，不应直接比较成同一工作负载。该组是混合计算与通信的复合任务，AIC MAC 单一比例无法概括其全任务利用率。

## 覆盖及下一步

候选来自既有 1,280 个 layer scope 的 53,918 条唯一关联设备任务；6,862 个物理签名组中仅 4,930 个满足记录字段完整且八卡数量一致，其中 AIC 合格 1,596、AIV 合格 3,966；不合格和缺失组不能填零。同步事件、通信事件、无指标任务和捕获外任务均不应按这张榜补齐。采集有测量开销，也无法据此估计线上时延或给出全模型最低模块。

可进一步优先对同一固定签名内差异较大的 DispatchFFNCombine 层追查现有每卡原始计数、调度/专家路由可见元数据及时间线，核对有效工作量和输入状态；若无法建立等工作量和单个任务依赖，只能保留为待解释现象。无须先将 copy 与数学算子按 vector 比例强行合并排序。
