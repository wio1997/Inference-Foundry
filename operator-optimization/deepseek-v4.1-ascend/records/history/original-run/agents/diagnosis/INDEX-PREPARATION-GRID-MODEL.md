# 索引整理的条件性逻辑分块模型

`prepare_grid_partition_model.py` 复算保存的 Python helper 的分块与程序循环规则，针对上一轮 32 条同名采样任务对应的三组输入形状。当前 32 条 `COMPUTE_TASK_INFO.blockNum` 均为 48；`gridDim` 和 `blockDim` 字段值在已查询数据库的 STRING_IDS 中解码为 `N/A`，不能将其当作真实 grid 大小。

**以下是条件模型：**假设所选任务确由该冻结 helper 产生，且 `get_vectorcore_num()` 返回 48，相关 compile/runtime 逻辑未更改。仅凭采样的 `blockNum=48` 不能证明这些假设。按源码和 K=512 计算，每块 8 行，grid=48，各逻辑程序分配连续块：

| 行数 | 样本数 | 逻辑块数 | 非空程序数 | 每个程序分配的块数：0 / 1 / 2 / 3 |
| ---: | ---: | ---: | ---: | --- |
| 595 | 8 | 75 | 38 | 10 / 1 / 37 / 0 |
| 643 | 8 | 81 | 41 | 7 / 1 / 40 / 0 |
| 1023 | 16 | 128 | 43 | 5 / 0 / 1 / 42 |

这说明在给定假设下，部分启动的**逻辑程序**循环体没有块；它不能直接解释为同数目的物理核心闲置，也不能推断全芯片利用率或 profiler 计数。另一种理论上的均衡分配可令 48 个程序都分到块，但对这三个例子，单程序最大整块数仍分别为 2、2、3；因此仅凭消除空程序也不能证明关键路径缩短或提速。实现是否允许不同映射、尾块、对齐、缓存、寄存器资源、跨流并发和调度开销都需要另行判断。
