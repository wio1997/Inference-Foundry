# F08 独立 scatter 接口的信息下界（条件证明）

## 样本与问题

已有只读分析 `agents/fusion/f08-actual-triples.json`（SHA-256 `e6c18bd23809d47652cc58faf8d5ac81f7879be0e483fc72d70264cd3a3940d5`）记录 1,280 个已选三任务 scope，其中 640 个 scatter 输出参数形状包含 `8180,512` 的 BF16 更新数据。`agents/fusion/F08-KV-NORM-ROPE-SWA-REVIEW.md`（SHA-256 `d27ff96234a52e0c6e453d97951d1b9fa7c6a68f593fe47176fd41a57375477b`）已指出：8,376,320 是 values 的逻辑容量，并不自动是 HBM 实际或必须流量。本分析不假定历史样本的 slot 唯一、数值独立、地址和时间窗口已绑定，也不假定参考实现与这次设备任务完全绑定。

## 人工限定的独立接口语义

把一个 scatter 问题单独作为精确接口来讨论，并非声称历史整模型必然提供这个接口。固定接收侧初始 cache、索引和外部状态，使 8,180 个有效槽位两两不同，每个槽位恰写入 512 个 BF16 元素。每个更新元素独立从 256 个有限、正的 BF16 编码 `0x3f00` 到 `0x3fff` 中选择；例如把 BF16 看成 16 位编码，这一范围不含 Inf 或 NaN。接收侧最终必须能以原样 bit 精度观察上述全部元素；对于不写入的其他位置也要保持原契约。

指定一个信息 cut，将更新的独立选择留在源侧：源输入只在窗口开始后获知，窗口开始时接收侧的存储、预处理、共享随机种子、在途信息与其他所有输入均固定，不包含可区分本次选择的副本或摘要。所有可使接收侧获知源选择的路径，包括其他设备、host、共享内存、控制、长度、消息边界、终止、时序和静默等，都必须包括进该 cut 的有限离散 transcript 或由其他已计算在内的有限编码承载；不允许免费的无限精度时间信道。允许融合、重新分块、预计算与重排、计算复用、对输入无损压缩、交互及其他任何实现，不要求原始设备 task 或 HBM 布局。

这是比固定执行某一 kernel 更宽、但仍是特定独立接口和人为输入族的条件域。如果真实数据只能产生部分这样的组合，或 cache 最终状态不必保持 bit 精度可观察，或存在已知副本与旁路，此界不自动成立。

## 证明

元素数 `n = 8180 × 512 = 4,188,160`，可选输入总数 `M = 256^n = 2^(8n)`。槽位不重复，故其中每两个不同更新数组得到不同的可观察最终 cache 状态。

固定接收侧初态及随机种子。若两个更新数组穿过 cut 的完整入站 transcript 相同，则接收侧不能区分二者，无法对两者都输出不同且精确的目标 cache。即所有 `M` 个输入的 transcript 必须互异。对长度最多 b bit 的可变长二进制 transcript，一共只有 `2^(b+1)-1` 种；如果声称所有输入最多 `8n−1` bit，则只能区分 `2^(8n)-1 < M` 种，因此**至少存在一个合法输入**，需要传递至少：

```text
8n = 33,505,280 bit = 4,188,160 byte 的可区分信息。
```

这是该人工输入族的最坏情况界，不是所有输入各自都要传这么多；全常数或事先已知的输入可以被更短地编码。即使恰好收到 33,505,280 bit，也并不推断任何具体算法实现或者其报文开销；如果时间、消息长度等本身带信息，须把其占用的编码或能分辨的状态计入总量。

当且仅当整个 cut 所有通道在同一窗口的任意前缀具有可证明的离散信息硬容量包络 `I(t) ≤ β + B·t`（包括窗口前在途信息对应的信用 β，B 为 bit/s），且上面的终态必须在本窗口内交付，则对这个接口族中的**至少一个**输入，`T ≥ max(0, 33,505,280−β)/B`。并行计算、搬运与该项可能重叠；跨不同资源的必要界只能按已证依赖和容量组合，不能无条件相加。实际 169 的 B、β 未证明，因此不带入数字。

该结论是不同于「8,376,320 字节必须写 HBM」的独立条件界：它限定接收侧必须观察精确 cache 状态，量的是可区分信息，并覆盖融合及压缩；若物理模型没有把其它信道、初态或容量计入，它不等于 HBM 交易字节，也不是模型 TPS 的上界。现有观测不能证明历史请求中 8,180 个槽位不同、独立取值可达、scatter cache 终态就是对整模型必要的外部契约、或用户输出必须依赖所有值。特别是上游 RMSNorm/RoPE 和固定权重可能使 reachable 状态集远小于 256^n；另有初始 cache 命中和旁路时，必要通信可能远小于此界。

要将本界用于真实样本，先证明相同请求、cache 初态和实际槽位的绑定与唯一性，定义 bit 精度及是否允许替代最终 cache 物化；然后为已允许的上游激活及模型权重推导可达结果数下界（不是只拿张量形状），确认窗口前缓存/传输和所有跨 cut 路径，最后取得该 cut 的短窗口硬容量和突发信用。任一缺失时，本次实际数值界保持 UNKNOWN。不能用更多同样缺少数值/身份的 profile 来补足可达性证明。
