## 补充：固定客户端协议下的解压后 SSE 字节界

两份 `evidence/fixed-output-conditional-bound.json` 中的详情 JSONL 已重新哈希，均与记录一致；每轮 8 条成功记录，输出 token 汇总均为 8192，prediction 的 UTF-8 字节和分别为 32628 和 33024。复核只打印数值，不输出预测文本：

```python
import hashlib, json, pathlib
j = json.loads(pathlib.Path('evidence/fixed-output-conditional-bound.json').read_text())
for s in j['samples']:
    data = pathlib.Path(s['input_path']).read_bytes()
    rows = [json.loads(x) for x in data.splitlines()]
    assert hashlib.sha256(data).hexdigest() == s['sha256']
    print(len(rows), sum(bool(r['success']) for r in rows),
          sum(len(r['prediction'].encode('utf-8')) for r in rows),
          sum(r['output_tokens'] for r in rows))
```

在历史客户端确用与 manifest 一致的源码、对象不被额外改写、`prediction` 由普通 completions 流的 text 片段累加形成的条件下，`output.py` 的 content 与 reasoning_content 均初始为空，`vllm_custom_api.py:179-185` 只将每个 `choices[0].text` 追加 content；`vllm_prefix_cache_api.py:150-186` 对收到的每个非 DONE SSE 数据块读取原始 `raw_chunk` 后调用解析器。`RequestOutput.get_metrics` 会清除 content 和 reasoning_content 字段，所以 JSONL 中没有 content 字段**不能作为** reasoning 为空的证据；这里依据已核验的正常源码路径及未改写条件。

定义边界为客户端 **aiohttp 可选 HTTP 解压完成后，SSE 迭代器向应用交付原始字节块** 的逻辑接口。对应正常 JSON/SSE 文本字段的 UTF-8 或转义编码字节数不会少于恢复后文本的 UTF-8 字节数，且每轮所有文本片段均须通过该接口。因此，保持此客户端协议和这些固定输出时，聚合所有请求，在所记录客户端窗内至少交付 32628 / 33024 字节；模型融合、服务器预计算或网络层压缩不改变此逻辑接口的已解压结果。客户端发送请求前记录各请求起点，每个非 DONE 数据块在读取并解码后、JSON parse 前记录时点，而汇总窗为最早起点至最晚时点；据此所需文本块已于窗口内到达。若历史路径另有定制、文本合成、数据初始状态或时间记录被改写，此推导不再自动成立。

这是**逻辑 API 字节交付量**，不是内存总线拷贝、TCP/HBM 流量或模型算子必要数据量。若另证明同一客户端计时窗口内、所有并发请求及可用交付路径的累计交付量对任意前缀满足 `Q(t)≤β+B_decoded,max t`，其中 `β≥0` 是按该逻辑字节口径计量的初始突发/在途信用，`B_decoded,max>0` 为聚合包络斜率，则 `T≥max(0,D−β)/B_decoded,max`；当 `β<D` 且同一窗口对应的固定成功输出为 8192 token，`TPS≤8192 B_decoded,max/(D−β)`。两轮各自代入 `D=32628` 或 `D=33024`，不得把一轮的文本与另一轮的窗口混用。**仅在另证 β=0 且对全部前缀成立时**，这两个系数才分别简化为 `(2048/8157)B_decoded,max` 与 `(32/129)B_decoded,max`；若 `β≥D`，这个包络只给出零延时下界，不能据此给出有限 TPS 上界。该接口的物理容量与 CPU/解码路径、内存、调度、共享及分块依赖尚未定义或证明，`B_decoded,max` 和 `β` 均 UNKNOWN；不可用单次实测速率、网卡参数或已被数据路径绕过的 HBM 参数代替。并发请求与计算、通信可重叠，其他有效时间下界取最大，不直接相加。改动客户端协议或使用不同输出内容时必须重新证明该轮的 `D` 和输出 token 数。

短窗口信用反例：如果只知某资源的长期速率为 `B=10 B/s`，同时允许初始突发信用 `β=100 B`，则 `Q(t)=100`（`t>0`）满足 `Q(t)≤β+Bt`；例如 `0.1 s` 内已交付 100 B，却违反错误推断的 `T≥100/10=10 s`。这是数学包络反例，不是断言历史客户端存在此信用或该事件物理实现可用。必须以真实窗口、该解压后接口的计数约定和所有并行路径为对象另证 `β,B`；不能拿未经绑定的 NPU 或网卡参数替代。CPU 可复算（不读取请求或运行设备）：`python3 -c 'from fractions import Fraction; print(Fraction(8192,32628), Fraction(8192,33024)); assert 100 <= 100+10*0.1 and 0.1 < 100/10'`。

## 单请求可绑定的逻辑输出下界与符号速率界（2026-10-29）

此前已有两轮 8 请求聚合的 SSE 字节界；这里取**第一轮 details.jsonl 第 1 行**，绑定到一个具体的单请求结果而不是 8 请求总和。复核该文件 SHA-256 为 `7f175801a7f9d181126aaf30c9cec3deb5966f1a14e51695eab8549cc664c96f`；此行 `success=true`、`output_tokens=1024`，其 `prediction` 的 UTF-8 编码长度是 **4068 B**。这是客户端留存的输出数据及客户端报告 token 数，既不是 NPU 工作量，也不是服务端逐 token 轨迹。

假设该请求确实使用已核对的客户端源码、标准 completions SSE 解析与字符串拼接路径，且最终 `prediction` 等于本行留存文本：这条请求的 `choices[0].text` 片段必经 **该请求的 aiohttp 解压后 SSE 迭代接口**，其 JSON 文本表示所占字节总量至少为 4068 B（JSON 的必要转义可增加字节）。这不需要假设文本在服务器侧实时计算；服务端缓存、投机生成、网络压缩和多请求并行，都不会使这个**指定解压后客户端逻辑接口**上该请求最终文本部分的字节数小于 4068 B。若协议更换、客户端另有解码/生成内容路径、采集实际对象不同或保留文本不同，则不能直接套用。它不是 TCP/PCIe/HBM 物理传输字节保证，也不证明任何具体 NPU 算子必须运行。

若相同请求从发送前客户端开始计时到包含**最后一个贡献文本的 SSE chunk 已交付并处理**所需时间为 `T_request`；再独立证明该请求实际使用的所有输出交付路径满足短窗口容量包络 `Q(t)≤b+B*t`，其中 `B` 为字节/秒的严格硬上限、`b` 为可提前缓存/在途数据形成的最大初始突发预算，且这 4068 B 均需在所选时间窗口交付，则有：

`T_request ≥ max(0,4068−b)/B`，且若 `b<4068`，该请求的从请求开始到最后文本到达的平均输出率满足 `1024/T_request ≤ 1024 B/(4068−b)`。

当 `b=0` 只是额外假设时，才简化为 `T_request ≥ 4068/B` 和 `1024/T_request ≤ (256/1017)B`。这不是基线 Decode TPOT、单次迭代的理论下界或服务器算力上界：计时包含请求发起后的所有阶段，不能直接换成首 token 后的 TPOT；其他请求争用、host、计算、通信可重叠，须将其他独立有效下界取最大值而非逐项相加。**B 与 b 未获证明，因此尚无数值极限。** 就算之后得到该界，也只限定固定客户端协议与该条固定文本对应的端到端输出交付；它不能回答 NPU 算子的极限。

CPU-only 复核（不打印输入/输出文本）：`python3 -c 'import json,hashlib,pathlib; p=pathlib.Path(json.load(open("evidence/fixed-output-conditional-bound.json"))["samples"][0]["input_path"]); data=p.read_bytes(); assert hashlib.sha256(data).hexdigest()=="7f175801a7f9d181126aaf30c9cec3deb5966f1a14e51695eab8549cc664c96f"; r=json.loads(data.splitlines()[0]); assert r["success"] and r["output_tokens"]==1024 and len(r["prediction"].encode("utf-8"))==4068; print("verified",1024,4068)'`。本轮仅读已有结果，无 NPU 任务。

## 多请求逐流交付约束：共享总容量之外的条件界（2026-10-30）

沿用上节固定输出、客户端协议及同一整体计时窗的前提，将第 `i` 个请求的最终 prediction UTF-8 长度记为 `D_i`。如果额外证明：对每个请求，窗口内其解压后 SSE 逻辑交付路径的累计交付满足逐前缀包络 `Q_i(t) ≤ β_i + B_i t`，其中 `B_i>0` 是涵盖该请求所有允许交付方式的速率硬上限、`β_i≥0` 是该口径下的初始突发/在途信用，那么完成全部请求的窗口时长满足

`T ≥ max_i ((D_i−β_i)_+ / B_i)`。

证明：所需文本的 SSE 字节属于该请求的流，且在该窗口内交付；对每个流分别在 `t=T` 代入包络，得到 `D_i ≤ Q_i(T) ≤ β_i+B_iT`，再取最大值。若另有适用于同一窗口和接口的聚合包络 `Q_all(t)≤β_all+B_all t`，应取

`T ≥ max(max_i ((D_i−β_i)_+/B_i), (ΣD_i−β_all)_+/B_all)`。

这个关系容许流间并发、计算和通信重叠，不要求流对应独立物理设备或服务器实时生成文本；即使多个流共享 CPU 或链路，逐流包络经独立证明后仍可成立。反过来，**只知道聚合上限并不能推出每条流的上限**：如果全聚合容量都可以被一条流使用，就没有理由套用单流 `B_all/8`。逻辑接口包络也不能自动由网卡、NPU 名义带宽或一次实测推得；不同请求的起始时刻及缓存/在途初态必须包含在包络的证明中。若某流 `β_i≥D_i`，该流不能提供正的时间界。

为说明为何独立逐流限制可能比总量限制更紧，采用**假设示例**：8 个流分别具有相同硬包络斜率 `B`、每个初始信用为 0，且聚合上限取 `8B`。重新核对两份 details JSONL 原始 SHA 后，第 1 轮 `ΣD_i=32628`、`max_i D_i=4095` 字节；第 2 轮分别为 `33024`、`4144` 字节。逐流下界分别为 `4095/B`、`4144/B` 秒，总量界分别为 `4078.5/B`、`4128/B` 秒。假设成立时的对应 8192-token 总输出 TPS 上界分别为 `8192B/4095`、`8192B/4144`；总量界则分别为 `8192B/4078.5`、`8192B/4128`。逐流下界只比这些假设的总量界高约 0.405% 和 0.388%；这是固定文本字节分布的数学结果，**不是推理加速空间或已证明的硬件上界**。

各流 `B_i`、`β_i` 和具体数据路径目前均 UNKNOWN；这些约束只能作为将来证据齐备时可收紧的交付路径条件界，不能推导 NPU 计算容量、模型实际瓶颈或本机数值 TPS 上限。保留上节聚合公式，使用哪个更紧取决于各自证明条件与数值。

只读复核方法：读取 `evidence/fixed-output-conditional-bound.json` 两条 manifest 指定的 JSONL，校验各自 SHA-256、8 条成功记录和 `output_tokens=1024`，对各 `prediction.encode('utf-8')` 求长度的最大值与总和；不输出文本，不运行设备。原始文件和认证哈希见上节。

## 两段窗口汇总观测值与可行下界的严格口径（2026-10-30）

若把候选解集合 `A` 定义为能完成这两轮各自固定请求及输出合同，并允许各自**与历史执行相同的初态及前置准备**；同时目标函数明确定义为 `S(a)=16384/(T1(a)+T2(a))`，其中两段都使用上述同一客户端记录规则，并且历史行为确属 `A`，那么集合上确界 `sup_(a∈A) S(a) ≥ S(历史执行)`。约 519.8441 是这个条件性命题的观测近似值；严格的数值下界还须考虑计时、token 计数和运行身份不确定性。特别是分母不含每轮 seed、两轮之间的空隙和 HTTP `[DONE]` 后处理，**不能**将它视为两轮连续墙钟吞吐、任意冷缓存/不同请求的可达下界或长期稳定吞吐。也不能把某一轮的 522.3665 与两轮合并的 519.8441 当作同一个目标函数上的可比最优值；分母、输入和初态不同。

若按已核验的 `VLLMPrefixCacheAPI.stream_infer`、`default_perf.py` 与 `default_perf_metric_calculator.py` 正常路径，客户端先在 POST 前记起点，再对每个非空、非注释、非 `[DONE]` SSE 数据块在 JSON 解析前记时间；每请求 end 是其最后一个此类记录，整轮取最大 end 减最小 start。这不等于最后 token engine 产生、最后数据解析完成或整个 HTTP 请求退出的准确时刻。客户端源码与历史保存哈希相符，实际导入和额外运行时改写仍有边界，详见 `stage-101-local-benchmark-client-review.md`。实际 NPU/系统的不可超越吞吐上界仍缺硬容量与不可避免工作量证明，不能从任一观测速率反推。没有新增设备负载。

## 两轮组合目标：分窗界须分别成立（2026-10-30）

历史公开的 `519.8441 token/s` 对应 `S=16384/(T₁+T₂)`，而不是连续墙钟或单轮速率。对同一两轮输入、输出合同及两个客户端时间窗，若对**每个合法实现**分别证明每轮时间下界 `Tᵢ≥Lᵢ≥0`，则即使每轮内部的 NPU 计算、通信、搬运和请求之间完全重叠，仍有 `T₁+T₂≥L₁+L₂`；当和大于零时，`S≤16384/(L₁+L₂)`。这里相加的是目标函数定义中的两个窗口时长下界，不是假设同一窗口内不同资源串行；两个窗口之间的准备和间隔仍不计入该目标函数。不同实现若允许前一轮提前准备下一轮的数据，对下一轮采用的初态信用和容量证书须覆盖该行为，不能把第二轮假设为独立冷启动。

作为说明，套用上节同轮逐流接口条件：假设两轮每条流的解压后 SSE 接口都分别有相同经证明的硬斜率 `B>0`、零初始突发信用，且全部固定文本通过对应计时窗口交付，则两轮最长流分别为 `4095`、`4144` B，得到 `L₁+L₂=(4095+4144)/B=8239/B`，因此 `S≤(16384/8239)B≈1.988591 B`。若另一个条件分析只提供两轮聚合 `8B` 包络、同样无信用，其界为 `(32768/16413)B≈1.996466 B`。只有逐流和聚合两套包络都单独成立时才可比较；前者的条件延时下界高约 0.396%。这些都是**逻辑接口条件界**，并非本机 B 的实测或 NPU 上界；真实 `B` 与信用未知，不给出数值 TPS，不构成优化收益。

复算（纯 CPU）：`python3 -c 'from fractions import Fraction as F; print(F(16384,4095+4144), F(16384*8,32628+33024), float((F(4095+4144,1)/F(32628+33024,8)-1)*100))'`。历史每轮输入、输出及各自时钟窗与上一节相同；这条组合式仅新增同一双窗口目标的逻辑表达，不证明任何实际资源容量。

## 部分请求共享容量：争用条件下的子集界（2026-10-30）

上面的逐流界和全体聚合界并未描述一部分请求共享受限路径的情况。仍沿用固定客户端协议、固定输出及同一完整客户端计时窗，任选请求集合 `S`，并将其所需输出文本 UTF-8 字节数之和记为 `D_S`。实现域明确限定为：这些固定文本必须经过该客户端的解压后 SSE 逻辑交付接口，且客户端通过已核验的 JSON text 路径恢复文本；JSON 转义及网络压缩允许，解压后的 JSON 表示占用至少对应文本 UTF-8 长度。若改用字典索引、客户端预置内容或其他可绕过该接口文本字段的协议，不能套用这条字节界。若独立证明该集合的全部解压后 SSE 交付，在该窗各前缀满足共享包络 `Q_S(t) ≤ β_S + B_S t`，则有 `T ≥ (D_S−β_S)_+ / B_S`。可以对有证书的各子集取最大值，并与单流和全体聚合界取最大值。这允许请求、计算和通信同时运行；不要求共享路径独占、不把同一资源的重叠时间重复相加，也不能仅凭某个物理拓扑假定这些包络成立。

子集包络不是逐流和全体包络自动推出的新事实：反例中四个流各以 `B` 速率交付，其他流为零，满足逐流不超过 `B` 和八流总计不超过 `8B`，但四流之和为 `4B`，违反子集不超过 `2B`。因此当独立证据确立更紧的子集约束时，它可增加信息；目前没有这种实际资源证书，本节只是扩展公式的适用方式，不是已发现的实际瓶颈。

具体可复现的假设示例：选每轮详情文件的前四条作为 `S`（只是确定性选择，不代表已知部署拓扑）。重新核对 SHA 和 8 条成功记录后，它们的文本字节和分别为 **16314** 和 **16491 B**；全部八条分别为 32628 和 33024 B。假设各轮子集包络速率恰由 `B_S=2B` 的严格上限界定，且 `β_S=0`，则对应下界为 `8157/B` 和 `8245.5/B` 秒。代入同轮已保存的客户端时窗 15.682475529843941、15.834666059818119 秒，只能得到这些假设若与历史观察一致时须满足 `B ≥ 520.1347`、`B ≥ 520.7246 B/s`。这是**假设参数的必要一致性检查，不是所测硬容量、数值 TPS 硬上界、实际争用程度或可达加速**；若初始信用非零，必要条件也随之改变。真实子集资源归属、`B_S` 和 `β_S` 均未知，任何未绑定到该逻辑交付接口的 NPU 带宽不能替代它们。

复核方法：依次读取 `evidence/fixed-output-conditional-bound.json` 中两条 `input_path`，核对其 `sha256`，解析 8 条 JSONL 且验证每条成功、`output_tokens=1024`，对前四条 `prediction.encode('utf-8')` 长度求和。只输出长度和计算结果，不打印文本、不运行设备。

## 固定 JSON 客户端协议的不可省结构开销（2026-10-30）

在上面已核验的客户端源码和未被运行时改写、`prediction` 为该 completions SSE 流中 `choices[0].text` 片段拼接的条件下，可以在不固定服务端算子、生成方式或响应分块数量的情况下，稍微收紧原来仅计文本字节的客户端逻辑接口必要量。每个请求的最终文本均非空，因此至少有一个被解析为 JSON 的数据块，其顶层是对象、`choices` 的第 0 项是对象并含非空 `text` 字符串。忽略允许省去的 `data:` 前缀、换行、空白、其他字段等，含空字符串时最短的此结构是 `{"choices":[{"text":""}]}`，共 **25 个 UTF-8 字节**；字符串 JSON 编码所占字节数不少于解码后的文本 UTF-8 字节数。多个 text 块各有结构开销，其他成功解析块只增加输入，故在允许任意合并分块时，每条非空回答至少需经该解压后接口交付 `D_i+25` 字节。JSON 键的 Unicode 转义不会比字面编码更短。如改协议、客户端直接获得预先填好的文本、使用不同解析代码或文本不同，必须重证。

对两轮已哈希核验的固定回答，8 条都非空，分别得 `32628+8×25=32828` 与 `33024+8×25=33224` B。这比单计文本多 200 B，分别收紧约 0.613% 与 0.606%；这是**逻辑字节必要量的变化**，不是性能提升。还须证明这些字节在计时窗口内通过该接口：包括窗口起点前预备、缓冲或在途的数据；窗口开始前已经通过接口的数据不能重复计入。对已核验的历史路径，请求先记录时间，再读取并解码块、记录块时间；故以对应输入输出不变、相同计时及正常代码运行作为条件，所需块交付位于请求计时窗口。以 `Q(t)≤β+B t` 表示每窗口前缀的交付包络，初始突发或在途信用计入 β，允许服务端提前准备全部输出；若 `β<D`，每轮条件 TPS 上界为 `8192B/(32828−β)` 或 `8192B/(33224−β)`。容量 B 与信用 β 均未证明；逻辑接口不是物理 HBM/网络流量，也不是 NPU 算力。

若额外要求每个请求保留历史成功解析的非 DONE 块数 n，而不是允许重分块，则每个成功解析并使用 `.get` 的 JSON 块至少为 2 字节 `{}`；有非空 text 的块至少为其文本 UTF-8 字节数加 25。对每个非空结果，设非空 text 块数 `q≥1`，因此 `D_i+25q+2(n_i−q)≥D_i+2n_i+23`。已归档时点数减一给两轮 n 分别总计 1767、1762，可得更窄条件界 `32628+2×1767+23×8=36346`、`33024+2×1762+23×8=36732` B。该更紧值依赖固定历史 chunk 数和 timepoint 与成功块逐一对应、正常源码执行等条件；允许把多个块合并时不再成立，不能声称服务必须发同样数量的 chunk，也不把它当宽实现域上界。

复核：`python3 -c 'import json; s=json.load(open("agents/scheduler/frozen-sse-boundary-check.json"))["rounds"]; t="{\"choices\":[{\"text\":\"\"}]}"; assert len(t.encode())==25; [(print(x["phase"],x["prediction_utf8_bytes"]+25*len(x["per_request_timepoints_minus_one"]),x["prediction_utf8_bytes"]+2*sum(x["per_request_timepoints_minus_one"])+23*len(x["per_request_timepoints_minus_one"]))) for x in s]'`。计数归档及客户端源码哈希见 `agents/scheduler/frozen-sse-boundary-check.json`，未打印回答文本或调用 NPU。


### 已观察 token 计数的 JSON 字段进一步收紧（条件逻辑接口）

两轮原始结果均为每轮八条、每条 `output_tokens=1024`；这与文本字节数来自同一轮结果但不是 NPU 执行量。在已核验客户端的未改写流式路径中，output 对象的 output_tokens 初始为 0，`vllm_custom_api.py:140–143,179–185` 由收到的 `usage.completion_tokens` 写入 1024；summarizer 只在该值缺失或 None 时才以 tokenizer 回退。客户端在 POST 前记录起点、接收 SSE 块并在解析前记录该块时点；本段仍以历史源码/采集身份及时间窗口成立为条件。若字段在别处注入或改写、客户端协议变更、usage 所在块不在对应计时窗，则此结论不适用。

一条非空回答必须有 `choices[0].text`，也必须有使最终计数为 1024 的 `usage.completion_tokens`。允许把两项放同一 JSON 块，其空文本最短骨架 `{"choices":[{"text":""}],"usage":{"completion_tokens":1024}}` 为 **60 B**；若分开两个块，最短骨架为 25+36=61 B。直写 ASCII 语法与键不长于其合法 JSON 转义，整数 1024 的 JSON 数字表示至少 4 字节；非空 text 的 JSON 编码字节不少于对应解码后的 UTF-8 字节。多块、额外字段、数据前缀或转义只会增加接口字节。允许服务端缓存、推测、跨请求并行、输出合块、分块和传输压缩；计量边界是压缩解码后的客户端逻辑 SSE 数据，不是网络物理字节。

因此固定两轮各八条结果和指定计时窗的条件下，必要交付量由此前 `D+8×25` 收紧为 `D+8×60`：分别为 **33108 / 33504 B**。若同一接口全部路径具备经证明的包络 `Q(t)≤β+B t` 且 `B>0`，对应 `T≥(33108−β)_+/B` 或 `T≥(33504−β)_+/B`；仅在分母为正时，固定 8192 输出 token 有相应 TPS 上界 `8192B/(D−β)`。这项收紧不能称为 NPU 算力上界或加速空间；B、β、历史运行逐对象绑定仍未知，不能填成数值 TPS。已有下游文本信息界在更宽域中仍可单独使用，不能与该包含文本的 JSON 字节重复相加。
