# 真实负载：执行域、硬件上限与依赖下界复核

## 结论

现有资料足以确定本次服务的启动选项和一个 DSpark 数值依赖链，也能写出在明确条件下可检验的输出组数及延迟公式；**尚不足以证明其等同于任意合法实现的不可避免关键路径，更没有证据给出 169 的无条件数值 TPS 上限**。

## 冻结的服务与用户负载

`evidence/frozen-serve.sh:28` 记录 `method=dspark`、`num_speculative_tokens=5`、eager draft、DP2/TP8/EP、`enable_dsa_cp=true` 和异步调度。`evidence/fixed-output-conditional-bound.json` 记录每轮 8 请求、每请求 1024 输出 token 的两次实际输出、字节数、计时方法和文件 SHA。trace 归属 16 个逻辑 rank，但它们的核、HBM、互联共享关系不能仅根据 rank 数量得出：不能无条件将 16 份单卡名义容量相加。

这些是**已观察到的基线实现域**。用户提出的允许重排、融合、分块、复用或另外设计的理想实现域更宽；既有函数调用、消息数量、屏障和一次提交的 token 数不一定对后者成立。

## 可证的当前代码值依赖

冻结源码 `vllm_ascend/spec_decode/llm_base_proposer.py:1550-1627`：在 DSpark 分支内，第 `idx` 次使用 `draft_token_ids[:, idx]` 求 Markov embedding 与 bias，并基于修正后的 logits 采样，将结果写入 `draft_token_ids[:, idx+1]`；下一次又读取后者。按该代码语义，`seed → draft1 → ... → draft5` 的值依赖存在。独立位置原始 logits 的计算可提前或并行，并行跨请求和向量处理也不被该值流禁止。

这只证明当前代码的值流，不证明每一步必然需要完整内核调用或必须等待一次 kernel launch；对于允许对各个前驱取值提前计算并选择、重新组织算子或缓存等更广泛实现，原代码的执行顺序不自动是硬件下界。具体 logits 对 token 的敏感性也没有逐输入证明。

## 可检验的有条件输出组数

定义一次请求的“提交组”为一次向其输出序列确定并计入若干 token 的事件，必须将首 token 和所有生成 token 各计一次。若进一步证明每组至多提交 `k+1=6` 个 token，那么对于一个完成 `Q=1024` token 的请求，简单计数给出：

`N_request ≥ ceil(Q/6) = 171`。

8 个请求各有 1024 token 时，请求组计数合计至少 `8×171=1368`。多个请求组可以属于同一个批次、在不同设备并行，所以 1368 不是串行次数，也不是设备运行次数。若已证明首 token 必须作为单独组提交，可另推 `1+ceil(1023/6)=172`；当前不采用这项更强假设。

支持线索：`dspark_proposer.py:39-45` 给出 5 个 draft 和大小为 6 的 draft 缓冲；上游 `llm_base_proposer.py:151` 以 `num_speculative_tokens+1` 设置 sampled token 容量。**还需逐段核验实际 sampler、首 token 和服务输出处理路径，才能证实任意一次提交确实最多 6 个、所有 token 都落入这个分组。** 即使证实，这仍是限定 DSpark 提交协议的组数，不适用于可以改变验证/预计算方式的更宽理想域。

## 两类端到端可检验公式

1. **输出 cut，固定输出条件下**：若 8 请求的固定目标文本共 `D_out` 个未压缩 UTF-8 字节均须在同一个客户端计时窗口内经过同一明确的解压后逻辑交付边界、不得通过其他路径绕过，且该窗口内所有请求的累计交付 `Q(t)` 对任意前缀满足经证明的总包络 `Q(t) ≤ β_out + B_out,max t`（`β_out≥0` 是对应口径的初始突发/在途信用，`B_out,max>0` 覆盖所有并行路径），则 `T ≥ max(0,D_out−β_out)/B_out,max`；当 `β_out<D_out`，固定这 8192 个成功输出 token 且采用同一窗口计时，`TPS ≤ 8192 B_out,max/(D_out−β_out)`。只有额外证明零信用的逐前缀包络 `Q(t)≤B_out,max t`，才能简化为 `T ≥ D_out/B_out,max` 与 `TPS ≤ 8192 B_out,max/D_out`。两轮固定文本分别为 32628 和 33024 字节；允许输出文本或协议变化时要重新证明相应 `D_out`，不能直接套用。该逻辑接口不是物理网卡/HBM cut，历史运行时绑定、初态信用和有效容量均未闭合，详见 `agents/bounds/baseline-client-count-provisional.md`。这不是 NPU 算力上界。
2. **多资源及关键路径**：各项定义在同一模型、测量窗、合法实现域的前提下，并分别证明资源的逐前缀容量包络与窗口内必要工作量，`T ≥ max((F_min−β_F)_+/P_max, (D_HBM,min−β_HBM)_+/B_HBM,max, (D_link,min−β_link)_+/B_link,max, L_causal,min, (D_out−β_out)_+/B_out,max)`，其中 `x_+=max(0,x)`、各信用分别采用对应工作量单位，各容量严格为正，`L_causal,min` 本身也须已证明。不同资源可以重叠，故取最大值；任何项的必要性、初态信用或硬容量未证明时应保持符号 UNKNOWN。仅在分别证明全部信用为零时才可写成未扣信用的工作量/容量公式。对于 `F_min` 是否在理想域中必要、各 rank 是否共享容量、通信与计算是否竞争同一硬资源，都必须先单独证明。

## 有限状态转移的并行组合：为何逐 token 值流不是串行 kernel 界

这里构造一个**条件性反例**，进一步说明上面 DSpark 当前源码的值依赖为什么不能直接转成 `K` 次不可重叠的 kernel 下界。不是建议部署，也不是历史运行的数值性能模型。

固定一个请求和长度 `K`，假定每个位置 `i` 的基础 logits、权重和其他确定性的元数据已经可用，所有可能需要的随机数 tape 也在本构造开始前可用。设完整有限状态集合为 `S`，状态须包含会影响未来结果的所有内容：至少前一 token、终止标志，以及必要时 RNG 状态或 tape 位置、采样 metadata 和其他可观察状态。对每个位置定义**确定性完整转移函数** `f_i:S→S`：给定状态与固定 tape，按照原契约进行 logits 修正、采样或 argmax，并产生下一状态。若相关代码存在未包含在状态中的外部副作用、跨请求耦合或不可枚举的在线输入，本构造不适用。

对概率采样，不能简单假设每步消耗一个均匀标量：原实现可能使用一组指数噪声或其他随机数，并且不同路径消耗的数量可能不同。必须将**完整的、顺序和类型均匹配原算法的随机 tape 及其读指针**纳入 `f_i` 的定义；对选中路径，要恢复与原实现一致的随机状态推进、采样结果，以及后续验证实际消费的概率张量和其他可观察输出。若 tape 由外部逐步在线揭示且在选择状态前不可获得，不能将其假设预先可用。若只要求输出分布等价、允许不同 RNG 路径，其证明义务则与逐种子逐位等价不同。

在**理想 PRAM 条件模型**中，先计算每个 `i`、每个 `s∈S` 的函数表项 `f_i(s)`；允许足够多处理器和容量、表项可独立计算，且将构表耗时单独计入。然后利用函数组合的结合律，并行计算前缀：`F_i=f_i∘f_{i−1}∘…∘f_1`。假定同时提供足够的处理器、每个函数表项随机访问和组合为单位时间，Hillis–Steele 扫描用 `ceil(log₂ K)` 轮并行组合；选定实际 seed `s₀` 后，各位置状态可由 `F_i(s₀)` 求出。一次扫描各轮按旧快照更新，避免用到同轮尚未完成的数据。这里具体假设 CREW PRAM 或允许并发读取的更宽模型：多个处理器可在同一轮读取同一个旧表项，写入各自互不冲突的新表项；用于索引和存储状态编号的机器字至少能表达 `|S|` 个不同状态，即至少 `ceil(log₂|S|)` 位，且相关读写和索引为模型中的单位成本。若实际访问模型不允许同地址并发读、需要复制或消解冲突，或者状态索引/表项不能由一个字表示，则必须另计复制、多字读写、同步和访问冲突的工作与深度，不能直接套用该理想轮次作为实际延迟。这个深度说的是**构表完成后的理想函数组合深度**，并不包含构表、随机数生成、表传输、同步、资源竞争、有效输出发布或最终概率张量恢复；并行扫描实现还须保持状态及概率等可观察量的正确对应。

若存在提前终止，可在状态中增加终止态，使后续转移保持该状态并只对原契约允许的位置发布结果；仍需证明结束 token、被屏蔽的后续输出、随机 tape 消耗和所有副作用与原行为一致。不能因为把后续计算放在推测分支就悄然推进全局 RNG 或提前写用户可见状态。当前冻结请求配置包含 `ignore_eos=True`，但这本身不证明所有可能的终止路径或运行时分支。

对于 `|S|` 个状态，函数表至少包含 `K×|S|` 项；一个直接的 Hillis–Steele 表扫描在该理想模型中需要 `O(K|S| log K)` 项组合工作、双缓冲等存储，以及每个转移表项自身的采样/计算成本。实际显存、带宽、设备随机访问、物理并行度及 RNG 访问均不免费，`S` 包含 RNG 指针等状态时可能极大。因而这是证明**值依赖不必对应逐步串行 kernel**的构造，不证明此方案在 910C 上能实现、节省时间、达到某个 TPS 或保留未列的副作用；也不否定原代码按所写顺序执行。真正的实时下界仍需证明输入的在线揭示、可区分性、资源硬容量和输出契约。

可在 CPU 上运行 `python3 agents/bounds/recheck_draft_transition_scan.py`，检查 `K=3`、`S={0,1}` 的确定性玩具表：两轮前缀组合与逐步执行都得到 `[1,0,1]`。脚本 SHA-256 `d99cc0441a6d0e3a0702fb5cf0e0193d6536903bb23247f9bfbd2397e2a35b90`；它不模拟 DSpark 概率、NPU 或性能，也没有修改服务。

## 草稿 Markov 形状候选：受限投影界及查表反例

stage243 在 EP8 两个固定时间窗口的八个间隔中各找到一条 `MatMulV2`，导出 BF16 `[4,256]`、`[129280,256]` → `[4,129280]`；八条时长约 24.000–24.619 μs。同窗 embedding 名称、形状及冻结配置的词表 129280、Markov rank 256 与草稿 `markov_embed→markov_bias` 路径相容，但**尚无 tensor、运行实例、实际有效行或该源码的逐调用绑定**，也未从这些导出字段单独验证 transpose 参数。详细记录和哈希见 `agents/diagnosis/DRAFT-EP7-QUERY-METADATA.md` 的 stage242–243。以下是以该物理形状为参数的受限数学模型，不是声称八条任务已满足所有条件。

限定一个独立投影窗口：四行都有效，确实需要计算 `X[4,256] × W[129280,256]^T` 的完整结果；规定只使用传统直接稠密乘加，全部 `4×256×129280 = 132382720` 个 BF16 MAC 必须在窗口内执行，不允许跳过零值、预计算、重编码、查表或使用窗口前已计算结果。如果涵盖**所有允许计算路径**的硬容量 `P_max`（MAC/s）满足每个窗口前缀的工作不超过 `P_max t`，则严格得到 `T ≥ 132382720/P_max`；仅按该四行输出计的行速率满足 `R_rows ≤ 4P_max/132382720 = P_max/33095680`。这是该算法与时间窗口的限制性工作守恒界，**不是**推理输出 token/s 界，不能将四个物理行直接当四个已生成 token。

若另限定原始 BF16 权重的 `256×129280×2 = 66191360` 字节在此窗口均需经过指定慢→快存储 cut，不允许其它权重副本、摘要或重编码替代；该 cut 快侧初态可提供至多 `C` 个必需字节，且其余都通过该 cut，cut 的逐前缀传输满足 `D(t)≤b+B_max t`，则同一窗口还有 `T ≥ max(0,66191360−C−b)/B_max`。只有当两个模型的前提同时成立，才有 `T ≥ max(132382720/P_max, max(0,66191360−C−b)/B_max)`；计算与传输可能流水，不把两项直接相加。若所有结果还必须经过某输出 cut，可另证明输出数据的不可区分性及该 cut 的初态和硬容量；逻辑 BF16 输出大小 `4×129280×2=1034240` 字节本身不证明实际物化或必要跨 cut 流量。

**为什么传统 MAC 不是理想实现域的普遍必要量。** 当前冻结源码 `DeepseekV41DSparkModel.markov_embed/markov_bias` 将 token id 送入 `DSparkMarkovHead.embed/bias`；已存 `qwen3_dspark.py:48–93` 表示前者为 embedding、后者通过 logits processor 调用 Markov projection。假如固定模型和 processor 对每个合法 token 的该步 bias 都是确定、状态无关且可在窗口前按原数值契约完整预计算，并且完整结果允许常驻或跨允许的边界获取，那么理论实现可按 token 查表，而不必在窗口内执行上述稠密 GEMM。这是说明执行域的反例，不证明 processor 的状态、并行分片、精度、加载或历史调用满足这些条件。

举个容量算术：如果输入 token 和完整输出词表各恰有 129280 个值，且每个预计算输出值确实按 BF16 存储、不考虑其他元数据，整表占 `129280²×2 = 33426636800` 字节，约 **31.131 GiB**；它可按完整 token 索引查找一行。该条件容量不是本机真实分配、建议部署、实际读量或更快的证明，实际存储 dtype、TP 切片、processor 中间状态、舍入以及表的静态有效期均未绑定；预计算也必须保留输出、随机性及可观察副作用。受动态 context 或其他状态影响时，表可能需要额外维度，甚至无法按 token 单独索引。有限查表说明：不能只根据观测 shape 宣称任意融合/预计算实现都不可避免做 132382720 MAC，也不能无条件将该量转为实际上界。

## 理想专家负载均衡与严格性能上界（2026-10-29）

昇腾 [MindIE 2.1.RC2 负载均衡限制](https://www.hiascend.com/doc_center/source/zh/mindie/21RC2/mindiellm/llmdev/mindie_llm0427.html) 将强制负载均衡描述为负载均衡的理论上限，并明确其不能用于正式业务；该页面列出的支持条件是 Atlas 800I A2、DeepSeek R1/V3 及指定 All2All 场景，不能据此断言本次 910C/DeepSeek V4.1/vLLM-Ascend 支持该功能。这里所说的负载均衡上限，不能自动等同于对本任务规定模型和负载不可超越的 TPS 硬上界。

一个纯数学构造说明为什么：假设模型的真实路由导致所有数据已有本地结果和权重，合法执行可在 1 个任意时间单位交付正确结果；另一个强制平均路由的合成工作负载被人为分到远端专家，受构造设定需 2 个时间单位。在两者输出 token 数相同的示例中，真实路由的吞吐高于强制平均负载。时间数字是构造假设，不是任何 Ascend 测量，也不是关于真实任务的判断。除工作量和通信变化外，专家本身不同也可能改变输出；因此强制均衡生成的测量值并不自动限制所有保持原模型可观察语义的实现。

## 三阶段均匀分块流水：有限块数的精确条件模型

这是解释如何把数据依赖与资源争用共同放进模型的**受限数学例子**，不是本次服务的实测或整模型硬上界。定义一个窗口内恰有 `n ≥ 1` 个独立块，每块依次完成搬入、计算、搬出，其各自固定处理时间分别为 `a, b, c ≥ 0`；每一阶段各有一条专属资源，同一资源同时最多处理一个块，三个资源互不争用，可完全重叠；任意块的每个阶段都必须完成前一阶段后才能开始。允许无限缓冲和跨块重排，但不允许将块继续细分、合并或省略任何处理，全部输入都在窗口起点可用，资源无初始在途工作。目标是所有块的结果均搬出的最早时间。

这个受限模型的最短时间恰为

```text
T* = a + b + c + (n - 1) × max(a, b, c).
```

证明下界：对于任意阶段 j，首个块到达该阶段不早于此前各阶段时长之和；该阶段必须累计处理 n 个块。最后一个离开该阶段的块随后仍须依次经过所有后续阶段，故总完成时间不小于“此前阶段时长之和 + n 倍本阶段时长 + 后续阶段时长之和”。对三阶段分别取最大，得到上式。构造达到该下界的调度：令 `d=max(a,b,c)`，每个阶段对第 k 块的开始时刻设为“该阶段之前的时长之和 + `(k-1)d`”。同块前一阶段恰已结束，相邻块在每阶段间隔 d，不会争用；最后一块搬出时恰等于上式。因此在所列假设下它既是下界，也是可达的数学最优值。

例如仅作算术演示，令 `n=1000, a=1 µs, b=4 µs, c=1 µs`，模型得 `T*=4002 µs`；逐块把三阶段相加得到 6000 µs，忽略了相邻块间的重叠。这个例子的时间参数并非设备测量。总工作量单独给出 `T≥max(1000,4000,1000) µs`，但还需首块准备和末块排空的依赖才能收紧到 4002 µs。

这条精确公式**不能无条件当作真实硬件或更宽实现域的下界**：若可以合法改变块数、按更小颗粒提前计算或搬出、合并操作、复用缓存或改变算法，就必须重新界定处理时间与依赖；若搬入和搬出共用一条单服务资源，还必须共同计入该资源的总工作，不再满足三资源独立假设。真实访存、通信、计算还可能争用同一部件、存在多核并行、在途信用和非均匀块，`a,b,c` 并非仅凭某个记录就能确定的硬下界。本任务尚未证明这些参数和约束适用于实际调用，不能将 4002 µs 代入 169 性能预测，也不构成可达提速承诺。

## 多资源替代关系：联合必要约束可以收紧理想界（2026-10-30）

分别求“所有合法实现里最少计算量”与“所有合法实现里最少搬运量”，再取两个资源时间界的最大值，有时会丢失信息：取得两项最小值的可能是**不同实现**。例如抽象模型中的实现可以在计算与查表间自由折中，窗口内非负工作量为 `C`、`M`；假定已经证明每个合法实现都满足联合约束 `C+M≥90`，且资源逐前缀硬容量为 `C(t)≤2t`、`M(t)≤t`。这里的数都是示例单位，不是 169 实测。虽然分别存在 `C=0` 和 `M=0` 的可选方案，因此各自全域最小值都是 0，但不能同时都为 0。把容量上界代入联合必要约束得 `90≤C+M≤3T`，故 `T≥30`；理想化的 `C=60, M=30, T=30` 只说明此抽象不等式组允许等号，不证明任何 NPU 实现能达到。这里两个资源可以全程并行，未相加其各自的实测时间；融合和重新选择算法也已包含在此前提规定的合法域中。

一般地，若为同一服务口径、初态和合法实现域中的**每一种**实现证明工作向量 `w=(w₁,…,wₙ)` 都满足 `Σᵢ λᵢ wᵢ≥W`，其中 `λᵢ≥0` 将不同单位的工作映射到同一证明量；且每个资源都有合法硬包络 `wᵢ(t)≤βᵢ+Pᵢt`，则必有 `T≥(W−Σᵢλᵢβᵢ)₊ / ΣᵢλᵢPᵢ`，分母须严格为正。多个独立必要约束均成立时，可分别求界并取最大值，或将其纳入同一线性规划求最小可行 T。固定该窗口有效输出 token 数 Q 后，才能从正下界转换为 `TPS≤Q/T_min`。β 的单位必须匹配各自资源计数，且共同初态与所统计的工作不能重复。

这个思路说明应寻找**对全部合法等价实现都成立的工作量权衡关系**，不能把某个 kernel 的 MAC、权重读取量或未证实的经验代价直接相加成 W。计算、通信和存储可以代替或共享工作时，λ 和 W 必须由完整信息流/计算复杂度论证；取一个来自现有实现的工作向量并不证明联合约束。现有 169 证据未给出覆盖任意融合、缓存和重组方案的非零 W，亦未给出对应的实机硬包络，所以本节**不提供该服务的数值性能上界**。它的贡献是明确可能比逐资源独立最小值更紧的证明目标，而不是把示例误称为测量或可达速度。

## 动态量化独立接口的条件信息界

### ID 补齐与映射的独立接口条件界

以已保存 320 条 pad 的物理 shape 为参数，INT64 `[595]→[643]` 的原始数组表示分别为 **4760 B / 5144 B**，其中尾 48 个输出为 384 B 的常量零；这不是实际 HBM 流量，也不是必要物化量。现有配置 `text_config.vocab_size=129280`，以下人工输入族只是假设每个原始位置都可独立取 `[0,129279]`，不声称历史输入的可达集合或具体值已被采集。

定义一个**独立精确输出接口**，要求 `y[i]=0` 当 `i≥595` 或 `x[i]==-1`，否则 `y[i]=x[i]`；限制上面的人工输入族时，该变换对每个输入互不混淆，所以有 `129280^595` 种不同输出。假设接收端初态不含输入或等价摘要，所有可区分信息，包括旁路、控制及可用时间信道，都计入同一个有限 bit transcript；允许压缩、分块、重算和合法融合。长度至多 10102 bit 的所有二进制 transcript 只有 `2^10103−1` 种，而 `129280^595 ≥ 2^10103`，因此该输入族中**至少一个输入**需要穿越此接口至少 **10103 bit** 的可区分信息；若以完整字节记录，至少为 **1263 B**。这不证明每个输入都需这么多，例如全零输入可以有更短描述。

若另证该接口所有路径对该窗口的累计信息传递满足 `I(t)≤β+B t`、B>0，则该输入族**最坏情况**的条件时间下界为 `(10103−β)_+/B`。这是逻辑信息界，不是 INT64 数组读写的物理字节、已观测 HBM 或 169 上界；真实初态、输入可达族、时间信道、硬容量 B、信用 β 和历史数据都未闭合。特别是若只观察 gate/最终模型输出、消费者已拥有原始 ID、或用上游融合/缓存消去此独立接口，则该界不自动适用。该最坏输入也未绑定到 pad 的 104 µs 中位样本，不能拿两者相除声称效率或加速。

纯 CPU 复算 `python3 agents/bounds/f20_id_information_bound.py`，脚本 SHA-256 `95bfd7aa8d74189c0c999c791347982c1840230a47dc98a087c88509c72434ce`，校验已有 pad shape 和模型配置后用整数次方比较；这只核对计数，不证明上面的接口或硬容量条件。

已有一次 shared expert 主机调用关联记录包含 BF16 输入形状 `[595,5120]`，但该次版本的逐位量化语义和真实 tensor 身份未闭合。只借用形状构造独立接口模型：对每行按 `scale=max(abs(x))/127`、`q=round(x/scale)` 输出 INT8 和逐行 scale；限定输入初态只在发送侧，接收侧初态对所有输入相同，接收侧必须精确观察整份 `(q,scale)`，各旁路、控制及时间信道的信息都纳入该边界计数。该语义与 `F22-SHARED-EXPERT-REVIEW.md` 引述的 TorchNPU 7.3 文档相容，不证明历史调用采用该规则。

构造输入族：每行最后一个值固定 BF16 精确表示的 127，其余 5119 个值独立取 0 到 127 的整数。每行 scale 为 1，量化输出原样保留每个整数，因此输出共有 `2^(7×595×5119) = 2^21320635` 种。对于有限二进制记录，所有长度小于 21,320,635 bit 的记录数量不足以区分这么多输出，因此存在该输入族的一个输入必须跨完整边界传递至少 **21,320,635 bit** 可区分信息；按完整字节计至少 2,665,080 字节。这个计数允许压缩、分块、计算重排和重算，但要求所有可用信道的编码都被计入，并非每个输入的下界。

若另有经证明的该完整边界信息传输包络 `I(t)≤β+Bt`（单位分别为 bit、bit/s，且适用全部合法方案及初态），则该输入族的**最坏情况**有 `T≥max(0,21320635−β)/B`。现有 B 和 β 未知，不能与历史 24.3595 µs 记录作数值差距比较。更重要的是：历史实际量化语义、可达激活输入族、输出身份及接收侧初态未绑定；若实际接口允许把量化中间结果融合掉、接收端仅观察最终模型输出，或接收端已持有相同输入信息，本独立接口界不自动适用。这不是 169 整模型的 TPS 上界，也不证明实际 HBM 流量。


## 隔离专家投影的跨设备信息界：条件 GF(2) 秩

这是辅助的条件性算子接口界，不声称适用于当前整模型。借用已存 INT8 第一专家投影形状，固定 `W∈INT8^{5120×4608}`，令 `r=rank_GF(2)(W mod 2)`。设一次动态输入 `x∈{0,1}^{5120}` 只在设备 A 上变化，设备 B 的初态可包含任意与固定 W 有关的预计算或缓存，但对这个输入族均相同。要求 B 在指定窗口内精确得到完整 INT32 输出 `y=xW`；假设 A→B 的单向通信 bit transcript 是 B 获取 x 相关信息的全部路径（含控制、编码和其他旁路的信息），并将任何时间/长度侧信道纳入该 transcript。先限定确定性协议；允许任意计算融合、分块、重算、权重预计算及无损编码。

证明：`y mod 2 = x(W mod 2)`；GF(2) 线性映射的像有 `2^r` 个不同结果，因此完整精确 y 至少有 `2^r` 种可能。B 以相同初态只看到 transcript；若所有输入的 transcript 都少于 r bit，则可用有限二进制串总数至多 `2^r−1`，无法区分这些结果。故至少存在一个输入要求跨 cut **≥r bit**。这并不要求每个输入都传 r bit；只有**通信 transcript 对所有输入强制为同一个固定长度 L bit**时，才由 `2^L≥2^r` 得到 L≥r，故每次实际发送均为 L。固定的是输出张量长度而非通信记录长度时，不能得出每个输入都需 r bit。例如 `W=I₂`、r=2，四种输入可分别编码为长度 0、1、1、2 的有限二进制记录（如空串、0、1、00），只保证最坏长度达到 2；此举还要求解码方可靠获知记录何时结束，长度/结束信道须纳入接口语义，不能假设时间侧信道免费。整数点积在此输入族范围不会溢出 INT32。若 B 的初态已有 x 相关信息，应按相同接收侧初态对应的剩余输入族重算，不能直接沿用该 r。对于多行，也只有证明各行能独立变化且 B 需观察全部逐行精确输出时，才可用乘积输入族给出相应信息计数。

若另证该 cut 的所有可用路径满足 `I(t)≤β+B t`、`B>0` 且窗口内必需传递对应信息，其中 I(t) 是计入所有载信道的协议工作量而非未经证明的 Shannon 互信息，该输入族最坏情形有 `T≥(r−β)_+/B`；与可并行计算项取最大值，不能直接相加。这里的 B 是 bit/s，β 是 bit，均未知。`r=0` 不代表没有输入依赖：例如 W=[[2]] 时模 2 秩为 0，但输入 0 和 1 的精确输出不同；该奇偶界只是可能很松的下界。CPU 小例枚举 `python3 agents/bounds/verify_gf2_cut_witness.py`，脚本 SHA-256 `ab6e95bca1d446af33ff64d6fa6911d882ce44f7d6907e54c8cf2baca742690d`。

**实际缺口：**真实动态激活是否可达该输入族、权重的 r、专家分配、目的侧已有副本/缓存、通信路径与容量、以及下游是否必须观察完整 INT32 中间量都未证。融合可能使 B 只需最终量化/非线性结果，或工作在 A 完成，因此该界不能被直接套到 169 MC2 的运行时、实际跨芯片字节或整模型 TPS。必要性不能由物理 shape 或算子调用名称代替。


**勘误（2026-10-30）：**上节先前将统一长度条件写成“输出长度固定”，该表述有歧义且若指输出张量长度则错误；现已明确为各输入通信 transcript 的统一固定 bit 长度。最坏输入存在的可变长度信息计数不变，但必须计入所有旁路及长度、时间信道；它不自动是物理链路字节界。

对共享随机数协议，上述确定性陈述不能直接写成“某个固定输入在每次随机运行中都至少传 r bit”。例如 W=I₂、r=2，双方共享与 x 独立的随机置换，将四个结果一一映射到可即时解码的前缀码 0、10、110、111；每个固定输入有 1/4 概率只发送 1 bit。若对有限输入族各输入都以概率 1 精确正确，可固定一个同时对全输入正确的随机种子，仍能证明该种子的最坏输入下界；这既不证明某个固定输入每次都达到 r，也不证明平均通信量或有误差概率情形的同一结论。交互式协议若允许回复，必须证明接收侧回复由已计量前缀和相同初态决定，并把所有轮次、结束、时间及旁路的载信信息计入；否则须重新构造证明。
