# 索引整理：接口必要依赖与受限比较排序界

## 对象与边界

针对保存的 `frozen-source/vllm_ascend/ops/triton/prepare_indexer_indices.py:15–56,59–149`，参照 `agents/fusion/F12-PREPARE-SEMANTICS-AND-REORDER.md`：对一行 `selected[0:K]`，在 `0 <= selected[j] < visible` 时保留原值，其余设为无效，排序后输出；允许重复值，且无效以 `-1` 表示。K=512 与部分 profile 输出的 shape 相容，但尚未绑定设备二进制、张量身份、运行时 visible 或输入值。这份分析不认定历史负载满足下面的条件。

## 无比较算法假设的接口依赖：最坏情况所有位置都可能影响结果

限定输入域：K 个位置各自是互不相同的可见合法索引，visible 至少 K+1；该输入行是整理阶段唯一可用的、关于这 K 个索引的精确信息，没有能代替未读取位置的等价摘要或预计算缓存。正确性要求对域内所有输入输出相同的排序结果。

对任一域内输入和任意位置 j，域内至少有一个可见索引 x 未被该行使用。将位置 j 改为 x，其他位置保持不变，排序输出的元素集合发生改变。因此任何正确的确定性适应式算法，若运行到输出时未获取位置 j 的值，则在原行与改动后行上得到同一观察和输出，却至少有一个结果错误。随机算法若要求每个随机选择下都精确正确，同理；如果只要求高概率正确，不能不加论证套用这条界。由于 j 任意，所有 K 个输入位置都必须在逻辑上影响可获得的信息；可分块并行读取、与上游产生过程融合，也可以以等价摘要传递信息。

这不是 K 次 HBM 读取、K 次 kernel、K 次串行指令或 K 倍访存时延的证明，更不是当前运行的实际内存流量界。若上游直接按位置产生结果、携带足够摘要，或模型实际输入受 score、可见性与去重等额外约束，整理边界可以消失，以上接口域的条件不再自动成立。

## 比较排序模型中的受限数量界

进一步假设：要求物化 K 个互异合法索引的升序排列，排序算法仅以二元比较来获取输入元素之间的次序，输出元素只能从输入路由，且所有 K! 种输入排列都属于算法必须正确处理的域。二元比较决策树的每个叶子至多对应一种输入排列所需的输出路由，而高度为 h 的树最多 2^h 个叶子，所以最坏情况下需要至少 `ceil(log2(K!))` 个二元比较结果。K=512 时这是 **3876 个比较结果**（`log2(512!) ≈ 3875.1661`）。

这是比较结果的逻辑数量，允许并行产生，不是设备指令数、比较周期、时间下界或 kernel 数量。整数 radix/counting、键域专用结构、上游直接按所需顺序生成、已知预计算状态以及融合后的不同数据表示，不在该模型中。该界不能直接收紧允许任意重组的推理框架上界。若存在浮点排序 bit 映射、invalid sentinel、重复项与长度输出等细节，也必须保持冻结源码语义；本界仅选了全部有效且互异的子域。

## 如何检验能否应用

需要证明实际运行确实走到相应 helper 并绑定二进制/shape，获取或证明 visible、索引有效性、重复情况和上游选出顺序，并界定可利用的上游信息和输出顺序契约；若要把受限比较数量换成时间，还必须证明实际算法域、资源容量与并行/窗口初态。现有数据不足，因此该文只明确理论作用域，不能作为 169 的数值 TPS 上界，也不能据此解释 profiler 耗时。

## 固定有限扇入数据流中的并行依赖深度

除比较数量外，可以证明另一条**受限的数据流深度界**。取 K=512、visible≥513 的允许子域，以一行 `[1,2,...,512]` 为基准；对任意位置 j，将该位置替换为 0，其余不变。所有数仍可见且互异，但升序输出的首项从 1 变为 0。所以首项对该行全部 512 个位置均敏感。

假定所研究实现可表示为一个**固定、输入无关的有向无环数据流图**，每个非输入节点至多接收 f 个独立前驱值，f≥2；该行全部原始输入在图的边界提供，允许常量，但没有包含输入信息的预计算状态或等价摘要。控制/选择、读地址和其他可能传递输入信息的逻辑，均须包含在该图及其扇入限制内。若首项的计算深度为 d，则逆向可达的输入节点最多为 f^d；由上面的敏感性，它必须覆盖全部 512 个位置，因此 `d >= ceil(log_f 512)`。例如 f=2 时 d≥9。这个推导适用于有无重复的更大合同中所选的上述互异子域，也允许同一层的节点并行，并没有将 512 次输入读取串行化。

它**不是无条件芯片周期或墙钟界**：节点不是已核实的昇腾指令，扇入没有对应实机定义，也没有每层统一的必需最小时延、前缀就绪时刻、初始在途状态或资源容量。硬件宽向量和专用排序操作可能在同一抽象节点合并多个值；若 f≥512，该公式只给出 1 层。若上游已排序、已经给出最小值/等价摘要，或者融合重组后不再要求此接口首项物化，边界与待证明性质都发生变化，不能把此界自动套到整个推理引擎。模型的 32K 真实调用还没有与该输入域、可见数、二进制或输出对象绑定，因此不能将 9 层换算成 169 的算子时间差、可达提速或服务 TPS 上界。

这个深度条件界和前述 `ceil(log2(K!))=3876` 最坏比较数量界回答不同问题：前者限制特定有限扇入图的最长因果链，后者限制比较模型的逻辑比较结果数量；不能把两者相加当时间。下一步如要继续收紧，应优先取证：同调用索引和 visible 的约束、是否必须保持跨层排序共享输出；核对目标设备支持的真实排序/比较原语及其适用形状，并证明覆盖窗口的最小前沿延迟和在途信用。现有资料不能把这些条件补齐，因此这里停止在逻辑模型层。
