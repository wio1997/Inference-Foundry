# 169 新诊断：理论界所需的最小输入与可复算模型

## 使用范围

目的：针对已观察到的 draft MC2、target 第 0 层 MC2、Indexer 和 F16 投影，建立**同一次调用、相同输入和输出契约、明确计时窗口**的证据包。先计算固定实现的工作账和诊断对照；只有再证明工作不可避免且硬件容量适用，才能将条件公式称为理论时间下界/吞吐上界。

负载沿用原业务基线时，记录完整请求参数、32K 输入、1K 输出、并发 8、前缀复用规则及实际命中，不把配置值当作真实命中率。原两轮业务记录各 8 请求、输出计数各 8192，但诊断运行必须重新核对本轮有效输出与计时；不能把旧业务计数与新 profile 强行合并。仅保存匿名、聚合的计数和元数据，不记录 prompt、生成文本或权重内容。采样时间开销、诊断与业务非同一运行的差异要单列。是否能无改码得到下表某项由本机具体工具能力决定；**未提供的记录为 UNKNOWN**，不将没有 API、缺失值或零显示理解为零活动。

### 每条记录共同需要的身份

| 最小字段 | 用途与可靠性要求 |
|---|---|
| 负载/配置 ID、模型与权重版本摘要、容器镜像与运行库版本、采集参数和 profiler 版本 | 锁定实验域；图片/代码快照不自动证明活进程加载同一对象。 |
| 匿名 request、engine、rank、layer、forward/replay、内部任务与 collective 实例 ID，来源及关联规则 | 每项需能追到同次执行；不要用复用的 globalTaskId 或跨卡相同 ordinal 单独认定同次 collective。工具不提供则记 UNKNOWN。 |
| 入口/终点时间、stream、设备与时间单位、时间戳源和误差，冷/热态；重叠区间 | 逐卡先在同一时钟域做差；跨卡对比必须有已证明的统一时钟与误差，不能把各卡时长相加当墙钟。 |
| 实际物理 shape、dtype、layout、stride/转置、tensor 匿名身份/别名、真实有效行和 pad/mask | 不能把 buffer 容量当真实工作量；如 tensor 身份/有效行不可获得，标 UNKNOWN。 |
| runtime 选中的 kernel/binary 标识与 SHA、真实 tiling/block 配置、动态 shape/quant 参数，以及查询来源 | 以执行实例绑定对象；CSV 算子名称、静态源码或已安装 binary 的反汇编单独不足。 |
| 请求入口/末尾、输出 token 数与输出等价/随机性契约，关联的服务生成事件和采集窗口 | 对比端到端 TPS；API usage、指标抓取差值、设备 task 和解码步不是天然同一事件。 |

## 按模块的最小新增字段

| 模块 | 静态已知线索，不能当动态事实 | 需要同次执行绑定的最小数据 | 数据如何取得/缺口 |
|---|---|---|---|
| target 第 0 层 MC2 | 旧样本本 rank 输入 `[3,5120]`、top-k 输入 `[3,6]`；源码读取来自 EP 汇总、再经 `maxOutputSize` 截断的每专家行数。 | 每源 rank 实际有效行与 mask 数，EP group 同次调用成员、每个目标 rank×专家的接收行数、重复/丢弃与裁剪、每段对应 `currentM`/容量、两阶段实际是否处理；关联 kernel/tiling 和任务时间。 | 可从 profiler 导出的匿名元数据/运行时计数取得时优先；否则需要工具原生的匿名张量统计或计数接口，且证明是该 replay、缓冲在读取时未覆盖。仅有 shape 或名称无法提供这些数；不要求记录 token 内容。 |
| draft MC2 | 已保存的六条草稿候选输入为 `[1,5120]`、`[1,3]`，权重导出 `[8,5120,4608]` 与 `[8,2304,5120]`；这不是全部调用/真实有效行证明。 | 与 target 相同的同次、按目标 rank/专家的实际行数、mask、裁剪及实现；增加草稿层/step、预测与接受计数对应关系。 | profiler 可归属则采集；若身份无法对齐、专家计数无法采得，保持 UNKNOWN。服务级 accepted 数不能直接转为某 kernel 工作量。 |
| Indexer / QLI | 冻结配置 top-k 512、32 heads、head_dim 128；历史 buffer 中的 2048 仅是容量，自定义 V3 不可套 V2 契约。 | 对每有效 query 的有效 key/候选数、mask、候选重复数与真实进入各阶段的数量；实际 QLI 版本、metadata 字段命名及 dtype/scale/layout、最终 top-k 的精度和 tie 契约。 | 有公开且版本匹配的 profiler/metadata 接口才可按字段读统计；否则只能标 UNKNOWN。保护请求数据，只输出长度/计数，不采 query/key 内容。 |
| F16 两级输出投影 | 48 对候选 shape 分别 `[24,1,4096]×[1,4096,1024]`、`[24,1024]×[5120,1024]`；EP8 单样本 perm 与 batch_split 和源码相容。 | 两级任务与图节点/tensor 身份、实际逻辑 M/N/K、有效行/padding、stride/轴变换、二级输入是否等于一级输出、真实 kernel/分块；BF16 累加/中间舍入和允许误差。 | 同一次调用的任务元数据或支持的图/算子接口可取则绑定；名称相邻、形状一致或源码中间变量名字都不能替代张量身份。24 物理行不等于 24 个用户输出 token。 |

对各模块，优先记录同一执行窗内各类型 task 及同 rank、同 stream 时间区间；`aic_mac_ratio`、`aiv_vec_ratio`、各 total_cycles、MTE、task duration 和缺失/零字段的原始显示均可供定位。还需采集器的版本、字段单位、block 聚合、MIX/multi-stream 重复和舍入契约，才能决定某字段是否能与另一字段相加或除；它们不是 FLOPs、实际带宽、通信等待或整个 NPU 利用率。

## 必要工作与容量：分别立证

### 可从新运行直接得到/核实

- 对绑定的每次任务记录 `T_obs`（时间窗及误差）、物理形状、有效行、路由和截断数量；若工具提供真实物理操作数/流量计数，保存计数定义、覆盖范围、重复/采样和完整性。没有这些能力时不从 shape 推物理计数。
- 对已经证明的固定实现，按逐项输出的逻辑尺寸和实际有效行核对其工作账；执行路径、精度语义和工作是否在该窗口必须另证。实际数据是历史工作量/可达观察，不能倒推硬件不可超越峰值。
- 对通信记录真实 group、各 rank 的有效跨 rank 流量、collective 实例、端点/流、开始结束与可重叠事件。实际发送字节是固定实现的观察，并非所有等价实现不可避免要传的字节。
- 锁定初态：相关权重/中间结果在设备、L2、片上存储、CPU 或其他节点的可用副本、预取时间、已有结果/共享缓存。仅给缓存大小不能证明缓存内容或 miss。

### 需要厂商或等价一手硬件契约

1. 对该台精确 BOM、每个逻辑设备与物理芯片绑定，指定 BF16 与 INT8 的**全部允许计算路径**，证明每种资源可同时提供的工作上限 `P_r`（MAC/s 或 ops/s，固定 `1 MAC = 2 ops`），包括频率所有合法状态、并发资源、吞吐粒度和前缀/突发条件。必要时分别给 Cube、Vector、Scalar，避免无依据相加。
2. 对选定的 HBM↔快存、跨芯片或 CPU↔NPU **有向 cut**，证明所有可并行路径共享后的前缀容量 `D(t)≤β+B·t`，分别说明字节单位、方向、协议及初始在途突发 `β`。双向标称和当前测得带宽不可直接代替单向硬值。
3. 需要模型输出精度/异常值、路由与 tie、允许预计算/缓存/融合/旁路范围，并证明在给定初态与合法输入范围内某些工作量或跨 cut 信息量不可消除。可观察 API 输出是必要结果，但不自动证明必须执行某个历史 kernel 或全部稠密 MAC。

## 两类模型与可复算公式

### A. 固定实现的条件工作账（不是不可超越界）

仅当采到并验证每专家的截断后有效行数 `a_e`、逻辑权重维度及两个阶段确实使用对应完整传统稠密点积时，令 `A=Σ_e a_e`，对已确认的 `K=5120,N=4608`：

`W_MC2 = A × (5120×4608 + 2304×5120) = 35,389,440 A MAC`。

这是**一个 rank、一个调用、对应阶段**的逻辑账；两阶段处理行数若不同，要分别用 `A1`、`A2` 计算，不能默认相等。跨 rank 聚合前必须绑定同次调用；`A` 是专家行数，不是请求数或输出 token 数。实际指令数、裁剪、零跳过、重复计算与实现仍须验证。

F16 的特定物理 shape 若被进一步确认为逻辑直接稠密计算且 24 行都有效，则前/后分别 `24×4096×1024=100,663,296 MAC` 和 `24×1024×5120=125,829,120 MAC`。其余情况用实际有效行/维度重算。仅在量和时间同一次绑定时计算 `W_logical/T_obs`，其名称是**条件逻辑 MAC 速率**，不是硬件算力利用率或跨请求 TPS。Indexer 可对确认的实际参与 query/head/key、量化与评分分支列逐项工作账；没有真实候选数或 V3 语义就不代入 2048 或 V2 公式。

官方 2201 Mmad 表的 BF16 `16×16×16`、INT8 `16×16×32` 为给定 Mmad 理论模型并行度；对同次真实指令的有效 tile 逐条采得且验证其适用后，可算 padding 比例和模型周期。没有 tile/有效行时只算不确定变量，不把原矩阵输入 M、每专家 M 或存储分形混同。单指令模型不自动成为多指令流水的墙钟界；未确认硬频率、共享资源和其他可并行路径前，模型数不称物理上限。

### B. 可认证的理论界（仅在全部证明条件成立后）

设 `T` 为明确的同一计时窗，`Q` 为该窗内必须完成且口径已绑定的输出数；`W_r,min` 是允许实现域中确实无法省去、必须在此窗由资源 r 完成的工作，且总服务受已证逐前缀硬上限 `P_r` 约束；`D_c,min` 是该窗在有向 cut c 上确实无法绕过的必要信息量，cut 硬容量为 `β_c+B_c t`。则

`T ≥ T_lb = max( max_r(W_r,min/P_r), max_c(max(0,D_c,min−β_c)/B_c), L_critical )`。

`L_critical` 仅在必要因果链和各段的硬最短延时已经证明、且窗口与对象一致时使用；未知项不得填猜测。计算和通信可重叠，以 `max` 合并；只有证明特定阶段不能重叠或共享资源的工作可作和，才可以收紧。预取、已有在途信息和快侧副本必须算入初态或 `β`，不重复扣减。

当 `T_lb>0` 且输出 `Q` 与同一窗口严格对应时，输出速率上界 `R_ub=Q/T_lb`；若 Q 是算子行数，单位仅为**行/秒**，不能叫模型输出 token/s。`T_obs` 是同契约同边界的实际可达时间，`R_obs=Q/T_obs`；证明无误时可算 `T_obs/T_lb≥1` 和 `R_obs/R_ub=T_lb/T_obs`。它表示上界与观测的数学间距，不证明能达到界或能省掉 `T_obs−T_lb`。计时有误差时先给 `T_obs` 的区间并传播区间；不得用独立实验中最低延时作为这个界的硬容量。

若只有厂商标称 `P_nom/B_nom` 或实测最佳 `P_meas/B_meas`，可另外计算**标称/经验模型对照** `T_model` 与 `T_obs/T_model`，清晰记录公式及硬件/工作假设；它可以低估或高估可行耗时，不能称不可超越界，也不能与上面的 `T_lb` 混写。任何 `W_min、D_min、P、B、β、L` 未满足条件时，对应结果显示 UNKNOWN，仍可报告具体缺失项和已观察数据。

## 优先采集顺序与判定

1. 冻结本轮服务/请求配置和可观察契约；确认 profiler 不影响其他任务，记录诊断开销与设备映射。只采获准容器内数据。
2. 同一次调用关联 target 第 0 层与 draft MC2 的有效专家数、kernel/分块、相应时间和通信事件；先判断两组是否同一调用/工作，**没有一致性证据时只描述分组**。同时采 QLI 有效候选数和 F16 真实布局/身份，缺什么标记什么。
3. 分别生成可追溯工作账、实际区间与上下游重叠；明确采集字段无法说明的内部通信和等待。可以用已观测的任务及时间做实现诊断，不把任务间隔当硬依赖或理论必要时间。
4. 找到同机厂商硬容量契约且证明必要工作后，填入 B 模型；否则只输出 A 的固定实现工作账、可复现对照与待证字段。不要以模型间比例当端到端收益。
