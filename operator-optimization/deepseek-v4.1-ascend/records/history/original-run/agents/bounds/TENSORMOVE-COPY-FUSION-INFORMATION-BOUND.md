# EP8 attention 输出 copy：独立接口界与跨边界融合的区别

## 样本与结论范围

[样本绑定](../diagnosis/TENSORMOVE-EP8-IDENTITY.md) 对应 attention 输出路径中的一次 TensorMove，两个输入形状 BF16 `[8184,5120]`，trace 显示该任务 37.0995 μs。逻辑元素数 `n=41,902,080`、每个张量的逻辑尺寸 `2n=83,804,160` 字节。这里的数字只定义独立接口问题的规模；历史运行时张量地址、真实分支和物理流量没有绑定。源码及实际分支条件见 [输出投影接口分析](../fusion/TENSORMOVE-O-PROJ-LINEAR-INTERFACE.md)。

## 对可融合实现依然成立的条件信息界

人为定义一个独立接口：接收侧初始状态固定，窗口开始后源侧获得 n 个相互独立的 BF16 元素，每个取有限正数编码 `0x3f00..0x3fff` 中任一值；窗口结束时接收侧必须能在这些位置观察到逐元素准确的相同编码。要求每一种组合都正确。无论采用 copy、改变生产者写出地址、分块、流水、融合、重计算、压缩或任何其他结构，凡能把这次选择的信息传给接收侧的路径都包括在同一个信息 cut 内；接收侧和所有非 cut 初态不得包含输入副本、摘要或相关预计算，窗口前在途信息须另计信用，长度、控制、时序、静默及其他信道不能免费携带无限信息。

这些条件下共有 `256^n = 2^(8n)` 个独立输入，对应同样多的可观察不同终态。固定接收侧初态和随机种子；如果两种输入的完整有限离散 transcript 相同，接收侧不可能分别恢复两种终态，所以 transcript 必须互异。至多 `8n-1` bit 的可变长度 transcript 一共只有 `2^(8n)-1` 种，少于输入数。因此**至少存在一个合法输入**，要跨此 cut 传递至少 `8n = 335,216,640` bit 即 **41,902,080 字节的信息**；不是所有输入都必须传这么多，不是物理交易字节，也不是 83,804,160 字节的必然 HBM 流量。

如果证明该 cut 包含全部信道，且窗口任意前缀可分辨信息受硬容量包络 `I(t) ≤ β + R·t` 限制（β 是窗口前在途/突发信用，R 单位 bit/s），则对上述接口族某个输入，`T ≥ max(0, 335,216,640−β)/R`。计算、搬运和通信可以相互重叠；仅有严格的因果或共享容量证明才能把时间项相加。实际 R、β 均未证，**不能代入卡的宣传带宽或声称得到真实数值 TPS 上界**。

此界对合法融合依然有效，是因为它针对输入到可观察输出的语义而非 kernel 数量；它同时严格依赖接口假设。历史真实投影输出由固定权重、上游激活及可能的通信约束产生，尚未证明能遍历这些独立组合；历史 graph output 是否需要在该 cut 对面物化、缓存和跨设备路径也未知。因此该界**不能作为本次真实模型的已证下界**。如被观察的只有经后续计算的结果，可能存在多个中间数组对应相同最终结果，必须重新计算可区分终态数；不能照搬此 n。

## 独立 copy 的更强流量条件，以及为何无法外推到融合

更窄的假设：源和目标为两个不重叠的完整 BF16 原始字节数组，源唯一副本在 HBM，目标原始字节必须完整更新至 HBM；数据和地址不可预知、没有缓存或在途副本、没有压缩/转发/额外存储通道；实现必须逐字节读取源并逐字节写目标，且这些读写都通过同一明确的 HBM 服务计量边界。**由这些附加前提**，独立 copy 的边界服务量为 `2×83,804,160 = 167,608,320` 字节；若该边界有短窗口硬容量 `β_B + B·t`，则 `T ≥ max(0,167,608,320−β_B)/B`。该结论来自预先限定的物理 I/O，不能由 tensor shape 或信息论单独推出；内部 DMA、压缩、缓存命中、初态相同或任何其他路径都可能使某个选定边界看到更少服务量。

融合后的生产者可能直接将值写入接收目标，因而**原先那次独立 copy 的额外读写可以为零**；但若目标必须最终物化且初态不含足够信息，仍需满足上面的信息 cut，不能把整个模块的信息传递成本判成零。反例：若 output 与 projected_output 实际完全别名、内容和生命周期均满足契约，那么额外 copy 可以语义等价为 no-op；反之若是独立已存在数组、目标会被独立观察，随意删掉赋值就产生错误。历史没有地址与生命周期证据，无法选定任何一侧。

## 为何不能把 37.0995 μs 当收益

假设一个只用于说明的理想依赖 DAG：投影 10 μs → copy 37.0995 μs → 后续 10 μs，另有独立任务 100 μs。原 makespan 为 `max(57.0995,100)=100 μs`，零开销融合后为 `max(20,100)=100 μs`，收益 0；如果没有独立任务，且其余时长、依赖和资源占用均不变，则收益可为 37.0995 μs。这两个构造不代表真实执行，也不说明融合后的内核不会变慢；实际 producer、consumer、重叠、争用、任务图及运行负载需绑定后才能推断。

## 用这条采样反向检验同窗口流量与容量假设（2026-10-30）

可以用已保存的 task 43441 记录做一个**可证伪的条件检查**，但不能由此推导实际 HBM 带宽。设备 trace 给出该任务持续 `T_trace=37.0995 µs`，同一采集的 CSV 显示 `37.100 µs`；两者不是独立实验。上节 `W=167,608,320 B` 只有在完整独立 copy 的两次原始读写确实均穿过指定共享 cut、且均在这同一个 task 计时区间完成的条件下才是该窗口必要工作。进一步假设 trace 时长精确适用于该 cut 的窗口、其合并读写在窗口任意前缀满足 `Q(t)≤β+B t`，则已观察到的任务与此模型相容必须满足：

`W ≤ β + B × T_trace`，即 `B ≥ (W−β)_+ / T_trace`。

若假设 `β=0`，该次候选运行要与模型相容，`B` 至少为 `167608320 / 0.0000370995 ≈ 4.517805 TB/s`（十进制 TB/s，读写合计）。这是对**假定容量的必要一致性条件**，并非测量的硬件最大带宽、在所有输入上成立的上界或可达到的速度。如果一个经过独立证明、针对**同一设备、cut、方向、计量口径和窗口**的硬带宽上限低于该数，且独立也证实零信用，那么该容量声明、完整读写经过该 cut、时窗覆盖及采样时长这几项中至少一项不能同时成立；无法单凭不等式判定具体哪一项错。

例如仅为校验不等式，令 `B=3.2×10^12 B/s` 为**虚拟假设**而不是本机规格，使用上述时间则需要 `β≥48,889,920 B`（约 `46.625 MiB`）；若同时额外设 `β=0` 就与该组假设及采样时长矛盾。这个信用是容量包络所允许的突发计数，不能直接称为已实测的预取字节。实际资源是否共享、数据是否命中缓存、源/目标是否重叠、cut 是否为 HBM、传输是否在记录时窗内、采集时间误差和硬容量都尚未证明。特别是公开资料中出现的 3.2 TB/s 不得因数值相同而被当成本次设备、方向及短窗口的硬约束；本例无须采用它。

这项检查说明，给定一条同口径实测，可以否定某些过于狭窄的**联合假设**，而不能把实测速率倒过来当硬上限或把矛盾归因为某个确定缓存路径。合法跨算子融合可直接写目标、改变计量边界或省去独立 copy，所以上述 167,608,320 B 不约束所有融合方案；计算和其他工作仍可与搬运重叠。CPU 算术复算：`python3 -c 'from decimal import Decimal as D; w=D(2)*D(8184)*D(5120)*D(2); t=D("37.0995")/D(10)**6; B=D("3.2")*D(10)**12; print(w, w/t/D(10)**12, w-B*t)'`；不读取设备或启动 NPU。

## 投影输出的可达状态：独立元素假设的有限域反例（2026-10-30）

[EP8 投影采样](ATTENTION-PROJECTION-EP8-MODEL.md)将 task 43440 关联到同一 host `vllm::unquantized_gemm` / `aten::linear` 调用：记录输入 BF16 `[8184,1024]`、权重 BF16 `[5120,1024]`、输出 BF16 `[8184,5120]`，host 输入类型第三项为 `None`。同一轮另有前述 TensorMove task 43441，两个 BF16 张量均为 `[8184,5120]`，且位于输出投影调用路径。**同一形状、相邻 task 和调用范围并不绑定两者 storage 或精确数据流**；实际 `W`、归约分支、hidden state、输出位值、历史二进制均未得到证明。

以同尺寸的独立投影接口建立一个受限但包含任意融合和重算的数学反例。令 `X` 是上述形状的 BF16 输入，`W` 是固定 BF16 权重，接收侧已知相同 `W`；规定最终 BF16 输出是一个确定函数 `Y=f(X;W,c)`。这里固定运算顺序、舍入及实现契约，使相同输入有相同输出；所有可能影响输出的 bias、scale、随机状态、其他 rank 的结果、量化参数和其他运行状态均纳入固定参数 `c`。如果某个此类量实际随输入变化，就必须把它纳入变化输入或传给接收侧，以下仅计算 `X` 的数字将不再自动适用。该定义不主张历史多卡执行满足这些条件。

BF16 元素有至多 `2^16` 种编码；所以对于 `M=8184,K=1024,N=5120`，无论函数内部如何计算，输入数组最多有 `2^(16MK) = 2^134086656` 种 bit 状态，而输出集合是该有限输入集合的确定映像，故至多也有这么多可区分状态。此前独立 copy 接口假设每个输出元素可以独立从 256 个编码取值，要求 `256^(MN) = 2^(8MN) = 2^335216640` 种输出状态。由于 `335216640 > 134086656`，**独立输出域与这个固定权重确定投影接口不可能同时成立**。这是计数反例，并不取决于设备执行矩阵乘的算法、融合、分块或并行程度。它不说明这个权重下实际可达多少个输出，也不能以差值推断模型熵或真实流量。

还可构造一种允许重算的逻辑表示：在 `W` 和所有 `c` 已在接收侧、接收侧能以等价实现重算并满足完成时间及输出 bit 契约的附加条件下，源侧传输完整 `X` 编码共 `2MK = 16,760,832` 字节，接收侧重算 `Y`；直接以 BF16 物化完整 `Y` 的逻辑容量是 `2MN = 83,804,160` 字节，前者是后者的五分之一。这只是数据表示与重组的存在性反例；不含发送 `W`、`c`、协议、布局及重算代价，不证明实际硬件支持、总耗时下降、物理流量或某个方向的容量。允许接收端预知的信息、设备资源和 bit 级等价方式都必须真实满足条件；若 `W` 不在接收侧、模型并非确定函数、需要额外通信归约，或原 `Y` 是另有外部消费者的独立契约，不能直接采用这个构造。

因此上节 `335,216,640 bit` 仍然是**人工独立 copy 接口**的有效最坏输入信息界，却不能从输出 shape 自动套用到此固定权重的投影输出，更不能作为该模型或 TensorMove 历史任务的必要流量。任务 43440 的 `320.893 μs` 和 task 43441 的 `37.0995 μs` 仍只是上述不同任务的 profile 时间；既不知道采样输出与源、接收侧初态和模型输入身份，又未证明所有相应合法实现的物理硬容量，所以不能用这两个样本把该计数转换成严格的真实时间下界或 TPS 上界。

复算（仅 CPU 整数运算）：

```sh
python3 - <<'PY'
m,k,n=8184,1024,5120
input_states_exp=16*m*k
independent_output_states_exp=8*m*n
assert independent_output_states_exp>input_states_exp
assert 2*m*n==5*(2*m*k)
print('input elements / output elements:',m*k,m*n)
print('input / independent-output exponents:',input_states_exp,independent_output_states_exp)
print('BF16 input / output bytes:',2*m*k,2*m*n)
PY
```

## 官方带宽测试口径对样本对照的限制（2026-10-30）

复核官方 [MindX DL 6.0.RC1 ToolBox 用户指南](https://www.hiascend.com/doc_center/source/zh/mindcluster/60rc1/toolbox/toolboxug/MindX%20DL%20ToolBox%206.0.RC1%20%E7%94%A8%E6%88%B7%E6%8C%87%E5%8D%97%2001.pdf) §5.6（PDF 第 27 页，印刷页 21）：文档说明 `ascend-dmi` 的 d2d 测试将数据读写总量除以耗时计算带宽，并明确缓存、预取等机制可能使该计算结果超过标称带宽。同章还指出较小传输尺寸或拷贝次数会影响硬件资源复用。此资料说明**逻辑读写总量/时间、某个物理 HBM cut 的真实传输速率和产品标称带宽是不同口径**，不可仅凭一个商用标称值去限制另一个口径的瞬时比率。

上述文档是 2024 年 6.0.RC1 工具指导，不能确认本次 169 所用的工具、固件、产品配置或该 TensorMove 的实际缓存/预取状态；它并未给出 9382 同一设备 HBM 读写方向的短窗口硬容量与突发包络，也不能证明发生了缓存命中。故它为此前对 task 43441 条件一致性检查提供原厂口径警示，**不改变**任务 37.0995 μs 的测量、不判定该条件模型是否发生、不增加可用于 169 的数值硬带宽界，也不证明 4.517805 TB/s 是实际带宽。应停止把该采样的逻辑字节除以时长与未绑定的标称值直接对比；若要升级资源界，仍需同一 SKU、方向及全部通道的短窗口容量和初始信用、实际张量数据/缓存初态，以及保证最终数据跨该 cut 的证据。
