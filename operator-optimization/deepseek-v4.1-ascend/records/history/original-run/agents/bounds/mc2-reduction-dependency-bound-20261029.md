# MC2 动态量化归约的条件依赖界（只读推导）

## 发现与适用范围

冻结参考源码中，MC2 的 SwiGLU 后量化不是逐元素独立操作：每条专家行先生成一组激活值，对绝对值求最大值，再用该最大值求本行 scale 和量化值。具体见 `block_epilogue_pertoken_swiglu.hpp:183–190, 234–277`：`ChunkTileLen=blockN/2`、`Abs`、`ReduceMax`、读取最大值、`GMubDequantScale/127`、`127/GMubDequantScale` 和后续 cast。上游 `dispatch_ffn_combine_kernel.hpp:920–953` 按两段等待 GMM1 和通知 GMM2；它允许分段流水，不能把两次 GMM 的整段耗时与归约耗时直接相加。参考文件 SHA-256 分别为 `baaacd84dc4c29d5efe72b7c7bd3b0cac64db233bc9431bd6fb678390cf2a0ad` 和 `7dcef4c08c4c47e38bdd01aef0dee997798658ee4d7b871c8e6c70f7ffe596ba`。尚未把参考源码与本次样本实际执行 binary 唯一绑定。

以已观察的 [1023,5120] 输入和 [24,5120,4608] 第一层权重**作为条件形状**，若该次实际 `blockN=4608` 且走上述分支，则每条有效行动态归约 `n=4608/2=2304` 个量。这个数是逻辑形状，不是实测指令数、vector 指令条数或真实计数行数。实际有效行 `R` 未知。

## 为什么存在跨元素依赖

考虑有限、非负、任意可变的 2304 元输入向量，输出要求同时包含该行的精确最大值对应的 scale，且不能使用计时前算好的答案或缓存。如果第 j 个量为 1，其他量均不超过 1，将另一个位置 k 从 1 改为 2，会把最大值从 1 改为 2；对精确该语义，结果必须区分这两个输入。因此任意一个位置都可能影响本行 scale，也可能影响位置 j 的量化值（理想算术下 127 变为约 63.5，再按指定 rounding 处理）。这一语义依赖与是否把算子融合无关；逐元素直接独立量化一般不能保留这种动态 scale 语义。

这是**人工规定的独立输入域与输出契约**：实际激活来自固定权重 GMM/SwiGLU，其元素可能相关、非有限值和边界处理也需核实。若 scale 在后续被消去且无需物化、权重或输入受限、容许近似或外部已有该答案，则不能自动套用。该段只证明可能依赖，不能把逻辑依赖直接等同于每个位置必须走一遍比较硬件。

## 可复算的有界 fan-in 归约模型

限定一个更窄、形式明确的执行域：对每一条有效行，使用不与其他行共享结果的精确 max 归约 DAG；每个 max 节点最多接收 `F≥2` 个此前互相独立的值，不能从节点外预知答案；同一行的最终 max 必须依赖全部 n 个输入。在这个纯 max DAG 中：

* 根节点沿依赖逆推最多每层扩展 F 倍，要覆盖 n 个输入至少需要 `D = ceil(log_F n)` 层。
* 每个节点最多把所需连通分量数减少 `F−1`，因此至少需要 `G = ceil((n−1)/(F−1))` 个节点。可通过分组归约和允许不满 F 的节点达到该计数；这是节点数下界，不是实际硬件指令数。

若每个节点从输入准备好到输出可供下一个依赖节点使用的时间，严格不小于 `δ_F>0`，并且总共所有允许归约执行资源有 `C_F` 个此类节点/秒的**不可超越总容量**，又确证 `R>0` 行的完整归约均位于同一目标时间窗，则：

```text
T ≥ max(ceil(log_F 2304) × δ_F,
        R × ceil(2303/(F−1)) / C_F).
```

上述容量项要求 `C_F` 是对该完整计时窗口可完成节点数量的严格界，不能带入未经验证的长期平均速率；若容许窗口开始时有在途节点或可证明的突发信用 `B`，工作项应放宽为 `max(0, R × ceil(2303/(F−1)) − B)/C_F`。初态和 B 未知时不能将无信用版本当作任意短窗硬界。

此处第一个是依赖深度下界、第二个是共享归约资源工作量下界；取最大值允许不同资源、不同 token 和分块完全重叠。若还**同时**满足此前标准稠密两 GMM 假设，且这些工作落入同一窗口，可以再加一个取最大项 `35,389,440 × R / P_max`，不应把这三项当作顺序时间相加。异构节点速率、分区资源或门融合应改用经过证明的相应容量模型；不能将 API 一次 ReduceMax 调用自动视为一个 F 路 max 节点，也不能用单次观测的最快 latency 作为硬下界。

例如 `F=2` 得到深度 12、每行至少 2303 个二元 max 节点；`F=16` 是深度 3、至少 154 个；`F=256` 是深度 2、至少 10 个。三者均是对不同**假设硬件原语**的符号算术，不代表 910C 的 fan-in、指令数或周期；向量归约可在一个指令内并行处理多个值，底层也可能采用不满足这里限定的不同实现。缺少可靠的 `F, δ_F, C_F, R`，**不能给出 169 数值上界或性能差距**。运行 `python3 -c 'import math; n=2304; [(print(f, math.ceil(math.log(n,f)),(n-1+f-2)//(f-1))) for f in (2,16,256)]'` 可复算示例。

## 与更宽理论界的区别及下一步

该界比只按总 MAC 和带宽的理想 roofline 多表达了动态 scale 的有向依赖：小 batch 时，若实际归约资源和延迟经过验证，依赖深度项可以高于简单工作量/峰值项。它不能自动成为允许任意等价算法、近似、预处理或跨算子代数变换的普适界，也不能证明当前耗时或低利用率的根因。要对真实实例使用，依次需要同次 binary 与该源码及 shape 绑定，确认 scale 语义、有效行数、测量窗口和可允许算法域，取得该型号上可证实的归约原语 fan-in/硬延迟/联合容量；任何一项未知都保留符号。

本分析只读已有源码及形状，不访问设备、不修改目标实现、不启动 NPU 负载。
