# 底层资料与接口的自主补证 — PEAK-CEILING-v4

## 目的与角色

为理想基线和每一次收紧提供证据。接口既可揭示某个开销可被消除，也可支持某个受限域的必要约束；当前接口缺少某能力，不代表允许新实现的物理上界也受它限制。

不需要先查出全部实现细节才能建立符号理想 model，不需要证明零开销/完美隐藏真实可达。真正需要查清的是：哪些工作和容量界有依据，哪些约束对声明域的全部合法实现必要。

## 固定检索链

1. 建立 unknown_id：要证的命题、单位/值域、影响哪层上界、需要何种事实或必要性证明。
2. 盘点用户资料、实际配置/源码/头文件、授权容器，以及工具清单提供的搜索、HTTP/API、仓库、设备只读查询、已有 profiler 数据；不猜工具名、API 或命令。
3. 本地用 rg/rg --files；公开网络用官方搜索、HTTP、原始源码或连接器。优先匹配实际产品与软件版本；原始论文用于理论依据，第三方只作线索。
4. 查到具体章节/符号/调用点，核对反面证据。摘要、营销峰值、函数名不单独充当严格上界依据。
5. 保存 source_id、URL/路径、厂商/作者、产品、版本/commit、取得时间、快照路径/SHA、章节/符号、提取方法和适用条件。
6. 写 claim，类型为 DOCUMENTED、MEASURED、DERIVED、ASSUMED 或 UNKNOWN；另写数学用途（必要工作、容量上限、最短延迟、观测、条件前提等）。推导列前提和公式。
7. 映射到 ideal model 或必要约束，保存源到字段的转换；审核其对全部声明实现是否适用。只对某算法/接口/布局成立就限定域。
8. 查清即可停止无关扩展；无可访问证据时记录已查入口和限制，保留符号/条件，不无限搜索或瞎填。新证据形成新快照，再重算受影响的界。

冻结资料后，数学模型应可不访问活网站而复算。输入快照、语义解释、必要性证明和数值计算分别保留；两位模型同意不是证据。

## 每项接口核对内容

使用 ../templates/records.json 的 source/claim 记录，接口说明另存到任务目录并通过 source_id 关联；按影响命题查必需字段，不追求无关接口大全：

- 框架调度→tensor/通信封装→运行时/库→内核/指令的调用链、实际版本、签名和头文件。
- 产品支持与实际调用证据；声明域是否允许新内核、新接口或更细粒度。
- 阻塞 host/stream/device/流水/通信参与者中的谁；入队、执行完成、生产发布、消费可见、host 可读、缓冲复用分别何时发生。
- 输入/输出范围、dtype/layout/量化公式、对齐和最小粒度；逐块生产/通知/消费是否受限制。
- 所用计算/搬运/HBM/链路、共享路径、并发/event/队列限制、参与者匹配及容量。
- 文档空白为 UNKNOWN。单一实现中的限制标为实现事实，未经跨实现必要性证明不降低通用吞吐上界。

不要求为建立理想上界而找到可执行这些理想行为的接口。可以明确放宽当前接口；收紧时才证明哪项限制不可绕过。

## 按命题选证据

| 命题 | 优先证据 | 不足以支撑普适上界的材料 |
|---|---|---|
| 硬件最多多快 | 匹配架构、精度、频率条件的容量上限/指令资料 | 实测有效速度、一次最高跑分 |
| 至少必须算多少 | 模型语义和声明算法域内的必要性推导 | 当前 kernel/指令总数 |
| 必须搬多少 | 初态、存储容量、复用/重算/压缩/分片取舍的下界 | 总权重字节/token |
| 必须等多久 | 跨允许实现不可绕过的依赖与最短延迟依据 | Python 同步、host 调用返回 |
| 不能无限细分 | 对应声明域的指令/搬运/通知粒度保证 | 当前任选 tile 大小 |
| 必须共用资源 | 真实数据路径/容量耦合的证据 | 两类工作名称相同或不同 |

## 测量、冲突与缺失

本阶段优先查资料与已有 trace；缺证据时按 ../PROFILING.md 准备有限诊断采集，在已有授权范围执行。没有授权就保留缺口，不发起优化实验。观测可以帮助发现模型遗漏，不自动证明容量最大值/时间最小值。无法得到严格界时保留条件上界；缺实测字段时记录所需证据及其对结论的影响。

远程查询只在已有授权主机/容器/目录，不能安装或修改宿主环境、停止别人任务。卡占用时继续离线工作。凭证不进公开快照/报告。

UNKNOWN 记录具体尝试、失败原因、下一可访问入口、符号或有依据参数集合、对哪层上界的影响。无依据区间也是编造；有意设开销为零的松弛可以用，但不能写成已查证的零开销事实。

冲突保留双方版本与条件，未解决时分支或降为条件/符号界。不能选择使吞吐数字更小的一方。身份/权限或用户语义选择确需补充时才问，其他推导继续。

## 检索入口（线索，不是冻结参数）

这些是官方/原始资料入口；使用时固定实际版本并保存证据，网页可变，不能直接当当前服务器规格。

- [HCCL 接口目录（9.0）](https://www.hiascend.com/doc_center/source/zh/canncommercial/900/API/hcclug/hcclcpp_07_0001.html)：查通信函数和安装头文件。
- [Ascend C 同步资料（8.0）](https://www.hiascend.com/doc_center/source/zh/canncommercial/800/developmentguide/opdevg/Ascendcopdevg/atlas_ascendc_10_0011.html)：查流水同步，需匹配实际版本。
- [LLVM MachinePipeliner](https://llvm.org/doxygen/MachinePipeliner_8cpp_source.html)：资源/循环下界的方法参考，不是 Ascend 成本来源。
- [NanoFlow 原始论文](https://arxiv.org/html/2408.12757v1)：资源并发与分块研究，不是本机最优性证明。
- [SGLang overlap/future-token](https://www.lmsys.org/blog/2024-12-04-sglang-v0-4/)：查可移除的框架开销和状态依赖。
- [DeepInfer ZOS 源码](https://github.com/deepseek-ai/DeepInfer/blob/main/deepinfer/model_executor/input_metadata/prepare_tensor_input_zos.py)：追元数据与设备引用；main 必须再固定 commit。
- [Ascend msmodeling](https://github.com/Ascend/msmodeling)：参考公式和接口，预测输出不自动成为理论上界。
