# v2 — 先发现融合机会，再定位低利用率

基于 OPERATOR-CEILING-v1 修订，当前阶段止于发现与诊断。

- 主流程由“单算子上界优先”改为“全范围融合/拆分重组扫描 → 覆盖与停止记录 → 模块利用率排名 → 实际性能与理论极限对比 → 最低模块原因定位”。
- 两两、三算子、多算子、分支和跨模块机会分别检查；保留候选图、条件、依赖/互斥关系和去重依据。
- 扫描只在声明范围和规则下结束，资料/预算缺口单列，不宣称全局不可融合。
- 模块利用率绑定已有实际实现，明确口径、覆盖、未知和并列情况。最低利用率模块必须分析，同时解释关键路径影响。
- 保留原理论模型、数学边界和精确有理数计算器，把算子/子图/模块的实际性能与理论极限对比设为固定环节；资料不足保留符号、条件或缺口。
- 当前不实现融合、不修改目标结构代码、不设计解决方案、不执行优化实验。
- 增加 PROFILING.md 及采集计划、文件索引、小摘要模板：已有数据优先，授权后有限诊断采集，原始证据保留，先全范围聚合再按模块定向读取。

包内仍没有真实硬件任务。原 v1 已另存为同级目录的 operator-ceiling-agent-kit-baseline-v1.zip；基线归档不包含后续修改，也不嵌入 v2 发布包。
