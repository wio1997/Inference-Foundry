# 算子极限模型怎么建立

本文件保留 v1 的理论方法，用于融合扫描后的固定性能与极限对比，以及模块原因定位。执行顺序见 PROTOCOL.md；建立完整上界不是开始融合扫描的前提。候选结构的理论分析不能冒充融合后实测。

## 先声明讨论范围

独立算子边界必须输出的张量，可能在更大的融合子图中无需落地。因此“独立算子极限”“融合子图极限”“框架极限”分别建模。声明域可以固定常规算法，也可以放宽算法；结论不能超出所声明范围。

输入是一个固定矩阵，还是所有给定 shape 的矩阵？是否允许稀疏/压缩、结果缓存、重算、近似、跨调用复用？这些会改变必要计算量。有限样例的实测不证明整个输入域的最坏情况或所有算法的极限。

## 必要工作与硬件能力

对每个资源 r，证明全程必要工作至少 W_min[r]，匹配条件下容量至多 C_max[r]，则 T ≥ W_min[r]/C_max[r]。多个独立下界可取最大值。

算子拆成加减乘除、指数、归约等基本语义后，不能无证据给每项分配固定指令数或周期：某些可融合、复用、近似或换算法；指数也不是单凭函数名就有固定成本。需要匹配声明算法与精度域。可以只保留已证必要的一部分工作获得更宽松但有效的界。

常规密集矩阵乘的 MNK 次 MAC，只是对应常规乘加算法域的计数。若按一次乘法加一次加法等于 2 OPS 计数，应与硬件公布口径一致。还要区分有效矩阵工作和当前实现 padding、打包、转换的额外工作。

指令路径核验解决“采用哪种计算资源”。每周期吞吐、依赖延迟、发射限制、核心数和最大频率，需要另外证据。SDK 头文件声明、反汇编指令存在、一次微测速度，各自能证明的内容不同。

## 访存与资源争用

逐层登记：寄存器/局部缓冲、片上缓存、设备内存、主机内存和互联。对每一层，证明最少有多少信息必须跨过该边界，才可除以该层速率上限。不能把所有层的字节相加后除以一个带宽。

同一物理通路上的必要读写累计；读写独立与否、DMA/通信是否争用 HBM、Cube/Vector 是否共享某段路径，都要查证。关系未知时允许先放宽为独立资源，不能凭经验添加减速比例。

初态已驻留、批内复用、跨调用常驻、有限容量导致重读、重算换搬运，都要覆盖。当前某个实现写出 workspace，不意味着理论上必须写。有效微测带宽是观测值，不能直接充当物理容量上限。

## 依赖与流水

记录数据范围和版本，区分真 RAW/控制依赖、WAR/WAW、接口顺序、实现人为顺序与资源冲突。按块可发布的结果应允许按块消费。

先允许无限缓冲、任意细分和零通知成本。收紧时再证明实际粒度、容量、生产消费最短延迟的必要性。只有属于一条不可重叠的必要链的时间才能相加。

“首块搬入 + 所有块计算 + 尾块搬出”可以是固定三阶段流水模型的精确时间，但不是自动成立的全算法极限。总搬运无法被计算覆盖时，它也不能描述真实最短完成时间。教学例子见 examples/tile-pipeline.md。

## 融合机会怎样进入分析

先登记生产者/消费者、所有用户、数据依赖、精度语义与中间存储。考虑两两、多个算子或拆分重组，判断哪些计算/读写可以消除；不要求当前 API 支持该融合才能建立乐观界。

融合可能减少 I/O，也可能增大活跃数据、争用资源或破坏原有重叠。可消除是候选命题；若用于严格计数或收紧，须限定域并给依据。融合后按整个子图重推，不把各独立算子的 I/O 下界或时间下界直接相加。

## 输出状态

- REVIEWED_CEILING_IN_STATED_DOMAIN：前提、必要性和算术均获明确复核，只在该域内有效。
- CONDITIONAL_CEILING：依赖未证实前提；逐条列条件。
- SYMBOLIC_CEILING：至少一项重要参数未知，保留公式，可同时给已有证据支持的较宽数值界。
- INCOMPLETE：必要工作或有效容量界尚未建立，不能给有限上界。

上界很宽不代表错误；有依据地继续收紧。不能用实现复杂、找不到可达排程或缺优化代码作为理论任务未完成的理由。
