# 融合机会扫描

## 扫描对象与覆盖

先固定原图、Case 和规则集合。扫描是对给定范围的覆盖承诺，不能把有限启发式搜索称为全局穷尽。每个节点、数据边、跨模块边、动态分支和允许改写规则必须能在覆盖表中找到 SCANNED、NOT_APPLICABLE 或 UNKNOWN 及其理由。

至少检查以下类别；“不适用”也需记录依据：

| 类别 | 检查内容 |
|---|---|
| 两两融合 | 生产者→消费者的直接边；共享输入/生产者的分支是否存在合并机会 |
| 三算子融合 | 连通的三个节点、链和分叉/汇合；不以两两候选成立为前提 |
| 更多算子 | 从连通子图和已有候选向外扩展；记录最大子图规模和未扩展边界 |
| 拆分重组 | 将复合算子按已知语义分解，重新归组、移动可交换部分或合并重复工作 |
| 跨模块融合 | 检查模块边界两侧的数据关系，不因命名边界直接跳过 |
| 分支与多消费者 | 检查中间结果能否保持语义并满足全部消费者，保留副作用与生命周期 |

单纯在文本调用序列中相邻不构成融合证据；需要数据关系或共享资源/输入的具体依据。重排、拆分的合法性以精度、归约顺序、状态更新、随机数和别名语义为条件。

## 候选记录

每项使用 records.json 的 fusion_candidate 模板：原图节点、所属模块、变换类型、候选图和到原图的映射、数学等价论证或未证条件、全部消费者、可消除工作/I/O、活跃数据和并行性顾虑、来源及状态。

状态为 OPPORTUNITY、CONDITIONAL、RULED_OUT_IN_SCOPE 或 UNKNOWN。OPPORTUNITY 仅表示在写明条件下识别出结构机会，不表示已实现、已证性能收益或已被目标 SDK 支持。当前接口不支持时记录实现可用性 UNKNOWN/UNSUPPORTED_CURRENT_API，不能单凭这一点否定允许新实现的语义机会。

理论上可合并不一定值得采用：融合可能增加活跃数据、重算或资源争用。这里只登记顾虑，不选择实现、不设计解决方案。互斥候选分别保留；使用 requires、conflicts、overlaps 记录关系，不能把所有候选直接合成一张已采用的图。

## 继续扫描与停止

每轮记录输入图指纹、规则集合、已检查对象、新候选、去重候选、未覆盖项和输出候选图。候选图只存在于分析产物，G0 始终保存。

两两候选为空后仍检查三算子、多算子和拆分规则。扩展后复扫受影响邻域；最后全范围覆盖检查没有新非等价候选且所有扫描项都有结论，才能标 SCAN_COMPLETE_IN_SCOPE。需要说明实际规则、规模限制及条件候选，不能写成“物理上再也不能融合”。

若图/语义不完整、资料不可访问或达到记录的预算，标 PAUSED_WITH_GAPS；若未执行任何扫描，标 NOT_STARTED。停止原因必须与证据相符。保存记录后转入模块诊断；候选存在本身不是继续实现的指令。
