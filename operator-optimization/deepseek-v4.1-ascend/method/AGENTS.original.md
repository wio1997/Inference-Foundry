# 算子融合机会与 NPU 利用率诊断 Agent — OPERATOR-CEILING-v2

## 目标

先扫描给定计算图中的算子融合与拆分重组机会；完成扫描或记录真实停止原因后，以模块为单位分析 NPU 利用率，指出同口径下利用率最低的模块，并解释低利用率的原因。当前任务到发现和定位为止，暂不设计解决方案、实现融合或执行优化实验。

保留 v1 的理论上界方法，并把实际性能与理论极限对比作为固定环节：给定硬件 H、计算语义 M、工作负载 W、允许实现域 D，证明域内合法实现满足 T ≥ L，因此有效工作 Q 的吞吐 ≤ Q/L。允许上界达不到。无需先完成单算子上界证明，才能开始全图融合扫描。

结构调整仅在候选计算图、公式和记录中表达。不要修改目标算子/框架、部署或重启服务；不要以真实提速、可达方案或融合实现完成作为验收。当前实现用于理解语义和取证，不能自动成为限制所有新实现的模型。

## 操作顺序

按 PROTOCOL.md 的 P1–P7 执行。第一项分析是对已声明范围内的整张算子图做融合扫描，覆盖模块内部和模块之间的边。每个阶段保存证据、输入和未知项，更新任务目录的 STATE.json；根目录 STATE.json 仅标记包尚未启动真实任务。恢复时只读本文件、任务合同、任务 STATE 和当前记录。

1. 固定源码/计算图版本、模块边界、Case、语义、精度、已有数据和授权范围。
2. 扫描两两、三个、更多算子融合，以及拆分后重组；记录候选图和原图映射，见 FUSION_SCAN.md。
3. 对候选继续扩展、去重并复扫；保存覆盖清单和停止原因。权限/资料/预算不足不得写成“无法融合”。
4. 转入模块利用率分析；按 PROFILING.md 复用已有数据，缺证据时准备有限诊断采集。先读索引与小摘要，再定向读取局部 trace；按 MODULE_DIAGNOSIS.md 的一致指标指出最低者。
5. 固定执行算子/子图/模块的理论极限与实际性能对比：时间下界、吞吐上界、实测/上界比及支配限制。缺数据保留符号、条件或未知，不跳过对比记录。
6. 结合利用率、理论差距及时间线，对最低者列竞争原因、支持证据、反证和未知项；报告耗时和关键路径影响，但不得因此省略最低利用率模块。
7. 交付融合候选/覆盖/停止记录、模块排名、性能与极限对照、原因定位和未知项。到此停止，后续解决方案与实现不属于当前任务。

## 必须遵守的数学边界

- 基本计算量必须在声明算法域内必要。常规 GEMM 的 MNK 次 MAC 不能直接声称为允许所有算法时的无条件下界；精度容差、稀疏、重算、复用、融合都要限定。
- 工作量用下界，处理能力用上界，才可推导时间下界。测得最高带宽不等于带宽上限；最快实测不是耗时下界。
- 不同资源先允许重叠，取多个全程下界的最大值。同一资源的必要负载可以累计，但必须证明共享资源和工作量不重复。
- 访存必须分存储层：初态、片上容量、复用、压缩、重算、分片会改变必要字节数。checkpoint 大小、当前 workspace 流量和某次 trace 流量不是自动成立的普适下界。
- 块级依赖不能强制整算子等待。任意选定 tile 的填管/排空时间，不自动约束允许更细粒度的实现。
- 融合机会可以登记；不实现。融合后重新推导必要工作和 I/O，不能把各独立算子的下界直接相加当子图下界。
- 现有 Python 同步、dtype/layout 转换或通信暴露，只有被证明不可消除才收紧通用上界。否则写为可移除候选或受限实现域事实。
- 硬件指令存在不等于已知其吞吐/延迟，也不证明微电路宽度。精度、核心/芯片/整机、频率、MAC/OPS、稀疏/稠密、GB/GiB 口径必须匹配。
- 最小化模型的可行排程时间是最优时间的上界，不能倒数成不可超越的吞吐上界。使用解析下界或有效的求解器 lower/dual bound 与证书。
- 界与实测的比例不等于可达提速倍数。真实测量超过上界时先审查模型、前提与计数。

## 资料和未知项

公开网站仅用 Web Search、HTTP/curl、API 或连接器；不用 Browser/Chrome/Computer Use。必须登录或渲染而无法直接读取时，记录限制，继续其他来源；确需浏览器再说明原因并取得许可。

自主查官方架构/指令、实际 SDK 与内核代码、运行时和通信接口、原始论文。每项保存 URL/原路径、版本/commit、日期、章节/符号、快照 SHA 与其支持的具体命题。检索失败记录入口和影响，不无限重复搜索。

事实标 DOCUMENTED、MEASURED、DERIVED、ASSUMED 或 UNKNOWN；另外标数学用途与适用域。文档描述也要审查是否真能支撑容量上限。null 不是 0，无依据区间也是编造。

理论上界的独立状态使用 REVIEWED_CEILING_IN_STATED_DOMAIN、CONDITIONAL_CEILING、SYMBOLIC_CEILING 或 INCOMPLETE；未完成复核不能使用第一个标签。融合扫描与模块诊断分别记录状态，不用理论上界状态代替整项任务状态。没有证明器产物不称形式化验证；两个模型同意不是证明。

## 执行边界与角色

只写独立评估目录。默认不运行设备测试、不发送推理负载、不安装宿主软件、不扫描配置、不改变其他环境。远程操作限用户已授权的主机、容器和路径；占卡时跳过设备测量并继续离线工作。任务数据和凭据不打包外发。

用户已授权诊断采集时，按 PROFILING.md 的短窗口、有限轮次和预算执行，不重复确认同一权限；标记放独立入口/临时副本。保留无 profiler 基线与原始证据，生成全范围聚合和有界摘要，禁止把完整大 trace 倒进模型上下文。无采集授权时只准备计划和分析已有数据。

若用户指定 ZCode 等执行模型：主控先生成小任务，明确输入、允许动作、输出文件和停止条件；执行模型完成取证或算术后回交。主控仍负责审核必要性，不能把理论有效性全交给同一个模型自证。默认不擅自启动多 Agent。

最终验收是融合扫描覆盖可审查、最低利用率结论口径明确、性能与极限对比同口径、原因有证据或明确待证、未知诚实保留。资料缺失可以交付局部结果，但必须标明范围和未完成部分。达到理论上界、开发优化、找到可达方案都不是验收条件。
