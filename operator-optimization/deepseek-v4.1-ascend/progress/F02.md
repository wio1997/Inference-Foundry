## 算子与原有流程

模型 self.hc_pre → npu_hc_pre_v3 / aclnnHcPre（历史profile语义名HcPre），随后 self.input_layernorm（RMSNorm；历史profile名RmsNorm）。新融合接口尚未实现。

HcPre 产生 BF16 Y 和新 pre/post/comb；独立的 input_layernorm 使用 Y、原训练权重及 self.norm_eps 做 RMSNorm。中间 Y 是两者之间的交接。

## 候选改动及其意义

本轮只看 F02-PRENORM 的 Attention 输入侧：把 HcPre 内生成 Y 的收尾与随后 RMSNorm 接入同一算子实现，保留舍入后的 Y 供整行归一化，直接输出归一化后的结果以及全部仍需保留的原输出。

融合减少的是可能的 Y 中间写出/再读取，以及单独归一化任务的启动/交接。归一化的平方、求和、开方、缩放和学习权重乘法仍要计算；本子方案不要求 F01 的拆分并行。

## 成立条件与证据边界

必须先得到按原 BF16 精度舍入的 Y，再做原 RMSNorm；保留完整 hidden 行的归约、原 gamma/epsilon、全部有效系数/残差及 rstd/其他观察者。能否留在片上取决于容量和切块方案；若仍有其他 Y 消费者，其所需物化不能删除。首层 embedding 复用、FFN 双输出和 F01 并行不纳入本轮结论。

## 本轮只讨论哪一项

F02 是候选族。本轮只讨论 **Attention 输入侧的 Y→RMSNorm 融合**。首层 embedding 复用和 FFN 的 RMSNormCast 双输出保留为其他子方案，未在本轮重新核对。

### 两个已有操作

原代码的关键关系是：

```python
x, attn_post, attn_comb, attn_pre = self.hc_pre(...)
x = self.input_layernorm(x)
```

第一行的 x 就是 BF16 的 Y。HcPre 其他三个输出仍有后续消费者。第二行使用学习到的权重和构造时传入的 self.norm_eps，不是任意换一个默认 epsilon。

HcPre 自己为新系数计算所做的4路X统计，与这里对1路Y的归一化是不同数据域；不能直接复用同一平方和。

### RMSNorm 的底层算法

把 Y 看成一排数字，学习权重 gamma 也是一排数字。对每一排：

1. 每个 Y 数字平方，求平均值。
2. 平均值加原 epsilon，再开平方，得到这一排共同的缩放分母。
3. 每个 Y 数字除以这个分母。
4. 再乘该位置的学习权重。

数学语义为 `Z[i] = gamma[i] * Y[i] / sqrt(mean(Y*Y) + epsilon)`。这不是对 native 指令/结合顺序的等价证明；融合实现还必须匹配原有归约与舍入要求。

### 怎样融合

```text
原来：生成Y → Y写入中间输出 → 独立RMSNorm读取Y → 计算并输出Z
候选：生成Y → 按原BF16舍入 → 在片上保留并做RMSNorm → 输出Z
```

新 pre/post/comb、原 residual 和其他有效输出仍保留。如果有别的读者需要原 Y，仍要为它保留输出，不能直接删除。

新融合接口需要接入原RMSNorm的gamma/epsilon，并约定归一化结果及仍存活的原输出；当前aclnnHcPre并没有因此自动具备输出归一化结果的能力。调用端也必须选择这个新接口，不能静默改变原HcPre输出含义。

片上是NPU内部的暂存空间。归一化需要完整5120维行的统计；不能把每个小块分别归一化后拼起来。若暂存不下，额外搬运或重算必须重新定价。

这里做的是生产者与消费者接合，属于新增融合候选；它不依赖 F01 提前交付 Y 的并行安排。两方案未来可以组合，但相同 Y 接口不能重复计算收益。

### 为什么原来的舍入必须保留

原来先把加权求和结果变为BF16的Y，RMSNorm处理的就是这份已经舍入的数据。融合后仍要在内部产生同样的数值，不能直接使用未舍入的FP32累加值去归一化。

```text
保留：加权求和 → BF16舍入后的Y → 原RMSNorm
未证明等价：加权求和的FP32临时值 → 直接RMSNorm
```

所以可以省去中间结果的外部交接，但不等于可以省去这个数值边界。

### 机会量与未证明事项

以旧profile登记的M=3、H=5120、BF16为例：Y本身是30720B（30KiB）；如果允许完全消除一次中间写和一次读，则逻辑接口为61440B（60KiB）。

这只是条件式逻辑字节数，不证明原数据必经HBM，不证明全部物理字节能删除，也不代表60KiB带宽换算就是端到端收益。原来的RMSNorm计算仍需执行，不能把它的整段耗时当成可省时间。

### 本轮结论

**源调用与数学语义支持把Y的生产和紧随的RMSNorm视为一个融合候选；片上容量、native归约等价、其他读者、新实现正确性及实测收益仍未验证。** F02 全族保持 CONDITIONAL，未实现、未声称提速。
