## 算子与原有流程

模型 self.hc_post → npu_hc_post（历史profile名HcPost）；随后 self.hc_pre → npu_hc_pre_v3（HcPre）。本轮只看Attention后的Post到同层FFN前Pre，且只研究指定交接。

Attention结果和旧4路residual经HcPost产生新的4路R；保存R作为后续FFN HcPost的residual；FFN HcPre读取R，以先前attn_pre生成Y，并计算本次新的ffn系数。

## 候选改动及其意义

研究把HcPost已按原BF16舍入的结果，直接交给下一HcPre中生成Y的部分，减少一次指定中间读取；其余系数工作和仍存活的R输出保留。必须覆盖实际生产者/消费者实现，不能仅在Python中包裹两次原调用。

生产者完成的4路数据就地供消费者继续乘配比/相加，避免该部分再次从中间输出读取。不是把矩阵权重预乘后跳过原舍入，也不假设整个4路residual可删除。

## 成立条件与证据边界

保持Post原乘法/加法次序及BF16 R，再按原配比生成下一Y并保留其舍入。R还供下一系数生产和未来FFN Post残差使用。真实tile布局、容量、就绪/存活协议及数值需验证；跨层Engram/aux读者不纳入本轮快捷路径，F02的norm收益不重复计算。

## 本轮只看哪一段

F03覆盖Post与后续Pre的重组。本轮先看最直接的**同一层内Attention HcPost→FFN HcPre**，不把跨层Engram/aux分支一起判定，也不把F02的归一化再次计入。

### 两个算子各自做什么

|操作|输入与算法|输出/用途|
|---|---|---|
|HcPost|把Attention新结果按post配比分到4路，再按comb配比混合旧4路residual，按原顺序相加并舍入|新的4路数据R|
|下一HcPre的Y生成部分|读取R，按先前Attention HcPre已产出的attn_pre逐项乘配比并沿4路相加，按原精度舍入|给FFN后续计算用的1路Y|
|下一HcPre的系数部分|另用完整R计算新的ffn_pre/post/comb|仍是必须保留的工作|

原模型关系为：

```python
hidden_states = self.hc_post(x, residual, attn_post, attn_comb)
residual = hidden_states
x, ffn_post, ffn_comb, ffn_pre = self.hc_pre(
    hidden_states, ..., attn_pre
)
# 中间还有FFN计算
hidden_states = self.hc_post(x, residual, ffn_post, ffn_comb)
```

以上为保留关键调用的摘录，省略参数不构成新实现。`residual = hidden_states`说明R在下一Pre消费后仍然被后面的FFN Post使用。

### 怎么接合

```text
原来：HcPost生成R → 写出4路R → 下一Pre重新读取R → 按配比生成Y
候选：HcPost生成并舍入R → 直接交给下一Y生成部分 → 输出原精度的Y
                      └→ R仍按其他读者的需要写出/保留
```

这属于生产者与消费者的融合/交接重组候选。新实现需要覆盖双方接口：既把R正确交过去，又让该消费者不再重复读取/重算这一部分。只把原HcPost和原HcPre放进一个Python函数不会自动实现。

### 为什么不能删掉R

当前R至少仍是：

- 下一HcPre中新系数生产的输入。
- 后续FFN HcPost的residual。

因此，本轮选定保留原4路数据发布的方案，只研究减少**下一Y生成的一个读取**，不声称R的写入或全部Pre读者都消失。

若以后另做长期片上保留、重算或状态表示方案，需要单独验证容量和所有读者，不能把它当作本轮已满足条件。跨层场景还可能有aux读取或Engram改写，不能跨过它们直接转交旧版本。

### 数值与代价约束

必须先保留HcPost的原BF16舍入，再做下一次加权混合。把两个矩阵/配比直接预乘、删除中间舍入，未证明等价；HcPre的新系数还依赖完整R及非线性处理。

以M=3、H=5120、4路BF16为例，一个选定R读取的逻辑大小为122880B（120KiB）。它不是已测HBM流量或提速，R写入及其他读者仍在。若进一步接norm，与F02相同接口只计一次。

### 本轮结论

**源码证明了指定的层内Post→Pre数据链及R的其他存活用途，支持研究直接交接；新接口/切块调度、数值等价和收益未验证。** F03全族保持CONDITIONAL，转下一条不代表之前方案实施完成。
