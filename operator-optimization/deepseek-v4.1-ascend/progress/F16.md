## 算子与原有流程

历史语义链：wo_a → BF16 中间值 → wo_b → 每 rank BF16 partial → ReduceScatter。

历史登记的原流程：wo_a → wo_b → output reduction。本页登记不等于对当前运行二进制完成重新绑定。

## 候选改动及其意义

WO_A、WO_B和ReduceScatter分块接力，减少中间物化。

保留两次矩阵计算，以块交接降低中间物化或延迟。

## 本轮记录：长prefill先做OA，再交换较窄结果

用户在2026-11-06表示“这个好像可以试试 先记录吧”。本轮将 **F16-OA-BEFORE-A2A** 保留为值得尝试的条件候选；仅登记用户选择和已有方案，不启动实施或提升正确性、性能及独立复核状态。其他F16分块接力方案保留原合同。

```text
原来：逆RoPE/pack → 交换4096维分组数据 → OA压到1024维 → OB → ReduceScatter
候选：源rank先按目的组做OA → 交换1024维结果 → 原OB → 原ReduceScatter
```

OA与OB的必要MAC不减少，OA之后的BF16舍入、原OB及ReduceScatter、TP行序、padding和所有参与者保留。每rank每层发送面的逻辑载荷可变为原来的四分之一；原pack只在OA直接产出发送布局时领取一次节省，与F14/F15去重。

代价是每个源rank需覆盖全部八份OA权重：每层逻辑覆盖8→64 MiB，额外读取56 MiB。40层常驻、原分片引用完整bank对应部分时，每rank新增2.1875 GiB；另保留原分片时新增2.50 GiB。实际峰值、构造临时面和KV容量仍待验证。

来源纠正（2026-11-06）：v168注入设备观测器和额外读者。此前1.20%仅保留历史诊断敏感度身份，撤销其生产收益预测或上限资格；不能据此为当前方案定价。载荷1/4和额外权重账本独立保留；真实长行净值UNKNOWN，M3 decode后置。

未来若执行，先比较真实BF16 OA中间值与原OB输出；通过后再对照同组完整pack→OB/ReduceScatter端点，计入权重供给、形状变化、布局、发布与内存/KV代价。合同不满足或新增成本抵消最终推进时，停止该变体。来源提交、文件SHA及登记边界见[本次用户决定](evidence/F16-oa-before-exchange-user-decision-20261106.json)。
