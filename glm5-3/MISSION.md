# 我们要解决什么

以 **GLM-5.3 W8A8 / Ascend 910C 超节点**为目标，在指定业务请求范围和延迟要求下提高**有效总吞吐**，逐步判断距离可达性能还有多少空间。当前研究使用现有正确算子并保持模型语义和精度。

优先复用 SGLang 作为研究起点，现有 vLLM 业务保留。框架提供实现和基线，不替我们定义设计空间：执行顺序、布局、切分、通信与组批方式均可研究。不预设改参数、框架 patch 或自研执行器中的任何一种必然是答案。

方案可以来自已观察的瓶颈，也可以来自对调度、执行、内存和通信的整体重设计。说明它为何有望提高目标业务的有效吞吐，并选择能检验关键假设的验证办法；实现位置与改动规模由方案决定。

研究主线是：明确可行边界，以已验证可行方案和有效性能上界夹住最优吞吐，再选择最值得验证的方向，逐步缩小差距。只有上下界在声明范围和误差条件下足够接近，才称接近最优；有限次搜索不保证全局最优。估计用于排序，不冒充证明；上界未知也可继续探索。具体判断见按需参考 [PLAN](PLAN.md)。

最终比较相同业务约束下的有效吞吐，同时检查延迟、正确性和实际完成的工作。单步或片段变快只证明其适用范围；标准 PD 业务仍需完整 P→KV 传输→D 验证，具体场景与当前缺项见 [HANDOFF](HANDOFF.md)。
