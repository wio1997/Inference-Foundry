| 普通脚本 | 启停、等待、压测、采样、计算指标与保存原始证据；重复工作直接执行脚本，不让模型反复观察相同日志。 |
| 参数调优执行者 | 由用户另行安排，负责配置搜索及基线/候选的公平调优；尚未创建或对接此任务。本研究保留必要配置对照，不承担持续扫描。 |
| 六台 910C | 完整业务验证先作为一个集群，沿用现场已可用的 P/D 与并行配置；片段实验按必要芯数与拓扑使用资源，不按 Agent 固定分机器。不预设 4P2D、3P3D 或六个独立副本；基线和候选在同一组资源上依次比较。 |

默认一个 Sol 决策入口、一个 DeepSeek 执行任务，同一实验集群只有一个作业控制者。独立代码分析可按需并行，不按服务器数量启动 Agent；服务器地址和集群入口由用户稍后补充。

首轮按实际依赖推进：

1. 接通本机 Zcode 的明确 CLI 入口，核验有效模型配置；先做本地有限任务验证，不自动部署 DeepSeek 权重到 910C。已有 [委派脚本](../scripts/delegate_zcode.py) 与 [交接工具](scripts/zcode_bridge.py) 可复用。当前 shell 的 PATH 无 `zcode`，默认 `~/.zcode/cli/config.json` 不存在；已找到应用 CLI `/Applications/ZCode.app/Contents/Resources/glm/zcode.cjs`，尚未调用，调用方式和有效模型仍需核验。工具的任务范围文字不等于系统级隔离。
2. 收到现场入口并恢复设备操作后，核验六台的版本、权重身份、拓扑、启动脚本和当前服务状态；复用现成环境，先不改实现。交付一份能重跑的启动配置与缺项清单。
3. 按可取得的真实请求分布选少量混合长度用例，采集匹配负载下的 TTFT/TPOT 分布、成功率、有效吞吐及一段有针对性的 trace；没有真实流量时标明合成诊断用例。交付基线证据和首个值得验证的设计，随后只推进一个候选的配对比较。

原始日志与 trace 留在文件；给 Sol 的回报通常只含变更、比较条件、正确性/性能结果、证据位置与待决定项，遇到可疑结论再定点查原始证据。新证据、异常或设计决策触发 Sol，不靠高频轮询维持研究。省 token 的效果以实际使用量和有效实验产出核验，不能仅靠换模型承诺。
