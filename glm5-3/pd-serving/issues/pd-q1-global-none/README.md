# 短输出诊断：已证实机制与结论边界

## 实验身份

本轮2P2D复现：配置输入81920（实际81932–81934），输出600，48请求，并发上限16，到达速率0.93请求/秒，temperature0、ignore_eos。D为DP16×TP2、MTP5、FULL_DECODE_ONLY。48/48成功，TPOT P50 22.1ms，输出吞吐447.3294 token/s。

旧正式614输出轮的21.9ms/约455 token/s不是本轮数据。旧profile与另一256输出实验在时间上重叠，不能替代600输出场景的因果证据。

## 发现过程

1. 核查旧profile与压测负载，不把全dynamic组和步间空洞直接认定同因。
2. 阅读实际runner的uniform判据和DP模式同步：MTP5要求uniform query length为6，DP同步取各rank模式最小值。
3. 加入可开关诊断日志，在每个DP的TP0记录step、请求身份、调度token数、uniform状态、本地/最终模式与DP向量；记录点在模式决策之后。未增加NPU同步，但未用严格A/B量化日志开销。
4. 按600输出复现并关联请求、KV完成和dispatch记录。内部衍生步骤数据去除了原请求身份，但仍不公开；原始证据由哈希固定。
5. 按相邻间隔的起点步模式分类，并用单一DP独立统计交叉验证。
6. 实测FULL配置，后端以UNIFORM_BATCH限制自动降回FULL_DECODE_ONLY；三个短请求首步仍NONE。仅改FULL不可用。

## 触发机制与观测

KV到达后的首次可见decode只有q=1；当前MTP5 uniform图要求q=6，因此uniform=False，本地NONE；DP同步使全部16个rank final NONE。

736完整全局步、11776条DP记录；48个请求各触发一次首步local NONE，合并为46全局NONE步。原始节点合并日志中48/48请求均先出现KV完成记录，再出现首步。该顺序不冒充跨节点精确时间测量。

| 起点→终点模式 | 间隔数 | 中位数ms |
|---|---:|---:|
| FULL→FULL | 643 | 76.891 |
| FULL→NONE | 46 | 80.297 |
| NONE→FULL | 46 | 262.955 |

全部46个>150ms间隔都紧随NONE步。单DP独立统计相应中位数为76.853和262.989ms。

间隔包含起点模型执行及下一步准备/同步，不是纯kernel或DFC时间。按普通FULL步作为反事实、按旧请求停留加权，额外时间约折合3.135ms/token；这是估算，不是修复A/B收益，也不能直接从TPOT P50减去。

## 纠错与未知

- 早期曾按间隔终点模式分类，产生约80ms和约0.06ms/token的错误归因；已撤回。当前按起点模式分类。
- 早期只审runner认为FULL可尝试，未覆盖后端能力限制；实际启动和请求证据已否定该配置方案。
- 两轮相继测试缓存不同，baseline约63.80%、trace约93.09%；193→447 token/s不能视为补丁收益。baseline另有单次KV调用122.512秒后ret=0，同请求另一TP约3.278秒；内部长尾原因未知。
- 历史145–150ms空洞的下一次DFC仍static，不能合并归因。其大型原始profile未包含在公开衍生数据中。
- 首步q1是已直接观测的触发条件，完整scheduler/spec-token生产链仍需进一步审查。
- 未证明全部TPOT差额由图回退引起、q1专用图可行、18ms可达，或整体吞吐只由D限制。
- 三短请求HTTP成功，但0/3严格字符串断言通过（含thinking内容）；无变更前同样对照，不作为正确性通过或回归证明。

候选后续方向为真正q1专用图描述符、捕获及调度路径，并验证KV/attention/MTP语义；不允许简单伪造uniform或dummy token就称修复。
