## 1. 优化目标与测量合同

用户的主要目标是**满足稳态TTFT/TPOT SLA时，最大化客户输入和输出token/s**。有效原生稳态窗口内六项门槛均须严格满足：TTFT P50<4s、P75<8s、P90<12s、P99<30s；TPOT P50<18ms、P90<40ms。全程的吞吐、六项SLA和失败率单独列出：稳态通过但全程失败时，必须明确标注，不能无条件称“SLA通过”。不临时从两种口径中挑好看的数。

固定80,000 raw输入、服务计数80,012输入、600输出，74,400-token共享前缀，request_rate=0闭环负载，模型/量化/拓扑/上下文能力不变。不通过延长输出、改变前缀热度或减少模型能力改善分数。输入/输出token比固定为133.3533，因此同一窗口两者的吞吐排名一致；输入包含缓存复用的逻辑输入，不是P新算token速度。新盐值、历史完整输入去重、逐条tokenizer检查与P4/D16预热覆盖沿用已验证流程。

| C64/N1024稳态 | 输入token/s | 输出token/s | TTFT P50 | TPOT P50 |
|---|---:|---:|---:|---:|
| 原始P8192/D5 | 260627.33 | 1954.41 | 6.021s | 23.255ms |
| P12288/D3 | 231211.77 | 1733.83 | 6.857s | 26.246ms |
| 当前P12288/D5 | 237488.51 | 1780.90 | 7.023s | 24.752ms |

当前TTFT P50要从7.023s降到4s边界，需下降43.05%；TPOT从24.752ms降到18ms边界，需下降27.28%。这两个比例以观测值为分母，不是“超门槛百分比”；严格通过还需要低于边界。阶段均值不能相加解释P50，也不能将某个平均开销直接从P50中扣除。

目前没有已验证的SLA可行配置；每配置只有单轮长测试，尚未量化独立重复的波动。MTP5相对MTP3的2.71%稳态吞吐改善是单轮观测，不能称已确定的增益。原始P8192也未通过SLA，所以回退不是解决方案。早期N384 C64稳态2089.38 token/s、N1024的1954.41 token/s不能拼成同条件重复；早期C64的“窗口条件通过”也不等于SLA通过。

## 2. 已有证据先复用：本轮完成的工作

本轮无新推理、无服务变更。复算三组已存metrics的迭代直方图和新算KV计数；只读取得P0实际安装的指标/调度三文件并核验哈希，没有将不匹配的本地源码冒充安装版。

**新确认：iteration_tokens_total不是每个scheduler step的真实调度token数。** 实际logger记录的是随输出更新的computed prompt tokens加emitted generation tokens；完整prefill统计可在输出时结算。源码锚点为安装版logger 1205–1208、stats 328–332及386–391、scheduler 1798–1806。因此直方图出现大于预算的记录，并不证明预算失效或已饱和。

| 三组正式窗口 | P记账次数 | P记账token总量 | 每次记账均值 | 每请求新算KV |
|---|---:|---:|---:|---:|
| P8192/D5 | 883 | 5780480 | 6546.41 | 5644 |
| P12288/D3 | 645 | 5780480 | 8961.98 | 5644 |
| P12288/D5 | 637 | 5780480 | 9074.54 | 5644 |

5644是请求级真实新算KV计数均值；两个此类尾部名义token量为11288，已小于12288。这只用于候选剪枝，不代表实际每步能打包两个请求。必须观察真实chunk、有效预算、请求状态和padding，才决定预算方向。真实调度锚点在安装版scheduler 1065–1066的scheduled-token总量及约束检查；110–115显示有效max_num_scheduled_tokens可能覆盖CLI max_num_batched_tokens，因此不能只记录启动参数。

其他可复用事实：当前P本地prefix92.7861%，加外部复用为92.9461%；D外部100%是本地miss的分母。当前稳态P running采样峰值3（上限8），D单engine峰值7（上限32），D capacity等待为0。离散采样不能证明从未短暂触顶，但足以说明现在没有增大seq的正面证据。D设备忙碌约98.5%不区分计算与通信；P主机CPU均值低也不排除绑定线程局部瓶颈。

## 3. 当前唯一优先诊断：D长步来自哪里

**假设H1**：在当前MTP5、C64、80K/600、93%共享前缀负载下，KV接续首步q=1仍使local NONE传播为全局NONE，且其后区间系统性变长。旧2P2D已有触发证据；当前4P2D只有间接证据，缺发生率与时间关联。诊断用于分流后续工作，不把相关性当作修复收益。

### 无重启诊断协议

| 项目 | 冻结设计 |
|---|---|
| 允许变化 | 只开/关已预置的D dispatch日志gate；服务性能参数不变 |
| 负载 | 一轮C64/N384，输入80012、输出600；新盐值、同共享前缀；它是诊断，不是新的SLA基线 |
| 启动前检查 | D实际MTP5/q=6、两节点gate路径已预置且关闭、无活动profiler/benchmark、服务健康、磁盘余量、全局单任务锁；检查不通过则停止，不为诊断重启服务 |
| 时段 | 进入持续满并发区间后开启gate，最长30秒；同一运行保留前后gate关闭区间。没有足够满并发区间则判证据不足，不混用起止段 |
| 覆盖 | 两台D，每DP仅TP0，目标覆盖16个记录rank；至少128个参考rank连续有效步、16次新KV接续首步。各rank覆盖及唯一匹配的全局步数另报；样本不足只标不确定，不自动追加大Run |
| 产物 | rank/step、实际scheduled tokens/reqs、max query length、uniform、local/final mode、DP mode/token向量、图descriptor；请求身份仅用于私有关联。保留客户端窗口、cache、请求结果和源哈希 |
| 硬边界 | gate最多30秒，新增日志总量最多64MiB；控制端finally清理与节点独立到期清理双重关闭。从预热开始到诊断请求结束总墙钟上限8分钟（设计预算，非预测时长）。采集异常、服务错误、超时或空间不足立即关gate、停止新请求并核对在途清理，不自动重启 |
| 归约 | step是各进程gate开启后递增的局部序号，不直接跨rank等值join。先核all_reduce状态、DP token/mode向量、事件顺序及gate边缘offset；重复向量或idle/skip无法唯一匹配时，只给rank内证据并标全局对应不确定。同rank按**起点**mode分类到下一dispatch的时间差；跨rank只在唯一匹配的step内比较，不声称跨主机亚毫秒同步 |
| 干扰审查 | 对比持续并发下off/on/off区间的请求完成速率和间隔分布，标注负载阶段差异；若on区间变化超出两off区间的差异范围且无法解释，则日志开销未知、时间归因不可信，不把该轮当性能证明 |

30秒、64MiB、8分钟、128步和16次事件是前置实验预算/覆盖门槛，不是已测的开销或置信保证。gate日志没有内置超时，执行前必须实现并检查外部清理控制器，也不直接记录kernel/graph replay耗时。相邻时间差包括源步执行、下一步准备及同步，**不能由它独立拆分CPU、通信、计算耗时**。完整步数量不能冒充独立统计样本；off/on/off检查也不是严格性能A/B。两类模式若没有可比的形状/活动请求数分组，只能描述共现，不能据此估算模式切换的独立代价。

### 结果如何改变下一步

| 观察结果 | 决定 |
|---|---|
| q1→local NONE→global NONE成立，且匹配形状/活动请求数后NONE起点区间仍明显更长 | 进入图执行路径诊断；先量化受影响请求与暴露时间。现有backend不支持仅靠加bucket/改FULL解决q1；候选属于图路径实现与正确性验证，不继续扫图参数 |
| q1事件已充分覆盖，但没有该mode传播链 | 否定H1在当前窗口的触发描述；停止沿旧q1结论继续调图参数 |
| NONE存在，但长区间主要发生在FULL，或两类差异不足以区分 | 图回退不是当前长间隙的充分解释；只对重复出现的代表性FULL/长区间补短timeline，区分host供给、rank同步、MoE通信和计算 |
| rank对不齐、事件不足、日志干扰明显 | INCONCLUSIVE；修复观测设计或停止。不能据此开新参数矩阵 |

时间份额只做条件化估算或上界排序，需报告重叠和反事实假设；不把“NONE区间全部耗时”当可消除开销。只有在TPOT对应请求分布上建立可消除开销上界，才能与P50所需27.28%的下降比较；只有平均/总wall份额时，仅作优先级排序，不据此证明该机制足够或不足以解决P50。实测修复后仍必须独立验收全部SLA，不许诺达标。

仅在上述结果留下明确CPU/设备分解问题时，才考虑一次已预配置的torch profiler短采集：它广播全部32个worker，非单rank轻量操作；max_iterations=4的实现以“>”判断停止，不能保证恰好4步，必须另设停止和文件大小约束。已有日志/profiler路径要核对两节点、采前目录基线和采后新增文件，不能直接清理历史trace。本轮不启动profiler，带profiler请求不能作为无观察器性能成绩。

## 4. 参数候选必须有进入条件

下面是条件决策表，不是执行队列。每次最多选择一个机制对照；保留MTP5/P12288只是维持参照，不是“最优参数”认证。

| 候选 | 必须先看到的证据 | 怎样选值/路径 | 淘汰条件 |
|---|---|---|---|
| P token预算 | 真实scheduled tokens耗尽有效预算，有可调度请求受阻，chunk/拼批损失可解释TTFT | 根据真实尾部和拼批分布、workspace/KV余量选**一个**新预算；不预定16384/24576。若大step导致等待，应评估减小而非只增大 | 预算非约束，或步长变长抵消收益，停止该方向 |
| P/D max_num_seqs | 真实step请求数持续触顶且token/KV有余量 | 只改变对应角色的请求槽位；不是把客户端C写到每engine上限 | 无触顶证据不测；当前采样不足以支持此项 |
| D graph buckets | FULL合法形状因bucket覆盖不足或padding出现明显额外工作 | 仅补实际形状分布需要的bucket，并验证capture覆盖 | q1非uniform失败不能靠bucket解决；已覆盖则不试 |
| D FlashComm / MoE通信 | 实际算子路径与TP/EP通信暴露时长明确，且安装版支持 | 先核有效开关：旧True启动文案只来自P，D有效状态仍需核；再选一个兼容路径 | 已启用则不重复开启；只有高利用率而无通信证据则不测 |
| shared-expert DP / overlap | shared-expert计算或通信在关键路径可避免/可重叠 | 先核权重布局、内存、流同步；fused MC2与overlap互斥时作为一个替代路径实验 | 不把互斥开关同时开启，也不把耦合路径称独立单参数收益 |
| P prefill MC2 | P MoE通信占比明确，EP64/量化/真实shape与安装版路径兼容 | 与现有通信路径做条件明确的替代；不套用别版本文档预算建议直接改服务 | 不支持或未实际走目标分支则不测；不能将P的EP64照搬D限制 |
| MTP深度 | draft、verify、接受长度及每轮时长分解支持某个档位可能降低每有效token成本 | 使用“本轮耗时/本轮有效输出”排序；当前MTP5优于MTP3的单轮方向先保留 | 不根据接受率高低继续5→3→1→0扫描；未知更大深度的收益不外推 |
| CPU线程/绑定 | 关键线程排队或核局部饱和与设备空洞对应 | 核实实际亲和/NUMA/IRQ，再选一个变更 | 主机均值低或启动绑定慢都不是调线程证据 |
| TP/DP拓扑 | 同拓扑的有效候选不足，timeline/内存模型支持改变单组工作量 | 单侧改变，并验证跨TP KV、路由、完整模型、热度及内存 | 不因“384物理域”直接扩大EP；P已经EP64，D当前EP32。结构试验成本高，排最后 |

P scheduler真实token/请求数/限制原因目前缺少现成的低开销观测。确有预算/seq决策价值时才补：有效上限、总scheduled tokens、prefill chunk、新/继续请求数、token与seq剩余、未调度原因、padding量与step时长。P现有gate未预置，不能声称touch即可生效；不为了“顺便采一下”重启四P，不做热注入。若需要改源启用，应并入下一次已被证据支持的维护窗口，且确认观测不会破坏同条件比较。

## 5. 对照、验收及并发搜索的成本限制

先证明目标路径实际执行且预测开销减少，再看端到端是否获益；功能、token/KV计数、错误率和cache是硬约束。配置变化与代码变化分别记账。

- **当下预算**：已有数据离线审计已完成；下一诊断最多1轮N384、0次重启、0个性能参数变化。不连带执行profiler、配置筛选或并发搜索。
- **每个后续候选**：默认只在与机制对应的一个C上做N384筛选；高并发路径问题优先C64，低负载固定开销问题才选择低C。最多再加一个会改变去留决定的负载点，不对每个候选重跑C16/32/64/96。筛选淘汰没有预测变化的候选，不能作为最终容量认证。
- **重启安排**：只重启受影响角色；同一机制必需的依赖一起改。两个独立性能假设不为少一次重启混在一起。每个restart前冻结真实effective config、候选diff、可行性检查、私有回滚快照和测量合同；候选不成立时关闭该路线，不自动回退并重复压测。
- **最终确认**：只保留一个候选配置/C，做两次独立N1024，均报告完整和有效稳态结果；已有相同合同的候选筛选不冒充独立确认。稳态窗口条件、计数或覆盖失败则不认证。近门槛或小收益缺少噪声依据时标INCONCLUSIVE，是否值得补对照由决定价值重新判断，不自动追加第三轮。需要对照环境漂移时先明确哪项结果会改变决定，避免为“重复完整”空转。
- **并发搜索**：先获得某个配置下的SLA可行点，才扩大C。旧配置的失败点只作先验，不当新配置的已测边界。有同配置实测通过/失败边界时取整数中点；没有上界时按预先记录的有限增量建立边界，该增量只是控制试验成本，不是预测最优C。每阶段最多2个新C点；边界足够接近或吞吐收益无法区分即停止，报告已测最优点和未测区间。C72只有在边界推导出它时才值得测。

并发升高可能改变batch效率，因此低C失败不构成高C必失败的数学证明；但现有C16–96均没有TPOT通过点，也没有支持“继续增C即可达18ms”的证据，所以当前不进入并发搜索。
