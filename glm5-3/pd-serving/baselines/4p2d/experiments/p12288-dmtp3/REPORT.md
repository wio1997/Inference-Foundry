# P12288 + D MTP3：组合试验未改善 SLA

2026-10-08（Asia/Shanghai）。按用户“少重启、直接重启容器”的要求，将四 P 的 token 预算从8192改为12288、两 D 的MTP从5改为3，一次维护批次验证组合效果。**结论：本轮不采纳该组合；全程和稳态吞吐均下降约11%，TTFT与TPOT均变差。没有新增代码级性能KEEP，不提升正式基线。**

基线为[同C64/1024请求的不重启诊断](../../diagnostics/c64-1024-no-restart/REPORT.md)，其文件和原始裁决保留。本次是配置组合筛选，未作单参数因果验收。

## 缓存与负载有效性

新输入沿用原工作负载的后缀内容分布，加入新命名空间/行盐值，1024条完整提示均重新分词验证为80000 raw token，服务模板后均80012 token。完整提示哈希在本轮唯一。新旧提示不是逐字相同，因此不是严格配对的输出轨迹实验。

容器重启后先恢复元数据，16条公共前缀预热成功：P0–P3各4次，D0–D15各1次。正式窗口独立before_full与after_full_settled差分：P各节点请求数259/255/254/256，D合计1024；P、D分别记录同一批请求，不能相加计费。

P和D的本地prefix命中率均为**92.786082%**，与基线一致，各endpoint/engine一致；无counter reset或缺失。P外部命中131072 / 外部查询5910528，D外部命中5910528 / 5910528。D外部100%的分母是本地未命中的KV，不是用户输入的prefix命中率100%。这些是聚合计数，不能证明每个请求的命中率上限。
