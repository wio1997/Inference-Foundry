# 按需参考：用性能边界收敛研究

主线：**定义可行边界 → 建立最优值的上下界 → 选择高价值假设 → 用最直接的办法验证 → 更新边界与下一决定。** 这是决策依据，不是必须依次完成的关卡；无需先证明完整极限或搭建求解器。当前事实只在 [HANDOFF](HANDOFF.md) 维护。

## 1. 定义我们在优化什么

可行域 F 由模型语义与精度、硬件资源及互联、支持的负载族、延迟与服务要求、允许的算子集合确定。Q(x) 是方案 x 在这些约束下的可持续有效吞吐；说明 token 统计、失败请求和多场景聚合口径。不得靠少完成工作改变比较目标。

组批预算、并行划分、布局、通信、缓存、图与执行顺序是设计变量，不能因为现有框架如此实现就冻结。修改外部合同或扩大算子集合会改变 F，必须显式建立新的比较边界。六台是待验证的实验规模，不是已证明的最小配置或架构限制。

## 2. 用两端夹住最优值

对最大化吞吐的问题：`L ≤ Q* ≤ U`，其中 Q* 是 F 内的最优吞吐值。

- L：已满足正确性与服务要求的可行方案所支持的保守吞吐下界。实测需注明工作负载、测量误差与置信条件，不能把一次峰值当保证。
- U：对整个声明可行域有效的吞吐上界，来自必要工作量、资源容量、数据依赖等约束。现有框架的额外同步、padding、重复读取不能直接算成所有方案都必须承担的工作。
- 启发式预测单独标为估计；微基准测出的带宽或模拟器结果不是物理上界。流水与并发下，不能任意相加阶段耗时或取最大值就称得到系统极限。

U 暂时未知可以继续研究。若实测推翻估计，应修正模型；不能压低实验结果去迎合预测。旧负载或其他机器规模的 L/U 不能直接迁移。

## 3. 用边界决定投入，而非按特性逐个打勾

对有希望改变下一决定的候选，只需说明：它可能消除或重组什么工作、适用范围、关键未知、最小判别办法，以及时间/机器/token 成本。证据弱可以先做廉价否证；不要求新结构先有性能证据，也不默认偏爱改动最少的代码。

- 只有某候选族的有效上界不超过 L，或已证明不满足约束，才能按证明排除该范围。单个实现失败不排除整个机制；只在单独启用时得到的上界也不排除协同组合。
- 上界不严谨时，按潜在端到端收益、信息价值和验证成本排序，暂缓与否定分开。宽松上界只说明尚不能排除，不代表收益一定大。保留对未建模机制的有限探索，不能让低置信度成为永久禁入理由。
- 观测到的瓶颈和整体重设计都可作为入口。CPU、设备片段、完整部署按问题选择；缩小实验需保留相关形状、工作集、路由与拓扑。局部收益还需检查关键路径、容量及组合交互。

高价值工作可以提高 L、收紧有效 U，或解决会改变投资方向的重要未知；不要求每轮都提速。重复没有新增信息的实验、无法影响系统目标的局部提速、不断增加流程设施，应降低优先级。

## 4. 什么时候可以说接近最优

若 L > 0，且覆盖整个 F 的有效 U 满足 `U / L - 1 ≤ ε`，则在已说明的假设和置信条件下，最优方案相对 L 最多还能提高 ε。例如 L=2000、U=2200 时，剩余提升最多为 10%；这是示例，不是 GLM 实测。ε 随业务价值和测量能力确定，不在此预设。

只覆盖某个有限候选集合的证明，就只声称该集合内的最优性。预算用尽或继续实验价值很低时可以停止，留下尚未解决的差距，不能因此称已最优。探索新执行结构或改变 F 后，重新检查上界和原来的排除结论。

数学参考：[Boyd 与 Mattingley，Branch and Bound Methods](https://see.stanford.edu/materials/lsocoee364b/17-bb_notes.pdf)。其收敛保证依赖有效且可收紧的界与规定搜索条件；借用上下界与剪枝原则，不声称本项目已具备完整分支定界算法或全局收敛保证。
