# 按需参考：研究执行机制与可达性能

主线：**从服务承诺和物理资源出发，构造更好的执行方式，用有辨别力的证据决定后续投入。** 研究对象包括每份有效服务的资源需求，以及工作在时间和设备上的组织；二者相互影响，不能仅在固定执行图上寻找更好的参数。性能边界是按需工具，不是必须先完成的证明。当前事实只在 [HANDOFF](HANDOFF.md) 维护。

## 1. 定义我们在优化什么

区分物理事实、用户约定和实现假设：有限资源与真实因果关系必须满足；模型、精度、业务范围和允许算子定义当前比较问题；批次、状态归属、布局、模块与框架调用顺序是可推翻的实现选择。保持服务承诺不等于保持当前内部行为。可行域 F 由本轮明确的约定与物理条件确定，Q(x) 是其中方案 x 的可持续有效吞吐；说明 token 统计、失败请求和聚合口径，不靠少完成工作改变目标。

用户同时要求更快的 TTFT、TPOT。以下吞吐上下界适用于已明确延迟约束的比较切面，不把多个目标强行合成一个分数；同时保留同资源、同到达负载下的延迟比较，报告取舍。无需先建完整性能曲线才可做首个实验。

资源代价可以交换：增加存储或计算可能减少通信与等待；高利用率并不证明当前工作量必需。候选须重新推导自身的必要依赖，不能把框架同步当作语义要求，也不能删除真实因果关系。在线策略只能使用当时可得信息，评估需计入后续排队与资源争用。

参数搜索交给用户安排的其他执行者；本线保留必要的配置对照，不以调参次数或新配置为主要交付。动态输出预算的机制可以研究，但仅替固定工况寻找数值仍属调参。不等待穷举参数才探索新机制；最终比较需排除基线明显失配，并说明各方调优程度，不能默认已充分调优。

修改外部合同或扩大算子集合会改变 F；范围外候选可讨论，但不能靠自行改写 F 变更用户约定。临时实验控制可按证据调整并记录，最终验收仍守住已授权范围。六台和标准 PD 是本轮实验与验收选择，不是最小配置或全域最优架构的结论。

## 2. 用证据决定研究投入

对有希望改变下一决定的候选，只需说明：它可能改变的执行代价或时间组织、关键未知、判别办法及时间/机器/token 成本；解释可以暂不完整。证据弱可先做廉价检验，不要求新结构先有性能证据，也不默认偏爱改动最少的代码。必要的组合可以整体验证，不要求每项拆开都提速；低成本实验优先不等于禁止大设计。

- 按潜在端到端收益、信息价值和验证成本安排投入；暂缓与否定分开，不要求先给出精确估计。保留对未建模机制的有限探索，不能让低置信度成为永久禁入理由。
- 单个实现失败不排除整个机制；只在单独启用时得到的界也不排除协同组合。未经证明的估计不能用来永久排除候选族，宽松上界也不代表收益一定大。
- 观测到的瓶颈和整体重设计都可作为入口；局部收益需检查关键路径、容量及组合交互。用下述最小验证选择环境，不把微基准提速直接当业务收益。

高价值工作可以改善已验证方案、澄清可达边界，或解决会改变投资方向的重要未知；不要求每轮都提速。重复没有新增信息的实验、无法影响系统目标的局部提速、不断增加流程设施，应降低优先级。

最小验证按结论的因果依赖选环境，减少无关工作，保留可能改变结论的因素。不是必须依次完成的 CPU→单卡→六台流程；需要完整拓扑的机制可以直接使用六台，也不要求先建设通用模拟平台。

| 要判断的机制 | 最小验证与结论边界 |
| --- | --- |
| CPU 数据结构、队列操作、调度计算 | Mac 可做逻辑测试与状态回放；部署性能需在目标同类 CPU、相关线程/进程与工作集条件下测量。无需加载模型，只证明 CPU 路径的正确性和成本。 |
| 接纳、组批等在线策略 | 状态回放可检查决策和不变量；策略改变组批后，旧 trace 的完成时间不能直接代表新策略。闭环模拟需使用经设备校准的耗时模型，结果仍是预测；决策不使用当时未知的未来信息。 |
| NPU 计算、布局或执行片段 | 按机制保留真实 shape、dtype、工作集、相关状态与执行方式，使用必要的逻辑芯；只加载所需片段。缩小层数或使用合成数据须说明哪些性质保留，小模型不能默认替代目标模型。 |
| 跨芯/跨机通信与重叠 | 保留必要 rank 数、消息量、路由、拓扑及竞争，必要时六台但不加载完整权重。两机或纯通信结果不能直接外推六台业务中的通信重叠。 |
| 完整服务收益 | 在已验证可运行的六台布局上，比较相同业务条件下的 TTFT/TPOT、成功率及可持续吞吐；包含排队、P→KV 传输→D 和资源争用。 |

已有真实片段与请求元数据优先复用，没有时可先做明确标注的合成逻辑验证。只补足下一决定所需的证据；CPU 可并行调查，设备实验按资源隔离，不能让其他作业污染性能对照。

## 3. 按需参考：性能界与最优性声明

对最大化吞吐的问题：`L ≤ Q* ≤ U`，其中 Q* 是 F 内的最优吞吐值。

- L：已满足正确性与服务要求的可行方案所支持的保守吞吐下界。实测需注明工作负载、测量误差与置信条件，不能把一次峰值当保证。
- U：对整个声明可行域有效的吞吐上界，来自必要工作量、资源容量、数据依赖等约束。现有框架的额外同步、padding、重复读取不能直接算成所有方案都必须承担的工作。
- 启发式预测单独标为估计；微基准测出的带宽或模拟器结果不是物理上界。流水与并发下，不能任意相加阶段耗时或取最大值就称得到系统极限。

U 暂时未知可以继续研究。实测推翻估计时修正模型，不压低结果迎合预测；旧负载或其他规模的 L/U 不能直接迁移。只有候选族的有效上界不超过 L，或已证明不满足约束，才能按证明排除该范围。

若 L > 0，且覆盖整个 F 的有效 U 满足 `U / L - 1 ≤ ε`，则在已说明的假设和置信条件下，最优方案相对 L 最多还能提高 ε。例如 L=2000、U=2200 时，剩余提升最多为 10%；这是示例，不是 GLM 实测。ε 随业务价值和测量能力确定，不在此预设。

只覆盖某个有限候选集合的证明，就只声称该集合内的最优性。预算用尽或继续实验价值很低时可以停止，留下尚未解决的差距，不能因此称已最优。探索新执行结构或改变 F 后，重新检查上界和原来的排除结论。

数学参考：[Boyd 与 Mattingley，Branch and Bound Methods](https://see.stanford.edu/materials/lsocoee364b/17-bb_notes.pdf)。其收敛保证依赖有效且可收紧的界与规定搜索条件；借用上下界与剪枝原则，不声称本项目已具备完整分支定界算法或全局收敛保证。
