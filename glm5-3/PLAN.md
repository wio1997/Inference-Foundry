# 按需参考：选择下一步

这里提供思考提示，不规定执行顺序或交付模板。当前进度只在 [HANDOFF](HANDOFF.md) 维护。

- 先弄清要改善的吞吐指标与比较条件。组批能力属于端到端性能，只有诊断相同工作执行差异时才固定实际 batch。
- 优先研究对结果影响大、已有证据支持且验证成本可控的问题。粗略上界、源码、trace 或一次直接对照都可以帮助选择；无需先完成全系统建模。
- 分开模型必要依赖与框架额外顺序。独立描述机制后，在现有框架或独立片段中选择更直接的实现；发现结构限制再替换对应模块。
- 若采用缩小实验，检查它是否保留相关 shape、KV/权重工作集、路由和通信拓扑，能否复现原瓶颈。小模型和重复同层不能自动代表原模型。
- 若测量没有改变下一决定，先检查假设和测量方法。局部收益成立后再验证原模型及业务吞吐，不为了增加实验次数反复测同一件事。
