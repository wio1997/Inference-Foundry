## What would decide the next code question

For repeated steady iterations, construct a non-overlapping interval timeline: device graph/compute/collective activity; actual graph submission boundaries; exposed device inactivity; the host or readiness boundary immediately preceding the next submission. Match same-ordinal collectives across ranks and correlate their enqueue/host-launch frontier. Device wait duration alone does not distinguish slow peer submission from required peer compute.

- Predominantly exposed pre-submit intervals with repeatable metadata/input/sampling host scopes would justify focusing on those concrete consumers.
