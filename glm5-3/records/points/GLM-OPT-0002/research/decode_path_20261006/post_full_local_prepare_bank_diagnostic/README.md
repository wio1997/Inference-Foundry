# H13 dual-bank research shim — staged, not installed

Only two installed-file replacements are proposed: prepare_finalize.py and model_runner_v1.py, with adjacent diffs/identity. Production7bb35e candidate is untouched and separate. No Run, service or device operation was performed. Device correctness and benefit are unknown.

Enable only with `GLM_H13_BANK_ROOT` pointing at a controller-created private directory containing exactly two-byte `h13_mode.bin` (mode0/1, observe0/1) and an empty `witnesses/`. No environment variable means both original class methods remain installed. Source hash/schema, H6/H5 modes, H11/H12 off, current target FULL bucket2/Noop/SFA/TP16 contract must be frozen and verified by controller; this diagnostic does not expand admission to other configurations.

At original initial capture (no existing entries), A wraps the current raw model and B wraps that identical raw model. Both receive explicit distinct torch.npu.graph_pool_handle values. Each calls the saved **Ascend** capture_model with its contexts intact; dispatcher/graph parameters are not reinitialized, workspace not unlocked, no graph reset. Process-local prepare override forces A original and B candidate including their eager warmups. Exception propagates after override cleanup: initialization must fail and the one recovery gate must run. Do not continue with the partial A bank.

A selector subclass of BreakableACLGraphWrapper preserves get_model()/unwrap behavior, holds both wrappers/pools/entry outputs, and dispatches the same descriptor to the chosen bank. FULL does not reenter prepare Python; NONE and eager MTP use current prepare mode. No sync/fence is removed. Strong Python references retain graph/capture/output objects; this does not turn underlying weak tensor references into independent owned storage, so native graph-pool lifetime remains device-correctness evidence to establish.

During original NONE warmups only, observe1 compares original/candidate tensor bytes on CPU, shape, stride, NPU format and hidden/router/mask nonmutation. It runs once per mode/shape key. FULL capture never executes this byte oracle. The immutable per-rank capture witness includes both layout records, graph pools and outputs. Subsequent FULL runtime witnesses only read metadata/pointers. observe0 executes no byte validation or filesystem witness writes (mode decoding/integrity checks remain). Model weights, KV, metadata and existing sampler paths are untouched.

Runtime mode writes are **only permitted by the owning controller at a verified idle request boundary**, after previous outputs/side copies have completed. Both ranks' mode transitions must be checked by ordinary all-rank witnesses outside measurement. The selector cannot infer scheduler quiescence from a model call and intentionally does not invent an idle check. A control-file write during a request is invalid and can mix eager MTP preparation with the selected target bank. Keep mode fixed throughout each request. One-byte mode/observe changes must be performed as one controller transaction while idle; the script reads both bytes as one mmap slice.

`check_shim_CPU.py` executes the actual new shim AST using the prior actual-source lifecycle setup, real temporary files/mmap, and graph/stream/tensor doubles. PASS covers two captures, private A/B/A/B outputs, NONE, observe0 no I/O/byte checking, immutable writes, invalid bytes, B capture failure, override cleanup and env-disabled original methods. Source hashes are in shim_CPU_result.json. Separate actual Torch CPU3888 provides numerical local-prepare evidence; this test does not duplicate or replace it. No torch/torch_npu imports occur. Initial local test setup needed its dataclass module registered; fixed before PASS.

Unproved: native NPU format of new_zeros, HCCL capture with two pools, actual graph allocation/weak-output lifetime, memory headroom for both banks, all-rank correctness and matched E2E. No production or performance promotion follows from CPU PASS. Review source/diffs before defining any device diagnostic; no external execution is authorized by these files.
