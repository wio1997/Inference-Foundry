# GLM Execution Research — AGENTS

规则版本：`GLM-EXECUTION-RESEARCH-v3`，2026-10-12。

用户当前目标：从 GLM-5.3 的模型语义、现有正确算子和 Ascend 910C 资源出发研究执行方案。SGLang / vLLM 是对照和可选集成环境，不限定候选的执行顺序、并行布局或运行时结构。框架局部 patch 可以成为工程成果，但不能自动代替这条研究主线。

## 恢复与操作范围

先核对 Git，再读本文件、[HANDOFF](HANDOFF.md) 和 [MISSION](MISSION.md)。按当前问题读代码/证据；不默认恢复旧 controller、next_action、模型路由或遍历全部 Run。

本轮授权仓库重构、离线证据分析和本地测试。此前用户暂停现场调优的约束仍有效：不连接/修改现役服务，不加载权重、不提交模型请求或 NPU Run。恢复设备实验需要用户明确恢复指令。这个边界不阻塞本地实现。

## 研究对象

- 必要依赖来自模型语义和状态生命周期；框架当前顺序是一个待比较的 plan。
- 先定义待验证机制，再截取保真片段。不能用无关小模型的性能替代 GLM，也不能默认缩层后缓存、KV 压力和拓扑仍相同。
- 候选写出不同于基线的执行决策、预期变化的关键路径、否定条件。开关/参数只有服务于机制对照时才进入实验。
- 允许重写执行器、布局和通信编排；当前算子实现与精度合同保持不变，新增计算 kernel / 量化路线需单独变更研究边界。
- 不预定使用 SGLang/vLLM 热路径，也不为了独立而重写无关服务功能。

## 证据与停止

`execution_lab/` 的估计只用于筛选；reference replay 只证明显式 callbacks 的 CPU 结果。二者不是 GLM/Ascend 正确性或性能证据。真实片段必须经原模型校准，正式产品仍需动态请求、标准 PD、完整功能及 SLO 验收。

每轮保留一个简短问题记录：假设、证据、干预、预期可回收时间、结果、下一决定。未降低关键不确定性时停止扩展该方向；不以 Run 数、patch 数、文件数作为进展。不因局部证据未满足产品 SLA 而抹除局部结论，也不将局部结论提升成产品 Current。

历史原件见 [legacy](legacy/README.md)，收益边界见 [审计](docs/RESEARCH_RESET.md)。不得改写旧 Run、补丁、manifest、hash 或把旧工作量重标为新模型。实验继续归档到 `records/`，不复制第二份性能账本。

协作按接口划分：独立计划、证据审计、正确性审查可并行；同一代码区域和设备由一个负责人控制。无需先搭代理模型路由、交接模拟或通用任务平台才能研究。模型选择使用当前会话配置，不从旧文档继承供应商/模型名。
