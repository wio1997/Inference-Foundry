# GLM Extreme — AGENTS

作用：固定目标与裁决，保留研究自主性；短入口用于恢复，细节按需读。

## 1. Project Goal

为GLM构建功能完整的专用推理框架，在现有两台服务器的可行域内寻找并逼近调度极限。支持动态请求、可变输入输出与PD/并行配置。当前用GLM-5.2研究性能；不做5.2/5.3精度比较或量化质量评测，不改算子计算实现、不自动转kernel。现场身份见MISSION；旧DeepSeek配置/DSpark/Current不继承。

## 2. Agent Autonomy

可探索未列方向、推翻前提、重排/合并工作、改变可行部署或大幅重构控制层。V2是优先候选，证据决定路线；不固定P/D比例、shape、cohort、模块、候选数量或一轮一项patch。无需完美DAG/数值界才做原型；流程和角色建议可调整。

## 3. Research Logic

必要语义/状态依赖 → shape与资源条件成本 → 最大可信Gap/未知 → 区分性实验与合法重构 → 真实E2E → 更新界。关注有效服务容量和延迟，沿输出关键链归因；prof热点/利用率不是极限证书。必要依赖来自模型与消费者，当前代码顺序可质疑。

完整功能默认保留，从接口、参数、协议、分支、测试和行为持续恢复，不让手工清单缩小范围。专用与兼容路径保持相同状态/提交/输出合同，成本计入E2E。检查深度与改动风险匹配。

## 4. Verdict and Limits

正式KEEP依据同口径、可重复、功能有效的完整E2E；profile/微测/模拟/内部TPS分别标记。有效计数、KV/状态、MTP提交及多rank匹配不能牺牲。更改工作量、部署或负载时说明类别与比较边界。

同工作包、有效合法类中L≤T*≤U，剩余可能TPS提升≤U/L−1；持续服务看达标稳定容量及有效上界。Stock固定节点/shape的界不证明重构空间极限；跨配置只覆盖当前可行域。缺界写unknown，不凭几个REJECT宣布到顶。[判据与方案](PLAN.md)。

需要额外硬件的方向记当前不可实施，不等待扩容。可给“该PD配置不适合当前资源/负载”的条件结论和当前最佳方案；D空闲须辨因，未来支持不成为本阶段完成门槛。

## 5. History and GitHub Records

昂贵实验前按机制查旧知识/优化点索引，记录适用差异和本次新增信息；旧证据足够则复用，不重跑。DSpark实现和旧收益不直接变成GLM成果；历史失败按原因与条件使用。读[复用入口](REUSE.md)。

GitHub是权威记录。优化点唯一ID关联代码与Run；KEEP/REJECT/INCONCLUSIVE/INVALID均留证据，Current只提升有效结果。提交与最小证据字段见[RECORDING.md](RECORDING.md)，不重复造账本或堆大trace。

## 6. Cost and Collaboration

先读已有证据；少量真实窗口区分假说，尽量复用驻留权重/资源。拓扑、地址、ABI或capture变更按依赖重建，不承诺任意热切。重型prof与正式性能分开；多实例/rank核对覆盖与时钟误差。单controller管理共享现场，只操作本次资源，不盲重跑或声称虚假后台。

简单可验收任务默认zcode --prompt，现成shell输入一条完整命令，代码任务说明范围/验收；主Agent核验内层执行与产物。建议持续主线Sol high，难题按需ultra/Astra；当前用户ultra不自动更改，不禁用Sol主Agent，不每Run双模型批准。

## 7. Context Efficiency

启动只读本文件、HANDOFF和当前优化点/Git状态，资料按需检索。HANDOFF保留Current、活动点、关键证据、已否定解释和下一问题；历史用索引，不重放会话或全仓库。只在有恢复价值的checkpoint更新相关记录，事实维护一份。省token不能省掉决定裁决的证据。
