# 按需参考：执行机制与最小验证

主线是：从必须交付的服务出发，构造更好的执行方式，用能影响下一决定的证据安排研究投入。硬件容量与速率、真实因果关系必须满足；当前算子调用、数据布局、状态所有权和同步方式属于可检验的实现选择。

## 怎样选择工作

系统问题是哪个合法实现提供更好的服务；研究问题是下一次花多少时间、机器与 token 能获得多少收益或有用信息。二者分别判断，不只选最容易改的代码，也不强迫先求完整理论界。

候选简述可能改变的资源代价或时间组织、关键未知和判别办法即可；解释可以暂不完整。允许跨模块组合与暂时没有单项收益的中间实现。单个实现失败不否定整个机制，没有信息增益的重复实验则应停止或转向。

参数组负责配置搜索；本线保留必要对照。最终说明基线与候选各自调优程度，避免明显失配，不等待参数穷举完成才探索机制。动态输出一个参数是否有价值，要看它是否解决了在线决策问题，不能只凭“动态”或改了代码判断。

## 按结论依赖选择环境

最小验证减少无关工作，保留可能改变结论的因素。下表是非穷尽的参考例子，说明各类证据能支持什么判断；不是候选范围或 CPU→单卡→六台的必经流程。

| 要验证的机制 | 最小环境与结论边界 |
| --- | --- |
| CPU 队列、数据结构与调度计算 | Mac 可做逻辑和状态回放；部署耗时需目标同类 CPU 与相关并发、工作集条件。无需模型权重，只证明 CPU 路径。 |
| 接纳、组批等在线策略 | 回放检查决策与不变量；未校准模拟可探索假设与敏感性，其数值不能作为真实收益或排除路线的证据。面向设备的定量预测需适用条件下的校准依据，仍不等于实测；新策略不能把旧批次完成时间当作自身结果，决策不使用当时未知的未来信息。 |
| NPU 计算、布局与执行片段 | 使用必要逻辑芯，保留相关 shape、dtype、工作集、路由和状态。优先真实模型片段；小模型或合成数据不能默认代表目标行为。 |
| 通信与计算重叠 | 保留必要 rank、消息量、拓扑及竞争；可能需要六台而不需要完整权重。两机或纯通信结果不能直接外推六台业务。 |
| 完整服务效果 | 使用已验证可运行的六台布局，比较匹配条件下的正确性、成功率、TTFT/TPOT 和可持续吞吐，包含排队、P→KV 传输→D 与资源争用。 |

已有真实输入与片段优先复用；缺失时可先做标注清楚的合成逻辑验证，不先建设通用平台。CPU 调查可并行，设备对照避免其他作业干扰，片段收益还需确认是否影响最终服务。

## 边界与证据

必要工作量、资源和依赖可帮助估计可达性能；当前框架的额外工作不能直接算作所有实现都必须承担的代价。条件估计、微基准和局部下界不冒充全域证明；上下界未知也可继续研究，实测反驳估计时修改模型。

只有覆盖声明范围的有效界，才能用于不可能性或接近最优的结论。当前没有新线的界或性能结果；预算耗尽、暂时找不到更好方案都不等于全局最优。记录与结论随实际证据产生，不先搭建复杂记录体系。
