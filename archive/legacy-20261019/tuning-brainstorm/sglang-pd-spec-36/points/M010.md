- 审阅状态：共享前缀/分裂源码类 CPU 已核验；候选与性能未决。
- 类型：conditional_candidate。
- 主线：PD 分离 + 推测解码保留；Ascend 实际配置待运行合同确认。
- 本文是用途、假设与最小实验设计，不是已取得加速的报告。

## 它干什么

前缀树把共享输入合并起来，匹配后直接复用已经算好的 KV；树节点主要管理键、索引和状态。

## 当前怎么做

压缩路径保存一段 token，匹配沿子节点向下，必要时切分节点。哈希块是另一种索引组织，不能只凭数据结构名字断言更快。

## 成本在哪里

CPU 比较、字典查找、token 切片及节点分裂；命中后 Attention 仍可能读取历史 KV。

## 这次考察的优化思路

复用 CACHE-009 的 offset 插入遍历：用原始 token 加当前位置替代每到一层复制剩余后缀，保留最终节点必须持有的独立键。

## 什么条件下可能适用

实际使用审计过的 Python TreeCore，长输入跨多节点；Rust 或其他缓存实现另核验。

## 新增成本与回退场景

短单节点收益小；误用原输入的可变视图破坏节点长期键；分裂时复制仍可能必需。

## 不能破坏的语义和生命周期

比较插入返回、树结构、键、匹配长度、索引、锁及淘汰候选；输入对象后续修改不影响树。

## 最小实验

**基线**

固定一棵树及 token 序列，记录原路径的复制元素量。

**唯一改动因素**

只改变插入遍历的后缀表达；不改匹配策略、LRU 或物理 KV。

**用例**

- 单节点全命中
- 长共享前缀后多分支
- 节点内部首次分裂
- 多轮请求延长与取消

**预测**

深路径的临时复制量下降；短路径接近不变，树结果逐事件一致。

**指标**

- 复制 token 元素数
- 临时对象量
- 插入 CPU
- P 调度暴露时间

**否定条件**

任一树状态不一致即失败；若运行路径已实现等价改动则标已有，不重复实现。

**第一个可执行动作**

读取实际缓存类及插入实现，与 CACHE-009 的有限状态证据分开记录。

**最低执行层级**

实现对齐 → 插入状态机 → P 服务

## 逼近物理极限的分析

**必要工作**

必须验证前缀身份、得到可复用边界并保证树键长期稳定；无法无条件跳过内容比较。

**资源与依赖边界**

可用前缀索引的信息量与必要读取决定乐观下界；CPU cache、对象与分支限制实际性能，O(n) 相同不代表常数相同。

**怎样校准可达上界**

用完全驻留、相同键长度/扇出/深度的对照数据量必要比较与复制，测最快正确实现的单操作服务时间及缓存冷热差异。

**怎样判断剩余空间**

offset 消除后继续核算重复字典查找、已算页键、索引收养与对象开销；每个改动单独证明再研究协同。

**条件特化与回退**

按长路径/高扇出、page、冷/热 CPU cache、共享边界和组件类型特化；实际 MTP/PD 只影响调用流与生命周期，不改变键身份。

**何时停止当前方向**

临时后缀复制已消除且剩余成本能归于必要键读取/状态更新；在受测数据结构与负载区间称近可达，不能据此证明 radix 全局胜过 hash。
