# 输入与输出 token 吞吐

按用户要求只记录数据，不设置价格。这里的输入吞吐是完成请求承载的逻辑输入 token/s，包括缓存命中的输入；不是 P 实际重新计算 token/s。P、D 的同一份输入只计一次，输出只计最终返回的 600 token，不累计被拒绝的 MTP 草稿。

每请求服务侧输入为 80,012 token，输出为 600 token；原始文本语料的 80,000 token 与服务封装后的计数不同。是否全部属于产品计费 usage，应由计费接口合同确认。

## 缓存与实际计算量

六轮正式窗口聚合结果一致：本地 prefix 命中 74,240 / 80,012 = 92.7861%；P 加上外部复用 128 token 后为 74,368 / 80,012 = 92.9461%，P 每请求剩余计算 5,644 token。D 接收本地 miss 对应的 5,772 token KV 是 PD 传输，不是另一次用户输入，也不能算作用户 prefix 命中率 100%。

| 测试 | 逻辑输入 token/s | 本地缓存输入 token/s | P 剩余计算输入 token/s |
|---|---:|---:|---:|
| rate093_c16_pilot | 57,839.59 | 53,667.09 | 4,079.97 |
| rate093_c32_pilot | 60,364.54 | 56,009.89 | 4,258.08 |
| sat_c16_pilot | 77,111.62 | 71,548.85 | 5,439.41 |
| sat_c32_pilot | 138,072.58 | 128,112.13 | 9,739.56 |
| sat_c64_pilot | 237,399.99 | 220,274.15 | 16,746.06 |
| sat_c96_pilot | 321,898.35 | 298,676.87 | 22,706.52 |

不能把内部 KV cache 命中计数直接当作商业缓存优惠 usage。以上为正式窗口聚合值，未证明逐请求命中率均不超过 93%；跨 saturation C16/C64 发现一条完整输入重复，未观察到聚合命中率抬高。后续实验须使用跨轮唯一后缀并继续检查命中率。
