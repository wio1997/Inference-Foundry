# GLM-5.3-Flash 多模态测试方案 v1

日期：2026-10-16（Asia/Shanghai）。本文件是新增测试设计，**尚未执行**，没有多模态正确率、带宽或吞吐成绩。适用于 Flash 的 vLLM-Ascend 14P→15D 与 SGLang 46P→47D；不把原 GLM-5.3 的文本 4P2D 结果当成 Flash 多模态成绩。

## 1. 当前支持边界和里程碑

官方 vLLM-Ascend Flash A3 文档使用 v0.30.0RC1、V1 runner，示例设置 `image:1, video:0`，包括 PD 示例。因此单图作为第一实现/验证目标；多图和视频列为待适配/待验证，不声称已经可用。PD 文档本身仍属于参考方案，不能以命令存在代替实际权重正确性。

SGLang Flash cookbook 的多模态配方面向 NVIDIA/AMD，不能替代 A3 验证；其中视频、encoder disaggregation、CUDA IPC/VMM 的参数不能直接搬到 NPU。模型结构支持视觉也不等于本镜像的加载器、processor、算子、图、PD 和缓存组合全支持。音频不属于本方案已确认的输入类型。

阶段顺序：文本功能参考 → 单机单图 → 真实 1P1D 单图 → 独立视觉前缀缓存 → 混合调度/图/MTP → 多图/多轮 → 视频。每阶段先有界正确性，通过后才启用该范围的性能矩阵。一次修改一类状态/接口，不在首轮同时打开所有未验证功能。

## 2. 功能和正确性矩阵

| 编号 | 用例 | 最低验证内容 | 初始范围 |
|---|---|---|---|
| MM01 | 单图识别、计数、空间关系 | 答案必须依赖图片，替换图片后答案相应变化 | 必做 |
| MM02 | OCR / 文档 / 表格 / 图表 | 文字、数值、结构关系正确；小字/纵横比/旋转预处理一致 | 必做 |
| MM03 | 分辨率与预处理边界 | 512×512、1024×1024、2048×1024、1024×2048 候选素材；记录实际 resize/crop/grid/视觉 token，不能把原像素当执行量 | 必做，服从真实 processor 上限 |
| MM04 | 图文长上下文 | 图像位于前/中/后，正确检索图像事实与远处文本线索；4K→16K→80K 逐级 | 必做 |
| MM05 | 两图及多图比较 | 两图相同/不同、交换顺序、不同尺寸，不能串图或忽略后图 | 单图通过后，先验证支持限制 |
| MM06 | 多轮带图对话 | 首轮带图、后轮只问文字；再次带图/换图；对话模板、图像引用和状态保持正确 | 适配验证 |
| MM07 | 原生视频理解 | 时序、事件先后、帧中 OCR；帧采样、时间戳、时域位置编码正确 | A3 待适配，不默认运行 |
| MM08 | 文本与图像/视频混合批次 | 形状变化、乱序完成、流式输出、图回放、MTP 接受/拒绝，无串请求 | 逐模态支持后 |
| MM09 | 取消、错误输入和资源回收 | 排队/视觉编码/PD 传输/解码中取消，损坏图片/视频、超限、缺文件、客户端断连 | 有界正确性，不计性能 |

首轮单图正确性建议 32 个独立样本：OCR8、文档/图表8、计数/空间8、视觉语义8。使用有许可的公开材料或自制可公开合成图，冻结人工标注答案与评分规则。每张图的首测及换图反事实必须真正依赖视觉信息，不能只用文字提示就猜中。矩阵 JSON 是用例设计，不是已准备数据；执行前补齐真实 SHA，不能填占位哈希冒充样本。

准确性测试采用足够的输出预算与任务评分，记录思考模式和截断；不为了固定600输出强迫准确性样本生成填充内容。性能测试单独固定实际600输出（含模型实际 reasoning/文本 token，明示计数口径）。temperature/seed/思考开关/预算/解析器两边固定；vLLM 只是参考，稳定 gold annotation 与模型语义共同判定，不能用回答措辞逐字相同作为所有正确性的要求。

## 3. 数据、预处理与接口一致性

每个素材 manifest 至少记录：素材字节 SHA、许可/来源、格式/原始尺寸/时长、解码库版本、processor/tokenizer/chat template 版本和 SHA、resize/crop/patch/grid/帧时间戳、展开后序列位置、文本与视觉边界、问题/答案与评分规则、请求 namespace 及完整序列/内容身份。

现场无外网：Mac 获取允许使用的素材和 ARM64 离线依赖，再校验并传入内网。客户端采用两边都支持的相同 OpenAI 多模态消息结构和同一素材字节；优先使用本地素材构造 data URI，冻结 payload 大小。不能一边公网拉图、一边预先给 embedding。若某接口不支持 data URI，则共同选择离线内网素材服务并记录其读取时间，不能擅自改成纯文本输入。

视频另固定原文件及解码后的帧、采样时间戳/顺序、帧率、尺寸与视觉预算。4s/16s/60s、2FPS 是待验证候选，不是 A3 已测值；最终服从固定权重 processor 的真实契约。若两边原生视频不能产生一致帧输入，不做直接数值/速度对比，先解决预处理差异。把视频抽帧作为多图输入只能叫“抽帧多图路径”，不能当原生视频支持通过。

MM 请求不能简单套文本 `/v1/completions` input_ids 方法：占位 token 一致仍可能对应不同图片 embedding。应使用支持多模态的接口，核对 processor 输出和真实模型输入；无法对齐预处理/有效输入量的 run 不能进入框架性能对比。

## 4. 80K/600 与约93%缓存的多模态定义

主测试继承独立前缀四轮政策：C=16/32/64，分别 C 个不同视觉+文本前缀，各自预热，四个全新后缀，4C=64/128/256 条不同完整请求。**不同前缀使用不同素材内容**，不让全体请求共享同一图片/视频或同一74K长文本。单个前缀在自身四轮中复用其素材是该请求族的正常上下文复用；完整输入始终不同。

80,000 的目标是 processor 展开后语言模型实际消费的序列位置数，包含文本、视觉位置及模板特殊 token；另列原始文字 token、视觉 token/patch/frame 数和 API usage。部分接口 usage 统计不含相同视觉展开语义时，必须保留原值并补真实输入证据，不能把80K文本再加图仍叫总80K，也不能仅用图片占位符长度计数。仅有API usage但无实际展开证据的 run 为待核验。

预热目标约74,400个逻辑位置；必须选择有效的完整媒体段/processor边界及混合 KDA 状态检查点，不能截断图片 token 块或随意裁剪卷积/recurrent state。必要时选择最接近的合法边界并记录偏差；目标93%不变为伪造常数，未能实现约定比例时先修生成器/检查点再验收。完整请求总位置仍精确80,000。旧文本路径74,368或bigram对象数不能硬编码给视觉混合缓存。

先完成仅本任务 namespace 的前缀预热并等待异步写回；之后不清L1/L2，保留自然驻留。模型/图形状预热、视觉预处理/encoder预热、前缀KV预热分开记录且排除正式吞吐。正式请求中实际发生的素材读取、解码/预处理、视觉编码、缓存加载、排队、P/D和输出全部计时，不再手动扣除“打KV”的正式阶段工作。

## 5. 多模态缓存正确性与来源

必须区分三类缓存：解码/预处理后的素材缓存，vision encoder 特征缓存，以及语言模型 KV+KDA/conv 状态缓存。命中其中一类不代表另外两类也命中，更不代表整个请求跳过93%的计算。

缓存身份包含素材内容身份、预处理配置、图片/帧顺序与位置、模型/量化版本以及文本上下文。执行以下有界反例：同文字换图片、同文件名/URL换字节、图片/帧换序、同图改变resize/crop、相同图片不同前置文字、相同prefix位置但KDA状态不同。应miss/部分miss时必须正确失效，不能只对文本IDs做LCP或用URL当完整内容身份。

每请求记录实际HBM/L2/L3命中逻辑位置、缓存层来源、外部对象/字节和混合状态检查点；原生字段缺失保持null，独立证据来源必须标明。检查再次续写、取消/回收和后继不同请求，确认无跨请求状态污染。自然命中HBM有效，不强制称L3命中；正确性中的有意miss只是保护用例，不做用户不需要的冷启动性能报告。

## 6. 1P1D 与 SDMA 验证

起点是在P进行视觉预处理/编码和prefill，D消费交接后的模型状态并解码；这是设计目标，需用实际算子调用/trace确认。逐项核验DSA KV/indexer/scale、KDA recurrent/conv状态、位置/时域/图像边界元信息、完成事件与槽位所有权。若实际模型路径仍需embedding或其他信息，明确传输内容，不能只传普通KV就宣称多模态PD通过。

记录P和D各自视觉编码调用次数、CPU/DRAM/HBM占用、传输的逻辑/物理字节及实际SDMA路径；检查D是否重复解码素材/执行encoder。即使D不执行encoder，是否可以删除其视觉权重也需按实现验证，不能直接套language-only开关。不同流量会竞争HCCS/SDMA与内存带宽，不能假设带宽简单相加。

首先保持每框架两台服务器的总资源，不借额外E节点。编码器分离、embedding传输合并/去重、CPU解码并行与视觉特征缓存是后续有证据的优化候选；需固定总NPU/HBM与资源账本再A/B。图/MTP验证需覆盖不同图像形状、文本/图片混合batch、MTP状态提交/回滚和真实graph replay，不只看启动capture。

## 7. 性能矩阵与计时

先完成C1有界功能门控，再C16→C32→C64，每档四批；不对未支持的多图/视频直接发448条。先选择单图低/高实际视觉token两档与80K/600主负载，再做固定50%文本+50%单图混合负载；视频通过正确性后才加入。混合比例是初始设计，必须执行前冻结并在两个框架间保持一致。

同时保存：

- 完整请求TTFT/TPOT/E2E与各分位数、总输出TPS、逻辑输入TPS（包含缓存命中）、未命中重算量、成功/超时/取消/截断。
- 客户端序列化/上传、媒体读取与解码、processor、vision encoder、语言prefill、缓存读入、SDMA交接、D准入/首次decode的区间。允许重叠，不能把区间相加冒充TTFT。
- images/s、frames/s、实际视觉tokens/s、每请求素材字节、视觉调用次数和峰值CPU/DRAM/HBM、真实DP运行/排队；同资源下增加视觉缓存可能挤占语言KV，需一同记录。
- 模型/形状/素材/前缀预热的请求、token、时间单列。原生AISBench稳态规则可用则报窗口与样本，否则N/A；四批结果不冒充长稳态。接收token窗口不冒充NPU生成时间。

正式E2E计时覆盖客户端请求构造/编码上传到完成；若AISBench原生TTFT从HTTP发送后起算，两种口径分别保存，不混称。主负载使用内网素材以避免公网噪声；不能提前算好encoder结果却报告端到端多模态吞吐。图片/帧吞吐仅在素材执行量相同且正确性通过时比较，文本TPS不能替代视觉工作量。

准确性单独成表。纯文本历史SLA不自动成为已经通过的多模态SLA；先给完整原始分位数，业务SLA另冻结，不以放宽门槛算优化。官方A3目前video关闭的示例不支持就记未验证/不支持本配置，不能伪造视频性能或悄悄降级为文本。

## 8. 交付物和运行门控

每阶段交付支持矩阵（代码支持/功能通过/性能测量分开）、固定版本与实际argv、素材/预处理manifest、gold正确性、逐请求原始记录、缓存键反例结果、PD状态/SDMA证明、图/MTP证据、失败及资源回收、全程/稳态报告。性能收益只在同一模态/素材/输入展开量/精度/缓存和硬件条件下计算。

`tracks/flash-adaptation/multimodal-matrix.json` 是机器可读计划，不是执行器或已生成素材。当前没有新多模态素材下载、现场部署或模型请求。执行仍需父审查冻结后经本机ZCode DeepSeek唯一launcher；不恢复定时任务，不增占别的实验线设备。
