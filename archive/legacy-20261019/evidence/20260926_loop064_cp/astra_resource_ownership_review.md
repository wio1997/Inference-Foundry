# Astra High Resource/Hardware Bound review: compulsory work versus CP cache replicas

Independent read-only review of source and existing Run242/247/250/256/Run99 evidence. No NPU use, no running-source modification. This file and the conditional static ownership table are review inputs, not implementation authorization or a KEEP verdict.

## Current resource accounting remains incomplete

Run242's155.676GFLOP/rank/cycle routed-GMM and Run256's58.385GFLOP Compressor two-projection counts are canonical arithmetic of sampled/current dispatches. They are neither the full model FLOP count nor proof of irreducible algorithmic work. Run242's8.462GB active packed experts and Run256's0.608174GB compressor weight footprint do not imply compulsory HBM reads: activation/KV/state/quant metadata, cache residency and replication remain unresolved. Run247'swhole-window median18.949755GB read and2.380327GB write describes current transactions; GMM9.244GB versus a different route sample cannot identify same-cycle amplification. Run250's265 collective events and25,651,200 reported payload bytes are current operation structure, not necessary wire work. Run99's571.681TPS is an implemented point; the512-cycle loose acceptance count floor is supported for that zero-initial-output fixed path but supplies no cycle-latency bound.

The largest identifiable conceptual gap is the distinction between per-rank executed work and the distribution actually required by the frozen state/consumer contract. No existing evidence establishes which entire current replica updates are mandatory. Hardware capacity under concurrent mixed AIC/AIV/HBM work also remains unknown; measured isolated throughput is an attained example, not a defensible maximum. Numeric Resource/Hardware and Product bounds remain unknown.

## Source-backed ownership hypothesis, with strict scope

The CP path uses local-token query partitioning, not an explicit temporal-KV-shard reduction in the inspected path. deepseek_v4.py:745-775 constructs replicated wq_a, CP wq_b and wkv; CP query covers all64 heads for each local token. context_parallel/dsa_cp.py:847-914 intersects each request's query interval with a rank's flat-token interval, and gives non-owner requests zero local query lengths and zero local KV lengths. _forward:1430-1547 performs local Q on hidden_states_local but computes SWA KV and indexer cache from all96 gathered hidden rows. Its main compressor likewise consumes the full hidden rows. Attention at1590-1640 receives local query/KV lengths and local ori/cmp cache pointers with per-request block tables. The explicit AllToAll in _restore_tp_head_layout:1650-1675 transfers attention OUTPUT, after local attention, rather than gathering KV or reducing distributed attention partials. ops/dsa.py:_build_kv_cache supplies the local layer cache tensors. These facts support investigating redundant request replicas; they do not alone prove safe deletion.

At actual query_start_loc=[0,8,...,96], rank0..7 each own12 query rows spanning exactly2 logical requests. Across ranks there are16 request-rank memberships; requests1,4,7,10 straddle rank boundaries. Current full updates represent96 request-rank memberships. See astra_cp_request_ownership_screen.json. These counts are conditional logical ownership, not a factor-six traffic or timing gain.

Crucially, an owner needs its requests' HISTORICAL KV, not only its12 current query rows. The simple candidate must retain all relevant history and update full8-token blocks for both owned requests (16rows), including the request shared with its neighbor. It must not truncate KV to the current query slice or assume cross-rank request fragments are self-contained. Future query positions move through those same sequences. Non-owned request state may only stop advancing if it remains unconsumed for the entire lifetime and no ownership changes or external cache readers occur.

Native source adds supporting, not final, evidence: ascendc/sparse_attn_sharedkv/arch32/sparse_attn_sharedkv_scfa_kernel.h:325-350 derives query/key lengths by batch id; :699-736 processes that batch's query size and handles zero-query cases. sparse_attn_sharedkv_scfa_block_cube.h:384-395 sets page-copy Position.bIdx=info.bIdx and reads that request's block-table row. Prefetch/flush behavior means zero logical queries must not be equated with literally zero physical reads. Confirm the actual compiled tiling/kernel used and inspect QLI's batch indexing before claiming native consumer closure.

## What is still unknown and must precede an intervention

1. Prove actual Runtime query_start_loc and local active masks, not just nominal96/12 shapes. FixedTargetMetadataUpdater computes _local_active at initialization and uses it subsequently, while advance_state/parking changes token positions but does not intentionally reassign slots. Verify this invariance across recorded cycles and every parking transition.
2. Map every target SWA/compressed/indexer/recurrent-state reader and writer to physical storage ranges and per-request block tables. Shared-prefix pages and partial blocks can alias logically different requests. A non-owner logical write may still touch an owner-readable physical page; such cases invalidate naive masking.
3. Prove that historical KV for both owned requests was initialized on that rank at handoff, and remains correct after acceptance rollback/replay and c4/c128 state updates. The candidate cannot drop history merely because the current query belongs to one rank.
4. Audit target versus DSpark cache aliases, cache-transfer/connector hooks, prefix-cache bookkeeping, post-cohort reuse and possible slot migration/refill. FixedCohortServing currently parks without replacing requests and returns a terminal bulk output, but subsequent cohorts and shared prefix state still require explicit lifecycle proof.
5. Match the installed attention/QLI kernel's per-batch addressing and absence of hidden remote-KV service requirements. The inspected Python call has no KV communication between update and attention, but that is not a proof for every supported architecture.

Existing Run84/243 summaries prove compressor write-cardinality/page-candidate coverage; they do not contain enough per-request physical read-consumer detail to close all these points. Do not call the80 non-owner request-rank updates removable yet.

## Highest-information experiment to prepare offline

Prepare a one-c4-layer ownership-aware indexer-cache-update A/B. A retains full96-row indexer compressor/rotate/quant/scatter. B, only after consumer/alias proof, uses the16 rows of this rank's two owned requests with correctly gathered per-request compressor state/block tables, start positions, cumulative lengths and physical scatter slots. Local indexer query/QLI, main compressor, sparse attention and all collective order remain unchanged. The intent is to test whether the other10 request replicas of this one indexer cache need updating, not to change attention history or query math. Original semantics must be restored after the bounded test. This is an experiment plan; no patch is installed.

Before NPU time is available, source-locate every field and prepare the exact per-rank ownership table, physical-region checker and expected changed/unchanged cache set. If available evidence cannot prove consumer closure, the next hardware measurement should first capture only those missing metadata/block-table/read-owner facts; do not guess them. There is no need to rerun completed global counters.

On hardware, use same-state A/B/A and continuous multiple-cycle replay through emission boundaries. Compare owner-visible indexer state/key/scale, TopK, attention/logits and acceptance against the self-replay floor; allow untouched non-owner replicas to differ only after their non-consumption is established. Test rollback, parking, exit/reentry and prefix reuse as appropriate to the proved lifecycle. Measure true16-row kernel selection/tiling, traffic, and complete layer/Target/cycle. Only a legal positive intervention can promote a resource term to removable work; shape reduction can leave weight reads/tile cost unchanged or become slower. No proportional scaling or numerical TPS upper bound is justified now.

The eventual work categories affected could include unowned SWA wkv/norm/RoPE/scatter, main/indexer compressor arithmetic and recurrent-state/KV traffic. This first experiment changes only the indexer cache-update category. It does not remove routed GMM, local Q/QLI/attention for owners, required historical KV, or the existing hidden/output collectives. Broader communication/layout changes would require separate derivation.

Confidence: inspected CP local-query/full-update organization high; conditional2-request-per-rank table high; full-lifetime non-owner KV non-consumption unresolved; resource/latency/E2E savings unknown. This ownership question is a larger architectural uncertainty worth resolving even if the current compressor/Rotary overlap candidate fails.
