## Repaired source-level edges

- The original Run345 draft paused after three slots and let each rank decide independently before entering a new HCCL collective. This candidate selects the first dynamically parked slot. After **every** Runtime step, all eight ranks must reach the same generation, request-ID digest, cycle, complete parked mask and original pre-parking stop-decision signature before any rank can take the pause or continuation branch. Early output digest is checked across ranks after Host read. This is a diagnostic synchronization cost, not free overlap.
- `FixedCohortServing.run()` decides whether to stop using the `progress` snapshot obtained **before** `_park_completed()`. Parking can flush Host mirrors for other slots. Run562 saves that exact snapshot and resumes until the same decision predicate holds; it does not reread a post-parking mirror to decide whether to skip the next step. A pause is rejected if no old work remains at that original decision point. This is the original loop decision, not proof that a separate real request is still missing output after the Host mirror flush.
- The component requires an initialized eight-rank group at pause entry. Continuation requires the original generation and can be consumed once. After completion, it exports every cycle's per-slot accepted count and sampled token IDs and their SHA256. It compares **all eight 32-bit words** of the SHA256 across ranks, rather than a 63-bit prefix. This ledger supports later matched-control comparison, but does **not** certify full fixed `W₀`: Target/Draft semantic inputs, positions, KV/state and logical evaluation identity remain to be joined.
