## Exact ownership cut

`ModelRunnerOutput` can carry a private partial frame at a full all-eight Runtime cycle boundary. EngineCore must intercept it **before** Ascend's patched `Scheduler.update_from_output` (`patch_kv_delivery_preemption.py:833`). That method decrements every scheduled request's in-flight count, requires every scheduled request in `req_id_to_index`, uses special Extreme bulk output handling, and eventually frees completed KV. A partial three-row call to this method, or two calls with the same original `SchedulerOutput`, would corrupt accounting or release pages addressed by the parked Runtime.

The smallest legal experimental cut instead publishes three terminal `EngineCoreOutput` records directly, retaining all twelve original Scheduler requests as **ghosts**. It does not settle the Scheduler, remove old requests, or free their KV. The original Runtime object, Graph addresses, Host progress mirror and token histories remain resident. A separate continuation worker RPC resumes it before any new normal schedule. The final twelve-row bulk is then settled through the original `SchedulerOutput` exactly once. At the external output layer, rows already published early are verified against the final Scheduler-trimmed output and suppressed. `OutputProcessor.process_outputs` removes a request on an explicit terminal `FinishReason.LENGTH` without automatically aborting it; an unknown final duplicate would otherwise be ignored, but explicit suppression and exact token comparison are the gate.

Early token count must use `request.num_output_tokens == len(request._output_token_ids)`, not `num_output_placeholders` or the cached `num_output_tokens` transport field (which includes async placeholders). For each early request, publish exactly `max_tokens - len(actual_prior_output_ids)` tokens from the Runtime prefix. The original final Scheduler path applies `check_stop` and truncates at the limit. Run332's worker cached marks at four measured handoffs reported nonzero **output-plus-placeholder** counts; those values do not establish actual prior output counts. A live B gate must log and compare actual prior token IDs, early IDs and final trimmed IDs on each request.

`FutureWrapper.done()` cannot be polled to await continuation: its response is consumed lazily only when `.result()` drains the FIFO RPC response queue, and `result(timeout=...)` is unsupported (`multiproc_executor.py:70–100`). The first B gate can block EngineCore on the continuation `.result()` while the existing input socket thread still receives true client ADD requests into `input_queue` (`core.py:1583–1685`). It can prove real arrival before old-nine completion, but **not** Scheduler waiting/admission or refill. New requests enter Scheduler only after final bulk settlement. A later nonblocking gate would need a single, owned RPC response reader; two readers must not drain the same futures queue.

The continuation block also delays ordinary input processing. It must reject or invalidate an early-publication trial if an old ghost receives abort, shutdown or prefix reset during this interval; it must never silently free or reuse old KV. Upon continuation failure, an already successful HTTP response cannot be retracted, so the whole run is invalid and remaining requests need controlled cleanup. The private gate must record all-eight identical segment cycle/slots, physical Runtime/KV retention, old-nine pause, actual API/input-queue arrival timestamps, final one-time Scheduler accounting and exactly-once client output. It must not use future prompts before the client sends them.
