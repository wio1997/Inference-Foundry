This is close to, though not identical with, Runs148/150 one-card GMM read/weight ratios of 1.055/1.075. GMM kernel-duration sum in this instrumented cohort is 9.730 ms median; that is neither an exposed critical-path duration nor a savings estimate.

The `other` group is substantial. In one latest rank0 cycle, leading read contributors are ordinary matmul 1.149 GB, transpose batch matmul 0.639 GB, inplace copy 0.618 GB, AivKernel 0.390 GB, and HcPre 0.340 GB. Classification must be expanded before assigning this 3.618 GB to specific target subsystems. Latest target trace scopes have 54.796 ms median and 47.228–75.982 ms range; profiler/synchronization overhead and rank schedule prevent comparison to formal E2E throughput. Counter bytes can include repeat reads and do not prove unique compulsory HBM traffic. They omit HCCL link bytes and cannot simply be divided by a one-card bandwidth to produce an eight-rank hardware bound.

Result: real graph GMM weight-read amplification is modest, while quant, compression, attention and other operations jointly carry 9.722 GB read per rank-cycle. Next bound work should decompose that traffic, identify real execution dependencies and shape-specific attainable bandwidth, then test an implementation candidate under the strict correctness and formal E2E gates.
