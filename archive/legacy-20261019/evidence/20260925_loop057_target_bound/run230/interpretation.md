# Run230 target bound and one source-grounded discriminator

Run98 target device stage median46.560ms; stage-median sum54.177ms. Run107/143 GMM family profiled sum9.966ms. Run146 active W4A8 packed reads8.462GB/rank/cycle; Run148/150 one-card throughput screens7.880ms packed-read-only or8.373ms with measured read amplification, leaving optimistic gross1.593-2.086ms before non-weight work, overlap and rank effects. Merely removing measured read excess screens0.586ms. These cross-run arithmetic screens are **not** an achievable lower bound or formal E2E prediction. Communication gross includes arrival wait (Run145); small FP32 gather and cache scatters are bounded by Run152/197. No existing source-backed >=1ms target saving is proven.

A concrete narrow opportunity is the official MRV2 `npu_rms_norm_cast` use in DeepSeek V4 FFN prelude (`models/deepseek_v4/model.py:734-741,783`). Installed V1 separately applies post-attention RMSNorm (`models/deepseek_v4.py:1002-1007`) and converts the normalized hidden state to FP32 for its router (`:476-480`); installed CANN custom op artifacts include `rms_norm_cast` for 910B3. The fused op could remove a cast and intermediate traffic in43 target layers, but live availability, numerical parity and per-call time are unknown. Run231 tests one-card BF16 [96,4096] with actual separate/fused operator APIs and alternating event timing. For a >=1ms stage screen, median saving must exceed23.26us per layer before integration overhead. This is a one-card discriminator, not an all-rank or E2E claim.

A tempting `enable_fused_mc2=1` flag is rejected as a product A/B: 910B3 A2 selector with frozen EP8/32 local experts stays ALLGATHER; the flag first disables shared-expert multistream and may then reset. Changing selector would be a separate unsupported kernel investigation. Community target graph manager does not supersede Extreme direct target replay.
