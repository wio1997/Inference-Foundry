## Required clarifications before implementation admission

1. **Separate allocation lifetime, buffer content generation and row writer generation.** A pointer or Python object ID is not an allocation-generation certificate; tensor _version also does not track all custom-op device writes. Obtain a stable storage owner/lifetime token at cache binding, retain that owner through export without changing production allocation policy, and record storage-base/view-offset/extent plus cache/group/layer identity. Assign an explicit monotonically increasing writer token per intercepted production scatter and map it to each valid destination byte range. Record metadata-buffer content versions on every relevant producer. Alias detection must compare underlying byte ranges, including views; layer labels alone do not prove disjoint storage. The design names these facts but has no implemented acquisition mechanism yet.

2. **Snapshot placement must be device ordered, not just Host observed.** Context/query slot maps and lengths are mutable device buffers. Copies must be enqueued on the stream that already orders the producer and overwrite, after the producer and before reuse; an eventual Host copy of the original pointer is stale. Pre-attention copies must capture the version passed to that invocation. Existing waits may supply cross-stream ordering; a ContextVar or Python call return does not. If an input is produced on a different stream without an existing usable dependency, record UNKNOWN rather than adding a synchronizing edge. Preallocation prevents allocation overhead, but copy kernels still perturb resource demand and stream timing.

3. **ContextVar is only Host call ownership.** Capture immutable rank/cohort/logical-cycle/request-row/layer/role/ordinal tokens at submission, reset scope in finally, then join them to native task/flow identities. Do not recover native cycle by current ContextVar, Host completion, timestamp bin, or the next Target scope. Run613 already supplies a counterexample. Specify capture-vs-replay behavior: a Python hook executed during Graph construction is not a replay-generation witness. Preserve actual FULL/NONE dispatch, padded/actual shapes, active/parked masks and request ordering for the chosen new-W0 pair; reject a mismatched stratum without silently selecting a favorable later pair.

4. **Pre-attention arguments are necessary but not a measured physical first read.** The record needs actual cu_seqlens_q, seqused_kv, block-size/layout/slot format, block-table and sparse-index generations, mask mode, left/right window, and padded/valid row mapping, including explicit None values. In installed dspark_proposer.py:293–330, per-group device kernels produce context/query slots; lines334–355 then mutate effective seq lengths and query layout. Both before/after identities therefore matter. Pin the selected sparse-attention implementation/loaded binary and its ABI semantics, then derive the logical row read domain. Do not infer physical HBM transactions, earliest internal load time, numerical influence or compulsory work from receiving ori_kv. If kernel semantics cannot establish that a selected row is read, classify its reader edge UNKNOWN. Include all aliases and intervening writers before calling any observed reader the first reader.

5. **Predecessor and successor are typed value lineages.** A window-entry cache snapshot proves bytes currently present, not their historical last writer or an exhaustive inventory of reusable results. Use a bounded predecessor write ledger for current-hazard provenance, or explicitly label old rows ENTRY_UNKNOWN. Draft64→Target65 and Draft65→Target66 need the actual token/state/input-consumer lineage; Target does not directly consume the draft SWA cache. Handoff seed, Host count-copy lag, query overwrite, parked rows and terminal output drain must remain distinguishable. A next-Target marker by itself does not close a consumer chain.

6. **Split Scheduling admission from Resource freshness admission.** The current phrase “negative fixtures reject pre-entry reuse, cross-request duplicate, query overwrite” needs scoping. These can be legitimate workload events. The validator must correctly model them; only a proposed fresh-unoverwritten W-minus witness should be rejected/NO_WITNESS. A query overwrite may itself be the most useful Scheduling hazard witness. Incomplete entry-credit coverage must leave conditional W-minus unknown while retaining sound typed storage evidence. Exhaustively disproving every pre-entry equivalent result is not achievable from a two-cycle trace alone; declare the restricted online fixed-expression class and audited result-store inventory. Same prefix/token/position or differing hash/address alone does not establish semantic freshness. One retained row does not prove positive time or compulsory HBM bytes.

## Concrete live-readiness gate

Before live, provide the reversible patch and schema with exact source/binary pins, record-count and byte limits, overflow rejection, and a host-only validator over raw snapshots. Enforce the 128KiB/rank extra row-operand cap after calculating actual dtype/dimensions; separately declare a numerical total metadata cap. Full block tables or sparse-index arrays can dominate this budget, so bound selected ranges and prove they cover the claimed read set. Do not silently truncate an array. Bound all8 total cost and preserve original raw evidence.

Tests must include pointer reuse with a new lifetime, two views of one storage, same-address changed slot content, duplicate writes to one destination, masked/invalid/parked rows, context overwritten by query, an intervening alias writer, delayed native execution crossing next Target Host submission, absent/duplicated flow, wrong layer/group mapping, stale block table, missing predecessor/successor, overflow, wrong quant/ownership, same-position/different-prefix and pre-entry/cross-request equivalent result. Include a passing fixture with a known row-level writer→reader chain. Tests must reject unsupported claims, not valid workload reuse.

Correctness requires unchanged operation/collective counts and current-W0 request/output/acceptance/KV/state lineage plus same-state oracle or replay checks for the touched path. Natural cross-run acceptance/output nondeterminism is not a valid automatic mismatch gate; define the comparator, self-replay noise and acceptance/count parity policy before collection. A matching 48-request output length alone is insufficient. The observer must add no model invocation, collective, synchronization or decision based on copied device values.

The packet can be useful without A0/A1 timing runs when admitted only for identity; any later cost/saving transfer needs observer controls and a legal schedule intervention under resource contention. Readiness also requires guarded cleanup/source restoration and tagged service ownership. No current design result shrinks a numerical Resource/Scheduling/Product interval. It reduces uncertainty about exactly which new evidence would do so.
