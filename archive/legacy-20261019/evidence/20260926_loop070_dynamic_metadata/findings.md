# Loop070 — dynamic metadata in private Graph

The fixture enters real frozen DP1×TP8 c12 layer2 c4 Target at one prestate. Native Compressor metadata generation is captured **inside** full A and owner16 B private Graphs; A bypasses the live Python metadata cache. Private backing stores preserve aliases, and live `start_pos` is restored before the original Target call. Synthetic start shifts 0/−1/−4 test whether captured metadata responds to input; Q, RoPE, sequence lengths, SWA slots and the rest of the Runtime state do not advance with those shifts. They are not real successive cycles.

Run313 exited 1. All eight ranks passed real-entry delta0 A/B/A2 metadata and producer→QLI→Sparse parity. Some ranks stopped at synthetic full A before B, initially reported as Sparse inequality. No owner conclusion follows from those stopped arms. Run314 froze a same-Graph A control and an eager A reference to disambiguate. At **delta0, all 8/8 ranks passed** eager A versus Graph A/B/A2, fresh native metadata fields, owner current typed writes, QLI and Sparse, with finite Sparse. Ranks0/2/4 completed all synthetic shifts. Ranks1/3/5 stopped on synthetic −1 Graph A, and ranks6/7 on synthetic −4 Graph A; in these five cases both eager A and Graph A Sparse were nonfinite. `torch.equal` of Graph A to its own clone returned false because NaN is unequal to itself. This is not evidence of an eager-versus-Graph numerical divergence, nor an owner B regression. The source of nonfinite Sparse under inconsistent synthetic state remains unknown; the criterion was not relaxed to mask it.

Run314's diagnostic request carrier could not complete after the five ranks raised at synthetic A. The service was stopped; runner exit1, 11/12 clients marked success but only 0.203 diagnostic tok/s and incomplete outputs. This is **not** a Product correctness or performance result. Its reversible dsa_cp and target-handoff sources were restored to the exact pre-run SHA, and all eight NPUs returned to idle. Raw rank fixtures, bench, install/restore, Runtime and service logs are retained under `run313/` and `run314/`.

**Decision: PIVOT.** The real-entry dynamic metadata branch now has stronger local parity evidence, while persistent next-cycle cache and metadata semantics remain unproved. Stop synthetic-shift repeats. The next gate is an inventoried two-step real Runtime A→A/B→B same-entry branch, with complete mutable-state restoration between branches but no reset between steps, A/A restoration control, both Graph dispatch keys, and all-rank first-difference typed checks. The proposed design is `evidence/20260926_loop071_two_cycle/design.md`. Only after that gate and exposed full Target/cycle improvement should a repeated frozen formal E2E be considered.
