## Smallest defensible candidate pair

Choose **one slot, first retained Target prediction, final layer42, one BF16 wo_a group**. Let W_candidate=8,388,608 conventional operations. Do not multiply it by ranks,43 layers,7 drafts, or49,152 tokens. The selected hidden index must be the actual value of `target_logits_indices[8*slot]`, with the final-layer local row/head transformations proved; its tensor position alone is insufficient.

This can support a strict statement **within an explicit class requiring that fresh group to be evaluated conventionally on Cube**. It is not an arithmetic-complexity lower bound for every equivalent inference architecture. Restricting output memoization alone does not exclude factoring, reused intermediate projections, decision-only argmax evaluation or alternate representations. Observing a kernel and downstream read also does not prove all its arithmetic is semantically unavoidable. Preserve the broader architecture-search class as unresolved.

The matched C+ may cover all eight devices' aggregate Cube capacity even though only one group is counted; that is conservative. If Vector/Scalar/AICPU/host execution is allowed for this arithmetic, either include a justified upper envelope for those engines or keep the certificate explicitly Cube-restricted. Missing HBM/HCCL maxima do not block this compute-subset relaxation.

**Rate-boundary qualification:** the simple theorem requires a cumulative service envelope, not merely an asymptotic throughput slogan. If the only available hardware statement yields `W ≤ C+T+B` because of issue/completion, clock phase or pipeline boundary effects, use `T ≥ max(0,W−−B)/C+` and require W−>B for a positive floor. Do not invent B. Fresh input/window provenance excludes charging completed pre-window work, but the hardware certificate must still define its rate and boundary convention. A single intuitively unavoidable arithmetic operation is therefore not automatically a usable positive-time witness paired with steady-state TFLOPS.
