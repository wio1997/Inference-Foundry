# Run506 — installed-source dependency closure screen

Scope: read-only installed CANN9.1 / torch_npu2.10.0.post4 source and Run502/503 artifacts. This is a **design check**, with no service, NPU timing, correctness repeat or Bound promotion.

## What is proved by the installed method

- `NPUGraph::replay` submits the model through `aclmdlRIExecuteAsync(model_ri_, current_stream)`; the CANN9.1 API defines this as asynchronous model execution. A successful Host return proves submission, not execution completion. See the source-pinned Run469 review and the [CANN9.1 API](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/API/runtimeapi/aclcppdevg_03_1822.html).
- [CANN9.1 cross-stream capture](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/910/others/acldevg/runtime_doc_dev_0031.html) requires captured child streams to rejoin the main capture stream by events before capture ends. This is a capture-validity rule. It does not label which Run502 internal stream is the caller replay stream or expose the terminal model-notify → caller event continuation.
- The actual selected after-update callable is `AscendMLAImpl.update_graph_params`, not the DSA no-op. Installed `mla_v1.py:968–1097` returns on zero attention keys; otherwise it zips keys, params, handles and events. Each executed iteration calls task-update begin, FIA.out, task-update end and `event.record(update_stream)`. At capture, `mla_v1.py:1884–1945` waits and resets the same Python `ExternalEvent` object before adding it to the graph params list and capturing FIA in a task group. Run502 recorded the selected callable and one return, not the list lengths/iteration count or same-generation event identity.

## Typed ReduceMean screen

Run503's exact installed metadata states `ReduceMean` inputs `x, axes`, output `y`, MIX core; its object SHA matches metadata. The three aux candidates use the same `_high_precision_2100900` task name and a 160-byte argument dump. On rank0 task2788, the aux0 data pointer occurs as the fourth raw hexadecimal word; task2848 and2925 show the same pattern. The dump also has a leading untyped word, `placeHolderAddr0/1`, two workspace-looking addresses and dynamic data words. No installed exporter/launch ABI was found that maps the mixed-core placeholder fields to typed `x, axes, y` slots. Thus the fourth raw word is **only a candidate**. Deleting placeholders or shifting indices by guess would fabricate a last-writer proof. The exact model source `deepseek_v4.py:1139–1140` calls `hidden_states.mean(dim=1)` for aux outputs, but Run502 did not pin that loaded model source at capture.

Historical prior: the pinned old-environment R04 report describes an ExternalEvent-based DeviceMetadataExecutor with first-consumer waits and buffer-reuse fences, but its measured candidate covered prefill metadata and was screened at about 0.6% of that old iteration. This is a dependency-design caution, not a DP1×TP8 Target result or reason to skip the current identity certificate. Source: `dsv4f-w4a8-ascend-logs` commit `db3beef`, `rounds/R04_p1_iteration_breakdown/REPORT.md:104–125`.

## Minimum next measured certificate

The first dynamic addition should record the *actual existing update call* without inserting waits: selected main/draft branch, `num_tokens`, attention keys, lengths of `attn_params`, handles and events lists, zip iteration count, and the same Python event/handle object identities captured for the selected FULL96 entry. Record one successful method return and replay ordinal. Source control flow then determines zero versus positive begin/FIA/end/record calls; if source branch or module changes, fail closed. Keep object identity scoped to the same process/generation; never equate Python `id(event)` to a raw `EVENT_WAIT` suffix. Positive iterations require a native correlation or targeted trace before declaring which in-flight replay they release. A zero count closes only this selected-call update-work uncertainty.

Separately record semantic `mean`/final-norm output descriptors at their actual capture callsites, then bind loaded native task and overlapping writes. The terminal model notify → caller R1 relation requires supported native/correlation evidence. Only after these joins should all-rank arrival, actual concurrent resource service and necessary/attainable scheduling times be combined. No Run487 45.986 ms timing transfers to Run502 merely because the shape matches.

Decision: **continue the Scheduling certificate track**, with a minimum update-count/object-identity acquisition before any optimization. The Resource track remains open on formal-window retained first-token work and authoritative all-engine 910B3 C-plus. Formal Current571.681 tok/s and every finite Bound endpoint remain unchanged.
